# Bridge 维护规则

- 先读 README.md、status.md 和 handoffs.md；本目录负责跨端协调资料。
- 业务规则和 API 真源在 `repos/orbits`，移动实现与生成副本在 `repos/orbit-app`。不要在 bridge 内复制 DTO、实现业务逻辑或存储用户业务数据。
- 记录证据对应的日期、Git SHA、未提交状态、运行环境和验证范围。开发者未提供的信息写“待确认”，不得伪造已接单或已批准。
- 区分源码存在、静态/单元检查通过、两端真实业务验收通过和生产已部署；不能用上一层替代下一层。
- 不把同路径路由、相同页面标题或逐字相同的类型副本视为业务完全对齐。
- 使用 handoffs.md 的固定 ID 和模板；更新状态时同步能力表及 history.md。快照按日期新增，保留旧基线；同日新快照增加序号。
- 不覆盖任一端既有未提交工作；修改业务符号前仍须遵守目标目录规则与 GitNexus impact 要求。
- 本地测试凭据只保存在原有忽略环境文件。这里最多记录变量名，不记录密码、Cookie、token、数据库连接串或真实联系人数据。
- 只有具备相应授权时才修改业务、执行数据迁移、提交、推送或部署；协调记录本身不构成这些操作的授权。
