# Orbit Web ↔ App Bridge

这里是 Web 开发、App 开发和跨端协调工作的共同交接入口。建立日期：2026-09-07（Asia/Tokyo）。

目标是让两端的业务能力、数据含义、权限、操作结果和发布依赖保持一致；界面可以按桌面和手机分别设计。Bridge 管理开发状态与交接，不参与运行时请求，也不是新的业务服务或数据库同步程序。

## 本次基线

Web/API 在 `repos/orbits`，iOS-first App 在 `repos/orbit-app`。本工作区两者属于同一个 Git 根仓库，当前分支 `chat-agent`、HEAD `862cb54b4`；目录名 `repos` 不意味着本轮是两个独立 Git 分支。其他工作树、远程分支和已部署版本未在本轮核实。

静态路由覆盖已具备：43 个 Web 产品路由均能找到 App 同路径入口，App 总计 58 个路由文件。功能并未因此全部对齐：Today 数据组成、Agent 高级设置和会话历史操作已有明确差异。12 个类型文件、1 个 Schema 文件及 2 个白名单字典当前逐字一致。

这是一份本地源码与测试基线，不是生产验收。历史上的小雨原生 QA 不能代替两端当前版本的双向读写验收；`handoffs.md` 中尚未验收的事项保持开放。

## 后续使用

开始跨端任务时先读 `status.md` 和 `handoffs.md`。任一开发者改动客户端可见行为后，用模板登记交接；协调者核实另一端影响，更新能力表和证据。只在两端适配及所需验收都完成后标记 `verified`。

目前没有后台自动同步、CI 定时任务或消息推送。这里的状态由开发者和协调者在任务开始、交接和结束时维护；实际副本校验继续复用已有测试，不另建一套同步真源。
