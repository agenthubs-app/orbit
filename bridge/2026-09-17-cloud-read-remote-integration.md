## 合并策略与修复

- 精确联系人读取保留远程统一 actor 授权，也保留本地 workspace/actor/contactId 限定及生命周期阶段投影；没有恢复全量读取。

- 提醒恢复必须在远程 delivery gate 内执行；已经交给新通知通道的 actor 不再重放旧投递，纯 in-app 已投递记录允许在旧计划保存失败后完成恢复。新增组合回归覆盖这一交界。
- 报名页保留远程版本回读、取消/重新报名与 single-flight；App 同时保留 canonical 报名、动态名册权限、关系任务路由与个人日程编辑。
- 修复允许缺少 `ConnectionDTO.suggestedActions` 后，详情、关系资料、聊天和 mock 推荐仍直接下标访问的问题。只容忍可选字段缺失，不编造下一步建议；新增稀疏关系回归，并复验 PostgreSQL 接受关系详情。
- 更新测试的 canonical actor 注入、提醒真实源任务和缺失源负例。报名 route 测试移除互相覆盖作用域的第二套 fixture；没有放宽生产鉴权或数据完整性校验。
- 联系人 UI 验证区分 SSR 未确认状态与挂载后关系回读，不能用旧 fixture 状态绕过新生命周期读取。
- Ask Orbit 发送按钮恢复共享 `.btn` 基础规范，按钮检查 3/3 通过。
- App 读取清单登记实际 canonical 参会者 controller 和关系生命周期消费者，移除已废弃页面调用；沿用已有领域与版本，写操作仍是 `online_only`，不表示新接口的离线业务验收已完成。根 `+html` 是文档外壳，不算可导航产品路由。
- App 任务页两个兄弟组件原来共用 `scopeKey` 作为 React key，导致联系人选择状态被错误重置；现在分别添加 lifecycle/tools 前缀，保留账号作用域改变时重置的行为。任务页真实路由/服务交互 16/16 通过。
