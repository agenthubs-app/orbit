## 源文档正文

日期：2026-07-11
状态：已与产品负责人逐节确认，待书面复核
范围：Orbit AI（`features/orbit-ai`）的产品定位、能力边界、执行深度、主动性档位与对话层规则。活动端（NFC 互换、现场 memo、活动方生态）另立第二份设计，本文末尾只保留已确认的决定备忘。

## 1. 背景与要解决的问题

Orbit AI 当前的全部能力停留在"只读建议"：四个白名单工具（`events.recommend`、`contacts.recommend`、`followups.reviewQueue`、`chat.context`）全部是 `read` 风险级，加日历只是本地预览，邮件发送未接通。产品面临的定位问题是：

- 只做窄工具（找人、找活动、跟进、memo、日历、邮件草稿），定价能力弱、体验受限；
- 做成"无限制人脉商务 AI Chat"，则直接与前沿模型厂商在回答质量上竞争，继承无限的质量期望，且与既有产品原则（处处有据、去 AI 感）冲突。

本设计确定第三条路：**对话无边界、行动有核心的三层漏斗**。

## 2. 定位

一句话定位：**懂你人脉的商务秘书，不是什么都能聊的商务 AI。**

- 目标用户：商业活动参与者——寻找机会的创业者、需要维护潜在客户的人。
- 产品形态：线下活动 + 线上维护结合的**活动关系闭环**。
- 明确不做：面向销售的 CRM（管道、成单管理已是红海，且与活动闭环定位不符）。

Orbit AI 的护城河不在"能聊"，在三样模型厂商没有的东西：

1. **私有关系数据**——双方确认过的互换记录、会面 memo、跟进历史。
2. **主动性**——基于真实日程与关系信号，在正确的时刻主动开口。
3. **可信执行**——把内部动作真正做掉（带确认），把对外草稿备到手边。

## 3. 三层漏斗架构

```
第一层：对话入口无边界（体验层）
  任何人脉/商务问题都接得住，不生硬拒绝。
  没有工具能接的问题 → 通用对话回答，自动注入关系上下文。

第二层：能力核心有边界（信任层）
  找人、找活动、跟进、memo、日历、邮件草稿——处处有据、来源可查。
  这是产品的"脸"，宣传与收费都指向这里。

第三层：执行闭环（价值层）
  从 read 走向 draft/write：真的建跟进、真的写日历、真草稿一键交付。
  订阅费的锚点是"每周帮你完成了 N 件关系工作"，不是"能聊"。
```

### 能力取舍的判断句

一个功能要不要做，只问一句：**它在会前 / 会中 / 会后闭环里吗？**

```
会前 ── 找活动（去哪）、找人（见谁）、加日历（排进日程）
会中 ── memo / 名片互换（记下遇到的人和聊的事）
会后 ── 建议跟进、邮件草稿（把一面之缘变成关系）+ 轻量持续维护
```

与 CRM 的分界线：CRM 管"已经在管道里的客户"；Orbit 管"从活动现场到成为关系"的那段路，以及之后的轻量维护。不做管道、不做成单管理。

## 4. 执行深度：A 档（draft + 确认执行）

采用 A 档起步，架构按 B 档（授权自动）预留：

| 动作类别 | 边界 | 说明 |
|---|---|---|
| 系统内写入（建跟进任务、写日历、记 memo） | agent 备好 → 用户确认 → 执行 | 属常规风险，确认后允许真实写入 |
| 对外沟通（邮件、消息） | **只产出草稿，发送永远不属于 agent** | 不开"确认后代发"，草稿的终点是交到用户手上 |
| 授权自动执行（B 档） | 本版不开放 | 风险分级（`read/draft/write/external`）与 autonomy settings 脚手架已在，待真实用户建立信任后逐动作开放 |
| 全自动（含自动发邮件） | 永久不做 | 一封发错的邮件毁掉的是用户的真实人脉 |

安全模型一句话：**Orbit 的手永远伸不出你的系统**——它能替你整理内部，但任何触达别人的动作，最后一下永远是用户自己按的。

既有安全边界继续全部生效：不执行任意 shell、不让模型定义工具、写入必须经过 confirmation / sandbox preview / audit、缺 provider key 时 fail closed、artifact 只是可复核视图。系统内写入从"预览"升级为"确认后真实执行"时，必须走 Actions 模块（action queue + confirmation + audit ledger），不允许 Orbit AI 绕过 Actions 直接写。

## 5. 主动性：档位 2（会敲门）

- 关键时机可以推送到手机：会后跟进窗口、活动前提醒、答应过的事到期——只在"错过就有真实代价"的时机敲门。
- 推送点开直接深链回 Orbit AI 聊天中对应的 proactive 消息 + 待确认草稿。
- 必须有频控与免打扰，用户可按类别关闭。
- Notifications 模块继续只负责底层投递与 deep link，不生成 proactive 文案（沿用现有边界）。
- 不做档位 3（高频提醒、升级催办）：秘书不能变成闹钟。

主动性是 A 档确认模式下"秘书在干活"体感的主要来源，是收费体验的核心。

## 6. 对话层规则（第一层）

1. **接得住**：人脉/商务相关的通用问题不生硬拒绝，给出通用回答。
2. **注入上下文**：回答时若存在相关关系上下文（认识的人、见过的面、聊过的事），自动注入，使回答质量高于裸问通用模型。
3. **引导回产品**：回答末尾在真的相关时自然引回产品能力（如"要我在你的人脉里找找有没有懂这个的人？"）。
4. **克制原则**：引导必须真的相关才出现，不硬塞——避免"去 AI 感"退化成"推销感"。
5. **不承诺**：不宣传、不承诺行业研究、合同分析、商业咨询这类纯知识问答的深度质量；礼貌地答，不为此负责。

## 7. 不做清单

- CRM 管道、成单管理、群发营销、线索购买。
- "无限制 AI Chat"定位（与"处处有据"冲突）。
- 自动发送邮件/消息（任何档位、任何授权形式）。
- 高频催办式主动性（档位 3）。
- 活动现场全场自动录音（理由见第 9 节备忘，永久出局）。

## 9. 活动端已确认决定（备忘，另立设计展开）

以下决定已与产品负责人确认，供第二份设计（活动端互换与生态）直接采用：

1. **互换即关系**：只有双方同意交换名片才成为好友；不提供"一键添加全场参会者"，保护活动方利益（参会名单不外泄、无法扫场子）。
2. **NFC-first，不做扫码主入口**：微信统治扫码心智，QR 只留深处兜底不宣传。载体为活动 NFC 胸牌（NTAG 贴纸级成本）与个人 NFC 名片卡；不做手机碰手机（iOS 不向第三方开放）。
3. **Consent 模型 A**：碰即成为好友（物理递卡动作即同意）+ 被碰方即时推送通知 + 一键移除；预留设置开关切换为"碰=发请求"（C 模型的开关位）。防批量收割靠物理一对一限制。
4. **病毒环**：被碰方无需装 app 即可经网页完成互换，装 app 的动机是"管理刚认识的人"。
5. **"碰一下 + 说一句"取代全场录音**：碰卡解决"对方是谁"（100% 精度），聊完后用户按住说 15 秒要点 → ASR → agent 结构化成 encounter note → 会后 proactive 提醒跟进。录的是自己的声音，零旁观者 consent 问题。
6. **全场自动录音永久出局**：说话人识别在嘈杂现场无解到可用级别且错误代价致命；旁观者 consent 无法律兜底；与信任模型自相矛盾。
7. **原生 app 计划确认存在**：iOS/Android app 在路线图上；档位 2 主动性的可靠 push 依赖它。
8. **活动方价值包方向**：会前匹配提升报名转化（"这场有 N 位你想认识的人"）、会后聚合 ROI 报告（促成 N 次互换/跟进）、NFC 胸牌套件作为活动增值服务。
