# Sprint AG00 — 在本机搭好 Agent 的测试环境，并给现有 Agent 记一次基线

## 要实现什么

在本机搭一套只给测试用的 Orbit：专用的数据库、服务、文件目录和日志目录。三个测试账号的数据由 Orbit 自己的保存功能生成，存成快照。一个运行器扮演网页和手机，像真人一样发消息、点按钮，把每一步都记进日志，再用机器检查和 Claude 评审得出结果。最后用现有的 Agent 把全部 222 个可见用例跑一遍，记成基线。这个 sprint 不改 Agent 的任何行为。

## 做完能看到什么

- 一条命令建好测试库、在 3100 端口起好服务并自检。测试期间只连得上 DeepSeek 和 Gemini，其他对外连接一律拦下并记录，出现一次这次运行就作废。
- 小、常规、较大三个账号（另有一个只用来检验隔离的账号乙）的人脉、笔记、待办、日程、活动、记忆和旧对话，数量与夹具一致；每次运行都从同一份快照恢复，起点相同。
- 每次运行留下一个目录：每个用例的对话、逐事件日志、数据前后差异、机器检查结果和评审材料；另有调用次数、用量、费用和 DeepSeek 余额。日志里没有密钥。
- 四个故意做坏的假 Agent（没等点击就写入、读了别人的数据、悄悄改数据不留记录、多说一句没依据的话）都会被抓出来。

## 怎么验收

- 测试：用例校验器能指出哪条用例写错了或引用了不存在的记录；拦截、快照、日志、费用和每一项机器检查各有自动测试，测试本身不花钱。
- 门槛运行：H 区 8 个用例在一次完整运行里全部通过（往外连的那一例按规定单独跑一次），每例由两个互不相见的 Claude 会话各评一次。
- 基线：现有 Agent 跑完全部可见用例，结果登记为 `RUNS.md` 的第一行。
- 不变：不设测试变量时，产品的行为和全套测试结果与开工前相同。
