# Sprint AG08 — 判断模型接入：先用规则筛，再交给判断模型

## 要实现什么

Orbit 里有几类步骤只需要在固定的几个选项里选一个：这个候选对不对口，这句话是不是要改记录，这条和已有的是不是同一件事，这段原文能不能支撑结论。这些步骤改由判断模型来答。候选太多时先用规则筛掉不相干的，只把排在前面的一小批送去判断。判断没把握、超时或不可用时，一律走保守的做法，不替用户做决定。

## 做完能看到什么

- 在两千位联系人里说“挑三个最适合聊独立出版的人”：送去判断的最多 50 位，判断只请求一次；回答写明细看了多少位、还有多少位没细看，不把这三位说成全部联系人里最合适的。
- 只按日期或时间排的清单，比如最久没联系的十位、活动按开始时间排，完全不调判断。
- 判断超时，照样按记录里的标签和时间排好交付，并说明这次没做主题匹配。
- 说“小林今天来电话了”，即使主模型误以为要记一笔，复核后也不出卡，只附一个“记到小林的往来里”的入口。
- 说“记一下：今天早上在车站碰到了小林”，而已有一篇笔记可能就是同一次时，请用户核对，不自动合并，也不自动新增。
- 每道题在中文、日文、英文上各自校准过门槛才启用，校准记录随代码一起交付；没校准的题不启用。

## 怎么验收

- 测试：判断接口的请求格式、3 秒超时和各种失败；送判断的候选上限（对话 50、定时任务 30）和覆盖范围；低于门槛、没校准时的保守结果；写入意图复核在什么情况下触发。
- 离线用例：判断区 8 例，加常规账号、较大账号各 1 例，连同不变量包在同一次完整运行里全部通过，每例由两个互不相见的 Claude 会话各评一次。判断模型只是被测对象，不参与打分。
- 校准记录：每题每种语言的样本数、选定的门槛和样本上的结果；样本不够的题如实标为未启用。
