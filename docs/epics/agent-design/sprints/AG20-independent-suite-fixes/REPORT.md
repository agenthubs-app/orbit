## 给产品负责人的决定（两条线提出的）

1. R1：一句话不会把卡清空，去掉最后一项时说「请点拒绝」（拒绝仍要点）；别的项依赖着的那一项（一场活动和它的「我去过」）不能单独去掉，会告诉用户。
2. R1：卡上有几项带日期时说「改到周五」，会问改哪一项，从不替用户选；改日程的「换一天」（不是换时间）不按话改。等确认的卡不列进第一层的待处理事项（那样每次有卡在等都会改变第一层的提示和路由），由代码在图之前认出改卡的话。
3. R5：有日子没钟点就是全天的私人活动。
4. R6：日程里点名的人不在联系人里，就建一个不挂人的日程。
5. R7：只说「最迟周五」现在是截止（原来算计划日），按设计稿 §3.5。
6. R18：跟进待办的日子只取用户说的；对方自己的截止留在笔记原文里。
7. 产品决定 8：卡上的钟点仍按部署所在时区显示（卡没有自己的时区）；人在外地时看到的截止时间是换算过的。把本轮时区带进冻结的卡要改账本，这次没做。
8. 产品决定 2：过时的几项和它们的值在会话状态里留一轮（短值和记录编号），这是「会话只存编号和名称」的一个例外；出卡前会再对一遍记录。
9. AG20b：第一层给出 `rank.basis` 时那几个字会变成排序主题（AE-ANS-010、AE-JDG-003）——这是热修复那条线的规则，已在热修复 1c 里改。联网查找的第二道把关没动，改它问模型的字需要重新校准。
