# Sprint AG04 — 没听懂时怎么办：按规则追问，答了就接上，不答也不纠缠

## 要实现什么

用户的话不清楚时，下一步由代码按设计稿 §3.11 的六种情况来定，不让模型临场发挥：读不出要做什么就说没看懂并给几个能点的方向；只是陈述或假设就照常回应、不提修改；只读的事按最可能的意思先做并写明是怎么理解的；要改记录却缺一项或有几种读法的，问一句再做。问过的事，用户点选或用文字回答都能接回原来那件事；用户不理会去说别的，也照常处理。

## 做完能看到什么

- 只发“小林”或“えっと…”，回一句没看懂，下面是两三个能点的方向，比如查资料、记一笔、设个提醒；这一轮不读任何资料。
- 说“小林今天来电话了”或“如果 Emily 周五前没发，我大概该建个待办”，Orbit 正常回应，不出确认卡，最多附一个“要记下来吗”的入口，用户点了才算提出。
- @ 一篇笔记说“帮我看看”，按“看摘要”来做，开头写明是这么理解的；说“帮我处理一下小林那件事”，先列出几种读法让用户选，不自己挑。
- 在追问下点了某个人，原来那件事从这里接着做，不再问第二遍；一句话既回答了追问又提了新问题，两件都有回应。
- 每件事最多问一次；用户不答去说别的，新问题照常回答，原来的追问隔两条消息后放下，标为没做完。

## 怎么验收

开发测试覆盖六种情况的判定、可点方向从哪来、消息接到哪件事上、追问暂停后恢复不重复调用模型，都用模拟的模型。

Agent 测试在本机隔离环境里跑本 sprint 的门槛：需求不清楚 12 例，加全部不变量用例；因为本 sprint 替换了 AG03 的简易追问，再跑一次 AG03 的门槛确认没有退步。真实调用 DeepSeek，每例两次独立评审都通过，日志和费用登记进运行台账。收口时跑一次全量测试，失败清单不新增。
