# Sprint AG02 — 一张卡只能由用户点按钮批准，而且只执行一次

## 要实现什么

Agent 准备好的修改会出成一张确认卡。这个 sprint 让这张卡只认用户在卡上的点击：打字说“好的”“确认”不算，模型自己说“已批准”也不算；两端同时点、连点、超时重发，都只批准一次、只执行一次；卡放过期了、被否决或取消了、内容或要改的数据已经变了，点了都不会执行旧内容。新的对话入口上，原来那条“不经卡片直接建待办”的路和“打字确认草稿”的路一起关掉。这个 sprint 不新增能执行的操作种类。

## 做完能看到什么

- 网页和手机同时点确认，只有一份批准，待办只建一条；同一次点击原样重发，拿回第一次的结果并标明是重复提交。
- 在对话里打“确认”“好的”“OK です”，卡仍然在等点击，回复会提醒用户点卡上的按钮。
- 别处先改了卡上要改的那条记录，或改了用来认出它的名称，点确认时卡提示“内容有变化，请再看一遍”，按现在的数据出新一版，不执行旧的。
- 卡放了 7 天以上、已否决、已取消，点了都是零写入；过期的卡可以重新生成，新版本仍要再点一次。
- 执行结果不清楚的那一项单独列为“需要核对”，可以重试、标为已完成或放弃，每种都留回执；重试不会多建一条。

## 怎么验收

- 测试：并发点击只批准一次；批准和出队在同一个事务里；重复的决定返回第一次的结果；文字和模型给的批准标志都被拒收；旧版本和变化了的内容不执行；过期、否决、取消零写入；待核对的三种处理各留回执、重试不重复。
- 门槛运行：BND 区 12 个用例和不变量包在一次完整运行里通过，每例由两个互不相见的 Claude 会话各评一次。
- 全套测试与开工前对比，没有新增失败；共享契约有改动时 App 的四个同步测试为绿。
