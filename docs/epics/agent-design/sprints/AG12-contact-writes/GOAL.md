# Sprint AG12 — 在对话里加人、改资料、删人、恢复和批量导入，都先看卡再点确认

## 要实现什么

用户在对话里说「加一位联系人」「把田中的职位改成采购部长」「把李薇删掉」「把前几天删的李薇恢复」或贴一段名单要导入，Orbit 都先出一张确认卡，写清要动哪一位、哪一项从什么改成什么；用户点了确认才改。每位联系人带一个修改次数的记号，每改一次加一，卡上记下当时的记号，点确认时对不上就不改。邮箱、电话这类联系方式，没有单独允许时不发给模型。

## 做完能看到什么

- 新加的人和已有的人很像（同名同公司，或只差一两个字）时，先列出已有的那几位请用户核对，并给「都不是，另建一位」；选了已有的就不新建，也不自动合并。
- 改资料只动说到的那一项，改前的值在「以前的值」里查得到；卡出来之后这一项在别处被改了，点确认不会覆盖，而是按现在的值重出一张卡。
- 删人的卡上列出她名下的笔记和待办，并写明这些不会被删、30 天内能恢复；恢复走同一种卡，恢复的是原来那一位。
- 贴一段名单导入时，卡上逐行写新增、可能重复、跳过及原因；说「第一行也新建」后卡片按新决定重出。

## 怎么验收

- 测试：每种改动在点击前零写入、点击后变化与卡上一致；修改次数记号在每次写入后加一，对不上时返回冲突；删除后笔记和待办原样；导入逐行归类；联系方式在所有发往模型的内容里都不出现。
- Agent 用例：联系人区 8 例和分给本 sprint 的 2 个大账号用例，在一次完整运行里全部通过，每例由两个互不相见的 Claude 会话各评一次；此前通过的用例不退步。
- 真实界面：同一张联系人卡在 Web 和 App 上各看一次，内容一致。
