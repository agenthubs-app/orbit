# Sprint AG03 — 一句话拆成几件事，各有去处；普通聊天直接回答

## 要实现什么

用户在新的对话入口发一句话，Orbit 先把它拆成几件要办的事，再由代码给每件事定去处：Orbit 自己做、换个做法再做、建议交给用户自己的 Codex 或 Claude，或者说明做不了。只是聊天的，一次模型调用就直接回答。这一轮还不读用户的资料，也不提出修改；需要读资料或修改的事先标好去处，告诉用户这次还没做。

## 做完能看到什么

- 发“帮我看看田中上次访谈里最在意什么，再查一下 Acme Cloud 官网的价格，另外做一份日本 SaaS 市场的进入调研”，结果里是三件事：前两件由 Orbit 承接，第三件建议交给外部 Agent；每件事引用的原话都能在原句里找到。
- 说了“等等，先别改”，或者用“如果……”提的假设，都不会被当成修改要求；要读另一个账号的笔记，回答说明没有授权，也不建议绕道。
- 问“第一封邮件是直接说来意好，还是先寒暄好”，直接得到建议，日志里没有读取任何资料。
- “他”“第二个”“那篇笔记”按最近 10 条消息和会话里记下的编号来认；隔了 60 分钟以上再说“他”，先问是哪一位，上次提到的人排第一；早先说过的请求不会再办一遍。
- 模型输出格式不对时只补救一次；一轮最多调用 4 次模型，用完就交付已经定下的部分，写明哪几件没做完、为什么没做完。

## 怎么验收

开发测试覆盖拆分和原话核对、去处判据、上文怎么取（10 条、60 分钟、只留编号）、补救一次和调用上限，全部用模拟的模型，不花钱。

Agent 测试在本机的隔离环境里跑本 sprint 的门槛：理解与去处 14 例、上文 8 例、常规和较大账号上的长对话 3 例，再加全部不变量用例。被测 Agent 真实调用 DeepSeek，每例由两个互不相见的 Claude 会话各评一次，都通过才算过；日志和费用登记进运行台账。

收口时跑一次全量测试，与开工前的失败清单对比，不能有新增。
