# Sprint AG19 — 回答要有排版，列出的每条记录都是一张能点进去的卡片

## 为什么做

2026-11-19 用户在正式站用 App 第 18 版问「最近有哪些活动适合我？」，得到三行纯文字。用户原话：「回答没有好的 layout 和字体安排，看起来很费劲」「推荐活动没有给出活动的卡片！我需要能够通过这个卡片连接到活动页面」。前面各 sprint 的验收和评测只看了文字内容，没有看「回答里的记录能不能点」。

## 要实现什么

iOrbit 的回答分成两种摆法，都由程序排版：

- **列表类**（有哪些活动、哪些待办、哪些人）：一句导语，下面每条记录一张卡片，整张可点，点了进那条记录的页面。活动、联系人、待办、笔记、日程、「我去过」用同一种卡片。
- **讨论、建议类**：第一句是结论，加粗；后面分短段，有几点列几点；文字下面放提到的记录的小卡片。

「这次没做的部分」收进一块灰底的说明条，和回答分开。正文字号放大、行距拉开。

## 做完能看到什么

- 问「最近有哪些活动适合我」，回答是一句导语加几张活动卡片，卡片上有类型、时间、名称、地点；点一张进那场活动的页面。App 和网页都一样。
- 列出的记录超过 5 条时先放 5 张，下面一行「还有 N 条」，点一下原地展开。
- 待办卡片打开的是那一条待办，不是待办列表。
- 回答里不再出现星号、井号这类符号。
- 「最近」只列还没开始的活动，最近的在前。紧跟着列表问「哪些值得去？为什么？」，接着刚才那份列表回答，不会被拆开或拒绝。

## 怎么验收

- 测试：结果文档里带结构化条目（类型、编号、标题、时间地点、顺序）；两端的链接表覆盖六类记录；旧版 App 只读文字时内容仍完整。
- Agent 用例：新增「回答排版」区，在同一次完整运行里全部通过，每例两次独立评审。
- 真实界面：网页 1440、375 宽和手机 App 各截图，与获批视觉稿逐块对照。
