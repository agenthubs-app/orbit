## 做法要点

1. **契约。** 在 `answer` 里新增有序的结构化内容（建议名 `blocks`），至少能表达：结论句、段落、要点列表、记录卡片组（含先显示几张）、说明条。记录条目带 `kind`、`id`、`title`、上行、下行、可选的一句理由、是否已不在；笔记条目带关联联系人的编号，供网页按 D5 选去处。新增字段全部可选，旧客户端忽略即可。形状以能干净实现视觉稿为准，定稿写进 REPORT。同一提交里跑 App 同步脚本和四个同步测试，更新契约快照。
2. **服务端。**
   - 代码写的列表、排序、提取类回答：直接从手里的记录生成卡片组和文字版，不经过模型。
   - 模型写的讨论类回答：让模型按结构化输出填「结论、段落、要点」，代码据此生成 `blocks` 和 `text`；模型输出里夹带的 Markdown 符号由代码清掉。结构化输出不合规时退回到「整段当一个段落」，不丢回答。
   - 回答提到的记录（已有的出处链接）转成小卡片；同一条记录不出现两次。
   - 「没做的部分」（被拒、未完成的子目标）转成说明条。
3. **网页。** 按 `blocks` 渲染；卡片的去处：活动→活动页，联系人→联系人页，待办→单条，笔记→D5，日程→日程所在页并定位到那一条，我去过→对应活动的「我去过」。出了卡片就不再重复那排小标签。
4. **App。** 同上；`agentLinkHref` 补齐活动、日程、单条待办、我去过。
5. **内容规则（SC6）。** 「最近」的默认时间方向、列表后的追问承接，都放在代码里，各有单元测试和 Agent 用例。
6. **评测。** 新增用例区 `ANS`（放 `docs/epics/agent-design/eval/cases/ANS.yaml`，8～10 例，`sprint: AG19`），覆盖：活动列表、超过 5 条、联系人列表、待办列表、笔记或日程、讨论类、带「没做的部分」、最近的活动只取未来、列表后追问、三个账号里的常规或较大账号至少 2 例。新增代码判定：结果文档的卡片条目与期望的记录编号、类型、顺序一致；`text` 无 Markdown 符号。运行器缺的检查按 eval README §3.4 的含义补在 `repos/orbits/tests/agent-eval/`。在 `SPRINTS.md` 登记表加 AG19 一行、在 `SPRINT_EXECUTION_ORDER` 里把 AG19 排在 AG11 之后（本 sprint 是新开的，允许改这两处；`RUNS.md` 仍由协调者登记）。
7. **真实界面。** 网页用自己写的无头浏览器脚本在本线端口上截 1440 和 375；App 在模拟器上连本线服务截图（先占 `sim` 槽）。与视觉稿并排放进证据目录。
