# Sprint AG07 — 网页和手机上看到的是同一张确认卡

## 要实现什么

在网页和手机 App 的对话里各放上新的确认卡。两端都只照着服务端给的同一份内容显示：卡顶一句「修改 1 项，新增 1 项」，每项写清改的是哪条、原来是什么、改成什么，下面两个按钮「确认以上 2 项」「不改了」。一端点了，另一端也跟着显示同样的结果。对话里另有四处小改动：排队时显示「已收到，等前一条处理完」，回答开头有一行依据，追问下面列出可点的候选，处理中显示「正在查你的笔记」这类进度。

## 做完能看到什么

- 小林那句话发出后，网页和手机上的卡逐字相同；在手机上提出、网页上确认，手机随即显示「已完成」。
- 卡放太久再去点，显示「这张卡放太久了，要重新生成一张吗？」；网页上点了「不改了」，手机重新联网后显示「已取消」。
- 手机离线时只显示「有 1 份待确认的修改」和「联网后才能确认」，看不到具体内容，也点不了；重新联网后不会把离线时的那一下补发出去。
- 手机上有一条还没同步的修改正好碰到卡上的记录时，确认按钮不可用，旁边写「先同步你的修改」；同步完卡上按最新数据重写，提示内容有变化、请再看一遍。

## 怎么验收

- 开工前提：确认卡和这四处小改动的手机稿、网页稿已由用户批准。没有批准不动界面代码。
- 测试：两端的卡片组件、离线、未同步修改各有测试；卡上的文字不出现「操作」「版本」「证据」「来源」这类内部词。
- 真实页面：网页在桌面 1440 宽和手机 375 宽各看一次，手机 App 在 375 宽的模拟器上看一次，两端登录同一个测试账号、看同一张卡。
- Agent 测试：本 sprint 的 6 个门槛用例和每个 sprint 都要跑的安全检查用例，在同一次完整运行里全部通过，每例由两个互不相见的 Claude 会话各评一次；真实模型调用每次完整运行不超过 30 元，合计不超过 150 元。
