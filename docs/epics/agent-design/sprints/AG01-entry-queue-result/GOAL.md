# Sprint AG01 — 发消息马上有回应，结果按编号随后取，同一个对话一条一条处理

## 要实现什么

用户发一条消息，马上收到“已收到”和一个编号，不用等 Agent 想完。结果做好后，凭这个编号随时能取到，断网或换一台设备也是同一份。同一个对话里的消息按收到的先后一条一条处理，正在处理时又来的消息排到下一轮；用户可以停掉正在处理的那一轮。新的做法放在一个开关后面，只读不写，处理仍交给现有的 Agent。

## 做完能看到什么

- 开关打开后，发消息立刻返回编号和状态（排队中或处理中）。同一条消息因为超时重发，拿回的还是原来的编号，不会被处理第二次。
- 网页和手机同时往同一个对话发消息，各得一个结果，按服务器收到的先后处理；处理中途发来的更正，等前一条答完再答，不打断也不合并。
- 发完就断网、换设备，按编号读到的结果和一直在线的那一端逐项一致；实时推送断了，重连后从断开的地方接着收。
- 点停止，这一轮结束，已经给出的内容留着，排在后面的消息照常处理。
- 开关关着时，发送和读取与现在完全一样。

## 怎么验收

- 测试：发送在模型返回之前就应答；重发不产生第二次处理；同一对话同时只有一轮在跑；按编号读取的结果在各端一致，别的账号读不到；实时通道断线后按序号续传；停止后不再调模型，迟到的结果不算交付；开关关着时旧协议原样不变。
- 门槛运行：ENT 区 8 个用例在一次完整运行里全部通过，每例由两个互不相见的 Claude 会话各评一次。
- 全套测试与开工前对比，没有新增失败；共享契约改动后 App 的四个同步测试为绿。
