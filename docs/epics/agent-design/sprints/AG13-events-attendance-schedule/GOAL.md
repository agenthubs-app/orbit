# Sprint AG13 — 自己的活动、「我去过」、日程和待办关联，都能在对话里经确认卡改

## 要实现什么

用户可以在对话里让 Orbit 建一场只有自己看得到的私人活动，记下「我去过」哪场活动（平台活动或私人活动都行），增改删自己的日程，给待办同时关联几个人和几场活动。每一项都先出确认卡，点了才改。自己记的「我去过」和主办方的签到、报名、日程三样东西分开存，谁也不替谁写。

## 做完能看到什么

- 说「11 月 14 日我去了大学同学聚会，Orbit 里还没有」，一张卡上两项：先建这场活动，再记我去过；活动没建成，第二项就跳过，不会留下一条没有归属的记录。
- 每周的周会说「只改明天这一次」，只动那一天，以后的照旧；说「整个系列」才改每一周。「隔周」「每月第二个周二」这种现在做不到，Orbit 直说，并给出能做的办法。
- 删一场被笔记、待办、「我去过」用到的私人活动，Orbit 先逐项列出来让用户选怎么处理；处理完还有别的引用（比如刚有人关联上），活动就保留并说明原因。
- 一条待办可以关联多个人、多场活动；旧版 App 只改了待办标题，这些关联一个不少。
- 「我的活动」里，自己记的显示为「我去过（自己记的）」，不会变成「已参加」。

## 怎么验收

- 测试：两个新存储的增改删、同一场活动只能记一次「我去过」、卡内先后依赖、重复日程的「仅本次」和「整个系列」、删除前后的引用检查、旧接口只改标题时关联保留。新的存储结构只在本机库上建好并验证，不碰正式库。
- Agent 用例：活动区 12 例和分给本 sprint 的 2 个大账号用例，在一次完整运行里全部通过，每例由两个互不相见的 Claude 会话各评一次；此前通过的用例不退步。
- 真实界面：「我的活动」在 Web 和 App 上各看一次；界面改动的样子先经你批准。
