# agent-design 的 Sprint 计划

本页是本 epic 的登记表和各 sprint 的契约摘要。每个 sprint 的 `GOAL.md` 和 `PLANNER.md`（含上下文包）已写好，放在 `sprints/AGnn-名称/` 下；本页的验收项原样进入 PLANNER，不得降低。各 sprint 共用的目录、接口名、开关和评测命令见 [sprints/CONVENTIONS.md](sprints/CONVENTIONS.md)。

PLANNER 是在所有 sprint 动工之前一次写成的，所以后面 sprint 的“前序交接要点”写的是约定而不是已经存在的代码。每个 sprint 启动时，先按前序 REPORT 核对自己的上下文包，有出入就追加更正记录，原文和原哈希保留。

测试的六条要求见 [eval/README.md](eval/README.md) 第 1 节：从产品的正常入口执行、三个规模的账号、带干扰的数据、全部在本机运行、真实模型调用与模拟分开记录、记录费用。

每个 sprint 的完成条件有三条，缺一不可：

1. 本页列出的验收项都有证据。
2. 该 sprint 的门槛用例在一次完整运行里全部通过，日志和评审结果登记在 [eval/RUNS.md](eval/RUNS.md)。
3. 不变量包全部通过，此前已通过的用例没有退步。

可见用例共 232 例，封存集 30 例。SCL 是跑在常规和较大两个账号上的用例，带同名、多实体关联、跨页、新旧冲突和长对话五类干扰；其余各区跑在小账号上。涉及读写数据的 sprint，门槛里三个账号的用例都要有。不变量包是可见用例里标了 `invariant: true` 的那些，从 AG02 起每个 sprint 都跑。

**门槛归属。** 用例的 `sprint` 字段写的是它检验哪个 sprint 的验收项；带 `gate` 字段的用例要用到更晚才交付的能力，门槛顺延到 `gate` 所写的 sprint。上表的门槛数按顺延之后计。不变量包在 AGnn 的门槛里只包含顺延之后不晚于 AGnn 的不变量用例。“早晚”按执行顺序算，不按编号：各 sprint 排在它依赖的 sprint 之后，AG11 依赖 AG13，所以顺序是 … AG10、AG12、AG13、AG11、AG14 …（评测代码的 `SPRINT_EXECUTION_ORDER`，测试按本表的依赖列核对；2026-11-18 AG12 run-02 起）。

**AG02 用预置的卡。** 确认边界的 12 例都要先由 Agent 从一句话出卡，这要到 AG06 才有。AG02 的门槛运行加 `--seed-cards`：运行器把用例里 `card_ops` 描述的那张卡以“来自对话”的出处直接预置进账本，后面的点击、重发、文字“确认”、过期等步骤照常从正常入口执行。AG06 起这 12 例按完整对话重跑，并列入 AG06 的门槛。

**不跑常规和较大账号的 sprint。** AG00、AG01、AG02、AG04、AG07、AG16 不实现业务数据的读写逻辑，门槛里没有 SCL 用例；AG18 跑全部用例。

## 阶段一　底座

### AG00　本机环境、评测底座与基线

**目标。** 一组离线用例能在本机的隔离环境里、从产品的正常入口跑完，留下完整日志，并由 Claude 评审出结果。

**范围。** 本机专用的数据库、应用服务、存储目录和日志目录；对外连接只放行 DeepSeek 与 Gemini 的守卫；小、常规、较大三个账号的数据经产品写入链路生成并存成快照；批量记录的生成器；用例与夹具的校验器；固定时钟和时区；联网回放；扮演客户端发消息、点按钮的运行器；逐事件的追踪日志；真实调用与模拟分开记录；费用与余额记录；代码判定；评审材料与评审结果的汇总；运行台账。

**不做。** 不改 Agent 的任何行为。

| 验收 | 可观察的结果 |
|---|---|
| AG00-1 | 校验器拒绝不合规的用例和引用了不存在记录的用例，并指出是哪一条。 |
| AG00-2 | 数据库、应用服务、存储和日志都在本机专用的一份里；运行期间除 DeepSeek 与 Gemini 外的对外连接被拦下并记录；三个账号的数据量与夹具规定一致，可从快照恢复到相同起点。 |
| AG00-3 | 一次运行从产品的正常入口执行，产出规范里的全部文件。抽三例核对：每次模型请求与响应、每次读取和写入、每张卡片都在日志里，没有密钥；真实调用与模拟分开计数；费用和 DeepSeek 余额有记录。 |
| AG00-4 | 判定可信：注入“未点击就写入”“读了另一个账号”的假实现时，代码判定把对应用例判为不通过；评审逐条引用日志序号，两次独立评审不一致的条目被标出。 |
| AG00-5 | 用现有 Agent 把全部可见用例跑一遍，登记为基线。 |

### AG01　入口、排队与结果文档

**目标。** 发消息立即得到应答，结果随后按编号取得；同一会话的消息按顺序处理。

**范围。** 协议版本 3 的发送；入口记录与去重；同一会话的顺序处理和中途到达的处理；结果文档与按 `requestId` 读取；可选的实时通道；停止当前这一轮；排队时长等指标。新入口放在功能开关后面，只读，处理部分先接现有运行时。

**不做。** 不改模型步骤，不开放写入。

| 验收 | 可观察的结果 |
|---|---|
| AG01-1 | 发送在模型跑完之前返回 `requestId` 和状态；同一客户端消息键重发，返回原委托，不产生第二次。 |
| AG01-2 | 同一会话里两端同时发消息，按接收顺序各得一个结果；处理中又来的消息排到下一轮。 |
| AG01-3 | 发送后断线、换设备，再按 `requestId` 读，得到与一直在线时逐项一致的结果。 |
| AG01-4 | 实时通道断开后重连能续上；只在通道里出现过的片段不算已交付。 |
| AG01-5 | 点停止后当前这一轮结束，已交付的部分保留，排在后面的消息继续处理。 |

### AG02　账本升级与确认边界

**目标。** 一张卡只能由用户的点击批准，且只执行一次；文字、过期的卡、旧版本都不能执行。

**范围。** 批准与出队合成一个事务并加条件更新；SHA‑256 哈希覆盖卡上可见内容；`origin`、`revision`、`expiresAt`；决定接口的幂等；过期；待核对项的三种处理；在新入口上关闭 Todo 直写和实体草稿的文字确认。

**不做。** 除待办的新建和修改两个执行器外，不新增领域执行器（其余从 AG06 起）。这两个执行器用来执行门槛运行里预置的卡。

| 验收 | 可观察的结果 |
|---|---|
| AG02-1 | 两端同时点确认，只有一份批准，每项最多一次业务效果。 |
| AG02-2 | 输入“好的”“确认”不会执行任何卡；模型给出的批准标志被拒收。 |
| AG02-3 | 卡片内容或目标数据变了，旧版本的点击返回最新状态并出新差异，不执行旧内容。 |
| AG02-4 | 过期、已否决、已取消的卡点击后零写入；重新生成得到新版本。 |
| AG02-5 | 执行结果未知的项进入待核对，重试、标为已完成、放弃各留回执，重试不产生第二条记录。 |

## 阶段二　小林切片

### AG03　流程骨架与第一层

**目标。** 一句话被拆成子目标并各自得到正确的去向；普通讨论直接回答。

**范围。** 接入 LangGraph；`intake`、`understand`、`route`、`answer`、`deliver` 五个节点；第一层的结构化输出与校验；承接三结论与去向；上文四样；调用预算。主模型改用 `deepseek-flash`。

**不做。** 不读业务记录（AG05），不提写入（AG06）。

| 验收 | 可观察的结果 |
|---|---|
| AG03-1 | 一句含三件事的话被拆成三个子目标，各自的原话引用是原句的子串，否定和先后关系保留。 |
| AG03-2 | 每个子目标的承接结论和去向符合设计稿 §3.1 的判据，包括建议外部 Agent 和无权限两种。 |
| AG03-3 | 普通讨论直接回答，日志里没有私有读取，也没有写入提议。 |
| AG03-4 | 上文按 §3.10 取：指代能解析；空闲超过 60 分钟后不猜对象；旧消息里的请求不被再次执行。 |
| AG03-5 | 模型输出不合规时最多修复一次；到调用上限就交付已确定的部分并列出未完成项。 |

### AG04　需求不清楚、追问与归属

**目标。** 需求模糊时按固定的规则决定下一步，追问有答就接上，没答也不纠缠。

**范围。** §3.11 的六种情况；可点方向的来源；追问的暂停与恢复；点选绑定；新消息归属到追问、卡片或新委托；一个子目标只问一次。

| 验收 | 可观察的结果 |
|---|---|
| AG04-1 | 读不出需求时零数据读取，回一句没看懂并给可点的方向，方向都是 Orbit 能做的事。 |
| AG04-2 | 陈述和假设不出卡；可附一个入口，用户点了才算提出。 |
| AG04-3 | 只读的多种读法按最可能的做并写明理解；涉及写入的不猜，列出读法让用户选。 |
| AG04-4 | 在追问下点选或用文字回答，原委托从该处恢复；一句话同时回答追问并提新请求时两者都被处理。 |
| AG04-5 | 每个子目标最多追问一次；用户不答而说别的，按新委托处理，原追问在两条消息后搁置。 |

### AG05　读取与带出处的回答

**目标。** 用户问自己的资料，得到有依据的回答，依据能打开。

**范围。** 五类现有记录的授权读取适配器；三个读取视图，其中“最近互动”从真实往来算出；六类引用的服务端授权；带引用的回答与代码校验；空结果、部分可读、读取失败三种情况的区分。

**不做。** 判断模型的证据核对在 AG08 接入。

| 验收 | 可观察的结果 |
|---|---|
| AG05-1 | “上次和小林聊了什么”得到 11 月 12 日那篇笔记的要点，引用指向原笔记。 |
| AG05-2 | 读取只发生在当前账号和工作区内；另一个账号的记录在回答和日志里都不出现。 |
| AG05-3 | 回答里的每条引用都属于本轮读过的记录；没有依据的内容不出现。 |
| AG05-4 | 没有记录、部分读不到、服务出错三种情况各有不同的说明，不把读不到说成没有。 |
| AG05-5 | 活动和笔记的引用经过授权才生效；已删除或撤权的引用提示重新选择，其余部分照常交付。 |

### AG06　小林切片：一张卡改待办、记往来

**目标。** 设计稿 §1 的那句话端到端可用：一个回答，一张卡，两项变化，点击后执行并有回执。

**范围。** 第二层提出操作；定位、消歧与依赖；`todo.update` 和 `memo.create` 两个适配器；Memo 的往来字段；同批出卡；决定后执行与逐项回执；写 Memo 时抑制自动提取。

| 验收 | 可观察的结果 |
|---|---|
| AG06-1 | 小林那句话得到一答一卡两项：待办的计划日从 11 月 18 日改到 11 月 20 日，新增一条 11 月 15 日的来电往来。 |
| AG06-2 | 有两位小林时先选人；只有待办不明时先交付查询，只问要改哪一条。 |
| AG06-3 | 点击前零写入；点击后数据的变化与卡上所列完全一致。 |
| AG06-4 | 一项成功一项失败时回执如实区分，已成功的不重做，依赖失败项的被跳过。 |
| AG06-5 | 新增往来后“最近互动”由读取得出，没有第三条业务记录；只被提到的人的最近互动不变。 |

### AG07　两端的确认卡与对话界面

**目标。** Web 和 App 用同一份数据显示同一张卡，状态一致。

**进入条件。** 确认卡和对话四处小改动的视觉稿已获用户批准。

**范围。** 两端的确认卡；排队提示、依据行、追问候选、进度；离线时只读；本机有未同步修改时不能确认；重开和跨端恢复。

| 验收 | 可观察的结果 |
|---|---|
| AG07-1 | 两端从同一份预览渲染出相同的条目、数量和差异，没有各自拼装的字段。 |
| AG07-2 | 一端确认后另一端显示同一结果；已否决或过期的卡点击后显示最新状态。 |
| AG07-3 | 离线时只显示有几份待确认，卡片内容和确认按钮不可用。 |
| AG07-4 | App 本机有未同步的修改时确认按钮不可用，同步后按最新数据重出差异。 |
| AG07-5 | 界面文字符合设计稿 §10 的说法，没有内部词；桌面 1440 和手机 375 各验证一次。 |

## 阶段三　能力补齐

### AG08　判断模型接入

**目标。** 输出是固定选项的步骤交给判断模型，候选先用规则过滤。

**范围。** Gemini Decision 适配器；题目清单与版本；门槛配置与校准记录；先过滤再判断的四步与候选上限；证据核对、写入意图复核、重复判断三处接入；超时与降级。

| 验收 | 可观察的结果 |
|---|---|
| AG08-1 | 候选两千个时送入判断的不超过上限，结果写明覆盖了多少、截掉多少；模型调用次数不随候选数增长。 |
| AG08-2 | 纯按时间或日期的排序不调判断。 |
| AG08-3 | 低于门槛的答案落到保守结果；没有校准过门槛的题目不启用。 |
| AG08-4 | 判断超时或不可用时按规则顺序交付并说明没做主题匹配；复核类按保守结果处理。 |
| AG08-5 | 像陈述的话被主模型标成写入请求时，经判断复核后不出卡。 |

### AG09　基础联网与出站把关

**目标。** 能查一次公开网页并带出处回答，私有内容不会随检索词离开 Orbit。

**范围。** DeepSeek Search 与 Fetch 适配器；每次委托共享的次数预算；检索词由代码拼出与七条规则；第二道闸；证据记录；回放测试。真实供应商各联验一次。

| 验收 | 可观察的结果 |
|---|---|
| AG09-1 | 给了官网链接就直接读取，不先搜索；只查内部资料时联网调用为零。 |
| AG09-2 | 发出的每条检索词都能逐词对回用户原话、点选的公开线索或固定词表。 |
| AG09-3 | 带私有笔记内容、联系方式或金额的检索词被拦下，不悄悄改写，并说明这次没有联网查。 |
| AG09-4 | 抓到的网页里的指令不被执行；后续检索词不含网页内容，也不抓网页给的链接。 |
| AG09-5 | 同名、未披露、两页冲突、超时四种情况各有相应的交付；拆分子任务和恢复会话都不重置额度。 |

### AG10　排序、提取与整理

**目标。** 能按有依据的标准挑选，能从笔记里整理出往来和跟进。

**范围。** `rankCandidates` 与没给标准时的规则；`extractInteractions`、`extractFollowUps`；比较、分组汇总、会前回顾；“整理一下”默认只给摘要；从笔记到往来和 Todo 的写提议与去重。

| 验收 | 可观察的结果 |
|---|---|
| AG10-1 | 有偏好或本会话目标时直接排并在开头写明依据；都没有时问一轮，不凭空定标准。 |
| AG10-2 | 结果只含授权范围内的候选；时间未知的保留为未知，同分顺序可复现，模型给出的不存在的候选被拒收。 |
| AG10-3 | 只被提到的人、打算下次联系、转述别人的通话，都不被登记为往来。 |
| AG10-4 | 本人承诺、对方承诺、仅供考虑三者被区分；计划日与截止日的差别保留。 |
| AG10-5 | 重复整理同一篇笔记能回到已有的往来或 Todo，不重复新增。 |

### AG11　两端用 @ 指定上下文

| 验收 | 可观察的结果 |

| AG11-1 | 两端都能搜索、多选、查看类型、移除六类记录。 |

| AG11-4 | 引用不授予修改权，也不自动建立关联或记忆。 |

### AG12　联系人写入

**目标。** 联系人的新增、修改、删除、恢复和批量导入都经确认卡完成。

### AG13　活动、参会、日程与 Todo 关联

### AG19　回答排版与记录卡片

**目标。** 回答由程序排版：列表类的回答每条记录一张能点开的卡片，讨论类的回答先结论后分点，没做的部分单独成一块说明。2026-11-19 用户在正式站试用 App 第 18 版后新增；视觉稿当天获批（D1–D6）。详见 [PLANNER](sprints/AG19-answer-cards/PLANNER.md)。

| 验收 | 可观察的结果 |
