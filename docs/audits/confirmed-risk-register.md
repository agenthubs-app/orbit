# iOrbit Confirmed Risk Register

This register contains code- or runtime-confirmed risks. Static candidates remain in `product-surface-risk-register.md` until reviewed.

| ID | Priority | Surface | Issue and trigger | User impact | Evidence | Status | Follow-up |
| --- | --- | --- | --- | --- | --- | --- | --- |
| AUTH-RETURN-001 | P0 | Login, Signup, Forgot Password | Anonymous navigation from `/app/agent` reached Login correctly, but Login helper links rendered `next=/home`, a non-canonical/non-production route. | Switching authentication mode could lose the original destination or redirect an authenticated request to a dead route. | Browser URL/DOM evidence in `runtime-verification-log.md`; source fallback was `defaultNext: "/home"`. | Fixed and desktop/mobile verified on 2026-07-27. | Keep loader, hydrated client query, proxy, and already-authenticated redirects on `normalizeOrbitAuthReturnPath`; retain targeted tests. |
| AUTH-RESET-001 | P0 | Forgot Password | Submitting a registered email only advanced local React state to a verification-code/new-password screen; no reset provider, API call, email, code, or persistence existed. | Users were told to expect a reset flow that never happened and could believe a password was changed. | `OrbitRealAccountAuth` pre-fix `setForgotStep(2)` branch; post-fix production Chrome evidence in `runtime-verification-log.md`. | Fixed and desktop/mobile verified on 2026-07-27. | Keep the explicit unavailable alert until a named reset provider, expiring token store, delivery audit, rate limit, and end-to-end test exist. |
| EVENT-REG-FALLBACK-001 | P0 | Event registration fallback | When the registration guide and event loader disagreed, the legacy fallback rendered editable textareas and a “confirm staged answers” button even though no handler or persistence existed and the page stated it would not write Profile data. | A user could enter participant-profile answers and press a confirmation control that saved nothing. | Pre-fix `RegistrationGuideForm`; source regression test; normal production registration path verified in `runtime-verification-log.md`. | Fixed on 2026-07-27; normal desktop/mobile registration path verified. | Keep mismatched/unverified event records read-only with explicit no-save copy and real recovery links; only `EventRegistrationWorkspace` may expose answer submission. |
| CONTACTS-FILTER-001 | P0 | Contacts list | The desktop “Ask” control and three hard-coded value-type chips were visible buttons with no handlers. The natural-language examples copied their full sentences into a plain substring filter, usually producing an empty result. | Users could press prominent search/filter controls without a meaningful result and could mistake local filtering for AI search. | Pre-fix `OrbitRealCardsList`; pure filtering tests; authenticated production Chrome evidence in `runtime-verification-log.md`. | Fixed and desktop/mobile verified on 2026-07-27. | Keep search explicitly local; derive value filters from route-provided `valueTags`; add AI semantics only through a real provider-backed search boundary with visible provenance/failure. |
| CONTACTS-PIPELINE-001 | P0 | Contacts pipeline | The route mixed source-backed contact cards with a hard-coded “AI Summit 2026” triage queue, reminders, and six dead actions. Stage buttons only changed component state and showed a success toast; the available stage API is explicitly mock/staged, read-only in live mode, and uses a different domain enum. | Users could believe relationship stages, summaries, tags, reminders, or email drafts had been saved when no authoritative write occurred. | Pre-fix `OrbitRealCardsPipelineView`; live provider and stage contract inspection; source regression test; authenticated production Chrome evidence in `runtime-verification-log.md`. | Fake/dead production affordances removed and desktop/mobile verified on 2026-07-27. | Keep the pipeline an explicitly read-only, source-backed classification until an authenticated write service maps contact/connection identity to domain `RelationshipStage`, persists to the live record store, returns readback/provenance, and has end-to-end tests. |
| STATE-RECOVERY-001 | P0 | Shared route-state boundary | `StateViewRecoveryAction` allowed actions without an `href` or callback and rendered them as buttons. The shared test explicitly locked this dead-button behavior across every route-state consumer. | Failure and pending states could present a prominent recovery control that did nothing on up to 24 direct consumers. | CRITICAL upstream impact analysis (24 direct callers, 49 upstream symbols, 16 flows); StateView render regression tests; production build TypeScript validation of all consumers. | Fixed on 2026-07-27. | Recovery actions must keep a real local `href`; use a separate typed callback control only after a concrete retry boundary exists. |
| ADMIN-ACTIONS-001 | P0 | Admin dashboard | Export, global AI matching, and team invitation buttons had no handlers or named service targets. The admin route-state contract also states the surface is source-reading only. | Operators could attempt work that never exported data, ran matching, or invited anyone. | Pre-fix `AdminDashContent`; admin-platform route boundary inspection; source regression test; production runtime evidence. | Removed and desktop/mobile verified on 2026-07-27. | Keep source metrics explicitly read-only until each action has an authenticated, scoped service and auditable result. |
| PARTY-FILTER-001 | P0 | Party recommendations | The visible Filter icon button had no handler even though every recommendation already carried a route-provided industry classification. | Users could not narrow recommendations through the advertised filter. | Pre-fix `PartyRecommendations`; route-derived industry regression test; authenticated production runtime evidence. | Fixed and desktop/mobile verified on 2026-07-27. | Keep options derived from `viewModel.recommendations`; do not introduce provider or AI claims for this local filter. |
| PLATFORM-MODERATION-001 | P0 | Platform admin | “More actions” was dead, while approve/reject controls only removed an item from React state and claimed publishing plus organizer notification without a write service. | Platform operators could believe an event was moderated, published, or communicated externally when nothing authoritative happened. | Pre-fix `OrbitRealPlatform.decide`; admin-platform route boundary explicitly prohibits these writes; source regression test; production runtime evidence. | Fake moderation removed and desktop/mobile verified on 2026-07-27. | Keep review and account access read-only until an authenticated moderation service persists decisions, publishing state, rejection reason, and notification receipt. |
