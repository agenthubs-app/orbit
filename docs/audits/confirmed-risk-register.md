# iOrbit Confirmed Risk Register

This register contains code- or runtime-confirmed risks. Static candidates remain in `product-surface-risk-register.md` until reviewed.

| ID | Priority | Surface | Issue and trigger | User impact | Evidence | Status | Follow-up |
| --- | --- | --- | --- | --- | --- | --- | --- |
| AUTH-RETURN-001 | P0 | Login, Signup, Forgot Password | Anonymous navigation from `/app/agent` reached Login correctly, but Login helper links rendered `next=/home`, a non-canonical/non-production route. | Switching authentication mode could lose the original destination or redirect an authenticated request to a dead route. | Browser URL/DOM evidence in `runtime-verification-log.md`; source fallback was `defaultNext: "/home"`. | Fixed and desktop/mobile verified on 2026-07-27. | Keep loader, hydrated client query, proxy, and already-authenticated redirects on `normalizeOrbitAuthReturnPath`; retain targeted tests. |
| AUTH-RESET-001 | P0 | Forgot Password | Submitting a registered email only advanced local React state to a verification-code/new-password screen; no reset provider, API call, email, code, or persistence existed. | Users were told to expect a reset flow that never happened and could believe a password was changed. | `OrbitRealAccountAuth` pre-fix `setForgotStep(2)` branch; post-fix production Chrome evidence in `runtime-verification-log.md`. | Fixed and desktop/mobile verified on 2026-07-27. | Keep the explicit unavailable alert until a named reset provider, expiring token store, delivery audit, rate limit, and end-to-end test exist. |
| EVENT-REG-FALLBACK-001 | P0 | Event registration fallback | When the registration guide and event loader disagreed, the legacy fallback rendered editable textareas and a “confirm staged answers” button even though no handler or persistence existed and the page stated it would not write Profile data. | A user could enter participant-profile answers and press a confirmation control that saved nothing. | Pre-fix `RegistrationGuideForm`; source regression test; normal production registration path verified in `runtime-verification-log.md`. | Fixed on 2026-07-27; normal desktop/mobile registration path verified. | Keep mismatched/unverified event records read-only with explicit no-save copy and real recovery links; only `EventRegistrationWorkspace` may expose answer submission. |
| CONTACTS-FILTER-001 | P0 | Contacts list | The desktop “Ask” control and three hard-coded value-type chips were visible buttons with no handlers. The natural-language examples copied their full sentences into a plain substring filter, usually producing an empty result. | Users could press prominent search/filter controls without a meaningful result and could mistake local filtering for AI search. | Pre-fix `OrbitRealCardsList`; pure filtering tests; authenticated production Chrome evidence in `runtime-verification-log.md`. | Fixed and desktop/mobile verified on 2026-07-27. | Keep search explicitly local; derive value filters from route-provided `valueTags`; add AI semantics only through a real provider-backed search boundary with visible provenance/failure. |
