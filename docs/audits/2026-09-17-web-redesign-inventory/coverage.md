## 4. 静态扫描的已知限制

| 限制 | 如何记录/避免误导 |
| --- | --- |
| 动态 dispatch、运行期 import、字符串生成 HTML、imperative DOM/第三方控件无法完整静态展开 | 尽可能收录可达辅助与 selector 证据；保留来源链接；不承诺穷尽运行时全部 DOM |
| 同模块 API 与按钮可能没有调用关系；wrapper/callback/context 会跨文件 | 控件列 handler，HTTP 列 owner；无法证实的链路不猜测，无 fetch 不代表服务端没读取 |
| API export 有 re-export/包装 | 全表空方法标为见源码，不当不可用；前端 requestJson 等方法可能由封装决定 |
| 文案动态生成、多语言、数组 map 与互斥响应式树 | 保留表达式，统计实现不统计「屏幕上的按钮总数」；不将数据常量当真实用户结果 |
| 长表达式会被节选 | 明确标记「完整表达式见源码」，源链接可追踪；原始 JSX/字典未修改 |
| Markdown 分卷可能在长表中间续接 | 分卷为大小控制，不是新画面；按模块来源与相邻分卷连续阅读 |
| query detector 只识别部分读法 | 路由表为读取线索，不是参数契约全表；例如 events 的 scope、analysis 的 initialTab、today 的 view、party 的活动上下文需结合页面模型/实际读取核对 |
| 通用 ModalShell 与内联编辑不都是 dialog 根 | 自动 12 个 overlayRoots 不用于弹窗数量结论；以人工目录 + 所有控件/状态明细阅读 |
| CSS/角色/时间/data gate 影响可见性 | 静态可达≠当前用户可見≠生产已接通；保留禁用/门槛和不可用边界 |
| dev capability 注册声明与模拟画面 | 与 production routes 分开；11 个能力分组不是 49 个具体 debug slug，也不替代 live 服务验证 |
| public 静态演示的内嵌模拟应用 | 登记外层菜单/控制与来源，不冒充现行业务，不计入正式控件数字；其内部弹层未另行逐项验收 |

所以本报告是「全路由源码底稿 + 可达 UI 明细 + 主要隐藏画面归纳」，不是「所有运行时画面及权限组合均已验收」。

## 5. 进一步运行时补齐需要的具体条件

| 待验范围 | 缺项/证据 | 为什么不能靠现在的隔离环境验证 |
| --- | --- | --- |
| 登录后的个人画面：agent、contacts、tasks、profile/settings 等 | 已授权的测试身份及对应稳定数据；本次未登录 | 需要真实 actor、版本/状态与数据；不能从匿名树验证个人弹层 |
| 活动目录/详情/报名/现场/会后 | canonical event service 配置、隔离活动及不同阶段数据 | 本地目录已明确配置错误；不能为了画面连接未知线上库、报名或触发生成 |
| 主办方/审核/签到/角色/报告 | 对应最小角色的测试身份、活动权限和隔离数据 | 单一普通账号不能证明所有权限；也不能未经授权授予角色或批准申请 |
| 成功、冲突、重复回执、过期/取消与失败恢复 | 可重放的隔离状态/fixture，必要写入的明确范围 | 只读扫描能定位分支，不能冒充写后验收；需要受控测试而非操作真实用户数据 |
| AI/OCR/语音与运营生成 | 测试 provider/mock 或明确允许的调用预算 | 有成本与写入/异步执行边界；本次未调用 |
| 线上与新版 worktree | 确定目标版本/部署、访问授权 | 当前 SHA 不能证明正在并行开发或生产部署的新版状态 |
| 移动、三语、键盘/焦点与视觉截面 | 按真实 actor/state 的浏览器矩阵 | 源码列了响应式/语言/焦点线索，尚未逐状态视觉 QA |

这些依赖只限制对应运行时验收，不限制源码清单、重设计信息架构和待审方案。现在可直接利用总览与域明细开始设计；无需把单一活动服务的配置阻塞扩大到整个重设计工作。
