# Web 逐页功能、文字、控件与分区总览

基线与验证边界见 [README](README.md) 和 [coverage](coverage.md)。这里是人读版；不是用产品设想补齐现状。所有原始文字、表达式、控件及源码链接在各域明细中。动态姓名、活动、数量、权限、状态文案不编造示例值。

表中「接口/动作」分为路由跳转、纯前端状态、服务端模型读取、HTTP 写入。一个页面有接口并不意味着页面上每个按钮都调用它。API 方法与模板另见 [全表](api-catalog.md)。`[id]` 是动态参数，不是实际测试对象。

## 1. 全局共享界面

证据：[入口与共享壳明细](01-entry-shell.md)、[任务与收件箱明细](07-schedule-tasks-chat.md)。共享壳并非所有页面都全部出现：鉴权页、现场页、后台页和开发页有各自分支。

| 画面/分区 | 显示内容 | 控件与结果 |
| --- | --- | --- |
| 公共顶栏 | Orbit 品牌；「iOrbit」「活动」「日程」「人脉」；账号与语言入口 | 品牌 → `/`；业务入口分别 → `/app/agent`、`/app/events`、`/app/today`、`/app/contacts`；语言切换按现有语言契约保留导航上下文 |
| 账号区/菜单 | 当前账号相关入口；登录态相关的画像、设置、活动方入口 | 打开菜单、导航、退出/登录入口；移动版菜单有遮罩、关闭与 Esc；不同身份可见项不等同 |
| CRM 侧栏 | 所有人脉、关系进展、引荐、人脉分析、全部操作、导入中心 | 当前/核心项优先；「更多」展开其他项；不是六项永久全部显示 |
| 全局 iOrbit 浮动入口 | 提问输入、当前页面上下文、提示、展开/收起 | 打开/关闭、输入、提交、进入完整工作区；提交通过共享上下文处理，不应将纯展开计作 AI 调用 |
| 关系收件箱抽屉 | 「对话」「提醒」；列表、未读/提醒状态、详情 | 打开/关闭、调整宽度、切 Tab；对话列表 → 详情/新建；提醒跳转、忽略与状态持久化 |
| 通用反馈层 | 加载、错误、不可用、权限边界、保存结果、复制提示 | 重试或关闭按具体来源；不可用说明不是业务成功提示 |
| 移动导航/底部栏 | 当前业务分支的移动导航 | 需要保留移动条件与现场专用导航；不能把 desktop-only 与 mobile-only 当同时可见 |

收件箱接口：`GET/POST /api/chat/relationship-inbox`；辅助草稿 `POST /api/chat/assist/email-draft`、`POST /api/chat/assist/rewrite`；提醒 `GET /api/notifications` 与 `/api/notifications/[id]/state` 状态接口。回复有编辑、暂存/交接状态，不可描述成「已向对方发送」。

## 3. iOrbit 主工作区

证据：[02 明细](02-ai.md)。

| 路由 | 功能及分区 | 主要文字/内容 | 控件与接口边界 |
| --- | --- | --- | --- |
| `/app/agent` | 登录后主入口；仪表盘、历史侧栏/移动抽屉、输入、消息流、结果与动作反馈 | 用户欢迎/真实概况、「即将到来的约谈」「现在可以做」「我的活动旅程」；历史会话名/分组；建议、依据、草稿与执行状态 | 新对话、选会话、更多、改名、置顶、移动分组、删会话、组织分组、输入/发送、取消 run、重试、卡片详情/复制/确认动作 |
| `/app/home` | 历史个人首页地址 | 无独立首页终态 | 重定向 `/app/agent` |
| `/app/chat` | 历史聊天地址 | 无独立聊天终态 | 重定向 `/app/agent` 并携带现有查询参数；真人沟通入口是收件箱等，不因路由名推断 chat 页面仍生效 |

主工作区内部画面：

- 仪表盘：概况、约谈、可行动事项、活动旅程；无真实数据时的空态与显式演示分支不同。
- 历史：会话列表、搜索/加载更多相关状态、分组组织区；行更多菜单有改名、分组、置顶、删除；删除有专门确认画面。
- 对话：普通文字、处理中、失败/重试、取消；会话恢复与新对话不是相同状态。
- 联系人/活动/任务结果：标题、对象、建议理由、证据/来源、详情与后续行动。
- 跟进草稿：生成中、可编辑、复制、交接、失败；复制和交接都不是邮件送达证明。
- 日程/承诺类结果：展开详情、选择条目、显式确认；不可直接把文本回答当已写入日程。
- 运行/动作反馈：run 状态与 ledger 状态分开；有确认、拒绝、重试/取消等可用能力边界。
- 结果评价：反馈控件与已提交/失败状态，和联系人本身属性编辑不是一回事。

主接口组：`POST /api/ai/conversations`；会话历史 `/api/ai/conversations/sessions` 及其 `[id]`；分组接口；`GET /api/ai/runs/[runId]`、`POST .../transition`；`POST /api/agent/ledger/[actionId]/transition`；反馈与业务结果接口以控件所属源码为准。

此根工作区基线请求里的 `references` 为空数组；不能把其他工作树正在开发的引用选择器当当前已交付界面。重设计需将当前存在的入口和未来能力分开。

## 4. 人脉 CRM

证据：[03 明细](03-contacts.md)。

| 路由 | 功能及分区 | 主要文字/内容 | 主要控件 → 动作/接口 |
| --- | --- | --- | --- |
| `/app/contacts` | 侧栏、标题/总数、搜索筛选、列表、空/错误态 | 联系人姓名、公司/角色、地区、强度/来源、互动与下一步相关元数据；「所有人脉」等 CRM 导航 | 搜索、筛选、列表卡片打开详情、导入入口；来源模型为联系人/连接服务，不能将文本搜索默认描述成每键一次服务器请求 |
| `/app/contacts/[id]` | 联系人主身份、联系信息、画像、标签、双向价值、关系/下一步、互动时间线、私密笔记、沟通/约谈相关区 | 主/次行业、邮箱/电话、认识途径、最近互动、自我介绍/背景、提供/寻求、话题、来源证据；阶段由 canonical 状态派生 | 编辑行业、标签、互动、笔记；关系初始化；沟通/约谈按权限出现；详情跳转与草稿动作。多个编辑器写 `PATCH /api/contacts/[id]` |
| `/app/contacts/pipeline` | 关系进展分组看板、每组联系人卡片 | 来源支持的进展分类、计数、联系人、判断/行动线索 | 搜索/打开联系人；当前实现是展示，不是自由拖拽修改阶段 |
| `/app/contacts/intros` | 引荐列表、发起、详情 | 引荐双方、原因、来源/状态、牵线信息 | 「发起引荐」→ 表单；分别选择两个联系人；确认保存；`POST /api/contacts/introductions`；不是默认向双方发送外部消息 |
| `/app/contacts/dashboard` | 分析页，概览/结构/机会三 Tab，共享目标/报告/覆盖信息 | 「人脉分析视图」「人脉结构」「下一步行动」「依据」「建议步骤」「重算机会」；目标、报告生成时间/版本/过期状态 | 切 Tab/维度、选桶、详情、编辑目标、刷新、重算、交给 iOrbit；`GET /api/mobile/contacts-dashboard`，`POST /api/dashboard/opportunities/recompute`，目标 `PUT /api/profile` |
| `/app/contacts/analysis/[dimension]/[bucketId]` | 分布桶详情：维度/桶头部、质量/结构信息、成员列表 | 桶名、统计、覆盖/分类信息、联系人；「返回人脉结构」 | 返回结构 Tab、打开成员详情；先验证 dimension/bucket，不伪造未知桶的数据 |
| `/app/contacts/graph` | 历史图谱地址 | 无独立旧图谱终态 | 重定向 `/app/contacts/dashboard?tab=structure`，保留语言 |
| `/app/contacts/all-actions` | iOrbit 操作台账；列表/状态、展开的详情、草稿与证据 | 操作标题/状态、为什么、实际操作、依据/Trace、内容预览；失败反馈 | 展开、复制草稿、编辑草稿；有权限/状态条件的重试、撤销、取消；`POST /api/agent/ledger/[entryId]/transition`，不是永远纯只读 |

联系人详情必须区分的子区：

1. 联系信息：有值才展示/可编辑条件不同；行业编辑是有分类约束的主次行业选择，不是任意全表编辑。
2. 画像与双向价值：联系人背景、话题、对方提供/需求等；证据缺失不能画成已经验证的推荐理由。
3. 标签：自定义标签编辑与来源标签不同。
4. 互动/时间线：明确记录与来源、日期、隐私；签到或同桌不能产生虚假的「已交流」。
5. 私密笔记：当前 ContactNotesEditor 更新联系人 notes；不要误连到同仓库其他 notes 接口。
6. 关系初始化：关系目标与有日期的下一步任务分开；收到名片不自动变成活跃关系。
7. 沟通/约谈：邀请、交换同意、权限状态、候选时间与确认状态；不跨过 consent 与 actor 范围。

分析三 Tab：概览展示指标/覆盖；结构包含维度切换、图表/桶选择及关系健康信息；机会显示判断、证据、步骤、主/次 CTA 与沉睡关系。主次 CTA 的实际 label/href 来自数据，而非页面统一固定按钮。「交给 iOrbit」是草稿预填/工作区交接，不是点击后无条件立即生成分析。

活动详情内的其他画面：

- 介绍与议程折叠、会前/会中/会后状态、已报名/审核中/无资格/取消/结果未发布。
- 推荐参会者卡片与可展开完整目录。当前 matchmaking 组件里的目录是展开状态，不据此称为独立 Tab。
- 参会者详情弹层：画像、推荐依据/分组、联系方式交换 consent；申请、同意、婉拒、撤回、再次申请受活动开放时间与 revision 约束。
- 约谈协商：草稿、等待回应、协商、已确认、改期中、取消、已完成；候选时段、时区、备注、地点媒介，反提/接受/拒绝/取消/改期；完成按钮有时间门槛。
- 交流记录：只保存用户明确填写的内容，签到/同桌不自动推断已谈话。
- 会后中心：交流/约谈事实、artifact 生成/读取、后续任务记录；异步生成、未生成、失败、刷新各有状态。
- 会后跟进采集弹窗：联系人搜索/选择、明确记录、文本或语音转写、审核与显式保存。

相关接口组：`GET /api/events/[id]/operations` 及 `/participants/[participantId]`；联系方式请求接口族；`GET/POST /api/appointments`，`GET /api/appointments/[id]`、`POST .../commands`；`/api/encounters`；`/api/events/[id]/post-event/artifact`、`.../followups`、`.../followup`；`POST /api/contacts/search`、`POST /api/agent/voice-memos/transcribe`。具体按钮的方法/payload 见源码明细，不将这些接口笼统连给所有活动 CTA。

设置内部需要拆开的子画面：

- 记忆：开关、关于我/目标/偏好/边界类别、创建/修改表单、删除确认、保存与冲突。
- 反馈：运行相关反馈记录及删除，不能误归类成用户私密笔记。
- 自动化：自然语言草案、编译、dry-run 预览、审核后保存；一次/每日/每周、时区/星期或事件信号；启用/暂停、手动运行与删除确认。
- playbook 类型与信号：联系人推荐、活动推荐、上下文/跟进审阅等来源允许能力，due/event-upcoming/relationship-stale 等配置；当前强调只读执行边界，不承诺代发消息或任意后台写入。
- 执行/集成：健康/失败状态、授权、重试与配置缺失；Google/email/calendar 有能力分支，不把「有按钮」当已授权。

主接口组：`/api/agent/memory`、`/api/agent/memory/[id]`、memory settings；feedback API；自动化实际路径 `/api/agent/automations` 及 compile/dry-run/`[id]/run`（界面称 Playbook）；`/api/agent/preferences`、`/api/integrations` 及 provider authorize/health、`/api/agent/operations/health`。精确方法、owner 与显示条件见 08 控件明细和 API 全表。
