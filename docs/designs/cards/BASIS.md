# 名片夹 · 依据清单 (Provenance Manifest)

> 原则（PRD §7.1）：**人脉必须有来源，关系必须有上下文。** 凡是"不是用户当场直接输入"的信息或建议，都必须能回答：① 怎么来的 ② 基于什么原始依据 ③ 能不能改。
> 本清单逐屏列出每个信息/按钮的依据来源、生成方式、字段/接口，以及在 UI 上如何把"依据"呈现出来。确认后据此改原型。

## 生成方式分类（贯穿全部界面的标记体系）

| 标记 | 含义 | UI 呈现 | 合约对应 |
|---|---|---|---|
| `你设定` | 用户手动填写/选择 | 无需依据浮层，可直接编辑 | 用户输入 |
| `证据直采` | 直接来自可查证据（名片OCR原文、扫码、邮件、日历） | 点开看**原始证据** + `evidenceId` | `provenance.evidenceIds`, `source` |
| `统计规则` | 由确定规则/计数得出（数量、分布、阈值判定） | 点开看**计算口径**（用了哪些字段、阈值） | `generationMethod:'rule-based'` |
| `AI 推断` | 模型推断（价值、双向价值、下一步、缺口） | 点开看**依据数据 + 理由**，**可编辑可反馈** | `generationMethod:'ai'` + rationale |

**框架层新增 `.basis` 组件**：一个常驻小标记（4 种之一的图标+色）+ 点击浮层（生成方式 / 依据数据 / 证据链接 / 可编辑）。复用现有 [shared/ui/provenance-disclosure.tsx](../../../repos/orbits/shared/ui/provenance-disclosure.tsx) 与 [source-chip.tsx](../../../repos/orbits/shared/ui/source-chip.tsx)，及合约里现成的 `provenance{ source, sourceLabel, evidenceIds, generationMethod }`。

**铁律：任何"目标驱动"的分析，目标本身必须有明确设定入口，且结果链回目标。**

## 0. 目标从哪来（贯穿表盘/缺口/机会/价值匹配）

"当前目标"是用户画像字段（PRD §20.1 用户对象 `当前目标 / 想获得资源 / 可提供资源`；§6.2.4 onboarding 引导问题设定，§6.2.5 可在对话中更新）。

- **设定入口**：用户画像页的"当前目标"区（新增/已在 profile）。表盘等处的目标 chip = 只读镜像 + 链回该入口。
- **UI**：目标 chip 标注来源与时间「来自你的画像目标 · 6/20 设定」，点击 → 目标设置；一切基于目标的分析（缺口、机会、价值匹配）都在"依据"里回指这个目标。
- 字段/接口：`profile.currentGoal`（[现有] profile 合约有目标概念，需确认字段名）；`getDashboard({ userId, goalContext })` 的 `goalContext` 来自 profile，不凭空传入。

### 表盘主视觉：发光轨道 + 密度光点（Orbit Rings）—— 解决"人多放不下 + 要炫酷 + 要有据"

- **你在正中心**；3–4 条同心**发光轨道环** = 关系层级：核心圈(强·高频) → 进行圈(沟通中) → 外圈(新识/弱) → 沉睡带(最外·暗)。**半径=关系近度**（依据：互动近度+阶段）。
- **不逐个放头像**：每环用**光点密度/光弧**表示人数（上百人=密集辉光），环上标计数徽标（核心 18 / 活跃 63 / 外圈 38 / 沉睡 9）。→ 海量人脉也装得下。
- **角度扇区 = 行业 或 价值类型**（可切换）：同扇区光点聚拢，一眼看出哪个行业密/稀（直接服务"缺口"）。依据：`industry` / `valueType`。
- 只对**少数关键光点**（核心人脉 / 本周该联系）加小头像+光晕，其余为密度点。
- **交互（真价值）**：点扇区/环 → drill 到筛选名片列表；hover 光点 → 迷你卡。缓慢自转/呼吸动效（尊重 reduced-motion）。
- **炫酷但有据**：星空轨道+辉光+动效贴合品牌名 Orbit，且半径/角度/亮度/大小每个编码都对应真实数据字段。
- 旁边固定「**本周行动队列**」：3–5 条建议，每条=依据+一键动作(起草邮件/约会议)+完成回写 → 表盘的日活价值(§15.3)。

## 6. 聊天 → 邮件式改造（不做即时聊天）

- 全站**不做 IM/即时气泡**。§13 站内聊天在 MVP 不做；对外沟通一律**异步、正式、只谈公事的邮件式草稿**。
- 02 的「发送打招呼」、05 的「打招呼消息」→ 统一为「**起草邮件 / 生成跟进邮件**」：AI 起草→用户可改→**发送前确认**。图标 message/气泡 → mail；文案改为邮件语气（主题/称呼/正文/预约链接）。
- 邮件草稿本身也"有据"：标注引用了哪些要素（来源活动、承诺事项、上次要点），对应 §12.4。
