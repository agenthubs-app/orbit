活动 › 发现：活动卡片太大、太空，改紧凑

对应 DiscoverTab.tsx 的 EventCard。字段不变：封面（或 emoji 色带）、报名人数 chip（≥10 人）、标题、日期 · 地点、「和你有关」标签（RelevanceChips，不打分）、费用或「已结束」。只改排布，并去掉单独的「详情」按钮——卡片本身已经整张可点（role=button），按钮与点卡片是同一个动作。示例活动为虚构。

问题（手机现状截图）

  1. 一张卡约 330px 高：2:1 封面在 354px 宽下约 177px；下面标题、日期地点、一个标签、一个按钮各占一行，行间 18px 空白。
  2. 一屏只看得到 1 张多：列表区（筛选下面到底部导航上面）约 —px，只放得下 — 张。
  3. 右下角孤零零一个「详情」：点卡片本身就进详情，按钮重复同一个动作；它独占一行，把卡片撑高。
  4. 费用：现状在左下角和「详情」同一行；没有费用时这一行只剩按钮。

两个方案

  1. A · 矮封面卡：封面高 120px（从 2:1 裁成约 3:1，居中）；标题最多 2 行；日期 · 地点 1 行；「和你有关」标签与费用同一行（标签左、费用右）；整张卡可点，不放「详情」。没封面画 120px emoji 色带，已结束整张置灰、费用位换「已结束」。
  2. B · 左图右文列表行（推荐，手机）：左边 88×88 缩略图（封面居中裁方，没封面用 emoji 色块），右边 标题（≤2 行）/ 日期 · 地点 / 标签 + 费用。三种卡同高 112px。
  3. 推荐：手机用 B，一屏从约 — 张变成约 — 张，适合「往下翻着挑」；834 / 1440 用 A 的卡片结构但封面保持 2:1（宽度够，不用裁）。同一组件按断点切换，与 b8 规范「表格 / 网格 → 手机卡片列表」一致。
  4. 桌面也要改：1440 的 span4 卡同样有「详情」独占一行、费用单独一行，比需要的高约 50px；改成 A 的底部一行（标签 + 费用），去掉按钮。

对标成熟产品的做法

  1. Luma（手机 Discover / 日历）：一行一个活动，右侧方形缩略图，左侧时间、标题、地点；整行可点，没有「详情」按钮。
  2. Meetup / Eventbrite（手机搜索结果）：左侧小图 + 右侧 日期 / 标题 / 地点 / 价格的列表行，一屏 4–5 个；桌面换成 2:1 封面的网格卡。
  3. Airbnb / App Store 卡片：整张卡就是点击区，卡内不放与点卡同义的按钮。
  4. B 选左图（Meetup / Eventbrite）而不是右图（Luma）：Orbit 的封面多是主办方海报，放左边先看到图，阅读顺序和 A 卡（图在上）一致。
