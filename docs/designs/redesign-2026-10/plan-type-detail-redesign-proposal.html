「该聊的人」类型详情：页头和头卡重排

路由 /app/plans/<planId>/types/<itemId>。只改布局和重复信息，不加功能：按钮、字段、文案都来自现有 PlanTypeDetailScreen.tsx 与 copy/plan.ts（zh）。头部和头卡按高保真画，下面的区块按低保真画，用来看清三档宽度下整页怎么排。示例人物、活动均为虚构。

问题（手机现状截图）

  1. 页头三个按钮乱排：返回钮、「这方面我已熟悉」「＋线下聊过」「下一步」挤在标题下面，返回钮被挤到第二行中间，按钮分两行右对齐，和返回钮不在一条线上。
  2. 头卡溢出：桌面的「标题 | 三格 | 分数」一行硬塞进 354px，三格那一块越出卡片右边缘。
  3. 格子太挤：三格只有约 90px 宽；进度条只占半宽；「人物画像」「能见到的活动」仍按桌面 5 / 7 两列并排，各剩 130–180px，标题「能见到的活动」和「参加活动栏 +5」都被折成两行。
  4. 同屏重复：「前 CFO」出现在标题和卡片小字两处；「配分10」与「/10分」重复；「人脉中还没有」与格子里的「人脉中没有」重复。

方案

  1. 标题行：← 返回 + 标题「前 CFO」+ 小字「Step 1」，左对齐一行（kit .hhead）。标题行不再放按钮。
  2. 动作只剩一组：主按钮「＋ 线下聊过」（实心、最宽）；次按钮「✦ 下一步」；「这方面我已熟悉」收进 ⋯ 菜单（不常用，而且是会改分数的操作）。手机放在头卡底部一行；834 / 1440 放在页头右侧。1440 有常驻右栏，所以不出「下一步」。
  3. 头卡改成纵向：MacTile + 小字「角色 × 处境」+ 一句话标题 → 三格一行（细分隔线，不是卡中卡）→ 进度整行（分数 + 「/10分 · 0/1人」+ 满宽进度条）。
  4. 去重：小字删掉「前 CFO ·」；副标题只留 Step；三格第一格标签固定写「人脉中的候选」，数字为 0 时变灰，不再换成「人脉中没有」。
  5. 下方区块：手机和 834 都单列满宽；1440 维持 5 / 7 两列。手机上活动表、候选表改成列表行（b8 断点规范「表格 → 卡片列表」）。
  6. 右栏去重：1440 右栏删掉「能见到这类人的活动」（主栏已有同一批活动），只留「问问这个类型」和草稿说明。

对标成熟产品的做法

  1. LinkedIn 个人页（手机）：头卡里一个实心主按钮（Message / Connect）占大半行，旁边一个次按钮 + 「More ⋯」；不常用操作全进 ⋯。本方案手机头卡底部的「线下聊过 / 下一步 / ⋯」照这个排。
  2. Linear issue 详情：标题区左侧是返回 + 标题，右上角只有一个主操作 + ⋯；桌面不在标题下面堆按钮。本方案 834 / 1440 页头照这个排。
  3. Notion / GitHub 移动端：属性和数字在窄屏改成纵向堆叠，统计做成一行带分隔线的小格（GitHub 仓库页 Stars · Forks · Watching），不做卡中卡。
  4. iOS 操作菜单：⋯ 在手机上打开底部弹层（与 b8「弹窗 → 底部 sheet」一致），桌面是锚定在按钮下的小菜单。
