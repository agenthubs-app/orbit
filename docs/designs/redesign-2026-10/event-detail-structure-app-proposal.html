活动详情：紹介 / アジェンダ / 主催 / 参加者 的信息结构

用户反馈：这四块用 tab 分开，但内容其实是一条顺序的信息，tab 和顺序排列并存不合理。App 现状（板 ⓪）是真切换的 tab：「主催」tab 里只有一行，「アジェンダ」只有几行，看完一场活动要点三次；「紹介」tab 里还混着参加者的预览。提案改成一页从上往下读完，参加者全名单另开一页。示例与 b2 同一场「CFO Night Tokyo vol.18」，人物/公司均为虚构。Web 稿由 Web 会话出，区块顺序与命名两端一致。

需要你拍板的点

S1　去掉 4 个 tab，详情页改成一页从上往下读吗？
推荐 A：去掉 tab，四块按顺序排在同一页（板 ①②）。对标 Luma / Meetup / connpass / Peatix：活动详情都是单列长页，没有 tab。
B：保留 tab，但只在内容真的很长时用（实际上四块都不长，等于不用）。
C：单列 + 顶部锚点 chip（点了滚到对应块）。页面不长，锚点多出一排控件，不推荐。
S2　四块的顺序？
推荐 A：紹介 → 参加者 → アジェンダ → 主催。Orbit 看活动的核心是「会遇到谁」，参加者放第二；主办方名字已经在封面卡标题上方，底部只放一行卡。
B：紹介 → アジェンダ → 参加者 → 主催（connpass / Peatix 的顺序，参加者靠后）。
S3　参加者在详情页放多少？
推荐 A：只放预览 —— 人数 + 头像 + 「プランに合う / 知り合い」人数 + 最多 3 位和你计划相关的人，下面「全員を見る」进全名单页（板 ③），筛选和搜索放在全名单页。对标 Luma「N Going」+ 全部一览、Meetup Attendees「See all」。
B：详情页直接放全名单（128 人时页面会非常长，主办方和 アジェンダ 被压到最底）。

已按推荐定的（不用拍板）

  1. 紹介超过 6 行折叠，渐隐 + 「続きを読む」原地展开（不跳页）。对标 Luma / Meetup 的 Read more。
  2. アジェンダ 超过 5 项折叠，「すべて見る（7）」原地展开；当天进行中的那一项圆点高亮（数据已有时间）。没有议程时整块不出（不放「未登録」空卡）。
  3. 主催 = 一行卡：主办方名 + 举办次数，有主办方页才有箭头可点；没有公开名字时这块不出（封面卡上已经不显示）。
  4. 名单锁着（报名确定前）：参加者块里显示人数和「参加登録すると見られます」，按钮去报名（板 ④）；主办方看到的是「運営ページで見る」。规则不变，只是从 tab 挪进同一页。
  5. 已结束：会場の記録 卡仍在封面卡下面（板 ⑤），参加者块的人行照旧能点开参加者シート。
  6. 原「紹介」tab 里的「会いたい人」卡并进参加者块的预览，不再单独一张卡；「知り合いも参加」那张卡也并进来（同一类信息不出两次）。
  7. 全名单页：路由 /events/[id]/people，段控件 プランに合う / 知り合い / 全員 + 搜索；行和现在一样，点人打开参加者シート；读取按页取（只取当前段的前 30 人，往下滚再取）。
