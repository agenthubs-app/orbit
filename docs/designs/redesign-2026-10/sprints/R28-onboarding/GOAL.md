# Sprint R28 — 新用户引导

**归属：** C 线账户 → 引导；执行者为 Codex 主开发会话，在 `redesign-c` / `line-c` 接 R18c 后实施。本 Sprint 文档是实施契约，尚不代表功能已完成。

## 要实现什么

把新用户从注册后的资料填写、可只读浏览的示例期、首页「はじめの 3ステップ」，带到计划 v2.2 的第一份真实计划。资料填写按 b1 A3 的五张资料画板重写；首页指南按现有 1 联系人 → 2 目标 → 3 计划的硬顺序推进；第三步进入 b1 A5 的四阶段计划流程（①目标、②背景、③问题、④AI 初版），最后一阶段复用 R22–R25 的计划 v2.2，不另造计划引擎。资料五屏、首页三步、计划四阶段是三种不同的计数，不混为一套进度。

本线重写 App `/profile/onboarding` 与 `/profile/continue`、补齐真正的 `/start` 指南页；重写 Web `/app/start`、`/app/profile/onboarding` 与 `/app/profile/continue`。Web 资料编辑复用 R18a 交出的 `use-profile-editor-session`，完成引用迁移后才删除旧 `profile-model` re-export。引导目标最多两个，修正 R18b 留下的 b1「1〜3個まで」。`guideState` v2 保存跨端停步、折叠与完成闩锁；`currentStep` 是停留位置，完成数由已确认联系人、已保存目标和生效计划派生，两端指南与首页读取同一真实进度投影。

## 做完能看到什么

- 新用户登录后资料未齐，落到可续填的资料页；刷新、换端或安全的邀请回跳不丢已确认字段，也不会陷入 `continue` 循环。生日在画板标「任意」；先让 App 兼容新版读取并登记 G18/G19 契约变更，再以 `policyVersion: 2` 放宽服务端资料门禁。
- App 和 Web 的指南都显示同一人的真实进度，首页进度与指南页均可在示例开关关闭时读取。三位已确认联系人、已保存目标和生效计划分别解锁三步；跳到尚未解锁的步骤仍回到当前可做的步骤。旧 `step1Skipped` 只读兼容，完成闩锁不会因后来删联系人而倒退。
- 在第三步点「计划をつくる」，以 `source: "onboarding"` 创建或续接 v2.2 intake，并按接口返回的 `href` 进入目标、背景、问题、AI 初版；生成、确认后回 Task › プラン，指南完成。失败、配额耗尽和中途离开都有可恢复出口，不重复扣费或建计划。
- 引导期的示例横条可收成药丸；示例数据标识清楚，写操作被拦截并给出「继续指南」出口。Task › プラン 的横条由 D 线按本 Sprint 请求恢复，C 线不编辑 D 线 Task 文件。
- App `/start` 是实际指南页，和 Web `/app/start` 的路由、鉴权与操作语义对齐；已知 `route-parity` 红项转绿，不靠例外清单掩盖。

## 怎么验收

以 [PLANNER.md](PLANNER.md) 的 SC-R28-01～16 为准。实施者先复核 R18c / R18a 实际交付、远端代码和画板预检，再分端完成操作链、契约与旧屏清理。每个本线画面有 b1 或补画画板的像素子 SC：App 真机模拟器浅／深，Web 1440／1024／390 浅／深；没有画板的状态附截图并标「设计稿无，不进门禁」，不能记为通过。R31a / R31b 组件合入后收口像素；两端全量测试、类型、文案与路由检查对照开工基线零新增失败，最后由主会话独立复核。

本地可用替身服务与有限次付费 AI 真调用验证，次数写进 REPORT；不连 Neon，不做生产迁移、部署、生产开关、TestFlight、合回或推送。需要这些动作的事项交主会话登记 DEFERRED「待用户授权」。
