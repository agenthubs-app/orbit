# Sprint R37a — 计划 v3：准备卡服务与 Web 计划主页

## 要实现什么

确定 v3 计划之后，服务端为「先做的事」生成准备卡；Web 的计划主页按定稿设计（`plan-draft-v5-proposal.html` v16 的「计划主页 · 执行」页）重做。

服务端：
- 系统先按规则列出候选（人脉里匹配到的人 + 活动库里匹配到的活动，编号），AI 只挑 1–3 个编号并写标题、理由和阶段目标一句。
- 对挑中的每件事生成一张准备卡（每份计划初次 ≤4 张）：用到的事实、切入点、为什么这样开口、开场白草稿。
- 开场白逐句对账：引用不存在的事实、画线片段不在引用的原文里 → 删该句；整段删空 → 通用模板「说清你是谁 + 很小的请求」。
- 没有记录的行（上次联系、备注、共同点）不渲染，`gaps` 给出「可以补充」的项。
- 新增备注或手动补一条事实后，相关准备卡 `staleSince` 置位，主页显示「资料有更新」；用户点「重新生成」计入每日 15 次。

Web 主页：
- 头部改成「目标结果 + 当前阶段在前、分数退后」，路线带完成标志。
- 「建议先从这 N 件开始」勾选清单；每件可展开准备卡（复制开场白、可以补充）。
- 「要认识的人」空位表（已认识头像 / 还需要认识 / 分量），点开看是什么样的人、去哪里认识、见面聊什么。
- 「为什么这么排」折叠，点开回看初稿的依据。
- `schemaVersion` 不是 3 的旧计划仍显示 R24 的概要画面。

## 做完能看到什么

- mock 模式切到三份设计稿示例 fixture（融资 / 开拓客户 / 招聘），`/app/plans/<planId>` 在 1440 与 390 宽的画面和原型逐像素一致（只有数据文字不同）。
- 确定一份 v3 草稿后，主页先显示「准备中」，随后出现 1–3 件事和对应的准备卡；勾选一件、刷新后仍是勾上的。
- 给其中一位联系人补一条事实 → 那张准备卡出现「资料有更新 · 重新生成」；点重新生成后标记消失，今日剩余次数少 1。
- 打开 v2 旧计划：仍是 R24 的概要画面。

## 怎么验收

- 像素门禁：三种目标 × 1440 / 390 × 浅色。
  - 原型没有深色和 1024：深色按 token 实现、1024 按 1440 流式，都只截图留档，不进门禁（D-8）。
  - 超阈值带全部 `[data]` / `[raster]` / `[contrast]`。
- 单元与接口测试：
  - 对账的三种坏输出 + 整段删空 → 通用模板；
  - 没记录的行不渲染且 `gaps` 正确；
  - `staleSince` 置位与清除；
  - 重新生成计入每日限额；初次生成不计；
  - 勾选持久化；v2 退回。
- 不涉及真实 AI、生产、部署。
