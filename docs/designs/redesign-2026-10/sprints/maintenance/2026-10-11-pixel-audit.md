> 依据：[README](../README.md) **RD-16 修订（用户决定 2026-10-11）**——每个画面必须和设计稿画板一模一样，只允许测试数据的**文字内容**不同；验收靠逐像素门禁（整屏 raw ≤ 0.02，`--grid` 逐带，超阈值带只能归因为 `[data]`）。
> 本轮**只盘点、不返工**，产品代码一行没改。工具：`repos/orbits/scripts/visual/compare-redesign.mjs`（Web）、`compare-redesign-app.mjs`（App），用法见 `repos/orbits/scripts/visual/README-redesign.md`。

## 结论（先看这里）

- **盘点范围 157 个画面**（Web 81、App 76，清单来自 R04–R07、R12、R23–R25 的 PLANNER / REPORT）。
- **比了 53 个画面、125 张截图（Web 85 张、App 40 张，各宽度 × 浅 / 深），一张都没通过**。整屏 raw 最小 0.021（Web 主标题区局部），中位数 0.109，最大 0.94（Web iOrbit 深色：旧屏不跟深色）。门槛是 0.02，所有截图都超，且每张都有大量超阈值带——差异不是「数据文字不同」，是**结构不同**。
- **62 个画面设计稿没有对应画板**（组件展示页、错误 / 上限 / STALE 等状态、加人入口页、Web 只有手机画板的弹层等），按新规则要先请用户拍板画法。
- **36 个画面本轮没截到**（要付费 OCR、要不可撤回的达成、本机 App 初版生成失败等），原因逐条写在总表；**6 个**并入同页的其他行。
- **擅自偏离设计 61 条**（D01–D61，「照设计稿做」19 条、「请用户拍板」42 条）+ **设计稿无的自加状态 32 条**（N01–N32）+ **本轮比对新发现、文档没登记的结构偏离 13 条**（X01–X13），见第 3 节。
- **最大的几类差异**（详见第 2 节「共性问题」）：
  1. **Web 主标题区结构不对**：设计稿把页签（カレンダー / To-do / プラン / メモ）放在主标题区左侧、标题下有日期副标题、右侧放主按钮（「目標を追加」等）；实现是标题单独一行居中、页签另起一行，主按钮没有。
  2. **Web 右栏缺失或内容不对**：设计稿 1440 宽的 Task / プラン / 生成流程页都有 iOrbit 右栏（搜索框在上、次の一手 / 今日のチャンス / 確定した方案 / AI 修正面板）；实现大多没有右栏，把这些卡片塞进主区第三列或页底。
  3. **Web 左栏多了东西**：多了「⌘K 検索」项（设计稿的搜索在主标题区左侧圆钮），主催图标不同，底部头像样式不同；390 宽顶部条多了搜索钮和一整行主标题区，少了「Orbit」字标。
  4. **App 顶栏结构不对**：设计稿是「左 🔍 · 中间标题 + 日期 · 右 ＋」居中三段式；实现是左对齐大标题、没有 🔍。生成流程页设计稿是 iOrbit 对话式（≡ / ✕、目标气泡、底部固定按钮），实现是普通表单页。
  5. **卡片与弹层形态不同**：计划概要的分数卡、確定した方案卡内容结构、目标切换（设计 = 标题下 popover，实现 = 底部 sheet）、面談を提案（设计 = 每人 3 个时段 chip，实现 = 日期选择器）、完了页缺「次の目標」候选。
  6. **旧屏还没换**：首页、人脈、iOrbit、イベント、Task 的カレンダー / To-do / メモ、受信箱仍是旧屏（各属 R10 / R11 / R13 / R20 / R21 / R26），iOrbit 等在深色下仍是浅色。
  7. **背景与细节**：设计稿两端页面背景有左上 / 右上两团雾面渐变（`--fog-a/b`），实现是纯色；部分卡片圆角、内边距、字重不同。
- **建议返工顺序**：先 Web 导航壳（影响所有 Web 画面）→ App 导航壳与顶栏 → Web 计划页 → App 计划页 → R12 Web 加人 → 组件库逐件对照；先把第 3 节 42 条「请用户拍板」和 62 个「设计稿无」画面交给用户定，再开工。合计约 **22–30 人日**（第 4 节）。

## 方法与环境

- **设计侧**：`python3 -m http.server 3320 -d docs/designs`，按画板（`.board` 里的 `.web` / `.phone` 画框，`--list` 可列出全部 ~650 块）定位截图；画框圆角、阴影、注释针去掉；深色把画框 `data-theme` 切成 `dark`（kit 的 token 按 `[data-theme]` 级联）。390 用 b6 / b8 的「手机浏览器」画框，去掉状态栏、Safari 底栏和 Home 条，胶囊导航放回视口底边之上同样间距。
- **Web 实现侧**：本机 dev server :3000（本机库 `orbit_newui_events_20260922`，qa@orbit.test）；计划类画面另起一个只读 mock 服务器 :3002（`ORBIT_REDESIGN_MOCK=plan-v2-summary`，计划数据走内存、不写库，演示数据「シリーズA 資金調達（3億円）」= 设计稿示例数据），这样同一画面同时有「真实数据」和「示例数据」两组数字。**完整页面**用「同一块高屏幕」渲染两侧（取两侧自然高度的最大值，实现视口直接设成这么高），避免 sticky 左栏只盖第一屏。
- **App 实现侧**：另启动一台 **iPhone 16e** 模拟器（390×844pt，与设计画框同尺寸，没动另一个会话在用的 17 Pro），装同一个开发包、日语、状态栏统一为 9:41；`xcrun simctl io` 截真实画面（不是 react-native-web），按点宽对齐后比对。状态栏（iOS 画的）两侧涂灰不计差异，灵动岛 / Home 条从设计侧去掉。
- **门禁口径**：单通道差 ≥ 24 记一个不一致像素；带高 100px、逐带 ±12px 上下搜索取最小值；阈值 0.02。**本轮没有提交归因文件**：所有超阈值带都含结构差异，没有一条能如实写成 `[data]`。
- **本机副作用**：App 端走生成流程时在本机库为 qa 留下一个未确定的 intake（目标「展示会で新規顧客を20社つくる」，免费 mock AI，没确定、不占目标名额，Task › プラン 的目標入力上会出现「作りかけのプラン」）；其余操作都是只读或 mock 内存。没连 Neon、没部署、没调付费 AI。
- **局限**：① 设计稿「スクロール後」类画板按「滚到同一段」近似对齐，数字偏大；② mock 模式在实现里显示「サンプル」标签（设计稿没有），这一处计入差异但不算返工项；③ 设计画板里演示用的悬停提示（如 1024 左栏「人脈」tooltip）计入差异；④ 本机缺 `ORBIT_SYNC_CURSOR_SECRET`，App 人脈 / Task 段显示「サーバーに接続できません」，属环境问题。

#### 共性问题（App）
1. 顶栏结构不一致：设计稿统一是「左圆形图标钮 + 居中标题（+ 居中副标题）+ 右圆形图标钮」，实现普遍是左对齐大标题或文字返回「‹ 戻る / ‹ ホーム」、右侧方形描边钮或文字链接。涉及 A-R05-01/02/03/04/05/07/09/11、A-R23-01/04/08、A-R24-01/04/09/12。
2. Task 容器标题：设计稿居中「Task」+ 居中副标题 + 左搜索圆钮；实现左对齐 24pt 特粗标题、无搜索钮、日期用半角括号「(日)」；分段控件更高、整体下移约 4pt，轨道为不透明浅灰而非半透明。涉及 A-R05-04/05/07、A-R23-01、A-R24-01/04、A-R25-01/11/12。
3. 底栏选中态与玻璃感：浅色下实现没有选中项的白色胶囊（深色有），底栏是不透明白底而不是半透明玻璃；未选中标签偏粗偏深。涉及 A-R05-01/02/03/07（以及所有带底栏的 Task/プラン 画面）。

9. BottomSheet 和弹层结构偏离：弹层形态不对（A-R25-11 应是 popover，做成了 sheet）；缺右上 ✕ 或「キャンセル」（A-R24-13、A-R25-12）；按钮从「全宽主按钮 + 文字取消」变成并排两按钮（A-R25-01、A-R25-12）；字段缺失（A-R25-12 的金額/背景/ひとこと，A-R24-13 的方式 chip/いつ/メモ）；弹层高度偏差 100pt 以上（A-R24-13、A-R25-12）。
