# Web 全量设计稿审计与修复（2026-10-25 夜 → 10-26）

用户要求：「按设计稿，其他所有的界面也看看还有哪里不对」，随后授权「自动分析原因然后修复，遵从项目目的和构思，按推荐来」。

## 1. 为什么会和设计稿不一样（根因）

1. **很多页面不是照设计稿的 DOM/CSS 写的**，而是按功能写了简化版（首页、iOrbit 起始页、設定各页、更新の提案、退会 / 書き出し）。门禁一直判 FAIL，但到了预算上限就记进 PX2「⑫ 已知像素差」收口，没有人回来修。
2. **PX2 的 D 类代定**：主会话把「画板对齐真实产品」定成规矩，直接改设计稿去迁就实现（例：受信箱空态 / 1024 被画成实现的双栏、b8 #9 iOrbit 文案被画成实现的旧文案、R18c 的 b12 补画稿）。这些改稿没有经过用户。
3. **共享组件的样式被旧页面的全局重置剥掉**：例如 `FilterOption`（kit `.fopt`）在带 `[data-orbit-real-page]` 的页面上失去底色，所有用到它的页面都受影响。
4. **壳在过门禁后被后续 Sprint 反复改动、没有重比**（10-25 已修首页与顶部标题栏）。

## 2. 审计范围与方法

- `scripts/visual/views/web-*.json` 共约 1000 个「画面 × 宽度 × 主题」键，第一批 16 组用 :3000 + qa，第二批用 r26 / r27 / r17 mock 服务器和公开页。
- 判定：三联图 + `--style-diff`，只记「结构 / 样式」差异；人名、数量、日期等数据差异不记。
- 证据：会话 scratchpad `audit/`、`fix/` 目录（会话结束即失效）；本文只记结论。
