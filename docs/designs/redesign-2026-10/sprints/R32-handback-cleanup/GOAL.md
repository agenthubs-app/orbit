# Sprint R32 — 组件轮交还的页面清理

## 要实现什么

接在 A 线 R29 后，处理 R31a REPORT 的 R31a-H1–H5、R31b REPORT §6 的 1–10，以及 R31a 复核留下的 A-R16-04 和 R05 壳区域门禁。组件已对齐的画面，修页面自身的结构、文案、演示数据或到达中途状态的步骤，再按原画板重比。W-R17-P26 依决定表 §52-1 只比抽屉区域。

本轮由乙的 Codex 在 `redesign-a`（`line-a`）执行。甲名下已完成页面按 RD-30 转给乙；动手前在交接表对应节留一句通知。组件及 token 不在页面修补；缺 Modal 520 档、带链接或 tablist 语义的组件能力时，写给 A 线组件维护的具体请求，并继续其他条目。R31b §6-10 的 Web 规格格缺件按组件请求逐格转出，不冒充页面已过门禁。

## 做完能看到什么

- App 活动九屏、加人草稿、导入选择、计划页各 sheet 和目标切换，按画板显示正确的内容与状态；A-R16-04 的重名标签在对应数据状态下核实，余差逐带处理。
- Web 计划页四个弹层、成员添加、活动参加コード、主办共同運営者抽屉、邀请确认页，按正确的页面数据和操作步骤重比；保留链接与 tablist 的原有交互语义。
- R05 顶栏与底栏区域清单改用 R31a 新门禁的 `region` / `design-region` 格式，重新产出自动结果与逐带归因；不沿用旧人工观察充当通过。
- 每条已过项在 `DEFERRED-A.md` 与交接表记 `done`、提交号和证据；未过或转给组件维护的项保留真实状态及下一责任人。

## 怎么验收

先做画板五项预检，按画面清单在真实 iOS 模拟器与 Web 指定宽度、浅深主题重比。所有超阈带须有属实的 `[data]` / `[raster]` / `[contrast]` 归因，raw 仅供参考；没有画板的主题或组件规格格不写“像素通过”。迭代用 `--only`，每条线同时最多排一个重任务，收口才跑本轮全量、既有通过画面的不退步门禁和两端全量测试。证据放 ORICO，REPORT 逐条列结论、提交号与未完成项；不连接 Neon 或生产环境。
