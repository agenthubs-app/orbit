# Sprint R24 — 计划 v2.2：概要、人物类型与记录加分

## 要实现什么

计划确定以后，用户每天打开 Task › プラン 看到的东西：分数和构成条、确定的方案、Step 和完成确认、每类要见的人、活动，以及「今日のチャンス」。点进一个人物类型，能看到为什么要见这类人、聊什么、谁是候补、怎么请人引荐、哪些活动能遇到；见过之后记一笔就加分，可以撤销；已经很熟的领域可以跳过。

两端都做。旧的 App「人脉需求匹配」页改为跳到这里。

## 做完能看到什么

- プラン概要：大分数（不封顶）、构成条（实色 / 斜纹 / 豆沙 / 灰）、「確定した方案」卡和 4 个统一按钮、今日のチャンス、Step（进度 chip、完成确认卡）、人物类型卡（三格迷你信息）、イベント一块。
- 人物タイプ詳細的三种去向：人脉里有候补、人脉里没有、已跳过；候补按推薦度排序，✓/✕ 确认才关联；「面談を提案」对 Orbit 用户发站内请求、对其他人只出草稿；紹介ルート的依頼文是草稿。
- 记录：面谈记录 / 线下聊过（名字可空）都会加分，同一人同一类型只算一次；超过目标人数后半分；5 秒内可撤销；跳过记满额（斜纹），可撤回。
- 面谈メモ打开「プランの話せた に使う」后，AI 判断 3 问聊到几问，2 问以上出一张确认卡，确认才加分；AI 不可用时改成手动勾选。
- 活动按固定 5 项标准打分，分数随「这类人还缺几个」变化；参加活动给イベント枠加分。
- 首页「プラン スコア」（R10）和这里的数字完全一致。

## 怎么验收

用 R22 的种子计划在两端走一遍：看概要、进三种人物类型详情、记录 / 撤销 / 跳过 / 撤回 / 超额、确认 Step、确认 memo 判定卡；分数在概要、首页契约、两端之间一致；与设计稿 b4 A1–A2、b10 ⑦⑧、app.html / web.html 的プラン部分截图对照；两端全量零新增失败。
