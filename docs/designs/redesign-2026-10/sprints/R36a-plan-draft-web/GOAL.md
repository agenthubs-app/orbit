# Sprint R36a — 计划 v3：初稿页 Web

## 要实现什么

Web 的「初版」画面按定稿设计（`plan-draft-v5-proposal.html` v16 的「初稿 · 确认」页）重做：结论区（目标结果、理由段带来源 / 回答引用与加粗、判定与信心、用到的你的信息）、路线（阶段 + 完成标志）、按阶段分组的可调人物类型表（删一类 / 调人数 / 调分量，合计 100 才能确定）、依据区（为什么这么排、对比条、关键数字、风险、来源清单含抓取日期与「可能已更新」）。初稿页上的调整不占「手动编辑 1 次」（D-1），确定时把调整随请求带给服务端。`schemaVersion` 不是 3 的旧草稿仍显示旧画面。

## 做完能看到什么

- mock 模式切到三份设计稿示例 fixture（融资 / 开拓客户 / 招聘），`/app/plans/flow/<intakeId>` 在 1440 与 390 宽的画面和原型逐像素一致（只有数据文字不同）；没有记录的行不显示。
- 删一类 / 改人数 / 改分量后合计实时变化，≠100 时「确定」按钮禁用并显示差多少；点确定 → 计划按调整后的内容建立，`manualEditUsed` 仍为 false。
- 用旧的 v2 草稿进入同一页：仍是 R23 的 DraftCard 画面；AI 修正、手动编辑入口照旧。

## 怎么验收

像素门禁：三种目标 × 1440 / 390 × 浅色（原型无深色、无 1024：深色按 token 实现只截图留档，1024 按 1440 布局流式，都不进门禁）；超阈值带全部 `[data]` / `[raster]` / `[contrast]`。单元与接口测试：确定带调整的契约、合计约束、v2 退回。不涉及真实 AI、生产、部署。

完整验收项和启动条件见 [PLANNER.md](PLANNER.md)。本页说明预期目标，不代表已实现；整体设计见 [plan-v3/DESIGN.md](../plan-v3/DESIGN.md)。
