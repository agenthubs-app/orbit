# Sprint R10 — ホーム：两端首页组件

**状态：待执行。** **档位：H。** **负责：D 线，Codex 主开发会话**（`/Volumes/ORICO/Dev/worktrees/orbit/redesign-d`，`line-d`）。接在 R20b 后，R19 iOS 小组件接在本 Sprint 后。执行和验收以 [PLANNER.md](PLANNER.md) 为唯一契约；本文件只说明目标。

## 一句话目标

让 `/home` 与 `/app/home` 成为真正可用、可编辑、可跨端保存布局的组件首页：打开便看到今天该做什么、当前计划、下一场活动、人脈和秘書提醒；没有数据时给出明确的下一步。

## 完成后用户能做什么

1. 在 App 与 Web 首页看同一账号的真实数据；Web 有新标题区和「次の一手」右栏，App 有日期、问候语、右上 🔔 红点和「編集」。新 App 屏用 `AppScreen inset="kit"`，只用新组件库。
2. 点「編集」或长按组件进入编辑；拖动排序、在小 / 中两种尺寸间切换、移除后用 Toast「元に戻す」、从按类筛选或搜索的组件库加回。编辑提示条可关闭；App 与 Web 各自保留自己的布局，换设备后可恢复。
3. 默认五块：**今日やること、プラン スコア、次のイベント、人脈、秘書から**。组件库另有 **判断待ち、今週、イベント推薦、メモ**；契约里的 `deadline` 保留兼容，但没有定稿画板时不造一个可见组件。
4. 今日やること在 R20a 最终交付、首页与 Task 同源回读后，读 `GET /api/todo/page` 与 `/api/schedule-items`，并挂 R16 已有的每天一问卡。计划卡读 `plans/v2/summary`：`current=null` 时显示「目標を決める」，`todayDelta<0` 照 N13 的负数口径。活动卡只把真实的下一场参加予定当参加事实。人脈卡读 R11a 的 `addedThisMonth`；最近四人待 B 线交付按加入时间排序的列表参数，此前仅取服务端现有顺序的前四并标 TODO。Web 点人打开 R11a 导出的 `ContactDrawer`。
5. 秘書卡接 R13 先交付的来源契约；R13 未交付时只在本机演示模式显示标明「サンプル」的演示数据，live 不冒充真实提醒。首次使用的「はじめの 3ステップ」沿用 guideState v2 的真实完成事实；R10 与 R28 共用独立于示例开关的进度投影，谁先开工谁单独提交该里程碑，另一方导入。引导入口交 R28。
6. Web 1024「次の一手」按钮、380 抽屉、三条建议与计数按较新的 b12 N07 / N07b；`AgentDock` 按主内容区居中。编辑完成后去掉两端「近日公開」Toast。

## 边界与依赖

- **上游**：R20a 最终交付的 `todo/page` 与 Task 同源回读、R20b 的メモ、R11a 已交的人脈汇总 / Web 抽屉及待 B 线补的 `sort=added` 类列表参数、R13 的秘書来源契约、R16 每天一问、R22 的计划 summary、R26 的参加予定、R31a / R31b 的新组件库。R28 负责引导流程本体；本 Sprint 只呈现首页入口并共用真实进度投影。缺跨线组件或契约向归属线提出请求，不直接改对方正在写的文件。
- **本 Sprint 拥有**：两端首页屏和首页专用组件、D-01 `home-layout` live 读写与 App 本地缓存、首页所需的 D 线导航壳接线。App `dashboard` 旧屏只在引用归零后删除；`home/events` 属活动线，不能顺手删除。
- **不做**：R19 的 WidgetKit / 锁屏小组件、R13/14 的收件箱和推送生产者、R28 的四步引导页面、生产迁移、Neon、部署或真机分发。需要外部授权的工作写进 DEFERRED「待用户授权」。
