# Sprint R17 — 主催：从建活动到会后

## 要实现什么

让主办方在 Orbit 里自己办一场活动，从头到尾不用找运营帮忙：

1. **建活动、发布**：填名称、时间、地点、参加费显示、定员，先存草稿；配好报名表后点「公開する」，系统生成报名页链接和 8 位「参加コード」。之后可以改，也可以中止，改动和中止都会自动通知已报名的人。
2. **报名设置与审核**：写说明文、2–5 个问题（可从模板开始），选「先着順」或「審査制」。审核制下，主办方在「参加者」里批准、候补或婉拒，申请人自动收到固定格式的通知。
3. **编组**：人数够了以后，按条件（每桌人数、轮数、同公司分开、每桌至少一位投资人等）自动生成桌次方案，主办方拖动调整后公开，参加者在会场就能看到自己的座位。
4. **当天受付**：平板上的受付画面可以扫参加者的二维码，也可以按姓名（平假名也行）搜索，点「到着」就完成签到，同时分配受付番号。几台设备一起用会自动同步；断网时也能继续受付，联网后自动补发。
5. **会后报告**：看到场率、名片交换、会后跟进的整体数字；也能只看「自己的角度」（见了谁、对自己的计划贡献多少）。参加者的个人数据只给汇总，人数太少的格子不显示。
6. **一起运营**：邀请其他人做管理者、受付或只读成员，链接 7 天有效。
7. **主办方公开页**：一个属于主办方的页面，有名称、介绍、办过几场、关注人数、即将举办和过去的活动，访客可以关注。

## 做完能看到什么

- Web 左栏「主催」进入「運営センター」：可以建活动、看待办，进入每场活动的六个页签（概要 / マッチング / 参加者 / 受付 / 申込設定 / レポート）和共同运营者抽屉。
- 平板受付画面（不显示导航），扫码签到、离线排队。
- App 上的运营中心、一场活动的运营（概要、编组结果、审核、受付）；入口在「マイページ」，由 R18 放上去。
- 公开主办方页 `/o/<名字>`。
- 两端旧的运营界面删掉。

## 怎么验收

用演示世界的六场活动（开催中、开催前、审核中、已结束各一些）走一遍：
1. 建一场新活动并发布，拿参加コード在另一个账号报名；
2. 主办方审核：批准 1 人、婉拒 1 人，双方都收到通知；
3. 生成编组、调整后公开，参加者的会场页能看到座位；
4. 受付：扫码 1 人、搜索 1 人，断网时再受付 1 人、联网后自动补发；
5. 看报告，邀请一位共同运营者，查看公开页。

每个有画板的画面都和设计稿逐像素对照（Web 浅 / 深、受付平板、App 浅 / 深；缺画板的宽度和画面先补画再比）。两端原有的测试一条都没有变坏。
