# Sprint R21 — iOrbit：起始屏、会話中、会話リスト

## 要实现什么

把 App `/ai`、`/ai/[id]` 和 Web `/app/agent` 重写为 b4 的 iOrbit：起始屏、会话中、历史列表及其搜索、置顶、改名、删除。App 全屏，使用 `AppScreen inset="kit"`，≡ 打开列表、✕ 或左缘右滑退出；Web 使用新壳、日文文案及浅深色。只用新组件库；组件或 token 缺项交给 A 线，导航壳改动交给 D 线。

会话保存 90 日：**第 90 日仍可见，逾期且未置顶才软删除**；置顶最多 5 个并由服务端原子校验。Web 页面上下文开关默认关闭，用户显式开启后才把当前页面的路由、筛选和结果数随提问发送；⌘K / 全局搜索的「iOrbit に聞く」仍只预填，不自动发送。会话搜索提供 `searchConversations(actorId, q, limit)` 给 R30 live 全局搜索，按平台转换两类会话的 href，打开「会話」chip，复验 W-R30-P01 / A-R30-P06。

会话内保留引用来源、流式生成、停止与继续、实体草稿确认及回执；从 R20a「判断待ち」进入 `entity_draft` 所属会话，核对卡片状态与回链。计划 v2.2 的入口和深链接现有服务；清理已无引用的 v1 计划与两端旧 iOrbit 屏。`notes-source` 被 R20b 页面共用，必须保留。

## 做完能看到什么

- App 和 Web 从新建会话、提问、生成、引用来源、实体草稿确认，到历史搜索、置顶、改名、删除与恢复，都有真实可用的链路；刷新、离线恢复和另一端回读结果一致。
- Web 页面上下文的开关和实际发送内容一致；关闭后请求不含上下文。全局提问入口只把文字放入输入框，用户按发送后才计一次调用。
- R30 live 搜索返回本人 iOrbit / 收件箱会话，第四个 chip 可点击并打开正确会话。计划入口跳到 v2 地址，旧地址有必要的兼容跳转。
- 旧 `AiScreen`、`AiConversationScreen` 和 `iorbit-0918` 的引用归零后删除；其他线依赖的来源与服务保留。

## 怎么验收

用隔离本机数据验证本人 / 他人隔离、会话分页、全文搜索、并发置顶第 6 个返回 `409 PIN_LIMIT`、第 90 日边界、置顶豁免、软删除与恢复。两端验证离线与同步、预填不发送、上下文首次进入和换页均不暗带、取消后迟到流事件不会覆盖结果、重连与另一设备并发、额度耗尽后的重试调用数，以及实体草稿确认的重复提交及回执；两类搜索会话都要打开正确的 Web / App 页面。付费 AI 只为必须的本机真实调用记次数。画板有对应状态才进像素门禁；无画板的组合附截图并标「设计稿无」。不连 Neon / 生产，不做生产清理任务启用或部署。

详细契约、画板与 SC、执行顺序和证据见 [PLANNER.md](PLANNER.md)。本页是目标，不代表已实现；状态以 [Sprint 登记表](../README.md) 为准。
