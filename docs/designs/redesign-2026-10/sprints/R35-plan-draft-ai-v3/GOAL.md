# Sprint R35 — 计划 v3：起草 AI

## 要实现什么

计划流程的「初版」这一步改成产出 v3 方案：DeepSeek 按新提示词给出目标结果、理由段（按句、带来源 / 回答引用、每句 ≤1 处加粗）、判定与信心、顺序理由、对比条、关键数字、风险，以及原有的阶段、人物类型和分量；经 `checkDraftV3` 校验与自动修正后以 `schemaVersion: 3` 存入草稿，详情接口把新字段原样给出。搜索结果通过一个可选依赖传进来（R34 提供实现，主会话合流时注入），没有时只用业界现状库并在风险里记一条「本次未能联网核实」。界面不动。

## 做完能看到什么

- mock 模式下对 fundraising / launch / sales 各起草一份：草稿 `analysis.schemaVersion` 为 3，新字段齐全，每个人物类型带 `stepKey`，`sources` 按 `S1…` 编号且理由段的引用都能对上。
- 用假的 DeepSeek 回包跑 deepseek 实现：好回包一次通过；「无来源的句子」「加粗非子串」「分量与判定相反」「引用不存在的来源号」四种坏回包分别被删句 / 去标记 / 修正一次 / 删句后通过；修复提示后仍坏 → 「没能起草」，草稿步骤记 failed，账本操作 failed。
- 没传搜索依赖或搜索 `unavailable` 时，`risks` 里多一条 `unverified` 的「本次未能联网核实」；`GET` 计划详情返回 v3 字段，v2 旧计划返回不变。

## 怎么验收

单元与集成测试：mock 三种目标；deepseek 实现用假 chat（真实调用 0 次）跑好 / 坏回包；flow-service 草稿步骤写入 v3；详情接口透传；v2 旧计划回归整文件通过。不涉及界面、生产库、部署、真实 DeepSeek 调用。
