# Sprint R29 — 运营后台换新

## 要实现什么

接在 R31a / R31b 组件库之后，更新运营后台的 Web 与 App 页面：Web `/app/admin`、`/app/admin/access`、`/app/admin/events`、`/app/admin/read-cost`、`/app/login-admin`、`/app/platform`；App `/admin`、`/admin/access`、`/admin/events`、`/login-admin`、`/platform`。这些页面**没有设计稿**，只换用新 token、文案体系和新组件库组件，不按其他画板重画，也不新增后台业务能力。

保留现有权限和数据边界：公开登录入口只引导登录；后台活动数据仍限于当前账号可见的来源记录；读取量仅 Web、仅获授权账号可看；平台级审核与管理员身份没有可信来源时保持不可用。App 的后台页使用 `AppScreen inset="kit"`，页面内容只用新组件。Web 后台内容使用新作用域和 CSS Modules；后台局部壳 `orbit-real-admin-shell.tsx` 由 R29 / A 线换新组件并完成集成，普通 Orbit2026Shell 主导航壳仍归 D 线。

## 做完能看到什么

- 两端后台页面在浅色、深色和窄屏下采用新 token 与组件，仍能走通登录、跳转、刷新、空态、失败态和返回。
- Web 后台局部壳的桌面导航、手机页签与退出入口均换新组件并接入后台页面；这项集成是 R29 完成条件。
- Web 读取量的日期、路由、账号、趋势与报警仍来自既有汇总读模型；同账号同数据逐项对账，缺存储或读取失败时显示可恢复的页面故障态，不冒充“暂无数据”；无权限时不泄露数据。
- App `admin/access` 与 `login-admin` 都是安全的公开入口，不在未登录时预取后台资料；`platform` 不把公开活动误称为平台审核结果。
- 本组旧屏在 Ionicons、写死文案、旧 UI 写法允许清单中的条目清零；被别处引用的基础设施保持可用。

## 怎么验收

用本机测试账号逐路由走成功、未登录、无权限、空态、失败 / 离线和返回；Web 取 1440 / 1024 / 390，App 用真实 iOS 模拟器，浅色 / 深色截图，逐页对照改前行为与改后界面。每张 R29 截图标 **「设计稿无，附截图，不进像素门禁」**；不填写 raw、超阈带或虚构画板编号。运行两端相关测试和全量门禁，记录零新增失败及跨端差异。生产迁移、部署、生产环境变量与 Neon 连接不在本 Sprint 执行。
