### 9.2 系统性发现（未修，交主会话）

1. **iOS 日文混排行距变大（主会话 2026-10-14 定：单开会话修，本轮不动；被它卡住的画面进「待 UiText 行距」暂缓）**
   - 原因：Hiragino Sans 字体自带 leading = 0.5em（NSFont 实测 16.5px：ascender 14.52 / descender −1.98 / leading 8.25，合计 24.75 = 1.5em；SF 16.5px：15.95 / −3.48 / leading 0，合计 19.43）。RN 把 lineHeight 写成 NSParagraphStyle 的 min/maxLineHeight，TextKit 的 maximumLineHeight 不压字体 leading。UiText 在日文 iOS 下把假名 / 汉字包成 Hiragino 嵌套 Text、拉丁字和数字留 SF（R05 选择 (b)）。结果：纯 Hiragino 行 = max(lineHeight, 1.5em)；**含 SF 拉丁字 / 数字的行 ≈ SF asc+desc + Hiragino leading ≈ 1.68em**。RN 0.86 `RCTApplyBaselineOffset` 只按最大字体 lineHeight 算基线偏移，不处理这一点。
   - 实测（`lines.mjs` 列文字行 y）：类型详情头卡标题 16.5px lh 24.75「シリーズA のリードを取れる VC の / パートナー」行间距 设计 24 / App 27（第 1 行含「A」「VC」）；候补理由 12px lh 18.6 设计 18 / App 20；生成流程回答气泡（含 ①②、拉丁字）设计约 20pt / App 约 24.6pt；N17a 目的阶梯说明 11.5px（含「1段」）与阶梯卡（含「Orbit」）各 +2–3pt，下面整块 +6–9。
   - 受影响（本轮暂缓 11 个）：A-R24-07 / 09 / 12b、A-R23-02b / 08 / 11（含 b12 副本 A-R23-09c #150 / #151）/ 12 / 15 / 16、N17a、A-R25-16。已过的 9 屏里多行混排的地方也有 1–2pt（在 3pt 以内）。
   - 修法候选（给新会话）：UiText 在 iOS 多行时按「含拉丁字的行」补偿 lineHeight / 给拉丁字 run 加负 baseline 偏移；或原生侧让 NSLayoutManager.usesFontLeading = NO（要 patch RN）；或拉丁字 run 也换成 leading 为 0 的同一族字体。改后 R05 壳 14 张、R12 36 张、计划已过 18 张都要 A/B 重比。
2. **iOS 折行引起的后续下移**：§19-2 把折行本身记 `[raster]`，但折行多出一行时下面整块下移 > 3pt（如 08 目的阶梯第 4 级「…ブランドにな / る」vs「…ブランドに / なる」）。是否也按 `[raster]` 计，或给这类文字改逐字折行，需主会话定。
