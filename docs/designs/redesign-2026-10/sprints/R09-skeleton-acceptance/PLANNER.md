## 要做的事

### 1. 规则写进仓库
在 `repos/orbits/AGENTS.md`、`repos/orbit-app/AGENTS.md` 各加一节「redesign 开发规则」（内容相同，指向本目录），至少包括：
- **分支**：在 `redesign` 上开发；个人分支 `redesign/R<编号>-<主题>` 从 `redesign` 开出、合回 `redesign`；`chat-agent` 冻结（RD-03）。
- **契约**：只加不改；每个文件写负责人和使用方；提交信息带 `contract:` 前缀并注明「App 需要同步」；破坏性改动走 `shared/contract/BREAKING.md`（R08）。
- **迁移**：每个模块独立编号、只向前；两人负责的模块不重叠（按功能 Sprint 的归属）。
- **新代码约定**：颜色、圆角、字号、动效只用 token；用户可见文字只进字典或文案文件，并通过 `copy-qa check`；界面只用新组件库；Web 新样式只用 CSS Modules，放在 `[data-orbit-2026]` 作用域内；新路由按说明登记。
- **热点文件归属**：见下表。非负责人要改热点文件时，先向负责人提需求，由负责人改。

| 热点文件 / 目录 | 建议负责人 | 理由 |
| --- | --- | --- |
| App `OrbitTabBar.tsx`、`app-navigation.ts`、`AppScreen.tsx`、`TaskScreen.tsx` 的插槽结构 | 乙 | App 是乙的主战场，Task 的三段也归乙 |
| App `src/components/ui/**` | 乙 | 同上；甲需要新组件时提需求 |
| Web `Orbit2026Shell`、Web Task 容器的插槽结构 | 甲 | Web 是甲的主战场 |
| Web `orbit-2026/ui/**` | 甲 | 同上 |
| `shared/design/tokens.json`、`icons.json` | 甲 | 骨架由甲建立 |
| `shared/copy/**`、术语表、写作规范、`copy-qa` | 甲 | 骨架由甲建立；乙新增文案按规范写，术语变更提给甲 |
| `shared/contract/.snapshot.json`、`BREAKING.md` | 改动该契约的负责人 | 按 R08 的契约归属 |

> 上表是建议。R09 开工时由产品负责人确认（可以调整），确认结果写进两端 `AGENTS.md`。
