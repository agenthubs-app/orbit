# PX2｜像素余项轮⑪

**状态：主会话已批准（§8）。**

## 目标

把功能 Sprint 已交给⑪、但仍缺有效逐屏像素通过证据的画面收成一份可执行账本。先交 A 线共享组件与 token 的确定性修正，再按现行页面归属由 B、C、D、E 分批复比；画板与真实契约矛盾的项由主会话先代定改稿。每张图保留最后有效的 raw、超阈带、缺块、三联图和未归因原因，未拍到目标状态则明记「未运行」。

## 范围

- 来源：R11a、R11b、R13、R14、R18a、R18b、R18c、R20a、R20b、R10、R19、R21、R28、R29、R32、PX1 的 REPORT／REPORT-D／REVIEW，以及这些报告引用的门禁清单和证据。PX1 的后拍覆盖 R11a/b/R21 的旧指标；R32 的 RD-25 重拍覆盖 P20 的旧图。
- 结果：同态 Web 认可画板的 1440／1024／390 × 浅／深，以及 App 真 iOS 模拟器浅／深；只有画板实际存在的组合才进入像素分母。R29 无设计画板，保留前后截图回归，不编造像素指标。R19 的 SwiftUI 局部 PNG 与正式 WidgetKit 实屏分账。
- 边界：本轮计划文档不修改产品、画板、归因或组件源码；后续实施仍须遵守各线文件归属和既有授权。不连接 Neon／生产、不部署、不碰 3000／3500 端口。正式签名、App Group、真机与发布等待用户另行授权。

## 完成定义

1. `PLANNER.md` 的每个待办键有唯一来源、最后有效证据或「未运行」理由、主类别 A／S／D／X 和下一责任线；同一屏的错态、过渡帧、旧版截图不得充作有效比较。
2. A 线修正后列出精确受影响键并重比；B/C/D/E 各自只改本线页面或 fixture，每个画面同一版本最多三轮，超限仍红的差异进入「已知像素差」并交⑫总验收。
3. RD-16／RD-29 的逐带合法归因、结构完整、同态数据和缺块人工复核均满足；至少抽查已过键的 20%。自动 `pass:true` 不替代目标态、画板版本和结构复核。
4. 主会话对 D 类逐项选定改稿与版本后，相关键才进入实施门禁；X 类取得签名／设备授权前只保留局部诊断，不宣称实屏通过。
