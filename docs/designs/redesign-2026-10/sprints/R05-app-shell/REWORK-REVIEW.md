### 中（M）

**M1 — 推入二级页的瞬间，旧的一级页先长出「‹ ホーム」顶栏，正文下移约 60pt**
- 在哪：`src/components/AppScreen.tsx:60`（`navVisible = showBack ?? (!mainTab && pathname !== "/ai")`，`pathname` 是全局当前路径）。
- 看到了什么：录屏 `d07.mp4`，抽帧 `d07b/key.png` 第 1 格：点首页头像后，路径先变成 `/profile`，还在屏幕上的首页（`HomeDashboardScreen` 用的是 `AppScreen`）重算出「不是一级页」，画出 ‹ 圆钮 + 标题「ホーム」，整页往下跳一截，然后マイページ 才推进来。所有用 `AppScreen` 的一级页（首页、Task 各段以外的页面）推入二级页时都会这样。
- 为什么是问题：判断逻辑本次没改，算旧问题；但新顶栏高 64pt、带圆钮，比旧的 48pt 文字栏显眼得多，正好和 D07「像原生那样推入」的目标冲突。

**M2 — D07 底栏不跟页面走：返回时盖在正要离开的マイページ上，推入时比页面先跑掉**
- 在哪：`src/components/OrbitTabBar.tsx:68–96`（`ShellTabBar`；`Animated.timing` 0 → −width，350ms，`bezier(0.2, 0.9, 0.3, 1)`，底栏画在整个导航栈之上）。
- 看到了什么：`d07b/key.png` 第 3、4 格（返回过程）：底栏已经大半回到屏幕，压在还没滑走的マイページ下部内容上（「投資人 · 供応商」等被挡）；推入时（第 2 格）首页才移出约 1/3，底栏已经完全不见。
- 为什么是问题：D07 的目标是像 iOS `hidesBottomBarWhenPushed`——底栏属于一级页、和一级页一起移动。现在它是一条独立动画，曲线和距离都和页面不同，而且画在最上层，返回时会盖住二级页。REPORT 说「与原生栈同速」，实际只是时长相同。
- 建议：底栏位移跟原生栈的转场进度走（成熟做法：react-navigation 的 `useCardAnimation` / native-stack 的 `transitionProgress`，或把底栏放进一级页自己的视图里，让它随页面一起被推走）；至少把位移改成与一级页相同的视差距离、并放到二级页之下。动画的中间帧截不准，验收用录屏抽帧。

**M3 — `cjkLift` / 标签 `translateY` 在所有平台都生效，只按 iOS 实测**
- 在哪：`src/components/ui/cjk-lift.ts:6`、`ShellTopBar.tsx`（标题 −1 / −2、副标题 −0.5 / −1）、`Segmented.tsx`（−1 / −1.5）、`OrbitTabBar.tsx:112`（−0.67）。
- 为什么是问题：偏移量是「iOS 比 Chrome 低多少」的实测，App 的 web 版（测试就在它上面跑，`useShellTopGap` 也专门区分了 web）用的是浏览器排版，本来就和设计稿一致，现在反而被上移 1–2pt。另外：只按「含不含 CJK 字符」分两档，中文走 PingFang、日文走 Hiragino，竖向度量不同，中文界面没量过；英文界面也没量过。
- 建议：至少和 `useShellTopGap` 一样只在 `Platform.OS === "ios"` 生效；在中文、英文界面各跑一次 Task 顶栏 / 底栏局部门禁，确认偏移量也合适（不合适就按语言或字体分开取值）。长期更稳的做法是排查行框差异的根因（`lineHeight` 与 iOS 字体 ascent 的关系），而不是逐处挪像素——这一条可以登记给 R01。大字号下偏移是固定 pt，不会放大，问题不大。

**M4 — D01 测试被放宽到 40，44pt 按压区不再有测试守着**
- 在哪：`tests/app-wide-primitives.test.ts:142–143`（`fits(back, 320, 44)` → `40`，`width >= 44` → `>= 40`）。注释写「hitSlop 把触控区扩到 44，不在 DOM 盒里」。

- 建议：断言恢复为「按钮盒 ≥ 44」，另加一条「里面画出来的圆是 40」；注释改成实际做法。

**M5 — REPORT 对剩余差异的分类与表格有出入**
