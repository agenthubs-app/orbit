# Sprint R37b — 计划 v3：App 计划主页

## 要实现什么

App 的计划主页（Task › プラン 里当前目标的概要）按定稿设计（`plan-draft-v5-proposal.html` v16「手机」视图的「计划主页 · 执行」页）重做，内容与 Web（R37a）相同。服务端（准备卡生成、对账、勾选 / 重新生成 / 补事实接口）R37a 已经做好，本 Sprint 只做 App 的界面部分：

- 头部「目标结果 + 结论 | 阶段 N / 总数 + 阶段名 + 进度条 + 人脉里 x / y 人 · s / 100 分」——阶段在前、分数退后。
- 路线，每个阶段下写「完成标志：…」。
- 「建议先从这 N 件开始」勾选清单：勾选持久化；每件可展开准备卡（行表、为什么这样开口、开场白画线 + 复制、资料有更新 · 重新生成、可以补充）。
- 「要认识的人」空位表（已认识头像 / 还需要认识 / 分量），点开看是什么样的人、已在人脉里的人或去哪里认识、见面聊什么。
- 「为什么这么排」折叠，点开回看初稿的依据区（复用 R36b 的部件）。
- 准备中每 3 秒重读、最多 10 次；没有可做的事显示「去认识」提示。
- `schemaVersion` 不是 3 或没有 `home` 的计划仍显示 R24 的概要画面。
- 目标切换、見直し、手动编辑、达成、前提、待确认卡等入口照 Web（R37a）放在页身之下（待用户过目，App 不另改）。

## 做完能看到什么

- 模拟器（iPhone 16e · iOS 26，日文）连 mock 服务器三份设计稿示例 fixture（`v16-home-fund / -sales / -hire`），Task › プラン 的浅色画面与原型「手机」视图逐像素一致（只有数据文字不同）。
- 勾一件、重进页面后仍是勾上的；准备卡点「重新生成」额度用完时显示上限提示、卡片不变；「+ 写一句当时聊了什么」保存后准备卡出现「资料有更新」。
- v2 旧计划仍是 R24 的概要画面。

## 怎么验收

像素门禁：三种目标 × 模拟器浅色（原型无深色：深色按 token 实现只截图留档，不进门禁）；超阈值带全部 `[data]` / `[raster]` / `[contrast]`。App 测试：三份 fixture 渲染、缺字段隐藏、勾选请求（`actionKey` URL 编码）与失败回滚、重新生成 409 `LIMIT`、补事实请求、准备中轮询、v2 退回；App typecheck；全量测试对照基线新增失败 0。收口时在 iOS 27 的 16e 上补一张启动截图。不涉及真实 AI、生产、部署、TestFlight。

完整验收项和启动条件见 [PLANNER.md](PLANNER.md)。本页说明预期目标，不代表已实现；整体设计见 [plan-v3/DESIGN.md](../plan-v3/DESIGN.md)。
