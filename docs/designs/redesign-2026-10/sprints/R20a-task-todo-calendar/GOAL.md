# Sprint R20a — Task：容器 + To-do + カレンダー

## 要实现什么

先把两端「フォロー」读不出来的问题查清并修好。然后加一个只读的 To-do 汇总接口：判断待ち、今日の一手、フォロー三块各带件数，后面首页（R10）和 iOS 小组件（R19）也读它。在这个接口上照设计稿重写两端的 To-do 和カレンダー：下書きエディタ、「送りましたか？」、左滑完成并留一句话、延期、タスク一覧与详情、フォロー完成后定下一步、月 / 週 / 日カレンダー、予定的编辑 / 繰り返し / 重複提醒、面談の日程提案、面談的详情 / 動かす / キャンセル，并能看到已连接的 Google カレンダー（只读，不存到 Orbit）。Task 容器的分段、左右滑和返回恢复按设计稿收好。旧的今日页、任务页、Agent 判断页和个人日程页全部换掉、删掉，旧地址跳到新位置；确认待ちの下書き页保留。メモ留给 R20b。

## 做完能看到什么

- 两端打开 Task › To-do，一屏能看到「判断待ち / 今日の一手 / フォロー」三块和各自的件数；已经过期的事还留在フォロー里，标成红色。
- 判断待ち 里也会出现 iOrbit 对话里等你确认的草稿（点开回到那段对话）和名片 / 导入后待确认的联系人（点开进原来的確認待ち页）。
- App 断网后 To-do 和カレンダー照样能打开，显示上次的内容，隔天打开会标「以前の情報」；本机任务的完成、延期马上反映出来，连上网后再同步。
- 判断待ち 里点「完了」可以顺手留一句话；今日の一手 只帮你写到下書き，发不发由你决定，回到 App 时会问一句「送りましたか？」。
- カレンダー能在月 / 週 / 日之间切换，新建或修改予定时会提示时间重叠。个人予定可以直接改时间；面談改时间时要重新给对方 3–5 个候选时间，也可以取消。已连接的 Google カレンダー 能看到，没连接时有「連携する」入口，连完回到カレンダー。
- 「面談の日程提案」做成一个独立的弹层组件，R11 把它挂到联系人详情里。
- 旧的 Today、旧英文任务页、Agent 判断页、个人日程页都没有了，旧链接会跳到 Task 里对应的位置。

## 怎么验收

フォロー 修复要在 REPORT 写清根因并带回归测试。To-do 汇总接口和 Google 日程接口要通过契约检查、演示数据测试；To-do 汇总接口另要通过 App 离线副本测试。两端每个画面都有操作链证据。组件库像素轮（R31a / R31b）合入后再跑像素门禁：Web 跑 1440 宽的浅色画板，有深色画板的再跑深色；App 跑浅色画板，有深色画板的再跑深色。设计稿没有画的宽度和深色（Web 1024 / 390 等）只附截图，并登记「设计稿无」。两端全量测试零新增失败。最后由独立复核自己重跑一遍。
