# 探す（イベント発見）· 时期与场所规则（2026-10-29 定稿）

用户 2026-10-29：「发现页默认筛选『今月／東京』，服务端时间窗口也只取当前时刻之后的活动，所以 4 场历史活动不会出现。按成熟产品的样式设计规则……都按你推荐来」。本表取代 R27 PLANNER 里「默认 今月 · 東京」的口径。

## 对标

| 产品 | 做法 |
| --- | --- |
| Luma / Meetup | 列表默认「Upcoming」，同一处有「Past」切换；过去的活动按时间倒序、不能报名 |
| connpass | 检索默认只列开催前，可切换包含已结束 |
| Peatix / Eventbrite | 发现页不默认按城市截断，地点是用户自己加的筛选 |

## 规则

| # | 规则 |
| --- | --- |
| D1 | **默认时期 = 「これから」**（新 period `upcoming`）：现在还没结束的公开活动（**含正在进行中的**），到目录上限（120 天）为止。 |
| D2 | **默认场所 = 不限**（「場所：すべて」）。东京等是用户自己加的筛选；URL 上 `areas=` 照旧可分享。 |
| D3 | 时期选项顺序：**これから · 今週 · 今月 · 来月 · 開催済み**。今週 / 今月 / 来月 的窗口照旧（东京时间自然周 / 月，从现在起），但**按时间重叠判断**——已经开始、还没结束的活动算在内。 |
| D4 | **「開催済み」**（`past`）：过去 1 年内已经结束的公开活动（生产上现有的 4 场历史活动在 3–6 月，90 天窗口会一场都看不到，所以取 1 年，对标 Meetup / connpass 的过去活动全量可查），**按开始时间倒序**（最近的在前）。不打分、不进「プランに効く」「コミュニティ」、不给「条件を広げる」；场所 / テーマ / 形式 / 無料のみ 照常生效。**与これから同一卡片样式、整体灰掉**（opacity .55 + 灰度），chip 显示「終了」，没有分数 / ☆保存 / 興味なし；卡片仍可点开详情。390 = 手机列表行同样灰掉。 |
| D5 | （10-29 追加修订：活动还少，不折叠）非「開催済み」时，在结果最下方**直接平铺**「開催済み · N件」灰卡片（同一场所 / テーマ等条件、过去 1 年、新しい順，最多 50 张）；超过 50 件时标题右侧给「すべて見る」切到「開催済み」。N = 0 不显示。没有计划 / 未登录的人也一样有。 |
| D6 | 打开已结束活动的详情：顶部「イベントは終了しました」，不出报名按钮；已参加的人给「会后」入口（详情页 ended 规则，同日实现）。 |
| D6b | 未登录的公开活动页（`/events` 落地，「公開イベント · N月」）不变：仍是 今月 · 東京。 |
| D7 | App 端探す 暂不改（仍默认 今月 · 東京，服务端兼容旧参数）；App 对齐登记为后续。 |
