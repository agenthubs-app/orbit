# Sprint R20b — Task › メモ

## 要实现什么

接在 R20a 的 Task 容器、To-do、カレンダー之后，完成两端的 メモ。App 整屏重写旧笔记列表、新建、详情、编辑四屏并删除旧实现；Web 新建 メモ 段的左列表、右详情和标题区「＋ メモを追加」。笔记按「すべて / 面談 / 自由メモ」查看；音声只标记输入来源，不另开一个分类。@人、@イベント 都是可保存、可读回、可跳到对象的 token。

保存链要把 `noteKind`、`usedForPlan` 和活动提及真正写入、读回；面談メモ的「プランの話せた に使う」接上 R24 的判定提议。Task 的 `planLink` 从现有可选契约落到任务记录，让人物タイプ詳細的「やること」能读到同一条 To-do。App 手入力的「メモ」在联系人保存成功后进入 Task › メモ 并带上联系人，而不继续当联系人备注。

本期不录音，隐藏 🎙；旧 `voice` 笔记只在读取时显示音声来源 chip。b5 #47 录音画板与 E3 的「一言メモ → AI が整理」、整理结果、自动建议写日程推迟下一期，登记 DEFERRED；不加原生依赖。原有离线写入、版本冲突、幂等和联系人作用域继续成立。

## 做完能看到什么

- App 与 Web 的 メモ 列表可切三类、搜索、翻页、打开详情、保存和编辑；Web 标题区有「＋ メモを追加」，App 的 Task「＋」进入新建页，正文没有重复的大标题。
- 输入 @ 可搜索人和活动；选择 @人 或 @イベント 后，token 与显示文字一起保存；重开、跨端读取、编辑正文后范围仍正确。联系人详情和活动链接指向可访问的对象。未知 token 编辑后原样回传。
- 面談メモ明确选择用于计划时，保存成功后才触发 R24 的判定提议；没有关联的计划或判定失败时，笔记仍保存成功，错误有记录。
- 离线的 App 仍能新建和编辑笔记并等待同步；手入力联系人的本机临时 id 先同步成真实 id，依赖它的笔记再出队。Web 断网时「＋」禁用。
- 面談の記録（`appointments/[id]/memo`）本期不并入 メモ 列表，登记 DEFERRED。
- 旧 `/notes` 链接导向 Task › メモ，带 `contactId` 的链接仍是联系人范围的独立二级页；四个旧屏实现删除，新屏与路由回归通过。

## 怎么验收

先核实 R20a 已完成并进入 D 线基线，再做本机契约、服务、离线和两端操作链。旧笔记 payload 往返不变；活动 mention 按 `entityType` 分支严验，App 响应宽进；共享与 App 离线 strict schema 一起只加不改地放宽，`contactId` 改可选的破坏性变更登记在 `BREAKING.md`。画板以 app.html #26、web.html #19、b11 #36、b5 #46 / #49–51 的非 AI、非录音部分为准；b5 #52 作废不进 Web 门禁。缺 Web 1024 / 390 / 深色画板按 R20a「设计稿无」规则留截图和交接。组件库 R31a / R31b 合入后跑像素门禁；两端全量测试与独立复核零新增失败。不连 Neon 或生产，不部署。
