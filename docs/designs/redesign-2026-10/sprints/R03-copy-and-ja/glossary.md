**依据：** [`research.md`](research.md)（15 个产品 / 指南）、设计稿 `01-system.html`（以下简称「设计稿」，标注行号）、`kit/kit.js`、README 用户决定 RD-02 / RD-20。
**优先级：** ① 用户决定和已定稿设计稿里的名字（导航、Task 分段、草稿边界）；② 日本商务产品惯例（Eight、Sansan、LinkedIn 日本版）；③ iOS 自带 App；④ 三份风格指南定写法细节。② 与 ① 冲突时保留 ①，在「选择理由」里写明风险。

每条字段：概念 / 日 / 中 / 英 / 词性 / 用在哪里 / 禁用写法（原因）/ 例句 / 调研依据 / 选择理由。词性：名 = 名词，动 = 动作（按钮形式见 style-guide §1.1），状 = 状态标签（体言止め，≤8 字），句 = 提示句。

**「禁用写法」分两类（审校 M12）：**
- **全局禁用**（不论上下文都不能出现）：只有下面这张「全局禁用清单」里的写法，由自动检查报告。R03 的 `repos/orbits/scripts/copy-qa/check.mjs`（本 Sprint 新建）照这张清单实现，两者不一致时以本清单为准、改代码。

  | 语言 | 全局禁用写法 | 原因 |
  | --- | --- | --- |
  | 日 | エラーが発生しました | 笼统失败句 |
  | 日 | 送信しました、送信済み、送信する | Orbit 不代发（否定式「送信はしません」和「送信はあなたが行います」允许） |
  | 日 | 私たち；〜させていただきます、〜でございます、ご〜になられます | 人称、过度敬语 |
  | 日 | コンタクト、受信トレイ、ドラフト、リトライ、環境設定 | 术语统一 |
  | 日 | ToDo、TODO、To Do | 写「To-do」 |
  | 日 | 再試行してください、再度実行 | 句子用「もう一度お試しください」 |
  | 日 | 词尾缺长音：ユーザ、カレンダ、メンバ、リマインダ、サーバ（后面没有「ー」时） | 长音规则 |
  | 中 | 发生错误、出错了、已发送、发送成功 | 笼统失败句；不代发 |
  | 英 | An error occurred、Something went wrong、Sent、we / our | 笼统失败句；不代发；不用 we |

  匹配方式（审校 L35）：英文按整词、不分大小写（`we` 不命中 week / your）；日文和中文按字串，但**外部服务名在白名单里**（Google コンタクト、Microsoft To Do 不报）；中文「已发送」「发送成功」只在按钮和 Toast 里查（「对方已发送交换申请」这类叙述句不报）。
- **场合禁用**（其余所有「禁用写法」）：只在该行「用在哪里」的场合不能用，同一个词在别处可能是正式术语（如「つながり」「タスク」「イベント」），由人工审校按本表判断，不进自动检查。
- 白名单优先于禁用表：设计稿原文和本表例句里出现的写法一律允许。

## 10. 待产品负责人事后过目的取舍

1. **受信箱 vs 受信トレイ**：保留设计稿「受信箱」。
2. **プラン 与付费方案撞名**：功能名保留「プラン」，付费方案写「ご利用プラン」。
3. **再試行（按钮）vs もう一度（句子）**：按钮沿用设计稿「再試行」，提示句用「もう一度お試しください」；连携失败卡按设计稿用「もう一度」。
4. **中文导航「Task」不翻译**：避免「待办 › 待办」。
5. **秘書**：作为功能区名保留，英文「Mail briefing」，AI 助手本身叫 iOrbit。
6. **参加予定 ≠ 已报名**：未申込时必须同时显示「未申込」或申込按钮；补「申込済み」。
