## 1. 日语

### 1.1 语气与句式

| 场景 | 规则 | 例 | 依据 |
| --- | --- | --- | --- |
| 正文、说明、提示句 | です・ます体，句末加「。」 ✔ | 通信状況を確認して、もう一度お試しください。 | MS §4.2；JTF 1.1 |
| 按钮 | ① 不用です・ます，不加「。」 ✔；② 形式限于：汉语名词（保存、削除）、「〜する」（削除する）、和语动词原形（開く、閉じる、やめる、元に戻す）、「〜を + 汉语名词 / 动词原形」（下書きを作成、参加を取り消す）；③ **确认框和 AI 确认卡里的主按钮用具体动词**：「〜する」（削除する、追加する、公開する），或设计稿定稿的「〜を + 动词原形」「〜して〜」（参加を取り消す、承認して交換）；只读告知的唯一按钮用「わかりました」（审校 L22）；**页面和列表里的入口按钮用名词形**（削除、編集、保存） | — | MS 按钮惯例；设计稿 ②④ |
| 标签、导航、页签、状态 chip | 体言止め，不加「。」 ✔ | 期限超過 / 参加予定 | JTF 1.1.4 |
| Toast | **主句**：过去式「〜しました」「〜できませんでした」或体言止め，不加「。」 ✔；**副句**（主句下的一行）：可用现在时（接続後に同期します、10月8日（木）朝 8:00 に通知） | 完了にしました / 副句：接続後に同期します | 设计稿 ① |
| 标题（页面、对话框） | 不加「。」；确认框标题用问句「〜しますか？」 ✔ | このタスクを削除しますか？ | 设计稿 ② |
| 敬语 | 允许定型的美化语和定型礼貌句：ご利用、お知らせします、お試しください、お問い合わせください、お礼；**禁止过度敬语**：〜させていただきます、〜でございます、ご〜になられます ✔；道歉「申し訳ございません」只用于严重故障 | 大事なときだけ、お知らせします | MS §4.2；设计稿 |
| 人称 | 不写可有可无的「あなたの」；**需要区分用户与 AI / 他人时用「あなた」**（あなたの判断待ち、あなたが補った項目、送信はあなたが行います）；「私たち」一律不用，需要主语时写「Orbit」或「iOrbit」 ✔（检查「私たち」） | Orbit からは送信しません | Apple HIG（反对可有可无的所有格）；设计稿 |
| 失败 | 一句说什么失败 + 一句原因 + 下一步；禁用笼统的「エラーが発生しました」 ✔ | タスクを読み込めませんでした。通信状況を確認して、もう一度お試しください。 | 设计稿 ⑧；MS |
| 发送 | 禁止以 Orbit 为主语的肯定式：送信する、送る（作按钮）、送信しました、送信済み ✔；允许否定式和询问用户式：送信はしません、送りません、送りましたか？、送信はあなたが行います | — | 设计稿 ⑯ |
| 平台动词 | App 用「タップ」，Web 用「クリック」；两端共用的文案不出现这两个词，改说「〜を選ぶ」「〜を開く」 | 「Orbit」をタップ（仅 App） | Apple HIG；设计稿 |

### 1.3 字符与标点

| 规则 | 写法 | 依据 |
| --- | --- | --- |
| 数字、拉丁字母 | 半角 ✔ | JTF 基本规则 7–8 |
| 拉丁字母单词与日文之间 | **加半角空格**（产品名、英文缩写、外部服务名）：「iOrbit に聞く」「Google カレンダー」「AI の提案」；句读点、括号、「」两侧不加 ✔（检查拉丁字母与假名 / 汉字紧贴）。例外：拉丁字母是日文词的一部分时紧贴（「シリーズA」「To-do」），自动检查跳过单个大写字母后缀（审校 L21） | 设计稿全篇；Google、ChatGPT 实际写法（research §3.4） |
| 数字 | 数字 + 量词紧贴（12枚、4件、30分、3名、あと2日）；数字前接名词时加空格（名刺 12枚、今日やること 4件）；时刻前后加空格（「朝 8:00 に通知」「今日 23:59 まで」）；数字前接名词或助词时加空格（「候補は 3名です」，与设计稿一致，审校 L31）；配额例外「今月あと 2 回」「あと 25日」只用于配额（设计稿原文，数字用数字字体）（审校 L21） | 设计稿 |
| 括号 | 「」（）全角；英文内容外侧也用全角（「（木）」） ✔ | JTF 规则 9 |
| 句读点 | 「、」「。」全角 ✔ | JTF 规则 2 |
| 问号、感叹号 | 全角「？」 ✔；尽量不用「！」 | JTF |
| 范围 | 「〜」**U+301C**（跟随设计稿，有意偏离 JTF 的 U+FF5E）；`copy-qa` 报告 U+FF5E「～」和半角「~」 ✔ | 设计稿 |
| 分隔 | 信息块分隔用「 · 」（U+00B7，两侧半角空格）；名词并列用「・」（U+30FB，不加空格：タスク・予定・メモ） | 设计稿 |
| 长音 | 词尾长音保留：ユーザー、カレンダー、リマインダー、メンバー、サーバー ✔ | JTF 规则 5 |
| 字形 | 不得出现简体中文字形（关、设、发、录、页……） ✔ | — |

### 1.4 日期与时间

- 正文和标题：「10月7日（水）」；需要年份时「2026年10月7日」；不加空格 ✔（检查「10 月」）。
- 根拠、列表行、紧凑场景：「10/2」（半角斜线，不补零）。
- 时间 24 小时制「19:00」；相对时间「あと30分」「今日 23:59 まで」。

## 2. 简体中文（大陆）

| 规则 | 写法 |
| --- | --- |
| 第二人称 | 用「你」（与现有 App 字典一致）；不用「您」 |
| 语气 | 简洁、直接；正文可用「请」 |
| 标点 | 全角「，。？：（）」 ✔；引号用「」与日文版保持一致——**有意偏离**大陆标准的“”（产品既有约定） |
| 数字与英文 | 半角；中文与数字之间不加空格（「12张」）；中文与拉丁字母单词（产品名、外部服务名、英文缩写）之间加半角空格（「问 iOrbit」「Google 日历」），与日文规则一致（审校 L29） |
| 按钮 | 动词或动宾短语，不加句号（「保存」「生成草稿」） |
| 失败 | 「无法……」，不用「发生错误」「出错了」 ✔ |
| 发送 | 不得出现「发送」按钮、「已发送」提示 ✔；否定式说明可用（「不会替你发送」） |
| 日期 | 「10月7日（周三）」；紧凑场景「10/2」 |
| 长度 | 与日文同一套上限（按全角计）（审校 L28） |

## 3. English

| 规则 | 写法 |
| --- | --- |
| Case | Sentence case for buttons, titles, tabs, chips: "Create draft" ✔（检查第二个词起的大写，产品名和 iOS App 名除外） |
| Tone | Short, plain; contractions OK ("Can't", "Couldn't"); no "we" — say "Orbit" when a subject is needed ✔ |
| Punctuation | No period on buttons, labels, chips, toast titles; periods in body sentences |
| Errors | "Couldn't …" + reason + next step; never "An error occurred" / "Something went wrong" ✔ |
| Sending | Never "Send" as a button or "Sent" as a result ✔ |
| Dates | "Wed, Oct 7"; compact "10/2" |
| Length | Chips ≤ 20 characters, buttons ≤ 24, toast titles ≤ 32; tab and nav names ≤ 12 (review L28, M15) |

## 4. 三语一致性（✔ 自动检查）

- 同一个 key 三语都有值，不得为空。
- 占位符 `{name}` 三语集合一致。
- 日语与中文完全相同时报告（疑似没翻译）；白名单：产品名（iOrbit、Task、To-do）和同形词（保存、主催、名刺、予定、通知、編集、追加……，逐条登记在 `scripts/copy-qa/check.mjs` 的 `SAME_OK`）。
- 只报告术语表开头「全局禁用清单」里的写法；其余「禁用写法」是场合禁用，由人工审校（审校 M12 / M14）。

## 5. 插值与拼接

- 不在代码里拼句子；句子整句进字典，变量用 `{name}` 占位。
- 计数句整句写出单位：「{count}件を表示」，不写 `count + "件"`。
- 日语没有复数变化；英文需要单复数时写两个 key（`…One` / `…Other`），不用代码判断拼 s。
