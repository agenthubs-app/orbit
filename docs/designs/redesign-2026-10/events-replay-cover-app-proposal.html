活动页：结束后回看 · 参加者资料 · 活动图片

需求 1：参加过的活动，参加者资料能点开；活动结束后，当天会场里的「おすすめ / 参加者 / グループ / 予定」都能回看。需求 2：主办方可以给活动加一张图，显示在卡片顶部。示例与 b2 同一场「CFO Night Tokyo vol.18」，人物/公司均为虚构。Web 稿由 Web 会话另出，流程与内容两端一致。

需要你拍板的点（与 Web 稿 P1–P4 共用一套答案）

D1 = Web P1　活动结束后，还能向没交换过的人申请交换吗？
推荐 A：结束后 30 天内可以申请，之后资料只能看（按钮换成「申請期間は終了しました」）。对标 Brella / Swapcard：活动结束后社交区仍开放一段时间再关闭。
B：结束后一律不能申请，只能看。　C：一直可以申请。
D2（App 新提，Web 卡片网格同样适用）同一排卡片里，有的活动有图、有的没图时怎么排？
推荐 A：这一排里只要有一张有图，没图的卡用它自己的 emoji 色带补成同样的 2:1 顶部（板 ⑧b）；整排都没图时保持现在的样子。对标 Luma / Peatix：卡片网格里顶部图位总是齐的。
B：有图才出图，没图的卡保持现样（卡片高低不齐；Web 稿目前画的是 B）。
Web P4　报名了但没签到的人，结束后能看会場の記録吗？
推荐：只要在主办方公开的分组结果里就能看（导入的中日创业交流会参加者多数没有签到记录）。App 按同一规则做。
Web P3　App 上主办方能上传活动图片吗？
推荐：这次只在 Web 上传，App 只显示（App 的编辑活动本来就是「PC が便利です」页）。

已按推荐定的（不用拍板）

  1. 回看叫「会場の記録」，入口放在活动详情页：结束后封面卡下面出入口卡（板 ①，Web 是详情页右上主按钮，去向与条件相同）。对标 Meetup / Luma：过去的活动仍是同一个详情页，下面接当天的内容。
  2. 会場の記録 = 会场页的只读版，同一套底栏，去掉「現場」和「関係マップ」（只在当天有意义），留 おすすめ / 参加者 / グループ / 予定，进去默认停在グループ；グループ 把 3 轮都列出来（当天只看当前轮）。写操作只剩自己的メモ和弹层里的交换申请（D1）。
  3. 参加者资料统一用会场里已有的「参加者シート」弹层（板 ⑤⑥），从详情页参加者 tab、回看页、会后页点人名都打开它。对标 LinkedIn Events / Brella：点人出资料卡，不跳整页。
  4. 弹层里只放这场活动里的事实：同桌过哪一轮、是不是你的おすすめ和理由、TA 公开的参加用プロフィール、你自己的メモ。不显示邮箱电话；交换过的人给「連絡先を開く」去联系人详情。
  5. 谁能看会場の記録：报名者且在主办方公开的分组结果里（不要求签到，Web P4 推荐）；没进分组的人不出入口卡，旧链接进来看到说明卡 + 参加者一覧 / アジェンダ 两个入口（板 ⑦）。
  6. 图片只放卡片顶部 2:1，图上只叠「申込 N名」一个 chip（与 Web 相同）；详情页原来压在色带上的「残り N枠 / 終了」挪到标题下的状态行（板 ⑩）。对标 Luma / Peatix 封面图都不压字。
  7. 探す「すべて」列表行、コミュニティ行不放图，保持日期块：行高只有 60，缩略图看不清，日期更有用。
