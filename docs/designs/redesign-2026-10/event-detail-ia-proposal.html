活动详情 Web：去掉「紹介 / アジェンダ / 主催 / 参加者」tab，改成一页读完

用户反馈：「四个 tab 但其实是顺序排列放置的，这合理吗？」——不合理。Web 现状里 tab 只是锚点：点了会滚动，但 tab 下面永远显示介绍、滚回去 tab 也不变；手机宽度下同一组 tab 却是真切换。提案：两端都去掉 tab，一页从上往下读完；Web 右栏只放「你和这场活动」（参加状态 + 唯一主按钮、和你有关、主办方）。区块顺序与 App 一致：紹介 → アジェンダ → 参加者 → 主催（≥1280 主催在右栏）。示例与 App 稿同一场「CFO Night Tokyo vol.18」，人物 / 公司均为虚构。

需要你拍板的点

W1　去掉 tab，详情页改成一页从上往下读吗？
推荐 A：去掉 tab，四块按 紹介 → アジェンダ → 参加者 → 主催 排在同一页（与 App 同序）。对标：Luma、Peatix、connpass、Eventbrite、Meetup 五家活动详情都是单页纵向排列，没有一家用 tab，也没有吸顶的锚点导航（2026-11-21 逐页核实，来源见下方对标表）。
B：保留成「吸顶锚点导航」——滚动时高亮当前块、缺的块不出。能修好联动，但页面本来不长（介绍 6 行折叠后约两屏），多一排控件不划算；五家都没做。
C：改成真 tab（和手机现状一样切换内容）。主催 / アジェンダ 往往只有几行，切过去大片空白（见 ⓪c），不推荐。
W2　报名 / 状态主按钮放哪？（现状：页头右上「参加登録」+ 右栏「参加登録をはじめる」两个同样的按钮）
推荐 A：≥1280 只放右栏第一张「参加」卡，页头右上只留分享（已报名多一个 ⋯）。右栏本身固定不随正文滚动，等于 Eventbrite（右栏 sticky「Get tickets」）/ Meetup（右栏 sticky 日时卡）的做法。768–1279 没有右栏，按钮在页头右上；<768 在底部固定条（Peatix / connpass / Eventbrite / Meetup 手机都是底部条）。
B：三档都放页头右上，右栏不放报名卡。位置统一，但长介绍往下滚时按钮跟着页头滚走。

已定（两端对齐 / 按推荐）

  1. 区块顺序：紹介 → アジェンダ → 参加者 → 主催（两端同序）。≥1280 主催在右栏，主栏 = 紹介 → アジェンダ → 参加者；<1280 和手机主催排在主栏末尾。对标 connpass（右栏グループ卡）、Luma（侧栏主办 + 关注）。
  2. 主栏单列（方案 A）；紹介 / アジェンダ 并排的方案 B 只作附录。
  3. 主按钮文案：「参加登録」（两端统一）。
  4. 紹介：超过 6 行渐隐折叠，「続きを読む」原地展开；没有介绍整块不出。对标 Peatix「もっと読む」、Eventbrite / Meetup「Read more」。
  5. アジェンダ：超过 5 项折叠「すべて見る」；活动中当前那一项高亮；没有议程整块不出（现状是灰字空卡）。
  6. 参加者（详情页里）：只放 人数 + 头像叠 + 最多 3 位「会いたい人」+「全員を見る N名」；名单锁着时只有人数 + 马赛克头像叠 + 一句，不放按钮（同屏已有）。
  7. 全名单页 /app/events/[id]/people：筛选 プランに合う / 知り合い / すべて + 搜索，按页读取；点人 = 右栏「参加者の詳細」（<1280 抽屉）。对标 connpass「参加者一覧」独立页、Meetup Attendees「See all」；与 App 同一页。
  8. 状态只说一次：「イベントは終了しました」现状在页头、封面、右栏出现三次；改为只在封面 chip。
  9. 右栏「会えそうな人」去掉：会いたい人已在主栏「参加者」里，右栏「あなたに関係すること」只留事实行（≤3 行）。
  10. 报名卡不配说明句：去掉「AI が5問だけ質問します（約3分）…」，卡里只有封面没有的 締切 / 審査 + 按钮。
  11. 已报名卡不重复日时场所：只写状态 chip + 主按钮；⋯ 菜单（カレンダー / プロフィール編集 / 取り消し）挪进这张卡。
  12. 已结束：右栏「参加」卡主按钮换成「会場の記録」（有记录时）/「ふりかえり」；会いたい人 行可点，右栏换成参加者の詳細。没报名的人：右栏不出「参加」卡，主办方卡里有「次回」。
  13. 活动中（新状态）：右栏「参加」卡显示受付 QR + 主按钮「会場モード」；アジェンダ 高亮当前项。现状详情页没有活动中状态，路由沿用 /live。
  14. >1440：沿用已上线规则，整个 1440 框架居中；本提案不改 1440 内部栅格。
