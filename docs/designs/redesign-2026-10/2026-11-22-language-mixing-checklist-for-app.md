# 界面语言混杂：Web 的根因与 App 检查清单（2026-11-22）

用户反馈：同一屏混着日文、中文、英文。Web 已全站查过、修完（chat-agent 分支）。下面写清 Web 的根因，再列出 App 要逐条核对的项目。App 不一定有完全相同的 bug，但这些都是同一类问题的常见入口。

## 一、Web 查到的根因

1. **接口参数改写了用户保存的语言。** proxy 对所有请求都读 `?lang=`，并写回 `orbit-lang` cookie。页面里有组件请求 `/api/contacts/value-lines?lang=en`（AI 文案只有中英两种，日文界面就传了 en），结果 cookie 被改成 en，下次整页加载整个界面变成英文。外壳（导航）只在整页加载时读语言，页面内容每次换页都重读，所以会出现「导航日文、内容英文」。
   - 修法：只有页面导航的 `?lang=` 才记住语言，`/api/*` 的 `lang` 参数只影响这一次响应。另外，语言 cookie 与页面不一致时整页重载一次，不让外壳和内容各说各的。
2. **缺日文时回落英文。** `t({ zh, en })` 没写 ja，日文界面就显示英文。很多旧组件只写了中英，例如「提案とアクション」页整页是英文。
3. **按词替换的「翻译器」把内容翻坏。** 旧的 `localizeOrbitTree` 把中文词逐个换成英文，作用在整份数据上，连主办方写的活动名都被改成「验收用: Finance科技Startup者之夜」。日文界面则完全不处理，于是显示中文。
   - 修法：只做整句精确匹配，不再做子串替换；用户内容、主办方内容不经过它。
4. **只分 en / zh 两档的分支。** 例如 `language === "en" ? "en" : "zh"`，日文界面落到中文；或者 `language === "zh" ? "zh" : "en"`，日文界面落到英文。
5. **内部 id 被当成文字显示。** 封面主题 id（finance / relationship）、数据来源类型（event_import）被直接显示出来。
6. **数据里存了固定语言的界面文字。** 选项值（業界、参加の目的）按主办方填写的语言存，例如「IT・ソフトウェア」，在中文、英文界面原样显示。注册时还把账户名存成 `${姓名} 的 Orbit`（中文）。
7. **服务端 view model 拿不到语言。** 有些视图模型在服务端拼好文案，但调用时没传语言，只能用写死的默认语言。

## 二、内容分类规则（两端一致）

| 类别 | 例子 | 怎么显示 |
|---|---|---|
| 界面文案 | 导航、标题、按钮、标签、字段名、空状态、提示、Toast、placeholder、无障碍标签、日期和数量格式 | 必须跟当前语言，ja / zh / en 三语齐全 |
| 选项值（界面的一部分） | 業界、参加の目的、会いたい人 等题库选项 | 按题库映射到当前语言；题库里找不到的主办方自定义选项原样显示 |
| 字段名 | 「参加の目的」「業界」 | 用字段 id 查三语标签，不用存储里的问题原文 |
| 用户内容 | 姓名、公司、自我介绍、笔记 | 原样显示，不翻译 |
| 主办方内容 | 活动名、桌主题、活动介绍 | 原样显示，不翻译 |
| AI 内容 | 桌说明、推荐理由、价值线 | 目前按生成时的语言显示（大多是中文），怎么处理待用户决定，见第四节 |

## 三、App 检查清单

- [ ] **请求参数不改保存的语言。** App 发给 Web API 的 `lang` 参数只影响这一次响应；App 自己保存的界面语言只能由设置页修改。检查有没有在收到响应后按响应语言改本地设置的代码。
- [ ] **没有缺 ja 的文案对象。** 搜 `{ zh:`、`{ en:` 这类只有两种语言的对象，以及 `t({ zh, en })` 的调用。缺 ja 时的回落顺序要确认：不允许日文界面默默显示英文。
- [ ] **没有只分两档的语言分支。** 搜 `=== "en" ?`、`=== "zh" ?`、`=== 'en' ?`，逐个确认 ja 走到了正确分支。
- [ ] **日期、数字格式按三语。** 搜 `toLocaleDateString`、`Intl.DateTimeFormat`、`"zh-CN"`、`"en-US"`，确认 ja 用 `ja-JP`，不要落到 zh-CN。
- [ ] **选项值经过映射。** 活动参加者资料、名片、人脉列表里的業界和参加の目的等选项值，要用和 Web 同一张题库表映射（Web：`shared/domain/host-question-library.ts` 的 `localizeLibraryAnswerText`，以及 `features/events/journey/attendee-answer-language.ts` 的 `attendeeAnswerInLanguage`）。接口现在会带 `field`（字段 id），用它查字段名，不要显示存储里的问题原文。
- [ ] **不显示内部 id。** 封面主题 id、来源类型（event_import 等）、状态码，不能出现在界面上。
- [ ] **用户和主办方内容不做逐词替换。** 如果 App 有类似的「词典替换」，只能整句精确匹配界面文案，不能作用在整份数据上。
- [ ] **中文标点。** zh 文案用「、」「·」，不要用日文的「・」；en 文案里不出现汉字和假名（语言名的自称除外，例如语言切换上的「中」「日」）。
- [ ] **示例和演示数据三语。** 演示模式里的示例人物、公司、事件也是产品写的，必须三语。
- [ ] **加一条自动检查。** 参考 Web 的 `tests/ui/language-consistency.test.ts`（zh 文案无假名和「・」、en 文案无 CJK、JSX 里没有写死的英文句子），以及 `tests/ui/no-hardcoded-copy.test.ts`（写死文案计数只减不增）。
- [ ] **三语走查一遍。** 每个一级页和常用弹层，在 ja / zh / en 下各截一张图，看有没有别的语言混进来。Web 用的扫描脚本：`repos/orbits/scripts/lang-mix-scan.mjs`，它会列出「当前语言下出现了别的语言」的文字和所在页面。

## 四、待用户决定（两端共用）

1. **AI 内容的语言。** 桌说明和推荐理由在活动发布时生成一次，目前默认中文。三个做法：
   - A：页面上加「翻译」按钮，按语言缓存。首次查看某语言时花一次付费 AI。
   - B（推荐）：发布时一次生成 ja / zh / en 三份，存在同一行，接口只返回当前语言那份。每场活动多花约 2 倍输出 token，只花一次，成本是每场几分钱。读取量不变。
   - C：保持原文，加语言标记。零成本。
2. **价值线（value-lines）只有中英两种。** 日文界面暂时显示英文；要支持日文需要改提示词并重新生成（付费 AI）。
3. **账户名 `${姓名} 的 Orbit`。** 存在数据库里，会作为本人联系人的公司出现在人脉列表。要改注册逻辑，并对存量数据做一次回填（生产写入，需要授权）。
4. **已经被错误改成 en 的用户。** Web 修好后不会再被改；但已经被改过 cookie 的人，需要在设置里切回一次。
