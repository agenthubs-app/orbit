# Orbit UI/UX 系统性审计（2026-07-26）

审计对象：`repos/orbits`（Next.js 16 / React 18，产品路由组 `app/(app)/app/**`）
方法：本地 dev server 实跑 + 逐页浏览器截图 + DOM/computed style 取证 + 源码交叉验证
覆盖：桌面 1440×900 与移动 375×812，light / dark 双主题，18 个产品页面 + 主要弹层

---

## 0. 一句话诊断

**Orbit 现在没有"设计系统"，只有一条由四层互相打补丁的样式管线。**
基础样式来自一个 5 MB 的静态 HTML 原型（运行时解包提取 CSS），上面叠了 2790 行覆盖层，
再叠一层 light-theme 反向补丁，再加上 **1825 处内联 `style={{}}`、229 个硬编码色值**。
因此：token 存在但不生效、按钮有 7 个变体但 45% 的按钮不用它们、弹窗有 8 套实现、
字号有 26 个值、圆角有 20 个值。你看到的"按钮点不动/显示不正常/加载慢"不是零散 bug，
而是这条管线的必然产物。

---

## 1. 架构取证：问题的真正来源

### 1.1 样式管线（这是所有不一致的根）

| 层 | 文件 | 体量 | 内容 |
|---|---|---|---|
| L1 基础 | `public/orbit-reference/orbit-reference.html` | **5,001,544 bytes** | 原型 HTML，运行时用正则从 `<iframe srcdoc>` 里解包出 `<style>` |
| L2 覆盖 | `app/(app)/app/orbit-reference-styles.tsx` | **2,790 行** | isolation reset + party 页 + audit round 1 + starfield 暗色 token 重映射 + audit round 2 + coordination + namecard |
| L3 主题 | `app/(app)/app/orbit-theme.tsx` | 310 行 | `html[data-theme=light]` 反向覆盖，外加一堆"把硬编码暗玻璃改回浅色"的补丁 |
| L4 页面 | 50 个 `.tsx` | **1,825 处 `style={{}}`** | 逐页内联样式 |
| L5 旁路 | `shared/ui/state-view.tsx` | — | 第三套视觉语言（见 §2.1） |

取证：`orbit-reference-styles.tsx:2600+` 的 `readReferenceStyles()` 用
`html.match(/<iframe class="browser-frame"[^>]*srcdoc="([\s\S]*?)"><\/iframe>/)`
把原型里的 CSS 抠出来注入。**设计系统的真实源头是一个没人会去编辑的 5 MB HTML 文件。**

L2 的注释自己承认这一点：
> `/* Radius scale — migrated from public/orbit-reference/orbit-reference.html (the prototype asset previously the ONLY source of these values, extracted at runtime by 152 call sites) */`

**根因判定：不是"页面写得随意"，是"没有可编辑的 token 源"。** 每次要改一个视觉决策，
唯一可行的做法就是在 L2/L3 再加一条覆盖规则 —— 于是覆盖层越滚越大，
今天 L2 已经比任何一个页面文件都大。

### 1.2 字体系统实际是失效的

| token 声明 | 实际生效 |
|---|---|
| `--ff: 'Noto Sans SC', 'Inter', …` | Noto Sans SC（Inter 永远轮不到） |
| `--ff-serif` / `--ff-display` / `--ff-tight` | `'Noto Serif SC','Songti SC',Georgia,serif` |
| `--ff-mono: 'JetBrains Mono','Geist Mono',…` | JetBrains Mono（Geist Mono 永远轮不到） |

但 L1 原型里仍然内联了 **140 个 `@font-face`，全部是 Inter / Inter Tight / Geist Mono
的 base64 woff2** —— 这三个字体族**一个都不会被渲染**，却占了页面 95% 的体积（见 §3.1）。

浏览器实测（`/app/contacts`）：`document.fonts.check("16px 'Inter'") === false`，
页面注册 `document.fonts.size === 973` 个 font-face。

## 2. P0 —— 必须立刻修

### P0-1 联系人详情页全线打不开，且错误页是第三套设计语言

- **位置**：`/app/contacts/[id]`（从 `/app/contacts` 点任意一张名片进入）
- **现象**：整页只剩 `Contact detail could not load`，**没有顶栏、没有侧栏、没有任何 app chrome**。
- **依据**：
  - 列表卡片 href = `/app/contacts/contact:kenji-watanabe`（`read_page` 取证），
    进入后渲染 `ContactDetailRouteStateView`（`app/(app)/app/contacts/[id]/page.tsx:52`）。
  - 这是主列表**唯一的**下钻入口 —— 产品核心动线 100% 断掉。
- **附带三个独立缺陷**：
  1. 两个按钮 `Retry contact detail` / `Return to contacts list` 的说明文案**完全相同**。
     根因在 `page.tsx:66` —— `recoveryCopy: routeModel.nextStep` 对所有 action 传同一个值。
  2. 全英文 + `为什么重要 / Why this matters` 这种全站独一份的双语排版。
  3. `shared/ui/state-view.tsx` 里 **硬编码了 `#52615d` `#d5ddd9` `#0f4758` `#e8f2f0` `#51447a`**
     和 `0.94rem / 0.88rem / 0.82rem / font-weight:760` —— 这些值来自 dev workbench 的
     `--orbit-*` 调色板，产品端一个都不用。
- **暗色模式下直接不可读**：切到 dark 后卡片背景仍是硬编码白，而标题走 `var(--ink)`
  变成亮色 —— 实测对比度 **1.14:1**（`rgb(236,234,246)` on `rgb(249,251,250)`）。
- **影响**：P0
- **根因**：`shared/ui/*` 是脱离产品 token 体系的旁路样式；route 失败态没有被纳入设计系统。
- **建议**：① 先修数据（id 解析）；② StateView 改为消费 `--*` token 并渲染在 app shell 内；
  ③ `recoveryCopy` 按 action 分别提供。
- **文件**：`app/(app)/app/contacts/[id]/page.tsx`、`shared/ui/state-view.tsx`
- **立刻改**：是

### P0-2 每个页面下发 10 MB HTML，FCP 4.9 秒

- **位置**：全站（`OrbitReferenceStyles`，`app/(app)/app/orbit-reference-styles.tsx:2788`）
- **实测**（`/app/contacts`，Chrome Performance API）：

  | 指标 | 值 |
  |---|---|
  | HTML decoded | **10.11 MB** |
  | HTML transfer | 7.35 MB |
  | TTFB | 1524 ms |
  | domInteractive | 2291 ms |
  | **First Contentful Paint** | **4856 ms** |
  | DOM 节点 | 仅 401 个 |
  | 注册的 @font-face | 973 |

- **依据**：`curl` 拿到的 HTML 里有 **280 个 `data:font/woff2;base64`**，合计 **9.56 MB**；
  `<style>` 标签总计 5.03 MB（其中最大的一个 5.01 MB）。
  也就是 **约 95% 的 CSS 体积是 base64 字体**，而这些字体（Inter/Inter Tight/Geist Mono）
  按 §1.2 根本不会被渲染。
- **DOM 只有 401 个节点却 FCP 4.9 秒 —— 慢的全部来自这块内联 CSS。**
- **而且它是内联的，所以跨页面零缓存**：每次路由跳转重新下发 7.35 MB。
- **影响**：P0
- **根因**：把原型 HTML 当成样式源，连同 base64 字体一起 inline 进 RSC 输出
  （同一份内容还会在 RSC flight payload 里重复一次，5 MB × 2 ≈ 10 MB）。
- **建议**：
  1. 构建期把 L1 CSS 抽成 `public/orbit-reference.css`，用 `<link rel="stylesheet">` 引入 → 立即可缓存；
  2. 删掉 Inter / Inter Tight / Geist Mono 的 140 个 `@font-face`（无渲染贡献），预计减重 ≈ 4.8 MB；
  3. Noto Sans/Serif SC 已经是外部 woff2（`public/iorbit-starfield/fonts/*`），保持不变即可；
  4. 长期：把 L1 换成手写的 `tokens.css` + `components.css`（实际有效规则只有 ~2205 条）。
- **文件**：`app/(app)/app/orbit-reference-styles.tsx`、`public/orbit-reference/orbit-reference.html`
- **立刻改**：是（1+2 两步就能把 10 MB 打到 <300 KB）

### P0-3 移动端顶栏页面标题竖排折行，挤爆 56px 导航条

- **位置**：`.orbit-nav-page-title`（`app/(app)/app/orbit-public-shell.tsx`），375px 下全站可见
- **现象**：`/app/home` 的"我的"渲染成竖排"我 / 的"，`/app/contacts` 的"人脉"渲染成"人 / 脉"。
- **依据**（computed style）：元素 **23 × 49 px**，`white-space: normal`，
  父容器 `.orbit-nav-lead` 只有 58 px 宽；而 `<header>` 高度是 56 px —— 内容 49px 直接顶满。
  同时 `.orbit-top-actions` `scrollWidth 283 > clientWidth 279`，
  `.orbit-lang-toggle` `scrollWidth 91 > clientWidth 82`（各自溢出 4~9px）。
- **成因**：375px 内塞了 7 组控件（品牌 / 页面标题 / 中·EN·日 / 铃铛 / 注册 / iOrbit 图标 / 汉堡），
  没有任何优先级或折叠策略。
- **影响**：P0（首屏第一眼就是坏的）
- **根因**：移动端顶栏没有 overflow 策略；语言切换器（3 个按钮 + 2 个分隔符）在移动端不该常驻。
- **建议**：标题加 `white-space: nowrap; min-width: 0; text-overflow: ellipsis`；
  语言切换移入汉堡菜单（`浅色模式` 已经在里面了，同一处理）；顶栏最多保留 品牌 / 标题 / 铃铛 / 汉堡。
- **文件**：`app/(app)/app/orbit-public-shell.tsx`、`orbit-reference-styles.tsx`
- **立刻改**：是

### P0-4 登录态自相矛盾：顶栏显示"登录/注册"，页面主体显示"退出登录"

- **位置**：全站顶栏 + `/app/home`
- **依据**：
  - `curl /api/auth/session` → `{"message":"There was a problem with the server configuration…"}`
  - `OrbitNavAccountControl`（`orbit-public-shell.tsx:38`）客户端 fetch 该接口，
    拿不到 session → 渲染 `登录` / `注册`。
  - 同一屏的 `/app/home` 主体渲染 mock profile "Ari Lane / 创始人" 并提供 `退出登录`。
- **影响**：P0（用户完全无法判断自己是否登录）
- **根因**：**身份有两个真相来源** —— 页面 view-model 用 mock fixture，导航用真实 session。
- **建议**：统一到一个 session source；在 session 未就绪时导航区渲染 skeleton 而不是"登录"。
- **文件**：`app/(app)/app/orbit-public-shell.tsx`、`app/(app)/app/home/*`
- **立刻改**：是

### P0-5 页面底色挂在 `body` 而不是 `html`，路由切换/过度滚动露白

- **依据**：`getComputedStyle(document.documentElement).backgroundColor === "rgb(255,255,255)"`，

- **建议**：把 canvas 背景提到 `html`（或 `:root`）并同步 `color-scheme`。
- **文件**：`app/(app)/app/orbit-reference-styles.tsx`、`orbit-theme.tsx`
- **立刻改**：是

## 3. P1 —— 按钮与弹窗（你重点要求的部分）

### 3.1 按钮体系现状

**规范部分（L1 定义，是好的）**：

```
.btn          height 44 / padding 0 20 / r-sm(10) / 15px / weight 550
.btn-sm       height 36 / padding 0 14 / r-xs(7)  / 13.5px
.btn-lg       height 50 / padding 0 24 / r-md(14) / 16px
变体：btn-primary / btn-dark / btn-soft / btn-ghost / btn-quiet / btn-block
```

**实际使用统计**（`grep` 产品路由组）：

| 指标 | 数字 |
|---|---|
| `<button>` 总数 | **240** |
| 使用 `.btn` 体系 | **131（55%）** |
| 自定义 `orbit-*-btn/button` 类 | **12 个** |
| `btn-ghost` / `btn-primary` / `btn-quiet` / `btn-soft` / `btn-sm` / `btn-icon` / `btn-dark` | 59 / 53 / 12 / 9 / 8 / 3 / 2 |

→ **45% 的按钮是一次性写的**。这是"同类按钮长得不一样"的直接原因。

#### P1-a `.btn-quiet` 在静止态零可供性，反而不如旁边的非交互徽章像按钮

- **位置**：`/app/contacts/all-actions`
- **依据**（computed style）：`撤销` / `重试失败项` = `.btn.btn-quiet`，
  `background: rgba(0,0,0,0)`、无边框、无阴影；只有 `:hover` 才出现 `var(--surface-3)`。
  而同一行右侧的 `等待确认` / `已完成` / `部分失败` 是**不可点的状态徽章**，却有实心药丸底色。
- **后果**：用户会去点徽章，而真正的操作看起来像纯文字。**可供性倒置**。
- **影响**：P1
- **根因**：`btn-quiet` 只为"低优先级但已知可点"的语境设计，被当成表格行内主操作用了。
- **建议**：行内操作统一用 `btn-ghost`（有边框有底）；`btn-quiet` 仅限已明确处于操作区的场景。

#### P1-b 同一对控件用了两个不同变体

- **位置**：`/app/contacts/graph` 右上缩放控件
- **依据**：`缩小` = `btn btn-ghost btn-sm hit-44`（白底，35×36）；
  `放大` = `btn btn-primary btn-sm hit-44`（teal 实心，38×36）。
- **后果**：一对对称控件视觉权重完全不等，且宽度不一致（35 vs 38）。
- **影响**：P2 → 但它是"变体乱用"的典型样本
- **建议**：成对/成组控件必须同变体同尺寸；引入 `ButtonGroup` 原语。

#### P1-c 四个不同外观的按钮指向同一个 URL

- **位置**：`/app/contacts`
- **依据**（`read_page`）：`扫名片`(ghost)、`导入人脉`(primary)、侧栏 `导入中心`、侧栏 `扫名片`
  —— **全部 `href="/app/contacts/new"`**，没有任何 query 区分。
- **影响**：P1（用户以为是 4 个功能，实际是 1 个）
- **建议**：合并为 1 个主 CTA，或用 `?source=scan|import` 让落地页预选来源。

#### P1-d 点击后只弹 toast，没有任何实际行为

- **实拍**：`/app/contacts` 空输入点 `智能搜索` → 弹 `已执行：智能搜索`，列表毫无变化；
  `/app/contacts/new` 点 `拍照扫描` → 弹 `已执行：拍照扫描`，无相机、无对话框。
- **影响**：P1 —— **这就是你感知到的"按钮不能点击"**。技术上它响应了，
  但给了假的成功反馈，比不响应更糟（违反 `submit-feedback` / `error-clarity`）。
- **建议**：未接通的能力应显式 disabled + tooltip 说明，或跳转到真实流程；
  成功 toast 只在真的产生了副作用时才出。

#### P1-e disabled 态不可辨认，且同一动作在列表页可点、详情页 disabled

- **位置**：`/app/events/demo-event-1`
- **依据**：`已结束` 与 `回看` 都是 `.btn.is-disabled`，
  `background: rgb(29,25,54)`、`color: rgb(110,106,143)`、**`opacity: 1`**。
  而页面 surface 是 `rgb(18,16,31)` —— **disabled 按钮比周围更亮**，看起来像可用的 soft 按钮。
  同一个"回看"在 `/app/events` 列表页是可点的 `btn-soft`。
- **影响**：P1
- **根因**：`.btn[disabled]` 只换了颜色没降不透明度，且暗色重映射后 `--surface-3` 比 `--surface` 亮。
- **建议**：`.btn:disabled { opacity: .45; filter: saturate(.6); }` + 保持背景不高于所在 surface。

#### P1-f `.btn-icon` 是 40×40，低于 44 最小触控

- **依据**：`orbit-reference-styles.tsx:669` → `.btn-icon { height:40px; width:40px }`。
- 另有 `.hit-44` 辅助类（`:669`/`:1722`，44×44 伪元素扩大热区），
  但**是手动 opt-in，只在 15 个文件 36 处使用**。
- **未覆盖的小目标实测**：
  | 控件 | 尺寸 |
  |---|---|
  | 语言切换 中 / EN / 日 | **19×29 / 22×28 / 19×29** |
  | 品牌 link（移动端） | 24×24 |
  | `注册`（移动端） | 57×34 |
  | `nc-chip-sm`（表盘 按行业/按价值） | **56×24** |
  | 侧栏导航项 | 183×40 |
  | `.chip` | 30 高 |
  | 收件箱铃铛 | 36×36（有 hit-44） |
- **影响**：P1（移动端 P0）
- **根因**：触控尺寸是"记得加类"而不是组件属性。
- **建议**：把 44px 最小热区做进 `.btn` / `.chip` / icon-button 原语本身，`hit-44` 退役。

### 3.2 弹窗 / 浮层现状

**共存 8 套实现**（`grep` 类名）：

| # | 实现 | 类名 |
|---|---|---|
| 1 | 账号鉴权弹窗 | `orbit-account-auth-modal` / `-backdrop` |
| 2 | 主办方创建/邀请 | `orbit-host-create-modal` / `orbit-host-invite-modal` / `orbit-host-modal-backdrop` / `-layer` |
| 3 | 主办方鉴权 | `orbit-host-auth-overlay` / `-backdrop` |
| 4 | 通用 modal | `orbit-modal-card` / `orbit-modal-overlay` / `orbit-modal-scrim` |
| 5 | party 选择器 | `orbit-party-picker-overlay` / `orbit-party-auth-overlay` |
| 6 | 名片夹侧抽屉 | `.nc-sheet` + `.nc-scrim` |
| 7 | 移动端导航菜单 | `.orbit-nav-menu-layer` / `-scrim` / `-panel` |
| 8 | 关系收件箱 | `relationship-inbox-panel` |

#### P1-g 焦点陷阱/Esc/焦点归还只有 10% 的浮层用上

- **依据**：`useOrbitModalA11y`（`orbit-modal-a11y.ts`，实现质量很好：initial focus + Tab trap + Esc + restore）
  **只有 2 个文件引用**（`orbit-account-shell.tsx`、`account/orbit-real-account-auth.tsx`），
  而渲染 overlay/modal/sheet 的文件有 **20+ 个**。
- 全站 `role="dialog"` 仅 **4** 处，`aria-modal` 仅 **5** 处。
- **影响**：P1（键盘/读屏用户在大多数浮层里会 Tab 到背景内容）
- **根因**：a11y 是一个"要记得调用的 hook"，不是"用了就有的组件"。
- **建议**：封装 `<OrbitDialog>` / `<OrbitSheet>`，内部强制 `role` + `aria-modal` + hook + scrim + Esc。

#### P1-h z-index 有规范但没人遵守，popover 会被顶栏盖住

- **规范**（`app/(app)/app/orbit-z.ts`）：`raised 10 / sticky 100 / dropdown 200 / overlay 300 / modal 400 / toast 500 / debug 900`
- **实际**（`orbit-reference-styles.tsx` 裸值）：`35`、`45`(z:90)、`60`、`70`、`100`、
  以及 namecard 层的 **`3900` / `3950` / `4000`**；移动端菜单实测 `layer z=70`、`header z=50`。
- **具体后果**：`.nc-basis-pop`（"查看依据"气泡）`z-index: 60`，
  **低于 sticky 顶栏/吸底栏**，靠近页面顶部时会被遮。
- **影响**：P1
- **建议**：把 `ORBIT_Z` 变成 CSS 自定义属性（`--z-dropdown` 等）注入到 `[data-orbit-real-page]`，
  CSS 里禁止裸数字；加一条 lint/test 断言。

#### P1-i toast 规格与位置

- `.nc-toast-host`：`position:fixed; bottom:26px; z-index:4000`，
  toast 本体 `background: var(--surface-3)` + `--sh-pop`，`opacity/transform` 过渡 180ms。
- 问题：① z 值越界；② 无 `aria-live`（读屏不播报）；③ 与移动端吸底 CTA 会重叠（bottom 26 固定）。
- **建议**：并入统一 `<Toast>` 组件，`role="status" aria-live="polite"`，
  bottom 用 `calc(env(safe-area-inset-bottom) + var(--sticky-bar-h, 0px) + 16px)`。

## 4. P1 —— 排版 / 颜色 / 间距体系

### P1-k 字号没有 scale：全站 26 个值，单页最多 18 个

- **内联 `fontSize` 实测分布**（出现次数）：
  `13(132) 14(88) 12(80) 15(40) 11(33) 12.5(23) 13.5(11) 16(9) 22(7) 18(6) 11.5(6) 24(5) 17(4) 14.5(4) 28(3) 26(3) 20(2) 19(2) 30(1) 21.84(1) 10.5(1)`
- CSS 侧再补：`9px 10px 23px`
- **单页取证**：`/app` 落地页 17 个不同字号；`/app/home` 18 个
  （30 / 28 / 26 / 22 / 21.84 / 20 / 18 / 17 / 16 / 15 / 14 / 13.5 / 13 / 12.5 / 12 / 11.5 / 11 / 9）。
- `21.84px` 是 em 计算出来的漂移值 —— 说明有地方在用相对单位叠加。
- **9px 正文**：品牌副标题"由 iOrbit 智能匹配引擎驱动"实测 `font-size: 9px`，
  颜色 `rgb(91,100,107)` —— 代码里自称有 11px 下限（`orbit-reference-styles.tsx:2600` 附近的注释），
  这条规则并没有覆盖到它。
- **影响**：P1
- **建议**：固定 8 级 scale 并只用 token：
  `--fs-2xs 11 / --fs-xs 12 / --fs-sm 13 / --fs-base 14 / --fs-md 16 / --fs-lg 20 / --fs-xl 26 / --fs-2xl 34`，
  **正文最小 12，辅助信息最小 11，禁止 <11**。

### P1-l 页面标题字体二选一，同级标题两种字族

- **依据**（同一页 computed style）：
  - `/app/today` 的 h1「今晚有 2 件事需要你决定。」→ `"Noto Sans SC"`，28px/700，**无 class**
  - 同页 `.h-title`「2026 年 7 月」→ `"Noto Serif SC","Songti SC",Georgia,serif`，20px/600
  - `/app/contacts`「全部人脉」、`/app/contacts/dashboard`「人脉表盘」→ 衬线
  - `/app/contacts/all-actions`「All actions」→ **无衬线 28px/700**
- **影响**：P1（页面标题在不同页面是两种字体，视觉识别断裂）
- **根因**：`.h-display / .h-title / .h-section` 是好的，但页面 h1 经常绕过它们直接内联。
- **建议**：h1 一律 `.h-display`，禁止裸 h1 内联 fontSize。

### P1-m 229 个硬编码色值绕过 token

- **依据**：产品路由组内 `#RRGGBB` 出现 **484 次，去重 229 个**。
- 同一个品牌紫写了 4 种：`#8b7bf0`(22) / `#8B7BF0`(6) / `#6359E9`(10) / `#a99fe8`(5)；
  白色写了 3 种：`#fff`(67) / `#ffffff`(30) / `#FFFFFF`(11)。
- **后果**：主题切换时这些值不跟着变 —— 这正是 `orbit-theme.tsx:125-192` 里
  那一大段"把硬编码暗玻璃在 light 下重述一遍"的补丁存在的原因（注释自己写了）。
- **影响**：P1
- **建议**：禁止组件层出现字面色值；把现有 229 个映射进语义 token，加 lint 规则。

### P1-n 圆角 20 个值，token scale 名存实亡

- token：`--r-xs 7 / --r-sm 10 / --r-md 14 / --r-lg 18 / --r-xl 24 / --r-pill 999`
- 内联实际：`var(104) 12(13) 16(9) 11(9) 999(6) 50%(6) 8(5) 14(5) 5(3) 24(3) 13(3) 9(2) 7 6 4 3 2 18 10`
  外加 `4px 16px 16px 16px`、`16px 16px 4px 16px`、`0 99px 99px 0` 三个异形。
- CSS 侧也混用 `10px / 8px / 9px / 12px / 5px / 20px` 与 `var(--r-*)`。
- 单页实测：`/app/home` 同屏出现 `999 / 18 / 16 / 14 / 13 / 12 / 11 / 10 / 9 / 7 / 50%`。
- **建议**：只保留 6 档，全部走 var；异形圆角（气泡尾巴）单独命名。

## 8. 推荐统一规则（目标态）

```css
[data-orbit-real-page] {
  /* Typography — 8 级，禁止其它值 */
  --fs-2xs: 11px;  --fs-xs: 12px;  --fs-sm: 13px;  --fs-base: 14px;
  --fs-md: 16px;   --fs-lg: 20px;  --fs-xl: 26px;  --fs-2xl: 34px;
  --lh-tight: 1.25; --lh-body: 1.55;
  --fw-regular: 400; --fw-medium: 500; --fw-semibold: 600;
  /* 字族只有两个角色 */
  --ff-sans: 'Noto Sans SC', system-ui, sans-serif;   /* 全部 UI 文本 */
  --ff-display: 'Noto Serif SC','Songti SC',Georgia,serif; /* 仅 h1/h2 与大数字 */
  --ff-mono: 'JetBrains Mono', ui-monospace, monospace;    /* 仅时间/ID/数值 */

  /* Spacing — 4pt 基准，7 档 */
  --sp-1: 4px; --sp-2: 8px; --sp-3: 12px; --sp-4: 16px;
  --sp-5: 24px; --sp-6: 32px; --sp-7: 48px;

  /* Radius — 6 档（已存在，补上强制力） */
  --r-xs: 7px; --r-sm: 10px; --r-md: 14px; --r-lg: 18px; --r-xl: 24px; --r-pill: 999px;

  /* Elevation — 5 档（已存在） */
  --sh-xs / --sh-sm / --sh-md / --sh-lg / --sh-pop

  /* Z — 从 ORBIT_Z 注入，CSS 里禁止裸数字 */
  --z-raised: 10; --z-sticky: 100; --z-dropdown: 200;
  --z-overlay: 300; --z-modal: 400; --z-toast: 500;

  /* 控件尺寸 */
  --ctl-sm: 36px; --ctl-md: 44px; --ctl-lg: 50px;
  --tap-min: 44px;  /* 所有可点元素的最小热区，写进原语 */
}
```

**按钮规范（收敛成 5 个变体 × 3 个尺寸）**

| 变体 | 用途 | 每屏数量 |
|---|---|---|
| `primary` | 页面唯一主动作 | ≤1 |
| `secondary`（原 ghost） | 并列次要动作、行内操作 | 不限 |
| `soft` | 卡片内轻量动作 | 不限 |
| `quiet` | **仅**用于已在操作区内的低优先项 | 不限 |
| `danger` | 破坏性动作（当前**缺失**，删除类操作现在没有语义色） | ≤1 |

- 五态必须齐全：`default / hover / active / focus-visible / disabled(opacity .45)`；
  另加 `loading`（spinner + `aria-busy` + 禁点）。
- 尺寸只有 sm(36) / md(44) / lg(50)；**图标按钮最小 44×44**（`.btn-icon` 从 40 改 44）。
- 成对/成组控件必须同变体同尺寸。

**弹窗规范（收敛成 3 种）**

| 形态 | 场景 | 规格 |
|---|---|---|
| `Dialog` | 确认、短表单 | 桌面居中 `max-width: 520px`；移动端从底部升起占 ≤90dvh；`--r-lg` |
| `Sheet` | 长内容、详情、收件箱 | 桌面右侧 `min(460px, 94%)`；移动端全屏 |
| `Popover` | 依据气泡、下拉菜单 | 锚定触发器，`--z-dropdown`，`max-width: 280px` |

统一契约：
scrim `var(--scrim)` + `--z-overlay` → 面板 `--z-modal` →
`role="dialog" aria-modal="true"` + `aria-labelledby` →
`useOrbitModalA11y`（内建，不再 opt-in）→ 右上关闭按钮 44×44 →
footer 按钮顺序固定「次要在左 / 主要在右」，移动端全宽堆叠 →
有未保存内容时关闭需二次确认 → 进 240ms `ease-out`，出 160ms `ease-in`。
