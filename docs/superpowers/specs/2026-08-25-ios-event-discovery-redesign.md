# Orbit iOS 活动发现页重构设计

> 日期：2026-08-25
>
> 范围：`repos/orbit-app` 的活动发现首页，不改活动详情、报名或运营中心的数据契约。

## 目标

让活动页能承载持续增长、类型多样的活动集合，同时保持 Orbit 现有的视觉系统和关系价值定位。页面首先帮助用户发现“现在值得参加的活动”，再提供搜索和筛选，不再把所有活动作为同样醒目的大海报顺序堆叠。

## 调研结论

### Meetup

- 用日期范围、地点和兴趣类别缩小海量活动集合。
- 推荐内容按“热门”“职业与商业”等主题分区，不把所有内容放进一个无差别列表。
- 活动条目保持紧凑，时间、地点和参与者是主要扫描信息。

### Luma

- 首屏先展示本地热门和个性化活动，再提供类别与城市入口。
- 图片服务于辨认活动，不让单张图片长期占据整个视口。
- 发现与主办是不同任务，主办入口存在但不抢占发现流的第一优先级。

### Eventbrite

- 搜索与地点是发现页的固定入口，筛选通过单独控制收敛。
- 活动列表使用图片加文本的紧凑模块，日期、场地、价格或状态放在标题附近。
- 推荐、关注的主办方和一般结果被分成有标题的内容区，而不是一条无限同构列表。

### Peatix

- 面向数万活动时，地点、日期、线上/线下和类别是基础检索维度。
- 个性化推荐建立在参加历史与兴趣之上，默认发现流不应该被历史活动淹没。

### Apple iOS 指南

- 搜索应处在主要位置并即时更新结果。
- 范围清晰的状态适合用 scope bar；类别和地点适合作为可选择的过滤项。
- 图片集合适合标准横向行或网格；文字信息密集的内容更适合紧凑列表。

## 当前问题

1. 一张活动卡接近一个视口，只能低效地逐张浏览。
2. `全部` 默认混入大量已取消或历史活动，弱化可行动内容。
3. 搜索、结果数量和四个状态按钮被包在一个过高的面板中。
4. 个性化推荐在普通列表之后，用户几乎看不到 Orbit 的差异化价值。
5. `imported` 和 `Organizer #...` 等数据实现标签进入用户界面。
6. 当前主题只依赖可选字段，已有数据缺少这些字段时无法形成类别入口。
7. 活动只有“查看更多”式分页，卡片密度不足，无法自然承载更大的集合。

## 选定方案

采用“推荐横向集合 + 紧凑垂直结果流”的混合结构。

### 1. 页面顺序

1. 页面标题“活动”，保留 Orbit 的背景、字体、颜色与返回按钮。
2. 紧凑搜索框，支持标题、地点、主办方和主题即时搜索。
3. 状态 scope：`即将`、`进行中`、`历史`、`全部`，默认 `即将`。
4. 地点和主题水平过滤条；数据增长时可以横向滚动，不占多行高度。
5. 登录用户的“为你推荐”横向集合，展示匹配分、理由和活动图片。
6. “近期活动”紧凑垂直列表；搜索时标题变为“搜索结果”。
7. “我负责的活动”作为紧凑次级入口，不再占据首屏大卡。

### 2. 推荐卡

- 宽度约为屏幕的 78%，露出下一张卡提示横向滚动。
- 图片比例稳定，不使用全卡暗色覆盖。
- 显示匹配分、优先级、标题、时间地点和一条推荐理由。
- 保留“记下推荐”的既有确认行为和“查看活动”导航。
- 推荐接口失败时不阻断普通活动列表。

### 3. 活动列表项

- 左侧固定比例缩略图，右侧显示日期、标题、地点和参与状态。
- 每项高度稳定，标题最多两行；不在列表中展示长描述。
- 仅展示用户能理解的状态：`可报名`、`进行中`、`已结束`、`已取消`。
- 不展示内部来源、actor ID 或占位主办方名称。
- 每页先显示 8 项，按 8 项增量展开；紧凑密度使一屏能看到约 3 项。

### 4. 分类与兼容

- API 提供 `industry`、`theme` 或 `tags` 时直接使用。
- 老数据缺少分类时，根据活动标题给出有限、确定性的中文类别回退，例如 `AI 科技`、`创投融资`、`跨境商务`、`人脉社群`、`工作坊`。
- 地点从现有 `location` 字段去重生成，不新增后端接口。
- `imported` 在公开发现页映射为 `可报名`；`Organizer #...` 不作为副标题展示。

## 状态与行为

- 默认：`即将`，推荐可见，近期活动按现有 API 顺序展示。
- 输入搜索：即时过滤，推荐暂时隐藏，避免推荐与搜索结果混淆。
- 选择地点或主题：与状态、搜索取交集；再次点击取消。
- 无结果：保留当前清晰空态，并提供清空筛选操作。
- 推荐加载或失败：普通活动流继续工作，不出现整页阻塞。
- 活动源为空：沿用当前加载、离线、失败和空状态。

## 代码范围

- 修改 `repos/orbit-app/src/screens/events/EventsScreen.tsx`
- 修改 `repos/orbit-app/tests/events-screen-source.test.ts`
- 地点筛选、标题分类回退和公开标签清理保持在 `EventsScreen.tsx` 的发现页展示层，不修改 HIGH/CRITICAL 风险的共享活动 view model。
- 视需要补充推荐组件的源测试，不改 Web API 契约。

## 验收标准

1. 默认首屏不再显示巨大海报列表，能看到搜索、状态范围、推荐或至少两个紧凑活动模块。
2. 即将、进行中、历史和全部状态可切换并向 VoiceOver 暴露选中状态。
3. 地点与主题可以和搜索、状态组合过滤。
4. 推荐区在普通结果之前，失败时不影响普通列表。
5. 不再显示 `imported`、`Organizer #...` 等实现标签。
6. 现有详情、报名、推荐确认和运营中心入口仍可到达。
7. 375pt 与 393pt iPhone 视口无文字遮挡、重叠或横向溢出。
8. iOS 全量测试、TypeScript 检查和模拟器交互验收通过。

## 研究来源

- Meetup App Store：活动、兴趣类别、地图与保存能力。
- Luma App Store：本地热门、类别、城市与日历订阅。
- Eventbrite App Store 与官方产品页：个性化发现、搜索筛选和紧凑活动模块。
- Peatix App Store：大规模活动下的地点、日期和类别筛选。
- Apple Human Interface Guidelines：Search Fields、Searching、Collections。
