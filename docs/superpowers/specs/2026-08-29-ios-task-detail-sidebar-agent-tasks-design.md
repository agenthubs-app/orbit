# iOS 待办详情、Orbit AI 侧栏与对话建待办设计

日期：2026-08-29
状态：已确认，进入实现

## 目标

本轮只调整 iOS 的三个连续体验，并复用既有视觉语言与数据边界：

1. 待办详情改为安静、可直接编辑的单页，类别保留为系统属性但不占据主界面。
2. Orbit AI 左侧栏采用已选方案：顶部新对话和搜索，中部常用入口，下部最近对话，底部账号。
3. 对话中识别待办需求。明确要求立即创建；推断出的需求只询问一次是否加入待办。

## 待办详情

主界面按重要性排列：完成状态、标题、日期/提醒、常驻备注、关联内容、完成按钮。备注直接显示为多行输入框，不再出现“详情与记录”二级标题。

- 标题和备注离开输入焦点后自动保存，失败时明确显示错误。
- 类别不再展示六个选择按钮；保留在数据库中，后续通过更多菜单编辑。
- 活动历史、删除和恢复等低频动作移入右上角更多菜单。
- 提醒只展示当前状态和一个入口，不在详情主页面常驻全部快捷预设。

## Orbit AI 侧栏

- 标题使用 `Orbit AI`，右侧提供收件箱入口及角标。
- 顶部操作为“新对话”和搜索历史。
- 常用入口只保留“今天、人脉、活动”；收件箱不再重复出现在列表。
- 最近对话直接显示在侧栏下半部，搜索在同一侧栏内过滤，不再打开第二个历史弹层。
- 保留滑动打开/关闭、账号和设置入口，沿用现有颜色、图标、圆角和虚化风格。

## 对话建待办

### 明确创建

当用户明确说“创建/添加/记一个待办”等，并且规划器给出结构化标题时，服务端直接创建正式 Task：

- `source = ai_confirmed`
- 绑定当前 `relatedConversationId`
- 使用消息和会话生成稳定幂等键
- 响应返回 `taskInteraction.state = created`

明确命令本身就是用户确认，不再要求用户二次点击。

### 主动建议

当对话表达了清晰的未来行动或承诺，但没有明确要求创建待办时：

- 只创建 `TaskSuggestion`，不进入正式待办计数。
- 对话显示紧凑确认卡，提供“加入待办”和“暂不需要”。
- 确认调用既有 task suggestion accept API，产生 `ai_confirmed` Task。
- 同一用户六小时内最多出现一次由对话触发的主动建议。节流由服务端持久化记录判断，不由模型决定。

## 契约

会话响应新增可选 `taskInteraction`：

```ts
interface OrbitAiTaskInteractionContract {
  state: "created" | "suggested";
  title: string;
  category: TaskCategory;
  dueAt?: string;
  taskId?: string;
  suggestionId?: string;
}
```

旧客户端忽略该可选字段，Web 端现有消息、artifact 和 action contract 不变。

## 非目标

- 不扩展 CRITICAL 风险的通用 Agent domain executor。
- 不把类别改成可见标签墙。
- 不引入新的项目、子任务或重复任务模型。
- 不改变 Web 首页和 Web 侧栏。
