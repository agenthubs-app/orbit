# Orbit Web 封闭测试上线方案（待评审）

日期：2026-09-16，Asia/Tokyo。

状态：方案草案，不是已批准的实施规格，也不是部署完成报告。本轮不购买资源、不读取密钥、不迁移业务数据、不修改产品代码、不提交或推送。

## 1. 目标与结论

先把现有 Web/API 服务发布为稳定的 HTTPS 封闭测试环境，再提供适合 iPhone 的 App 式浏览器体验。暂不依赖 Apple Developer Program、TestFlight 或原生系统推送。

推荐沿用已有 Vercel + Neon + 私有 Blob + Vercel Queues 的部署路径，升级并隔离测试环境，不另起 Netlify + Supabase。首批建议 5～10 位受邀用户，在线使用为主；不把全域离线同步、所有 AI 功能和第三方授权全部完成设为服务上线前提，但未完成模块必须有真实的关闭边界。

这里的“上线”分为两次放行：

1. 服务就绪：指定版本的 API、数据库、存储和必要后台任务在公网环境可验证，尚未邀请用户。
2. 用户测试：通过真实 iPhone 浏览器核心流程后，开放邀请名单；不等于全部产品功能正式商用发布。

## 3. 部署方案选择

| 方案 | 收益 | 成本/风险 | 建议 |
| --- | --- | --- | --- |
| A. 延续 Vercel + Neon + Blob + Queues | 现有代码、SDK 和历史云端验证最接近，减少迁移 | Queues 仍为 Beta；需要验证限额、计费、跨部署队列行为 | 首选 |
| B. Node 容器/VM + PostgreSQL + 对象存储 + 常驻 worker | 后台进程和资源控制更直接 | 当前 Blob/队列适配需要重新评估，还要维护 TLS、更新、备份及监控 | 平台限制实际阻塞时再选择 |
| C. 回到 Netlify + Supabase | 有早期配置文档可参考 | 新代码已依赖 Vercel 消费者和私有直传，属于额外平台迁移 | 不作为这轮捷径 |

推荐逻辑拓扑：

```text
iPhone Safari / 桌面浏览器 / 后续手机 Web 壳
  -> 正式测试域名 + HTTPS
  -> Vercel: 现有 Next.js Web + /api + 认证
       -> Neon PostgreSQL（权威业务数据）
       -> 私有 Blob（名片原件、衍生图）
       -> Queues（名片、邮件、Agent、维护）
       -> 明确启用的 AI/OCR provider 和邮件服务
```

首版不拆一个全新后端项目，不让浏览器直连数据库。网页和 API 优先保持同源；将来即使使用 Expo Web，也需要明确同源代理方案或精确 CORS、cookie 和 Origin 校验，不靠 `*` 解决带会话的跨域问题。

地区先不下单：根据测试者所在地选择应用函数与数据库相近的可用地区，先核对现有 Neon region，再做日本/中国大陆真实手机网络测试。不能只因开发者在日本就确定东京，也不能保证某个海外平台在中国大陆各网络都稳定。

## 4. 环境与发布版本

保留本地开发环境；区分受保护的 Staging 与用户 Beta，至少隔离数据库、workspace、Blob 存储、队列环境、认证密钥和 provider 费用归属。不得让每个开发 Preview 自动连接用户 Beta 数据库。

采用以下发布流程：

1. 从协调者确认的固定、已提交 SHA 建立隔离发布候选，不从当前脏工作区执行上传，也不自动收进仍开发中的 0033～0036。
2. 保存发布清单：Web/API commit、共享契约版本、迁移版本、Node/lockfile、前端构建版本、功能开关和已知限制。
3. Staging 使用独立账号与数据完成验证，记录准确部署 ID。
4. 经批准后将同一个候选发布到 Beta，重新验证环境差异、真实域名和后台消费者；不假设 Preview 配置会自动出现在 Production。
5. 不把所有 `chat-agent` 推送自动发布给朋友。先走人工放行，稳定后再考虑自动发布。

## 5. 首发功能范围

### 默认候选

- 邀请准入、邮箱密码登录、退出、密码找回和个人资料。
- 联系人列表/详情及已验收的维护入口；私密笔记、事项、日程及关联来源。
- AI 会话列表/组织和历史读取；受额度约束的显式 AI 请求在真实验收后开启。
- 联系人真实聊天、已读与刷新；明确在线/刷新语义，不承诺 WebSocket 级实时性。
- 三类站内通知、来源回查和处理状态；通知已读不能等同于源任务已完成。
- 已有活动列表/详情/报名在当前数据和运营能力可验证时开放。

### 单独放行或延后

- 名片 OCR、双面确认、大 PDF/HEIC：沿用现有私有直传，完成 iPhone 真文件上传、处理、纠错和幂等验收再开启；否则只保留确实可用的手工路径，不展示不可用上传入口。
- 自主发现：先关闭运行入口和配置，完成授权、历史费用核对、独立预算与真实模型验收后再开；仅隐藏按钮不是关闭后台任务。
- 原生 Push / Web Push：首批不承诺。现有 Expo token/设备所有权链不能直接当作 Web Push 订阅使用。
- 全域离线读取/写入、自动恢复及 AI 全域读取：不把未完成 Sprint 当上线能力。
- Calendar/Gmail/Microsoft 外部同步继续后移；未验收 Google 登录不作为唯一登录方式。

原需求和 Sprint 的 blocked/failed 状态继续保留。缩小 Beta 功能范围需要明确接受，不能通过删测试、改状态或改宣传掩盖未完成项。

## 6. 数据与配置准备

推荐用户 Beta 新建干净业务库/独立环境，只放明确批准的测试活动或种子数据；不默认上传开发机联系人、历史笔记、QA 账号或混合演示数据。若用户需要保留旧 Preview 账号和数据，另列迁移批次并确认对象。

上线前按当前版本盘点 records、Event Core/运营、名片、预约、身份归属、日程权威、通知/发现及队列相关结构与初始化入口。现有 `migrate-web-runtime.ts` 可作为入口之一，但其成功日志不足以证明最新日程权威数据迁移和按 actor 的通知切换都已完成。

迁移顺序：只读盘点 -> 备份及校验和 -> 独立恢复演练 -> 同版本空库/副本迁移演练 -> 差异报告 -> 目标批准 -> 暂停对应写入和消费者 -> apply -> 逐表/关键 collection/归属/关系/文件引用校验 -> 恢复流量。

通知切换使用已有 workspace/actor/batch 明确目标、dry-run hash 和回滚语义，不自动对全库所有账号执行。Schema 变更优先增量兼容；代码回滚与数据库回滚分开处理，不将恢复旧备份当作保留上线后新写入的回滚办法。

配置只通过部署平台密钥管理传递：

- live 模式、数据库连接与 workspace；核实事务、advisory lock、连接数及平台连接模式兼容。
- 独立 `AUTH_SECRET`、正式认证 URL、邮件回跳地址、精确 CORS origin。
- 私有 Blob、队列、内部维护凭证；Preview/Beta 消费者不能互相消耗任务。
- 明确的 AI/OCR provider 与模型、超时、并发和预算；未配置不得退回假数据或开发者隐式 key。
- `ORBIT_TYPED_INBOX_ACTORS` 使用服务端 canonical actor ID 控制首批名单，它不是注册邀请码，也不是外部测试准入策略。
- 自主发现专用配置与预算默认不启用；Push key 不因“不上 App”而假装必须配置，但依赖它的 worker 不得误开启。

## 7. 公网安全与后台工作

### 开放前必需

- 注册 route 和核心注册服务目前未看到邀请资格校验。先实现/验证服务端邀请准入或等效限制，再移除用户域名的 Vercel SSO；“链接只发朋友”不构成访问控制。
- 登录、注册、找回、AI、OCR 与上传的限流及滥用保护，拒绝批量刷号和无限模型费用。
- 检查跨账号访问、会话撤销、Origin/CSRF、私有文件授权与过期、公开资料字段边界、生产 `/dev` 隔离及管理接口权限。
- 平台保护可以保留在 Staging；用户 Beta 应直接进入 Orbit 登录流程，而不是要求朋友加入 Vercel 团队。
- 文档说明测试阶段限制、数据用途和删除/反馈入口；日志不含密码、密钥、聊天正文、护照或名片原件。
- 扫描锁定依赖的安全公告和部署兼容性，特别是 Next/Auth、文件解码和上传依赖。本轮没有进行安全审计，不能宣布当前版本安全无漏洞。

### 后台任务矩阵

| 通道 | 当前基础 | 首发要求 |
| --- | --- | --- |
| 名片与文件清理 | Vercel queue route、私有直传、数据库持久记录、维护补发 | 真图片/PDF 处理、失败重试、原件过期与孤儿文件回收；不在函数本地文件系统保存长期业务文件 |
| 密码找回邮件 | 邮件队列和维护补发，有历史真实收件 | 正式域名的邮件收件与重置闭环、过期/重放、旧会话失效 |
| Agent 动作 | action queue 与补发扫描 | 对首发已启用动作验证重试、幂等、用户确认与外部副作用；不开放未验收自动动作 |
| 维护心跳 | 现有 heartbeat + Cron + 有界 maintenance pass | 无人工访问时持续运行，漏 tick 告警，跨部署续接和手工恢复演练 |
| 三类站内通知 | GET 列表会刷新业务投影，actor 灰度开启 | 无原生 push 设备的纯 Web 账号也能看到和处理自己的记录；不能以“未注册设备”丢掉站内能力 |
| 自主发现 | 独立脚本，显式 actor 名单和专用 provider；现有维护任务列表未包含该发现 worker | 默认停用；要开启须正式绑定有界队列/调度，核实费用并真实验收，不把本机 watch 当云端部署 |

Vercel Queues 为至少一次投递且仍处 Beta，应用自己的幂等、去重、持久状态和补发不能省略；保留停消费者和查失败记录的运维入口。[官方 Queues 文档](https://vercel.com/docs/queues)

## 8. 手机 Web 的 App 式呈现

这是服务上线之后的独立交付，不等于将桌面网页缩窄，也不保证当前原生 UI 可以零修改导出。

| 路径 | 适合目标 | 必须验证 |
| --- | --- | --- |
| 现有 Next.js Web 移动壳 + PWA | 尽快稳定邀请测试，复用现有 Web 认证、上传、路由 | 按 App 导航/布局逐页适配；App 新 UI 不会自动同步到 Web |
| Expo Web + PWA，复用 `orbit-app` 页面 | 更强调与刚更新的 App 页面和交互一致 | 实际 Web export、原生模块浏览器兼容、登录 cookie/同源路由、文件上传、深链接、返回和键盘 |

默认以现有 Web 作为第一轮服务验收客户端；在正式决定手机前端实现前，对 Expo Web 做一个独立、有上限的兼容性验证，仅覆盖登录、首页、笔记编辑和图片上传四条代表链。若通过且重用收益明确，可选 Expo Web；若需要大范围替代存储/认证/原生模块，回到 Next.js 移动壳，不影响已准备好的 API。

代码已明确 `snapshot-store.web.ts` 不保存快照，`local-sync-database.web.ts` 声明 online-only。PWA 首版也采用在线优先：加入 manifest、图标、独立窗口、正确 start URL、safe-area 和键盘处理；不承诺离线写入。不缓存认证接口、私密 API 或账号相关 SSR 页面；若引入 service worker，仅缓存版本化静态资源并测试更新/登出边界。

验收包含 375/390/430px 手机视口、真实 iPhone Safari、添加主屏幕后重开、锁屏恢复、深链接、软键盘、长文本、图片选择/拍照、双账号切换与网络恢复。截图/几何检查不能替代真实键盘和权限验证。

Next.js 官方提供 manifest/PWA 路线；iOS Web Push 需要另行实现且有主屏幕安装等条件，首批不做。[Next.js PWA 指南](https://nextjs.org/docs/app/guides/progressive-web-apps)

## 9. 阶段与验收关卡

下列用时仅为规划估算，不是已承诺交付时间；账号权限、预算和复验发现的问题会影响排期。

| 阶段 | 工作/交付 | 放行标准 | 估算 |
| --- | --- | --- | --- |
| R0 发布盘点 | 固定候选 SHA、功能矩阵、云端项目/资源/账单/region 只读盘点 | 明确首发范围、用户地区、域名、预算与数据策略 | 半天 |
| R1 候选验证 | Node 22/锁文件安装、两端 typecheck/契约、Web 全量与生产构建、必要 App 回归 | 当前候选自身证据，不拼凑多 Sprint 结果；失败逐项修复或有边界的明确决策 | 1～2 天起 |
| R2 公网预备 | 隔离 Staging/Beta、配置、迁移演练、邀请/限流与必要后台任务 | 测试库恢复、域名/TLS、鉴权/隔离/任务恢复验证通过 | 1～2 天起 |
| R3 实际手机链路 | 双账号业务回读、真实邮件、AI/OCR 限额 canary，手机 Web 核心体验 | 所有开放功能可用，未开放功能有实际关闭边界 | 1～2 天起 |
| R4 封闭测试 | 先本人和 1 位朋友，再扩大至 5～10 人；必要时加 App 式壳/PWA | 48～72 小时观察后再扩容；无数据丢失/越权/持续任务积压 | 观察窗口另计 |

App 式界面的工作量在路径验证和页面差异清单完成后估算，不假定包含在上述基础服务工期内。R1 的非零全量测试不得自动忽略；即使暂不开放某功能，其鉴权、迁移、共享契约和后台副作用仍属于全局发布门槛。

### 必须走通的用户旅程

1. 受邀新用户注册 -> 资料 -> 退出/重登 -> 找回密码 -> 旧密码/旧会话失效。
2. 创建/维护联系人 -> 私密笔记 -> 关联事项 -> 完成/恢复 -> 另一浏览器回读同记录。
3. 两位真实测试账号邀请/绑定 -> 消息收发 -> 已读 -> 断网/刷新 -> 不重复、不串账号。
4. 日程编辑和三类通知 -> 查看来源 -> 单项/批量已读 -> 源任务状态不被误修改。
5. 启用 AI 时：显式发送 -> 流式结果/失败恢复 -> 历史重开 -> 重试不重复计费或写入；受控 provider 不替代真实验收。
6. 启用 OCR 时：真实 iPhone 图片/HEIC/PDF -> 私有直传 -> 后台处理 -> 复核 -> 重复确认同一联系人 -> 撤销/过期清理。
7. 两账号交叉读写联系人、笔记、消息、通知、文件及公开资料，确认私有内容不可见。
8. 无人打开网页时等待后台执行，部署重启后检查队列与业务回执；不以 HTTP 200 代表任务已完成。

## 10. 监控、恢复与费用

监控至少包括：登录/API 错误率与延迟、数据库连接/慢查询、队列积压和最旧任务年龄、心跳最后成功时间、邮件失败、OCR/AI 成功率与调用费用、私有文件清理失败。错误反馈应能关联部署 SHA 和脱敏请求 ID。

建议 Beta 运维目标为每日备份、RPO 不超过 24 小时、RTO 不超过 2 小时；这是待通过恢复演练确认的目标，不是现成保障。开启可用的数据库恢复能力，同时验证数据库与文件引用的一致性；费用/套餐不支持目标时应明确调整，不假设免费层自带完整备份。

出现越权、数据丢失、重复外部发送或预算失控时，先停止对应写入/消费者并保存诊断证据，再回退兼容版本；不能简单回滚网页而留下新版 worker 继续处理。回滚前后核对新写入、迁移台账、通知切换批次与队列状态。

费用建议按小规模 Beta 做每月约 USD 30～80 的初步规划区间，域名/税费、重 OCR/AI 和大批量文件另算。这个区间是工程预算估算，不是平台报价或当前账号账单；实际预算必须由用户确认，不能以估算授权付费。

Vercel Pro 当前平台费为 USD 20/月，含一个部署席位和 USD 20 用量额度，超额按用量收费；Hobby 限个人非商业用途，不能因为“暂时免费测试”就认定商业产品可长期使用 Hobby。[Pro 价格](https://vercel.com/docs/plans/pro-plan)、[Hobby 条款](https://vercel.com/docs/plans/hobby)

AI/OCR 使用独立项目/密钥、单请求上限、账号日限和全局硬上限；警告阈值与真正停止调用分别验证。未核清的历史 AI 账本不沿用为新预算，也不在本轮发起任何真实付费调用。

建议先批准“沿用 Vercel/Neon 架构、在线优先、邀请制、服务与手机壳分阶段”的方向，再进入 R0 只读资源盘点和发布候选选择。
