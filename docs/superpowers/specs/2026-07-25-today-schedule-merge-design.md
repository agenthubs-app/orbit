# Today × 日程 合并设计方案

日期：2026-07-25 ｜ 状态：提案（未实现）｜ 方法：ui-ux-pro-max（§4 风格匹配 / §5 布局层级 / §9 导航模式 / 渐进披露）

## 0. 三个界面到底各是什么

| 界面 | 回答的问题 | 核心资产 |
|---|---|---|
| **Today**（/app/today） | "**现在**需要我决定什么？" | 账本决策卡（勾选子操作+确认/稍后）、决策详情（为什么出现/证据/效果）、ORBIT 已准备、最近完成 |
| **旧日历**（/app/followups） | "我的**时间**上有什么约见？" | 迷你月历（翻月/今天）、当日/本月切换、会议卡（展开详情/查看名片/起草邮件）、**安排约见**弹窗（选人+日期+议题） |
| **关系安排**（/app/schedule） | "哪些安排**值得复核**？" | 可复核安排卡（关系原因/跟进时机/来源+证据数/深链）、统计（N 安排·M 证据）、添加来源、"不写入外部系统"护栏 |

它们是同一件事的三个高度：**决定（now）→ 时间（when）→ 依据（why）**。合并的正确形态不是三个 tab 并排，而是一个"时间为脊柱、行动为右手"的工作台。

## 1. 信息架构（推荐）

**一个页面：`/app/today`，导航一个入口。**

- 顶部导航从 5 项减为 4 项：`iOrbit · Today · 活动 · 人脉`（"日程"并入 Today）。导航更瘦符合 §9 nav-hierarchy；两个入口指向同一页面的不同锚点是反模式（navigation-consistency），不做。
- 旧路由 301 保留深链：`/app/followups → /app/today?view=calendar`、`/app/schedule → /app/today#arrangements`（state_preservation + deep-linking）。
- URL 即状态：`?date=2026-07-25`（选中日）、`?view=day|month`（沿用旧日历的当日/本月）、`?entry=`（决策选中，沿用现有）。刷新/分享/后退都不丢状态。

**左栏 = 时间脊柱**（旧日历回归 + 时间性内容合流）
- 迷你月历原样回归：翻月 ‹›、"今天"、点日期选中；**当日/本月**两态保留（=旧日历的两个 tab）。选中日期同时过滤左栏时间轴与右栏（右栏卡片按相关日期淡入排序，不隐藏——避免"我的决策去哪了"）。
- 当日时间轴：三类事件合流，同一时间轴渲染——旧日历的**约见卡**（展开详情/查看名片/起草邮件三动作原样）、关系安排里**已确认活动**（种子轮沙龙：时间/地点/查看活动安排预览）、Today 的**即将发生**（活动+目标联系人重叠）。时间用 `--ff-mono`（number-tabular 原则），左缘 hairline 竖线，与现有视觉语言一致。
- 空态沿用旧日历文案（"这一天暂无安排。换一天，或查看本月全部。"）。
- **安排约见**按钮提到页头（全局动作），弹窗原样复用（ModalShell，选人+日期+时间+议题）。

**右栏 = 行动流**（Today 的判断性内容 + 关系安排的复核卡）
- 区块一「需要你决定」：账本决策卡。**关键交互变化：决策详情从常驻右面板改为卡片原位展开**（accordion，渐进披露）——展开后完整保留原详情面板全部内容：为什么现在出现/建议基于什么信息（证据 chip）/确认后将会/草稿内联编辑/☑子操作勾选/确认执行·稍后处理/"只存草稿"护栏文案。一次只展开一张（escape-routes：Esc 或再点收起）。`?entry=` 依旧驱动展开态。
- 区块二「可复核安排」：关系安排的卡片原样迁入（关系原因/跟进时机/来源·证据数/打开联系人详情/查看活动安排预览），同样原位展开；区头小字合并统计"2 安排 · 13 来源证据"；**添加来源**在页头。护栏文案（"不会写入日历、提醒、消息或外部系统"）保留在展开卡内。
- 区块三/四「ORBIT 已准备」「最近完成」：默认折叠成计数行（content-priority——已完成信息不与待决策争夺注意力），点击展开列表，行为与现 Today 相同。

## 3. 移动端（≤760，单列，决策优先）

```
[顶栏] → [问候+决策数]
[周条日历 ←水平滑动→]      ← 月历折叠为一行周条，点开=全月（bottom-sheet）
[◎ 需要你决定 2]           ← 卡片原位展开，同桌面
[🕒 今日时间轴]             ← 约见/活动卡，动作齐全
[⌗ 可复核安排 2]
[✦ 已准备 1 / ✓ 完成 3]（折叠）
[＋] FAB → 安排约见 bottom-sheet
```
- 周条日历（7 格，44pt 触控），左右滑动换周；全月视图用 ModalShell bottom-sheet（已有 variant）。
- 段落顺序=决策优先；顶部 sticky 分段锚点（决定/日程/安排）可跳转。
- 约见入口用 FAB 而非页头按钮（拇指区）。

## 4. 功能保全对账（合并后逐项去处）

| 原功能 | 去处 |
|---|---|
| Today 问候+决策计数 | 页头一行 |
| 决策卡+详情面板全部内容/勾选/确认/稍后/草稿编辑 | 右栏区块一（原位展开） |
| ORBIT 已准备 / 最近完成 | 右栏折叠区 |
| 迷你月历/翻月/今天 | 左栏顶部 |
| 当日 / 本月全部 | 左栏视图切换（?view=） |
| 会议卡展开详情/查看名片/起草邮件 | 左栏时间轴卡 |
| 安排约见弹窗（选人/日期/时间/议题/发送约见） | 页头按钮/移动端 FAB，弹窗原样 |
| 可复核安排卡（关系原因/跟进时机/来源证据/深链） | 右栏区块二 |
| 统计（N 安排·M 证据） | 区块二区头 |
| 添加来源 | 页头 |
| 护栏文案（只存草稿/不写外部系统） | 各自卡内保留 |
| 即将发生（活动+联系人重叠） | 左栏时间轴 |
| ?entry= 深链 | 保留（驱动展开） |

## 5. 设计原则依据（ui-ux-pro-max）

- **§5 content-priority / visual-hierarchy**：待决策 > 今日时间 > 复核建议 > 已完成；已完成折叠。
- **渐进披露**（§8 progressive-disclosure）：决策详情由常驻面板改为按需展开，一屏容纳三类内容而不过载。
- **§9 deep-linking / state-preservation / back-behavior**：URL 承载 date/view/entry；旧路由 301。
- **§2 touch**：日历格/周条 44pt；展开手风琴整卡可点。
- **§7 动效**：展开 200ms ease-out、收起 140ms（exit-faster-than-enter）；respect reduced-motion。
- **风格**：不新增视觉语言——全部复用现有 token/scale/btn/ModalShell（Drill-Down 模式在现体系内实现）。
