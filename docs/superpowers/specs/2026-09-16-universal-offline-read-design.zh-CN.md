# Orbit 全域离线读取设计

**日期：** 2026-09-16

**范围：** Orbit 原生 App，Sprint 0033～0036

**状态：** 已完成方案讨论，等待书面审查

英文原文：[2026-09-16-universal-offline-read-design.md](2026-09-16-universal-offline-read-design.md)

## 1. 产品目标

账号完成首次同步后，即使没有网络，Orbit 原生 App 也必须能冷启动，并读取该账号离线范围内全部已授权、用户可见的结构化数据。

范围包括：完整的历史 AI 对话、联系人和人脉数据、笔记、任务和跟进、消息、通知、日程、会议、活动、预约、目标、个人资料与设置，以及当前账号因角色而有权查看的运营数据。

云端记录仍是最终权威。离线读取不会带来在线写入权限，不会扩大服务器权限，也不会让尚未同步的本地内容被云端 AI 读取。恢复网络后，App 先重新验证身份和权限，删除已经失去查看资格的数据，再上传 Sprint 0034 明确支持的离线操作，随后继续增量同步。

这组 Sprint 先解决原生 App。Web 继续作为在线权威客户端。浏览器离线需要单独设计安全机制和存储方案，不属于 0033～0036 的交付声明。

## 2. “全部数据”具体指什么

必须完整保存的是：当前账号拥有、参与或因角色获准查看，并且能从 App 读取入口进入的全部结构化数据和历史记录。列表、详情、子资源、搜索和聚合页面都算读取入口。

我们会维护一份“页面/API → 数据域”的清单。只要还有读取入口没有登记，或有数据投影没有经过验证，就不能宣布“全部数据已经支持离线读取”。

本地数据分成三类：

1. **完整结构化数据。** 文字、元数据、关系、历史、已读状态、可见性状态和用户可见的生成结果，都按增量方式下载并保存在加密本地镜像中。
2. **有边界的公共/共享浏览数据。** 公共活动目录这类可能不断增长的数据，由服务器下发明确的离线清单。清单可以包含用户已保存、已参加、已置顶、最近使用，或产品明确规定时间窗口内的数据。尚未下载完成时，界面必须显示 `not-downloaded` 或 `partial`，不能把不完整的本地目录显示成“空”或“已经全部同步”。
3. **二进制资源。** 图片、录音、扫描原图、名片原图和附件保存加密资源清单和完整性信息。文件本体在用户打开时下载，或由用户选择“保留离线”。即使文件本体尚未下载，相关文字和元数据仍然可以离线读取。

以下内容不得进入用户数据镜像：第三方 provider token、Cookie、服务器密钥、隐藏提示词、原始 provider context、邀请密钥、仅供后台使用的审计正文，以及未进入字段白名单的数据。

## 3. 数据域范围

数据域注册表必须覆盖 App 中的每个读取入口，至少包括下面这些业务族：

- 账号、个人资料、语言、时区、通知偏好、标签、连接状态和用户可见的资料建议；
- 笔记、提及、联系人关联笔记，以及产品允许用户查看的笔记历史；
- 普通任务、人脉跟进、任务活动历史、提醒、已确认事项，以及作为独立实体存在的任务建议；
- 个人日程、预约、会议、活动，以及用户可见的会议和活动详情；
- 联系人、连接关系、详情状态、人脉证据摘要、需求、介绍、Pipeline、关系图和关系分析；
- 已保存的导入结果、名片草稿、去重决定和批量复核状态；扫描、OCR 和实际导入命令仍要求在线；
- 普通会话、关系通信绑定、消息、已读游标、摘要、用户可见的提取结果、隐私状态和邀请状态，但不保存邀请密钥；
- AI 会话、分组、置顶、消息、用户可见的运行状态和输出，但不保存隐藏提示词或 provider context；
- 类型化通知、提醒投递、未读状态、人脉信号和处理结果；聚合收件箱行不能重复充当权威业务记录；
- 活动目录与详情、主办方页面、推荐、报名、用户可见的问卷答案、会员状态、参会人可见性、相遇记录、目标、准备度和现场关系图；
- 活动角色、审核、运营、任务、生成结果、签到和分析数据；只有当前账号角色允许时才能进入离线镜像；
- Agent 偏好、设置、信号、动作、账本、主动回合和用户可见的执行回执；真正产生外部副作用的动作仍要求在线；
- 首页、今日、Dashboard、分布、机会、来源，以及其他聚合视图。能从完整本地基础数据确定计算的就在本机计算，否则同步服务端生成的版本化投影。

本地离线注册表与 AI 可见性清单是两套独立规则。能够离线读取，不代表 AI 自动获得读取权限；AI 获得某个函数，也不代表客户端自动获得对应数据权限。

## 4. 技术架构

### 4.1 本地读取身份

`AuthSessionProvider` 提供五种明确状态：`checking`、`online`、`local-read`、`locked` 和 `revoked`。

`local-read` 只能读取上一次经服务器验证的账号及其授权 epoch 对应的加密镜像。它永远不能通过在线写入检查。

SecureStore 使用带版本的 envelope，绑定以下信息：

- 规范化后的 API Base URL；
- 规范化 actor ID；
- 认证 subject；
- 登录会话到期时间；
- `offlineReadExpiresAt`；
- 上次服务器验证时间；
- 已授权 workspace/domain epoch；
- 加密数据库密钥引用。

旧版只有 Cookie 的记录必须先联网升级，不能直接取得 `local-read` 资格。

`offlineReadExpiresAt` 由服务器签发，不得晚于登录会话到期时间，也不得超过上次验证后的七天。部署环境可以下发更短时间。离线资格到期后，App 锁住本地镜像，直到再次联网验证。

设备断网时不可能立即获知服务器端刚发生的权限撤销。产品界面和安全说明必须直说：App 只能在有限租期内使用上次验证过的权限，不能声称离线撤权会即时生效。

认证层的 401/403 会撤销整个本地读取租期。某个数据域返回权限 403 时，只锁定或清理该数据域，除非服务器明确表示账号整体无效。

用户离线退出时，App 立即取消本地读取资格并尝试做加密擦除；远程 sign-out 采用 best effort。清理失败时，旧账号数据保持锁定，不能向新登录账号暴露。

### 4.2 加密作用域

SQLCipher 数据库和资源缓存按规范化 Base URL 与 actor 隔离。每一行数据、游标、资源和索引还必须绑定 workspace 与 authorization epoch。客户端传入的 workspace 值不能成为授权依据。

本地 schema 迁移必须满足：事务执行、可重复运行、崩溃后可恢复，并在真实加密数据库上测试。修改 `CHECK` 约束或游标主键时，需要新建表、复制、校验再替换，不能指望 `CREATE TABLE IF NOT EXISTS` 自动更新旧表结构。

重置单个数据域时，只清理该 domain/workspace/epoch 下已经同步的行、索引、游标和资源。设备草稿和 Sprint 0034 的 outbox/conflict 数据保留。只有账号权限整体撤销时才执行完整的加密擦除。

### 4.3 数据域注册表和适配器

每个数据域必须登记：

- 稳定的 `domainId` 和 schema 版本；
- 权威数据源适配器和服务端授权函数；
- 字段白名单和稳定实体 ID；
- 变更、授权新增、授权撤销、删除与保留规则；
- 聚合视图依赖的数据域；
- App 消费页面、selector、本地搜索索引和排序规则；
- 分页、大小、历史范围和完整性限制；
- 离线租期级别和二进制资源策略；
- 是否存在经过批准的离线写入适配器；
- 独立声明的 AI 读取能力。

每个具体 API 路径族和界面写入动作还要分别声明三类策略：

- `readPersistence`：`durable_normalized`、`encrypted_ttl_snapshot`、`device_only` 或 `online_only_secret`；
- `mutationPolicy`：`offline_queue`、`local_only` 或 `online_only`；
- `binaryPolicy`：`metadata_only`、`on_demand_encrypted`、`user_pinned_encrypted` 或 `never_local`。

兼容旧页面的加密 snapshot store 也必须受策略约束，并记录 schema 版本、到期时间、authorization epoch、payload 大小和完整性 hash。未知 endpoint、密钥字段、无限大小 payload 和 raw/base64 二进制都要拒绝写入。

二进制文件只进入专用加密资源缓存。不能因为结构化数据在 SQLCipher 中，就假定数据库外部文件也已经加密。

默认行为是拒绝。未知 domain、版本、字段或 authorization epoch 必须显式失败。服务器新增字段后，它不会自动进入本地镜像，也不会自动发给 AI。

我们不会简单扩大现有 `orbit_records` SQL 的 `IN` 列表，然后宣称已经实现全域同步。预约、活动运营、关系通信、AI 对话等数据位于不同存储中，也有不同授权方式。它们必须各自提供经过授权的 read-model adapter 和事务型 change journal。

只有在领域适配器确实无法安全满足契约时，才修改全局共享存储或认证逻辑。

### 4.4 首次同步、增量、删除与撤权

服务器先返回带版本的数据域 manifest，再为各数据域返回独立的不透明游标。游标绑定 actor、workspace、domain、schema 版本、registry 版本、authorization epoch、快照 high-watermark 和签发时间。

每一页记录与其游标必须在同一个本地事务中落盘。

首次同步可以分批、可以断点续传，并受到页面数、字节数、时间、电量和磁盘空间预算限制。达到预算时，系统记录 `partial` 并安排下一轮继续，不能把该数据域标为完成。

历史 AI 消息等大数据可以跨多次前台运行逐步下载，已经完成的页不重新下载。

每个权威数据源的 journal 都要保留已提交的可见性变化：

- 新增角色权限时，补发该角色应看到的历史数据；
- 权限撤销时，即使原始实体没有改变，也要发送 visibility delete；
- 实体物理删除时，保留耐久 tombstone；
- 游标超出保留期时，只要求重置受影响的数据域。

跨数据域同步不能假装具有全局原子性。本地聚合视图记录它使用的各依赖版本。派生集合只有在同一代全部页面到齐后才替换旧集合，避免中途失败把仍然有效的本地成员误删。

### 4.5 App 读取行为

完成迁移的列表、详情、子资源、搜索和聚合页面都先读加密镜像。网络请求负责更新镜像，不再作为页面直接渲染的主要来源。

界面必须区分这些状态：`fresh`、`stale`、`partial`、`not-downloaded`、`not-authorized`、`locked` 和 `failure`。

网络失败时，过期但可用的本地数据继续显示。镜像为空且下载失败时，显示错误，不能显示成空列表。只有数据域 manifest 明确表示搜索范围已经完整时，本地搜索才可以给出“没有结果”。

在线写入继续使用现有 API，但必须通过新鲜的在线身份和权限验证。`local-read` 不能通过 raw fetch 或后台上传绕过写入限制。

## 5. Sprint 分工

### Sprint 0033：全域增量读取

0033 负责：

- `local-read` 身份；
- 加密作用域迁移；
- 数据域注册表和共享契约；
- 服务端授权适配器与 change journal；
- 每域 bootstrap、delta、tombstone 和权限撤销；
- 完整性状态与资源 manifest；
- 所有原生 App 读取入口的 mirror-first 迁移。

现有笔记、任务和个人日程只是已经验证的子集，不再是 0033 的完成边界。

0033 内部分阶段交付：覆盖清单与基础结构；身份和存储；协议和 registry；个人及基础人脉域；通信、完整日程和 AI 会话域；活动角色、Agent 和聚合域；资源、本地搜索与旧读取入口清理。

每个阶段的明确子范围完成后可以独立提交和合并。只有 route-to-domain 清单中未登记的读取入口为零时，0033 才能标记完成。

### Sprint 0034：按风险开放离线写入

0034 使用 0033 的注册表，但只为满足以下条件的操作增加离线写入适配器：操作结果确定、可逆、数据由当前 actor 私有、服务端事务能提供持久幂等回执和冲突证据。

首批已经具备基础的写入域是：笔记、个人任务/人脉跟进、个人日程。个人资料偏好和其他看似安全的域，只有在独立验证严格 patch、版本、幂等、回滚和权限语义后才能加入。

邀请、发送消息、报名、修改共享会议、角色/权限修改、删除账号、provider 操作、扫描/导入执行，以及 AI 或其他外部副作用，继续要求在线。它们的数据仍可离线读取。

Outbox、alias、eligibility、receipt 和 conflict 改成按领域适配。未支持的操作在入队前直接拒绝。

全局 mutation receipt 是批量重放的权威。服务器依次取得 mutation receipt lock、领域 transaction/CAS 和共享 sync-write lock，并在同一事务中保存领域结果、sync revision 与最终 receipt。原有领域 receipt 只保留为校验或兼容证据，不能形成第二套事务边界。

### Sprint 0035：全域失效检测与恢复

0035 用 registry 驱动的 domain watermark 和失效摘要替换固定的三个数据类型。

HTTP polling 是与 provider 无关的正确性路径。Realtime、SSE、WebSocket 或 Push 只提供提示，不能代替游标真相。

启动、回到前台、网络恢复、手动刷新、点击通知、游标过期、权限 epoch 变化和账号切换，都统一进入 0033 的分域恢复流程。

消息和通知等高频数据可以缩短提示周期；历史 AI 对话等大数据使用有预算的前台/后台分页。失效提示不携带业务正文，也不能代替 cursor。重复或乱序提示要合并，但不能漏掉同步结束后必须补跑的一轮。

### Sprint 0036：AI 覆盖与端到端验收

0036 为用户已经授权给 AI 的每个数据域提供明确读取函数，包括：历史 AI 对话、联系人与人脉证据、消息、通知、笔记、任务、跟进、日程、会议、活动、目标和用户可见的 Agent 数据。

这些函数共用 actor-scoped 权限注册表、严格字段白名单、有界分页、revision/freshness、证据引用和 prompt injection 防护。

服务端 AI 只读取云端权威记录。本地 pending change 和设备草稿不发送给 AI。App 要按领域和数量向用户说明哪些本地变化尚未被 AI 看见。

某个数据域即使支持离线读取，只要 AI 能力未开启，AI 就不能读取。

Data Atlas 和运行时验收矩阵必须逐域记录：离线读、离线写、AI 读、权威来源、存储位置、同步状态和剩余限制。

## 6. 与 Sprint 0037～0041 的关系

- 0037 提供联系人消息 ID、参与者、历史与已读游标；
- 0038 提供类型化通知 ID、生命周期和动作；
- 0039 提供基于证据的发现和来源授权；
- 0040 提供设备投递和通知偏好生命周期；
- 0041 提供首页消费者迁移。

这些 Sprint 提供各自的权威数据源和 App 消费者，但它们本身不能证明数据已经支持离线读取。

0033 通过领域适配器接入这些记录，不复制第二套权威数据。0041 只能在其依赖的 0033 版本通过验收后合并，或把自己的提交重放到已经通过验收的 0033 集成树上。

## 7. 安全规则

- 每次生成数据投影和恢复网络后都要重新执行服务端授权。缓存记录不能授予新权限。
- 每个存储和游标边界都要检查 actor、Base URL、workspace、角色、domain、schema 和 authorization epoch。
- 权限撤销后，删除本地可读投影和对应二进制资源。
- Provider token、凭据、隐藏提示词和后台专用审计数据不能进入镜像或 AI 返回值。
- `local-read` 不能上传、修改、邀请、发送、报名或触发外部副作用。
- 不完整数据不能产生误导性的“空”或“全部完成”结果。
- 正确性不能依赖单一云厂商 SDK。PostgreSQL 兼容 journal 和 HTTP polling 是可移植基线。
- 每项实现遵守 TDD；修改共享符号前执行 GitNexus impact，提交前执行 detect_changes。
- 每个通过验收的阶段单独提交。合并前审查，合并到 `chat-agent` 后在精确合并树重新验证，通过后才 push。

## 8. 验收标准

全部条件满足后，才能宣布这组 Sprint 完成：

1. route-to-domain 清单中没有未登记的原生 App 读取入口。
2. 每个数据域都证明：授权 bootstrap、delta、物理删除、权限撤销、游标重置和 actor/角色隔离正确。
3. 完成同步后，所有列表、详情、子资源、搜索和聚合页面都能在离线冷启动时从镜像渲染。
4. 历史尚未下载完成、磁盘不足、二进制缺失和本地读取租期到期都被如实显示。
5. 切换账号、Base URL、workspace 或角色时，不能读取上一个 scope 的数据。
6. 已支持的离线操作能跨重启保存、只在服务器生效一次，并显示冲突，且不会破坏 canonical read。
7. 失效提示丢失、重复、乱序，App 长时间在后台，以及进程被杀后，都能依靠游标恢复。
8. 每个 AI 已授权域都有明确并经过测试的函数；未授权字段无法进入模型上下文。
9. 服务端修改后重新构建并重启 production Web/API；Simulator 明确连接主线 Metro；使用同账号完成每个业务族的代表性新增、修改、删除和撤权验证。
10. Sprint 报告、Bridge 交接、Data Atlas、Commit SHA、合并树测试证据和远端 `chat-agent` SHA 完全一致。

## 9. 并行执行边界

- **A 线 / 0033：** 负责共享读取身份、registry、存储、同步契约、领域适配器和消费者迁移。
- **B 线 / 0034：** 负责写入分类、outbox/receipt/conflict 适配器，以及支持离线写入的界面；不得重新定义 0033 的读取身份或游标。
- **C 线 / 0035：** 负责 status/invalidation transport 和恢复调度；使用 0033 游标与 0034 上传状态，不修改它们的语义。
- **D 线 / 0036：** 负责 AI 权限与工具覆盖、freshness、本地 pending 提示、Data Atlas 和跨端验收；不得把 AI manifest 当作客户端授权依据。

A 线构建基础时，B/C 线可以依据已批准的契约准备测试和独立适配器，但不能合并依赖尚未通过验收的 0033 接口。

D 线可以在 AI 权限契约获批后，先补充不依赖本地同步的服务端查询函数；0033～0035 合入后，再完成跨端综合验收。
