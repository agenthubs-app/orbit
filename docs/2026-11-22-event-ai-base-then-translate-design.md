# 活动 AI 生成：日文底稿 → 翻译（设计，2026-11-22）

用户定的方向：

- 内部（身份、数量、名次、分桌、座位、校验）用程序规则；
- 参加者看到的文字全部由 AI 写，不用模板句，不用程序拼接；
- 每条推荐固定为理由 2 句、问题 2 句、提示 1 句。

另外三条按成熟做法定（父会话已转告用户）：

- 先写一份单语底稿，再翻译；
- 每人恰好推荐 N 人；
- 语义审核先只在小样本上评估，不进生产。

## 一、底稿语言：日文

- **为什么用日文：**
  - 参加者资料（需求、能提供的、话题、职位）大多是日文。用日文写底稿时 AI 直接引用资料原意，不用先翻译事实，事实层出错最少。
  - 活动在日本举办，产品默认语言是日文。
- **中文和英文：** 都从日文底稿翻译。
- **旧的单语字段：** 存储和接口里原来的字符串字段仍然填中文，内容取自三语里的中文，旧读者和旧版 App 不受影响。

## 二、流水线（每个推荐分片；任务、lease、局部重试、全部完成才发布，这些都不变）

### 第 1 步：选人并写日文底稿（Flash，1 次调用）

- **输入：** 本批 source 和它们的候选。只给键（S1、S1C3）、资料字段和 `hasCompany`，不给姓名和公司。
- **输出：** 固定键，不再用数组。

```json
{"S1":{"p1":{"target":"S1C3","score":88,
  "r1":"{S1}さんは資金調達先を探しており、{S1C3}さんは投資担当です。",
  "r2":"{S1C3}さんは医療分野のPoCにも関心があります。",
  "q1":"どの段階の企業に投資していますか？",
  "q2":"医療分野での実証はどこから始めますか？",
  "hint":"{S1}さんは調達計画の時期から話すとよいです。"},
  "p2":{…},"p3":{…},"p4":{…},"none":null}}
```

- **程序校验（不过就整批重试，不去重、不减数量）：**
  - 键完全符合；
  - 每个 source 的 `p1..pK` 都存在，其中 K = min(N, 候选数)，N 现为 4；
  - target 在本 source 的候选里，并且互不重复；
  - score 是 0–100 的整数；
  - 名次由程序按 p1..pK 的顺序给。
- **边界：** 候选数为 0 时，必须写 `none`（一句日文），并且不能有任何 p。候选少于 N 时，就推荐全部候选。
- **底稿检查：**
  - 占位符格式正确；
  - 作用域：一条推荐只能引用本行的 source 和这条的 target，公司占位符必须和同一人一起出现；
  - 日文是句子时必须含假名；
  - 不得出现资料里的姓名或公司名。

### 第 2 步：翻译（Flash，中文、英文各 1 次调用，并行）

- **输入和输出：** 扁平的「id → 文本」映射，翻译只换语言。

```json
{"S1.p1.r1":"{S1}さんは資金調達先を探しており、…","S1.p1.q1":"…"}
→ {"S1.p1.r1":"{S1}正在寻找融资渠道，…","S1.p1.q1":"…"}
```

- **翻译看不到、也不能改的东西：** 选人、名次、分数、target。
- **程序校验：**
  - id 集合完全一致；
  - 每条的占位符集合和数字（按数值）与日文一致；
  - 中文必须含汉字、不能有假名，英文字母只允许缩写；
  - 英文里不能有汉字或假名；
  - 任何语言都不得出现资料里的姓名或公司名。
- **失败处理：** 不合格的条目做一次有限修复：只重写不合格的那种语言，以同一条的日文底稿为源，占位符保持不变。修完再跑同一套完整校验，仍不合格就整批重试。

### 第 3 步：程序收尾

- 按 id 填入资料原名和公司（「无 / 暂无」类值不算公司）；
- 组装成原有形状：`reasons` 2 句、`icebreakers` 2 句、`memberHint` 1 句；
- 走原有的封闭 schema，再合并三语：原字段取中文，`i18n` 放 ja/zh/en。

### 分桌（每桌每轮）

- **第 1 步，日文底稿：** 成员只用短键 M1..Mn；座位由程序生成，AI 不写。

```json
{"theme":"…","rationale":"…","q1":"…","q2":"…","q3":"…",
 "members":{"M1":{"p1":"…","p2":"…","why":"{M1}さんは…"}, …}}
```

- **第 2 步：** 翻译和校验同上。

### 分组特征（不展示）

保持现有做法：中文、内部使用、不翻译。输入的推荐文字改为三语合并后的中文字段（和现在一样）。

## 三、校验总表

| 层 | 内容 | 失败处理 |
|---|---|---|
| 结构 | 固定键、恰好 K 个不同 target、在候选内、score 是整数 | 整批重试 |
| 作用域 | 占位符只能是本行 source 和本条 target（分桌是本桌成员），公司必须和同一人一起出现 | 整批重试 |
| 身份 | 不得出现资料里的姓名或公司名，名字只由占位符填 | 整批重试 |
| 翻译一致 | id 集合、占位符集合、数字（按数值）与日文一致 | 该语言该条修复一次，再复检 |
| 语言 | ja 句子含假名；zh 含汉字、不含假名；en 不含汉字和假名 | 同上 |
| 语义 | 事实归属、需求和供给方向、否定、译文增删 | **先不进生产**：12 人小样本上用独立模型（Pro）评估检出和误判，加上我人工逐条读三语，报数后再定 |

## 四、70 人预估（未实测）

- **推荐分片：** 每批 3 个 source（输出只有日文，较短），70 人 = 24 批。
- **调用数：**
  - 推荐：24 批 × 3 次（底稿 + 中文 + 英文）= 72 次；
  - 分组特征：24 次（不变）；
  - 分桌：12 桌 × 2 轮 × 3 次 = 72 次；
  - 合计约 168 次，另加少量修复和重试。
- **耗时：** 并发 32（引擎上限）时，推荐一波约 15 秒底稿 + 约 10 秒翻译（中英并行），分组特征和推荐重叠，分桌一波约 25 秒。全部一次通过约 1–1.5 分钟，有少量重试约 2–3 分钟。
- **费用（Flash 峰时价）：** 输入约 0.55M、输出约 0.33M token，约 $0.55/场。缓存命中会更低。
