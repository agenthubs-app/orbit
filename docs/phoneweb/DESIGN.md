# Phoneweb 已批准设计

批准：2026-09-16 当前对话“没问题，按照你的推荐执行”，并指定 `phoneweb-` session 前缀。

## 用户结果

投资人从手机浏览器打开 HTTPS 链接，经演示账号登录后，体验当前 Orbit App 的页面、导航、交互和在线业务。无需安装 App。外观基准是固定版本实际 App 的 Ink & Signal 页面及已有参考，不重新设计产品。

## 实现

复用 `repos/orbit-app` 的 Expo Router、React Native Web、现有 Screen/view-model/hooks，通过浏览器平台适配调用 `repos/orbits` 的既有 HTTP API。不从 App 构建时导入后端源码，不复制业务逻辑。现有桌面 Next.js 产品保持独立入口。

提供可复现的 Web 生产构建与部署候选。建议统一入口把 `/api/**` 转发至现有 Next 后端，页面与 API 同源；如现有认证使用非 `/api` 回调路径，明确列出路由规则。浏览器由安全 Cookie 管理会话，不把原生 cookie 字符串、密钥或固定演示密码打进 bundle。生产构建不能默默指向 localhost。

手机采用 App 的五入口导航：首页、人脉、IORBIT、活动、我的。详情页、笔记、日程、事项、收件箱、名片、资料设置、活动运营等均进入逐入口清单；链接、写入、刷新回读、失败恢复和账号隔离逐项验证。宽屏可限制内容宽度，但手机不加假机框。保留现有浅色/深色、语言、字号和权限行为。

## 平台能力

当前 Web 是在线模式，现有 `.web.ts` 存储适配不提供原生 SQLCipher 镜像。不得声称离线可用。网络失败显示现有失败态并保留允许保留的草稿；不能把失败写入显示为已同步。

相机/图片选择/下载/分享/推送逐项验证可用性，提供完成同一用户目标的浏览器路径。后台原生 Push 和系统界面不能承诺逐像素一致；未提供对应能力必须列入差异与验收缺项，不隐式删入口或虚构成功。

键盘展开、动态视口、安全区、底栏遮挡、滚动容器、弹层焦点、浏览器后退和刷新深链是 Web 专项行为。优先 `.web` 文件或局部平台分支，共享组件改动必须验证原生既有行为。

## 数据、外部环境与费用

推荐已获批准：独立演示账号、示例数据、真实后端功能和持久化。只使用项目专属隔离环境，不读取或迁移其他线真实数据。不把预设 AI 回复当作实时生成。已知 AI/OCR 费用账本与配置缺项独立记录；无已确认剩余额度不运行付费场景。

发布前必须固定公网目标、服务版本、数据库、回调 URL、配置来源和回滚方式。当前授权覆盖本地实施与发布准备；不能把未知的生产账号/数据库当作已授权目标。本地生产进程、桌面模拟视口、浏览器引擎测试、实体手机和公网证据分别记录。

## 成功标准

1. 生产 Web bundle 可重建；进入链接、登录、刷新恢复、退出及未授权详情拦截正确。
2. 五主入口和全部可达业务入口有清单；同数据/尺寸与 App 对照，必要操作正常且错误可见。
3. 真实隔离环境下核心写入回读通过，至少覆盖笔记/待办、联系人、活动操作与会话相关场景；权限与重复提交按现有规则验收。
4. 手机键盘、返回、深链、窄屏/大字号不丢失关键操作；原生回归按改动影响验证。
5. 最终由 iPhone Safari 与 Android Chrome 经公网完成用户旅程；没有相应设备或公网环境时保持该项未完成，不以构建/单测替代。

第一阶段允许先交付在线闭环，但最终覆盖清单不得缩成五张静态首页。每个 Sprint 的 SC 最多五项；实际功能缺口按必要用户操作链分割，避免一个 Sprint 多 Generator。
