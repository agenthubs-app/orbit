# 联系人备注

联系人备注是当前账号写给自己看的补充文字。Web 和 App 使用现有 `PATCH /api/contacts/[id]`，只提交 `note: { body, authorLabel }`；不会因此创建任务、请求 AI 或发送消息。

## 服务端边界

- 认证账号由服务端会话决定，请求体不能指定备注所属账号。备注存于该账号和联系人的 `contact_detail_states`；另一账号即使引用同一联系人，也读取自己的详情状态。
- 新手动备注明确返回并持久化 `privacy: private`。它的来源为手动输入，不附带联系人的 OCR、活动等证据 ID。
- 已有手动备注缺少隐私标识时，仅在读取投影中补为私密；读取本身不写入数据库。明确标为 `relationship_shared` 的既有纪要不被改成私人备注。
- 现有去重规则使用账号、联系人、作者和去除首尾空白后的正文。同一输入重试不会增加备注，也不会改写首次创建时间；相同作者再次提交完全相同正文也会得到原备注。
- 备注更新保留已存的共享纪要、交流记录、标签、关系状态和最近互动。不会自动修复或迁移关系阶段。
- 演示服务采用相同的私密标识与无证据响应，但仍是无持久化的固定数据预览。

## 验证

`tests/capabilities/contact-notes.test.ts` 使用真实服务、存储适配器及隔离内存存储，覆盖私密持久化、原文回读、重复提交时间稳定、跨账号隔离、旧备注读取兼容及演示响应。`contact-detail-note-preservation.test.ts` 覆盖其他详情更新不丢失已有备注。

## 客户端

- Web 联系人详情的桌面和窄屏布局均有「联系人备注」区和添加按钮，页面只挂载一个编辑弹窗。共享互动时间线不重复展示私有备注。
- App 联系人详情有独立可展开的「联系人备注」区，默认收起，展示全部私有备注；原「更新联系人」中的「添加记录」表单已移入此区。收起再展开保留未保存草稿。
- 两端正文原样展示，不过滤用户写入的 CRM、mock、下划线词或换行，也不随界面语言翻译。明确显示「仅自己可见」。
- 保存时只 PATCH 备注，空白输入不请求、保存中禁止重复提交；失败或回执不匹配时保留正文。确认联系人、正文、作者及私密标识匹配后才清空。旧备注的非 ISO 时间仍按共享 Schema 接受。
- 已确认备注按 note ID 合并，刷新返回旧数据时不吞掉刚保存的备注。Web 的组件由服务端认证账号与联系人共同设 key；换账号会重建全部本地状态。App 草稿与回执显式绑定 actorId、联系人及客户端，详情读取启用可选 scopeKey，隔离旧账号数据与在途 GET 去重。其余资源调用未启用此选项。
- `shared/api-schema/contact-notes.ts` 经既有 `sync:contract` 复制到 App，未新增 HTTP 路由、请求字段或扩展 domain 同步白名单。

`tests/pages/app-contact-notes.test.tsx` 覆盖三语原文、真实父组件刷新竞态、账号 key 重置、失败/旧回执，以及真实 PATCH→live 服务→隔离内存存储的丢回执重试。`tests/pages/app-contact-notes.browser.mjs` 验证桌面/窄屏操作与焦点恢复。App 的 `contact-notes-interactions.test.ts` 运行真实页面和 API client；`api-resource-scope.test.ts` 运行真实资源 hook，验证同客户端账号切换时迟到 GET 不串号。

验证不连接真实账号或数据库，不代表已上线、真实跨设备同步验收或 iOS 真机键盘验收。演示服务刷新后仍会恢复固定数据；持久化保证由 live 服务存储测试验证。
