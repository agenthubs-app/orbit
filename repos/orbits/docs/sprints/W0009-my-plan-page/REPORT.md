# Sprint W0009 — 执行总结

## 目标实现情况

- 本轮要实现：用户在「我的计划」里看到本周要做的事并打勾，iOrbit 的本周推进跟着更新；有计划时活动推荐理由改为对应阶段。
- 已验证能做到：
  - `/app/agent/plan` 重写为「我的计划」：目标原文作报头、「计划 vN · 生成日期」、目标分析默认折叠、周进度刻度（阶段区间与本周高亮）；没有计划时显示空状态并指向引导（开关关时回 iOrbit）（SC-01）。
  - 本周列表只列建议周次 ≤ 本周且未完成的行动，逾期的滚入本周并标「已延后 N 周」；打勾走 W0007 接口，乐观更新、失败只回滚这一条并提示；刚勾掉的行在本页暂留以便撤销、刷新后消失（SC-02）。
  - 右栏人脉需求显示已建立联系／已关联计数，人员按添加时间倒序、姓名按 id 为本人批量解析；计划里的活动；底部进展记录可手动添加，一次提交用同一个幂等键，失败重试不会重复写入（SC-03）。
  - iOrbit 本周推进：有计划时显示阶段名、「第 n 周 / 共 N 周」、最多 3 件未完成行动（可打勾）、行动数与已建立联系人数、「查看完整计划 →」；无计划保持原账本显示；示例模式不请求计划接口（SC-04）。
  - 有计划时推荐理由改为「对应你计划第 n 阶段：认识 ___」（阶段只有一个人脉需求时）或「对应你计划第 n 阶段：{阶段名}」（多个需求时），无计划保持 W0003 的匹配词理由；旧「4 周推进节奏」占位删除（SC-05）。
  - 周次从 `plans.starts_on` 起算、东京时区，不复用跟进队列的时钟逻辑；勾选框点击区保持 44px。
- 仍未实现或未验证：
  - **有计划时的浏览器验证没做**：用户账号没有计划，生成一份会写入用户数据；真实页面只验证了空状态（渲染正常、无 console 错误）。
  - 「重新分析」只是说明还未开放的文字标记（W0012）；「待确认 N」角标位置已留、未渲染（W0010）；「延后 ≥2 次提示调整」留给 W0012。
  - 旧计划屏的 CSS 规则与 `iorbitPlanWeeks` 已无调用方，但仍有既有测试断言它们存在，未删（建议另开清理）；`scripts/visual/attribution-0918-iorbit.json` 对计划屏已不适用。
