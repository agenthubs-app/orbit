# Sprint W0036 — 今日要事吸收计划行动与补人脉，抽出共享推荐活动池

## 要实现什么

做完三步引导、已有计划的人打开 iOrbit 首页，「今日要事」不再是空的：本周计划里该做的行动（拖期的优先，最多 2 条）和「补几位新联系人」的提示会补进前 3 条，可以直接勾掉、今天先不做、点标题去对应的人／活动／计划条目；报头导语按第一条要事拼一句话。同时抽出一份「推荐活动池」，给后面的活动小模组（W0037）和月历圆点（W0038）共用。

## 做完能看到什么

- 名片待确认、人脉匹配等原有要事不足 3 条时，本周计划行动补进来，标「本周计划 · 第 N 阶段 阶段名」，拖期的标「已顺延 N 周」。勾掉后「本周推进」同步打勾；保存失败两处都恢复原状并提示。「今天先不做」只在这台浏览器隐藏到东京时间明天，不改计划、不算顺延。原有要事占满 3 条时，计划行动只留在「本周推进」。
- 已确认联系人不到 10 位时，提示「补几位新联系人」，文案提到计划当前阶段，按钮打开名片上传区；可以「7 天内不再提示」；到 10 位后不再出现。
- 报头导语：第一条是计划行动时写「今天可以推进一步：约 狄建安 聊 20 分钟」；今天没有要事、也没有日程时写「今天没有安排，10/2 有一场适合你的活动：……」（取活动池第一场）。都由规则拼成，不调 AI。
- 推荐活动池按「计划里提到 → 匹配目标里的词 → 近期活动」排好，排除已报名、已开始、已取消、本人主办；理由只写真实来源。本 Sprint 只把池算出来，不新增页面上的活动卡片和月历圆点。

## 怎么验收

- 纯函数测试：计划行动的挑选与名额、拖期周数、跳转地址；活动池的排序、去重、排除和理由。
- 首页组件测试：勾掉同步与失败回滚、「今天先不做」的本地存储（按账号和东京日期，存储不可用时也不报错）、补人脉出现与消失、导语两种新句式；计划仍只请求一次。
- 页面测试计数：真实首页不新增客户端请求；示例首页在既有的示例判定读取（首页复合数据 1 次，不交给示例壳）之外，只新增活动目录和本人报名各 1 次。
- 计划里点名的活动即使在目录里排得很靠后（第 13 场以后）也排在活动池最前；活动标题按界面语言显示（日文界面用英文），地点保持来源原文。
- REPORT 给一张统一的数据库月流量预算表（基线 1,106.83 MB + 示例期 + 无目标兜底 + 社群），上限 1.6 GB（D39），超出如实登记，不取消兜底；首页与策略页的 HTTP 响应体单独一张表，不混进数据库预算。
- 在 3001 验收环境走「新用户三步引导 → 首页」和「老用户有计划、人少」两条路径，桌面 1440、手机 375 各一次；一次全量测试对照基线；一次 Codex 代码 review。
