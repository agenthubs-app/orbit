# Sprint W0048a — 共享人脉分析快照与两池 AI 配额

## 要实现什么

有至少 3 位已确认联系人的用户，系统按人存一份处处带依据、中英双语的「人脉分析快照」，数据没变就不调用模型，新人脉按三层规则更新；所有非名片识别的 AI 调用都记在同一张账本里，分「用户主动」与「后台自动」两池计量，超限不调用并告诉用户「明天更新」。

## 做完能看到什么

- `GET /api/network/snapshot` 返回当前快照（只带当前语言的文字与依据）以及「新增 N 人未纳入」「正在更新」「明天更新」等状态；数据没变时打开多少次都不调用模型；新增 ≥3 人或 ≥20%、目标改了、或从不足 3 人恢复时后台自动重算一次；计划的阶段与目标永远不会被重算改写。
- 额度按「操作」计（一次重新分析、一次计划生成、一批 ≤20 人的洞察各算 1 次），花费按每次 AI 请求一条明细记账。「重新分析」每天最多 3 次，用户主动的操作每人每天合计最多 10 次（用满按钮置灰、提示今天次数已用完明天可用）；memo 提取、洞察批量、导入补全、快照自动重算共用后台池（每人每东京日 60 次操作、每批 ≤20 人），用完顺延到次日，对应位置显示「明天更新」；名片识别不经过账本。
- W0046 接好的 memo 提取从此开闸（后台池），导入与其他新人脉经同一个「三层更新」入口进入：补全 → 规则匹配进「待确认」→ 达阈值才重算快照。

## 怎么验收

定向测试证明：版本未变 0 次模型调用、阈值／目标／恢复三种触发、并发只算一次、校验器丢弃编造的依据 id、模型给的分数不进快照、两池分别计数互不占用、后台池满时 0 次调用且排到第二天、手动第 4 次被拒、计划三表在重算前后不变。本地测试库跑迁移、仓储与账本并发测试；新增读取实测字节并按 D39 总账估算；真实 DeepSeek 调用不超过 PLANNER 写明的上限并在 REPORT 记录 token。
