# Sprint W0027 — 活动详情页按账号 id 判定报名、主办方与私密访问

## 要实现什么

已登录用户打开活动详情页 `/app/events/[id]`，「已报名」、报名者名单是否可见、「主办方后台 →」入口、私密活动能否打开，全部按账号 id 判定——与报名、建活动、分配活动角色这些写入接口用的 id 一致。账号 id 与登录会话 id 不同时，不再把报过名的人当成未报名，不再把主办方当成访客；只挂在会话 id 上的数据也不会因此获得访问权。

## 做完能看到什么

- 报名记在账号 id 下：详情页显示已报名，能看到报名者名单；只记在会话 id 下时按未报名处理，名单不可见。
- 活动的主办方（或被分配了活动角色的账号）是账号 id 时，能看到「主办方后台 →」并能打开私密活动；只在会话 id 上有权限时，私密活动显示「无权访问」。
- 未登录打开私密活动仍然跳转登录；已登录但账号解析失败时显示「暂时不可用」，不跳登录（不会死循环），也不改用会话 id。
- 公开活动未登录时和现在完全一样。

## 怎么验收

- 页面测试造出「账号 id ≠ 会话 id」的账号，逐项证明：已报名、名单、主办方入口、活动角色、私密访问、未登录、账号解析失败。
- 读取计数：登录时账号解析 1 次，未登录 0 次；本机测量新增读取的返回字节并估算月增量。
- 3001 验收 server 上用 verify-plan（已报名）、verify-host（主办方）、verify-legacy（未报名）各看一次详情页，桌面 1440 和手机 375。
