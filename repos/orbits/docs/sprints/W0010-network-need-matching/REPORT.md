# Sprint W0010 — 执行总结

## 目标实现情况

- 本轮要实现：扫进名片后，系统提示其中谁可能填上计划里需要的某类人；确认后本周多一条「约 TA」行动。
- 已验证能做到：
  - 名片批次转为完成的同一事务里写入匹配任务，同一批次只一个任务（并发确认最后两张、重放都只生成一个）；单张批次按用户 + 东京自然日聚合；匹配表未建时名片确认照常完成（SC-01）。
  - 规则层：二级行业相同为强候选、一级相同为候选、行业缺失不参与，输入所有生效的人脉需求（不设「已填满」）；AI 层（DeepSeek，复用名片识别文本模型配置）按公司、职位做第二轮，只接受本批联系人与本计划需求的 id，失败或超时只保留规则结果，崩溃重试不再重复计费（SC-02）。
  - 触发：审阅页确认完成后在请求内执行（前端最多等 8 秒）；`plan-match` 维护任务每日兜底，不依赖浏览器（SC-01）。
  - 一个确认组件用在三处：名片审阅最后一屏、iOrbit 今日要事「N 位新联系人可能对应你的计划」、计划页人脉需求旁「待确认 N」；每批只显示本批候选（同一天多个单张批次互不串）；「是／不是」与关联、行动、日志在同一事务内原子完成，并发时一个成功一个 409（SC-03，review 后补）。
  - 确认后本周生成「约 TA」行动，带三个按钮：定时间（跳到个人日程页）、起草邮件（点击才生成，模板草稿、可编辑可复制、不发送）、记一次互动（写进展记录并标为已建立联系）；联系人详情里可手动「关联到计划人脉需求」（SC-03）。
  - 所有接口与任务严格按 actor 隔离，读不到也改不了他人的批次、候选、计划与联系人（SC-04）。
  - 需求按添加时间倒序读取与展示；一次 AI 调用覆盖全部生效需求（安全上限 200）（review 后补）。
- 仍未实现或未验证：
  - **浏览器验证没做**：需要一批真实上传的名片和一份真实计划，都会写入用户数据。
  - **起草邮件不用 AI**（协调者按用户授权的决定）：为起草邮件付费调用 AI 不在 D5 授权内，先用模板实现并留好 provider 接口，接 AI 只需改一行，需用户决定。
  - 定时间只是跳到个人日程页，不预填联系人；记一次互动只写入计划，不写联系人模块自己的互动时间线。
  - 生产库迁移未执行（需授权）；执行前名片确认照常，但不会生成匹配任务。
