# Sprint W0025 — 跟进排序运行时白名单与首页「部分来源不可用」

## 要实现什么

跟进来源（策略页「先联系谁」、首页跟进补位、`/app/tasks` 跟进分页、关系任务分页接口）的排序运行时检查，从「只认一个 Node/ICU 组合」改成「经差分测试的组合白名单」，本机组合在差分测试通过后加入；首页在跟进来源读不到时不再下「今天没有必须处理的事」这种确定结论。

## 做完能看到什么

- 本机验收 server（Node 26.10.0 / ICU 78.3）上，策略页「先联系谁」显示真实的跟进联系人；没有跟进时显示「当前没有待推进的联系人机会」，不再显示「来源暂时不可用」。
- 不在白名单里的运行时仍然拒绝排序（`LIFECYCLE_SORT_RUNTIME_UNVERIFIED`），页面显示来源不可用，不给错误顺序。
- 跟进来源不可用时，首页不显示「今天没有必须处理的事」。
- REPORT 给 W0019 写明发布门：生产 Node/ICU 与 Neon PG／排序规则版本没验证前，不能把这部分当作生产可用。

## 怎么验收

- 用本机 PG 跑两组现有差分测试（`lifecycle-task-pages-postgres`、`relationship-task-page-postgres`），0 skip，全部通过后才把本机组合写进白名单。
- 单测证明：白名单内的组合放行，其他组合抛错。
- 首页组件测试证明跟进来源不可用时不下确定结论。
- 3001 上用 verify-legacy 看策略页和首页，桌面 1440、手机 375 各一次。
