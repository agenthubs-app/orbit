- **P1｜`PLANNER.md:72–78、167`：写前“强制新鲜确认”仍允许合并普通 in-flight 请求，不能证明确认发生在写操作之前。** 普通读取可能早于用户点击写操作发出，随后账号已经切换；写路径复用它仍会以旧账号执行。建议为写操作设置独立的 fresh generation/barrier：不得加入更早开始的普通确认，只能合并同一批写前确认；新增“普通确认 pending → 切换账号 → 发起写操作”的竞态测试。

- **P1｜`PLANNER.md:72–77、142、167(b)(d)`：取消与失效只覆盖单调用方结果，没有定义共享请求晚到时的缓存竞争。** 所有调用方都取消后，底层请求仍可能完成并写入缓存；账号不一致清缓存后，先前的 A 请求也可能晚到并重新缓存 A。建议使用 epoch/generation 校验，只有请求完成时 generation 未变化且仍有有效消费者才可写缓存；补测“全部消费者取消后完成”和“失效后旧请求晚于 B 请求完成”两种交错。

- **P1｜`PLANNER.md:80–89、168`：轻量会话读取复用 `identitySql.read/customRead`，但未规定与 W0030 身份投影隔离的去重 key。** 两种 SQL 的参数可能相同、返回列却不同；若 key 相撞，并发时会话读取可能拿到缺少 `updated_at/evidence_ids` 的身份读取结果，无法保持深相等。建议明确 key 必须包含读取用途、投影版本和查询参数，并新增 `readAccountSessionIdentity` 与 `readAccountSessionView` 同时读取相同 identity 的交叉并发测试，同时验证各自计量与写入驱逐。

- **P1｜`PLANNER.md:141、166、175、179`：生产构建隔离和清理步骤还不足以证明不影响 3001。** 方案没有明确构建和 `next start` 两端都传同一个 `ORBIT_NEXT_DIST_DIR`，也没有要求启动前探测端口、记录本次 PID、仅终止该 PID；“两个构建目录”又与步骤中复用单个 `.next-w0031-prod` 不一致。建议基线和改后使用两个唯一 distDir，显式写出 build/start 命令与端口参数，启动前验证端口空闲并记录 PID，结束后先确认 PID 退出再删除对应目录，最后探测 3001 的原 PID/健康状态保持不变。

- **P2｜`PLANNER.md:166`：60 秒内 `≤4` 次的判定存在计时边界歧义。** 若采样包含进入场景的立即读取以及第 60 秒边界 tick，正确的 15 秒轮询也可能记录为 5 次；“另允许打开面板或切页签多 1 次”也无法区分启动请求与稳态请求。建议分别记录启动阶段和稳态阶段，待首轮完成后从明确的半开区间开始计时，或按请求时间戳验证相邻稳态周期不少于 15 秒。

- **P2｜`PLANNER.md:167(f)`：要求“现有客户端测试断言不改”与本 Sprint 主动减少请求次数冲突。** 现有测试若断言旧调用次数，本应随批准的新语义更新；禁止修改断言可能迫使实现迁就旧行为。建议改为“非身份请求、可见状态及错误语义的既有断言保持；旧 `/api/account/me` 次数断言按新契约更新，并由新增 RED 覆盖”。

- **P2｜`PLANNER.md:104–115、169`：流量重算没有要求区分请求数、账号解析次数与会话读取次数。** in-flight 去重只在同一进程内生效，生产请求还可能跨实例；直接用浏览器请求频次乘单次 SQL 字节，可能把实际数据库执行次数估高或估低。建议月表同时列客户端请求数、逻辑读取次数、实测 SQL 执行次数，并给出“单实例实测”和“跨实例不去重上限”；明确 MB/GB 使用十进制还是二进制口径。
