# Sprint W0055 — 大目标 4「人脉真分析」收口

## 要实现什么

W0043～W0054 全部合并回 `chat-agent` 后，补上老联系人的限流回填脚本（补全 → 强度 → 洞察 → 快照，只在本机验证，生产执行另行授权），确认网页端不再使用关键词版人脉需求匹配，清掉已经没有页面引用的旧组件和「所有人脉」里点不动的假筛选；再用一次全量对照、两条真实路径截图和一份读取总账，证明大目标 4 的三项成功标准成立。

## 做完能看到什么

- 回填脚本默认只预演（列出每个阶段会改多少条、会调几次 AI），加 `--apply` 才写；在本机对 50+ 联系人的验收账号跑一遍后，结构、机会、洞察三标签都有内容；再跑一次没有任何写入、没有任何 AI 调用；用户自己改过的补全值不被覆盖。
- 网页端没有任何页面或客户端代码调用 `/api/contacts/needs-matches`，但这个接口和 `features/contact-needs` 原样保留给手机 App；`orbit-crm-sidebar.tsx` 等旧组件删除后，全库 0 引用、类型检查通过；「所有人脉」页只剩真正能用的筛选。
- 3001 验收环境两条路径（桌面 1440、手机 375 各截图）：新用户经真实的名片确认或 CSV 导入加入至少 5 位联系人 → 设目标 → 生成计划 → 等后台任务跑完 → 人脉三标签有针对目标、带依据的内容；老用户 50+ 联系人且有跟进记录 → 管线按档位分组、三标签与洞察有内容、详情时间线有来源。大目标 4 新增的数据库读取汇总进 D39 的 1.6 GB 总账。
- 本轮不改手机 App：写一份 Bridge 交接记录，说明 Web 版本、对 App 的影响（新增的可选字段、App 契约副本需要同步）和没有验证的范围，交给 App 线。

## 怎么验收

看证据目录里的全量对照清单（大目标 4 开工 SHA 与合并后 HEAD 对称运行，新增失败为 0）、GitNexus 变更对照、`rg` 引用扫描、回填脚本预演与两次本机执行的输出、两条路径的截图与网络记录、读取总账表与 AI 调用次数／token 汇总。回填脚本不在生产执行；发现行为或数据问题另开 Sprint，本 Sprint 记 blocked 或 failed，不降低验收条件。
