# Sprint W0053 — 从 CSV、vCard 和参加过的活动导入人脉，去重合并要你确认

## 要实现什么

「导入人脉」页（`/app/contacts/new`）现在只有扫名片能用，CSV、通讯录、活动三种方式都写着「即将开放」，还挂着一句没有实现的「最多 10,000 条记录」。本 Sprint 把它们接通：

- **上传 CSV：**直接认 LinkedIn「Connections.csv」导出格式（自动跳过开头的说明行），其他表格按表头自动对应姓名、公司、职位、邮箱、电话、地址，用户可改对应关系。
- **导入通讯录：**上传从 iPhone／Google 通讯录导出的 vCard（.vcf）文件，走同一个导入器。
- **从活动添加：**列出你参加过、并在现场互相交换过联系方式的活动，把这些人补进人脉并记上「在该活动认识」。

每批导入先出一张核对表：新联系人、和已有联系人可能重复的、文件里自己重复的分开列出。**合并到已有联系人必须由你确认**（完全一致的会预先选好「合并」，但仍要你点确认）。确认后联系人走一遍 W0048a 的三层更新（AI 补全计入后台池，用完显示「补全明天继续」）：补全 → 规则匹配进计划的「待确认」→ 新增人数达到阈值时重算人脉分析。**导入不会自动改你的计划。**

## 为什么要做

老用户的人脉大多在 LinkedIn 和手机通讯录里，靠一张张扫名片进不来；人脉分析（大目标 4）没有足够的人就给不出判断。成熟产品（HubSpot、LinkedIn、Apollo）的导入都是「上传 → 字段对应 → 去重核对 → 导入」四步。

## 做完能看到什么

- 选「上传 CSV」或「导入通讯录」能选文件，看到识别出的格式、字段对应、行数和无法读取的行；确认后进入核对表。
- 核对表里每条可能重复的都显示命中原因（同邮箱、同电话、同姓名加公司）和两边的字段，可选「合并」「仍然新建」「跳过」；有「全部按建议处理」按钮。
- 导入完成后，导入记录里有这一批的来源、文件名、新建数和合并数；联系人列表里能按来源筛到它们。
- 页面上不再出现「10,000 条」「支持 .xlsx」这类没实现的说明，改为真实的上限。

## 怎么验收

- 测试：LinkedIn 样例、带 BOM 或日文编码的 CSV、多张卡的 vCard 都能正确解析；同一文件导入两次不产生重复联系人；没有用户确认不合并；导入前后计划条目逐项不变，只多出「待确认」候选；他人的数据不可见。
- 实测：按 D39 口径量一批导入（核对表与确认）的数据库读取字节，写进预算表。
- 真实页面：三种导入方式在桌面 1440、手机 375 各走一遍；H 档收口跑一次全量对照和一次代码 review。
