# Sprint W0037 — 今日要事的活动小模组与已报名栏

## 要实现什么

用户打开 iOrbit 首页，在「今日要事」下方能看到为自己挑的活动：今天没有要处理的事时，展开社群卡和两场推荐活动；今天有事时，缩成一行「本周还有 N 场适合你的活动 →」。底部「已报名活动」栏只放真正报名了的活动。示例首页同样有这个小模组，里面的活动和社群是真实数据。

## 做完能看到什么

- 今日要事为空时，展开三张卡：社群卡在最前（微信号、点「看二维码」才展开、「我已加入」）；下面两场活动，每张写日期和星期、标题、地点和推荐理由（没有真实费用数据，不显示费用行），点卡进活动详情，没有一键报名。已经加入社群的人看到三场活动。点「我已加入」后社群卡立刻收起，换成第三场活动；保存失败时社群卡回来并提示。
- 今日要事有内容时，只有一行「本周还有 N 场适合你的活动 →」（东京周一至周日，N=0 时不显示），点它去活动页。
- 推荐理由只写真实来源：「计划里提到」「匹配你目标里的『X』」「近期活动」。活动标题跟随界面语言（日文界面用英文），地点按来源原文显示。
- 「已报名活动」栏只列已报名的活动；没有报名时只写「还没有报名活动」。社群行、引导第 4 步那行和「看看推荐」链接都不再出现。
- 示例首页的小模组固定展开，用真实活动（W0036 已读入）和真实社群状态，可以真实点「我已加入」。其余示例数据不变；除示例判定本来就有的那次首页数据读取（不交给示例壳）外，只多读活动和社群两样。

## 怎么验收

- 组件测试覆盖：展开和收起的判定、卡片字段与推荐理由、「我已加入」的乐观更新和失败回滚、已报名栏的新内容。
- 页面测试计数示例期的真实读取：示例判定原有的首页复合读取 1 次（不交给示例壳）、活动目录与本人报名（W0036 已放开）各 1 次，本 Sprint 只新增社群状态 1 次，其余仍是 0 次；社群读取的流量并入 W0036 的统一月预算表。
- 按钮 ratchet、字号间距 ratchet 和 typecheck 都通过。在 3001 验收环境用桌面 1440 和手机 375 各看一次空态和有事两种情况。档位 H：一次全量对照基线和一次 Codex 代码 review。
