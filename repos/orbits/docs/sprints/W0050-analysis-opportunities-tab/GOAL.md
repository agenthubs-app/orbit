# Sprint W0050 — 「机会」标签：规则覆盖度、缺口补法、计划直链、待唤醒、报告卡

## 要实现什么

有计划的用户打开人脉分析的「机会」标签，看到按计划人脉需求用规则算出的目标覆盖度、每条没满足的需求可以去哪场活动或找哪位现有联系人补、本周该做的事（直链计划）、与目标相关的待唤醒关系，以及人脉分析快照的报告卡和每天最多 3 次的重新分析入口。

## 做完能看到什么

- 覆盖度 =「已确认关联人数 ÷ 计划人脉需求总人数」，每条需求显示「已有 a／还缺 b」；数字只由规则算，AI 不出分数。没有计划时这一块换成去生成计划的入口，其余照常。
- 每条没满足的需求下面列出活动池里可能遇到这类人的活动（带真实的匹配理由）和「待确认 N」的现有联系人，点开就是计划页同一个确认组件；本周建议动作就是计划本周行动加待确认匹配，点了跳到计划里对应的那一行。
- 待唤醒只列曾有往来、60 天没有记录、且和目标相关的人，附「为什么现在联系」与「起草邮件」（模板草稿，不发送）；底部报告卡写「生成于 X · 基于 N 人 · 新增 M 人未纳入」，可重新分析（每天最多 3 次），自动更新次数用完显示「明天更新」。

## 怎么验收

定向测试证明覆盖度是规则值且不受快照影响、无计划时的入口、缺口补法只来自活动池与计划匹配器（不再碰关键词版 `contact-needs`）、为现有联系人补候选不调用 AI、待唤醒的筛选条件、报告卡各状态与重新分析的次数限制、示例模式 0 次读取。真实页面在 1440／375 各截一次并查控制台；新增读取实测字节并按 D39 总账估算。
