# Sprint W0033 — 通知「查看来源」页打不开的修复

## 要实现什么

收件箱里有一类通知是 Orbit 从用户自己的笔记里发现的提醒或建议（discovery 来源）。点这类通知的「查看来源」，会打开 `/app/inbox/sources/<通知编号>`，本应显示原始笔记内容。现在这个页面总是显示「来源已变化或暂不可用」。

原因是通知编号被编码了两次。通知编号形如 `inbox:93610992…`，生成链接时冒号被编码成 `%3A`，这一步是对的。但 Next.js 交给页面的编号仍保持编码形式（`inbox%3A…`），页面去请求通知详情前又编码了一次，请求就变成了 `inbox%253A…`，服务器找不到，返回 404。改前的生产构建和 3001 验收 server 都是这样（W0031 观察项 2）。

本 Sprint 让页面先把编号还原一次，再按正常方式请求。做法与站内已有的任务详情页（`/app/tasks/[id]`）一致。

## 做完能看到什么

- 在收件箱通知详情里点「查看来源」，页面显示原始笔记的标题和正文（或原文摘录），不再报「来源不可用」。
- 通知编号里有冒号、斜杠、空格、中文或百分号时，请求到服务器的都是正确的编号，只编码一次。
- 安全边界不变：服务器仍只返回当前登录账号自己的通知，别人的通知编号照样 404；页面照旧核对返回的通知属于当前账号、笔记版本与通知记录一致；奇怪的编号（如 `..`、残缺的 `%`）不会让请求跑到别的接口上。

## 怎么验收

- **单元测试**：从生成链接到页面拿到编号、还原、再请求详情，整条链路用多种编号来回验证，每次还原后都等于原编号，请求路径只编码一次，且始终落在 `/api/inbox/notifications/` 下面。现有的链接生成与来源核对测试不改、照常通过。
- **真实页面**：在 3001 验收 server 上给验收账号造一条来源于笔记的 discovery 通知，从收件箱点「查看来源」和直接输入链接各打开一次，桌面和手机各看一次，页面显示笔记内容，控制台无错误，网络请求里是 `inbox%3A…` 而不是 `inbox%253A…`。验收完把验收账号恢复原状。

这是一个小范围修复（L 档），与 W0032 没有代码依赖，可以先做或并行做。
