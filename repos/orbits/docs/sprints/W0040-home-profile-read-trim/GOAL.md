# Sprint W0040 — 首页不再顺带读取「资料更新建议」

## 要实现什么

每次打开 iOrbit 首页 `/app/agent`，服务端都会为账户卡读一次个人资料。读资料用的是资料页同一套组合函数，它顺带计算「资料更新建议」，而这一步会把**整个 workspace**（生产只有一个，所有用户共用）的资料、联系人、关系、互动记忆和证据全部整行读回来，再在 Node 里挑出本人的部分。首页根本不显示这些建议。

本 Sprint 让首页（以及共用同一读取的 `/app/home/events` 和示例期判定）读资料时**跳过更新建议**，只读本人资料和账户。账户卡、示例判定、出错时的页面都和现在一样；资料页和 App 端的「更新建议」完全不动。

## 为什么要做

- 本机实测：首页一次服务端渲染读 9.59 MB，其中 99.4%（约 9.53 MB）来自这一步（调查报告 `~/orbit-sprint-evidence/web/investigation-home-db-read/REPORT.md`）。
- 生产按只读行数和本机行宽估算：现在每次打开首页约 276 KB；因为是全 workspace 扫描，单次成本随所有用户的数据总量增长，而不是只随本人增长。按「每人贡献相同」的假设粗算，十几位活跃用户就可能超过 D39 的 1.6 GB 上限（`PRODUCTION-COUNTS.md`；这是敏感度估算，不是实测）。

## 做完能看到什么

- 打开首页（真实期、示例期、开关关闭三种情况）时，数据库里不再出现对资料、联系人、关系、互动记忆、证据五个集合的整 workspace 读取；其他用户的数据再多，首页这部分读取量也不变。
- 首页账户卡（名字、头衔、目标等）和读不到资料时的出错页与现在一致；示例期仍按「有没有关系目标」判定。
- 资料页 `/app/profile`、管理台、`/api/profile/update-suggestions`（App 端资料建议页在用）照旧计算更新建议，结果不变。

## 怎么验收

- 测试：首页路径调用更新建议 0 次；资料页路径仍调用 1 次且结果字段不变；账户卡与各类失败页改前改后逐项相等；示例期／开关关闭的读取次数测试照旧通过。
- 实测：本机按 W0017 口径（每条语句返回行的 JSON 字节）量首页一次服务端渲染改前改后的字节与语句数；在测试库里给其他账号加噪声数据，首页字节不变。
- REPORT 重算数据库月流量预算表（D39 上限 1.6 GB），把以前没进账的首页服务端复合读取补进去，超出如实登记。
- 真实页面看一次账户卡（桌面 1440、手机 375）；H 档收口跑一次全量对照和一次 Codex 代码 review。
