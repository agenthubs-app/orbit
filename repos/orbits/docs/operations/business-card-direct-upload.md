# 名片大文件上传：问题与实现约束

状态：线上问题已复现，直传尚未实现。此文档用于约束接下来的实现与验收，不代表上传问题已修复。

## 已取得的证据

2026-09-07 在部署 `orbit-4uzy83c1n-liqys-projects-33c8ddec.vercel.app`，使用既有隔离 QA 账户上传合成 JPEG：原文件 6,291,456 字节，multipart 请求 6,291,667 字节，返回 413，响应包含 `FUNCTION_PAYLOAD_TOO_LARGE`，未创建批次。记录 `/tmp/orbit-large-upload-probe.log`；探针 `/tmp/orbit-large-upload-probe.cjs` 不打印账号凭证或配置密钥。

现有 V1 将全部图片或 PDF 放进一个 FormData 请求，图片上限 10 MiB、PDF 上限 50 MiB、批次上限 500 张；V2 按单项 PUT 上传，原图上限 10 MiB、批次上限 100 张。两条通路仍受函数入口限制，即使单个文件不大，多张图片的总请求也可能超限。

[Vercel 函数限制](https://vercel.com/docs/functions/limitations)规定请求体上限 4.5 MB；[Blob 客户端上传](https://vercel.com/docs/vercel-blob/client-upload)允许浏览器直接传文件到私有 Blob，由服务端授权单次上传。项目已安装的 `@vercel/blob` 类型声明支持 private upload、路径授权、maximumSizeInBytes、validUntil、allowOverwrite 和签名完成回调。无需读取或导出已部署的 Blob 配置密钥。

## 保持的产品范围

- 保留 V1 多图、50 MiB PDF 和现有每页一张名片的解析流程；不能只修 V2 或把 PDF 功能删除。
- 保留 V2 manifest、单项上传/替换、摘要匹配与续传，不改变 10 MiB 原图上限来绕开平台限制。
- 文件字节不再经过浏览器到应用函数的大请求体。应用接口只处理有明确数量和大小限制的上传元数据与文件标识。
- 保留本机开发路径；旧 API 的小文件兼容不能被当作大文件功能完成。

## 原始上传的持久化边界

原文件与供识别/复核使用的 JPEG 衍生图必须分开管理。原图或 PDF 在转换前也可能遇到断网、取消、函数重启，不能成为无记录的对象。

1. 服务端先创建上传记录，再签发有期限的上传许可。记录包含工作区、actor、服务器生成的对象路径、预期 MIME/字节数/摘要、目标通路、过期时间和处理状态。对象路径不得直接使用客户端提供的 URL 或文件名。
2. 令牌生成入口逐次校验当前会话、上传记录归属、路径和状态，限制大小与内容类型并禁止覆盖。完成回调必须通过 SDK 签名验证；回调不依赖浏览器登录 Cookie，也不能独自作为业务写入成功的依据。
3. 消费原文件时，从记录中的私有对象路径读取，按实际流量限制字节数，验证摘要和解码结果。不可根据客户端声称的大小直接无限读取，也不可接受任意远端 URL。
4. 消费需要持久化租约。目标批次/项目写入与上传记录的消费回执必须在同一事务中完成，或使用可证明等价的幂等目标标识；不能先创建批次再在另一个事务标记 consumed，否则超时重试会创建重复批次。
5. V1 的 PDF 解析和大批量转换需要验证函数执行时间与内存，而非只证明传输突破 4.5 MB。若必须移到后台，需持久化分页/项目进度、失败重试和取消，不用一个无进度的长请求替代。

## 删除与许可重放

不能在原文件消费后立即删除对象、却让同一路径的上传令牌继续有效：对象删除后，旧令牌可能重新上传并留下孤立文件。清理时间必须晚于该记录所有已签发许可的最大有效期及明确的时钟余量，或者采用经过验证的等价重放防护。

清理先提交不可再消费的 deleting 状态，再执行物理删除，最后写删除回执；崩溃后可重复删除。尚未完成上传的记录也要到期回收。待办判定、延迟唤醒及独立扫描应覆盖原文件，OCR 不可用不能阻止清理。原文件处理成功与衍生图回收记录的存在不能相互替代。

## 验收必须覆盖

- 真实 Preview：超过 4.5 MB 且不超过 10 MiB 的图片、超过 4.5 MB 的合法 PDF、多张图片合计超过 4.5 MB，均可进入正确批次/项目；随后取消并核对清理状态。
- 10 MiB 图片与 50 MiB PDF 的边界；超出应用限制时在上传授权前拒绝；实际对象大于声明时仍拒绝消费。
- 匿名、其他 actor、其他工作区、伪造路径/回调、过期许可、取消后的消费与重复提交。
- 上传成功后浏览器中断、转换失败、消费事务回滚、写入后响应丢失、删除后状态回写前重启。
- PDF 和批量转换的资源限制、部分进度及恢复；V2 替换/续传；本机小文件兼容。
- 浏览器成功、失败、进度、重试和重新选择文件的实际操作；不能用一次小图片 API 成功代替这些证据。

现有阻塞条件仍独立存在：Vercel 浏览器登录、有效 SMTP、真实模型/OCR、独立调度和目标用户试用。直传完成也不代表这些验收完成。
