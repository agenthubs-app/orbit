# Web Tasks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让网页用户通过现有 API 管理与 App 相同的待办。

**Architecture:** Today 增加独立加载的摘要，列表与详情使用页面内客户端适配层。服务端页面执行登录门禁；presenter 只接收页面 view model 与操作回调。

**Tech Stack:** 现有 Next.js 16 / React 18 / TypeScript / Node test / react-test-renderer / Playwright，不添加依赖。

**Spec:** `docs/superpowers/specs/2026-09-07-web-tasks-design.md`

## Global Constraints

- 只编辑 Web 目录，版本基线为外层仓库 `chat-agent` 分支。
- 复用已有 HTTP API，不改共享契约、数据库结构或业务服务。
- 不部署、不推送。
- Web 提醒仅用已有 `in_app` 渠道。
- 先运行预期失败测试；修改已有符号前 GitNexus impact；提交前 detect_changes。

### Task 1: API adapter and view models

**Files:** Create `app/(app)/app/tasks/tasks-client.ts`, `tasks-view-model.ts`; test `tests/pages/web-tasks-client.test.ts`.

**Interfaces:** `createTasksClient(fetcher?: typeof fetch)` produces loadList(status), loadToday(), loadTask(id), loadActivities(id), loadReminders(id), loadSuggestions(), create(title), update(task, title, notes), setCompleted(id, completed), remove(id), resolveSuggestion(id, action), addReminder(task, fireAt), cancelReminder(id). View models contain UI-ready identifiers, text, status and editable fields; raw DTOs stay in the adapter.

- [x] RED: assert client POST creates a task through real collection handler + in-memory TaskService; assert UTF-8/encoded ID reads, status mutations, conflict and malformed payload rejection.

```ts
const task = await client.create("准备访谈提纲");
assert.equal(task.title, "准备访谈提纲");
await client.setCompleted(task.id, true);
assert.equal((await client.loadList("completed"))[0].id, task.id);
```

- [x] GREEN: implement same-origin request boundary, envelope validation and typed mappers. Distinct mutations use fresh idempotency keys; uncertain retries within the mounted client reuse their key. Edits retain the draft baseline updatedAt. Inputs are trimmed; clearing existing notes reports the API limitation explicitly.
- [x] Verify handler integration plus invalid, unauthorized, failure and request-construction cases.

### Task 2: List and detail product pages

**Files:** Create `tasks/page.tsx`, `tasks/[id]/page.tsx`, `tasks-page-content.tsx`, `tasks-workspace.tsx`, `task-detail-workspace.tsx`, `tasks-styles.tsx`; test `tests/pages/web-tasks-workspace.test.tsx`.

**Interfaces:** `TasksWorkspace({initialStatus?})`, `TaskDetailWorkspace({taskId})` consume TaskClient. `TasksPageContent` wraps the chosen workspace with AccountTopNav, shared stylesheet and scoped task styles. Route pages authenticate before rendering content.

- [x] RED: mount real React components with the HTTP boundary stubbed; create/edit/complete/reopen/delete and failure states must change rendered content or visible errors.

```ts
await act(async () => root.root.findByProps({"aria-label": "待办标题"}).props.onChange({target: {value: "准备会面"}}));
assert.ok(root.toJSON()); // subsequent assertions check exact input retention and resulting task rows
```

- [x] GREEN: implement list segmented controls, inline creation/search and suggestion actions; detail editor, status mutation, confirmation, reminders and history. Preserve drafts on failures, ignore stale reads, show refresh errors separately from successful writes.
- [x] Verify direct detail links, language-aware navigation, loading/empty/error rendering and native keyboard-accessible controls. Browser verification covers Chinese; English copy uses the existing language context, not a separate browser acceptance run.
