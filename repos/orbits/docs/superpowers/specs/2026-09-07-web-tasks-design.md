# Web 待办接入

## 决策与范围

用户要求补网页端接入，并明确委托代理按照现有布局自行决定实现方案，不再逐项确认。
选择「今天摘要 + 独立待办列表/详情」：已有行动流、日历和关系安排保留；不把待办混成决策账本，也不替换 Today 的现有聚合器。单独列表便于查看完成历史，详情 URL 可以跨端定位同一个 task ID。

只编辑 Web 目录，版本基线为外层仓库 `chat-agent` 分支。内层旧 Git 基线及 App 的进行中改动不纳入提交。复用已有 HTTP API，不改共享契约、数据库结构或业务服务。不部署、不推送。

## 产品与视觉

- `/app/today` 右侧行动区增加紧凑「待办」摘要、快捷新增、完成操作和「全部待办」链接；使用 `/api/today?timeZone=Asia%2FTokyo` 的任务/建议，不改变日历筛选或原有三源数据。
- `/app/tasks` 提供待办/已完成切换、新增、标题搜索、完成/恢复、待办建议接受/忽略。
- `/app/tasks/[id]` 提供标题/备注编辑与明确保存、完成/恢复、确认删除、安排信息、站内提醒设置/取消、变更历史。安排日期和分类本轮仅显示，保持 App 的现有编辑范围。备注清空若 API 不支持，必须明确提示，不能假装保存成功。
- 用户在 Web 创建/修改的记录仍由相同账号和 task ID 标识；跨端刷新后重新读取。承诺显式刷新，不新增实时同步系统。
- 沿用 AccountTopNav 的 Today 归属、1180px 页面边界和现有字体。使用现有 CSS 变量：白色背景 `#ffffff`、次级表面 `#f7f8f8`、正文 `#171a1c`、次级文字 `#687078`、边框 `#e6e9eb`、强调色 `#176a73`。不引入新字体、插画、渐变或全局样式重构；深浅主题由现有变量控制。
- 列表为对齐的复选框、标题、日期行；操作只用现有按钮样式。窄屏自然换行，无横向滚动。键盘可达、可见焦点、字段有标签，反馈区使用 status/alert。
- 界面中文/英文跟随现有语言上下文；日文按项目约定回退英文。

## 边界与状态

页面入口要求登录。客户端适配层负责调用 `/api/tasks`、`/api/tasks/:id`、`/api/tasks/:id/activities`、`/api/task-suggestions`、`/api/reminders`，解析 envelope 和页面数据，组件只消费页面 view model。

读取使用 no-store；写操作携带幂等键，编辑带 expectedUpdatedAt。网络失败、401、404、版本冲突、无效数据均有可见提示。等待期间阻止重复提交；失败保留输入；切换记录/筛选后旧请求不得覆盖新数据；提醒或历史失败不阻止任务主体读取。写成功后的刷新失败明确区分于写失败。

Web 提醒仅用已有 `in_app` 渠道，不申请不存在的 Web Push 能力。已由 App 创建的提醒可读取/取消，新增提醒不暗示 iOS 推送已开通。

提醒保存 App 使用的 `/tasks/:id` deep link，Web 收件箱/首页的提醒 view-model 将其转换为 `/app/tasks/:id`；保留原 `/app/` 链接和旧承诺工作流 fallback，不改 App 路由约定。

详情编辑保存独立的基线版本：无草稿时刷新更新输入；有草稿时保留旧版本，发现新版后明确提示复制内容并选择「放弃草稿并载入最新内容」，不能静默覆盖 App 修改。成功写入使进行中的旧读取失效。幂等重试保证限定在当前挂载页面内；离开/重载页面不会持久化未确认操作。未确认的一小时提醒若已过期，提示返回列表后重新打开待办再设置。

## 验收

1. 新增任务在列表和详情可见，完成后移到已完成，恢复后回到待办；删除需要二次确认。
2. 同一服务的真实 handler + 内存 repository 测试覆盖 Web 请求与现有 API 的兼容性，任务 ID/actor 隔离不能改变。
3. 新增失败、保存冲突、失效记录、部分读取失败保持可操作且明确反馈。
4. Today 仍保留原有日历/决策/安排及其降级方式；待办加载失败独立处理。
5. 渲染与交互测试覆盖主流程，桌面/窄屏浏览器检查布局；类型检查、相关已有回归必须通过。
6. 实际账号的双端写入与通知送达若未实测，交接中标为未验证，不将夹具测试当作线上同步验收。

## 自检

方案未增加后端接口或 App 改动；提醒能力明确限定为站内；没有将 Today 账本条目混为 canonical task。设计由本次明确授权自行决定，随实现验证后交付。
