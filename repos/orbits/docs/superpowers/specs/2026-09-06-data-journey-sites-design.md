# Orbit 数据格式说明站

版本：v1，2026-09-06。方向已确认，本文待书面复核。

## 目标与范围

面向需要理解 Orbit 数据结构的产品与开发成员，用一个虚构联系人解释数据如何从存储
变成业务响应，再变成 Web 和 iOS 页面。站点为中文、默认私有，不连接真实数据库，
不包含真实联系人、账号、密钥或连接地址。不改 Orbit 产品界面。

## 页面与交互

单页，标题为「Orbit 数据格式」。第一屏直接展示数据流程和联系人示例，不设营销首页。
正文依次为：

1. 数据旅程：数据库记录、业务契约、客户端显示三个视图，可切换 JSON 节选与对应字段解释。
   同一个虚构联系人使用稳定的演示 ID；示例必须注明是节选，不伪装成可直接提交的完整请求。
2. 两条客户端路径：Web 的服务端页面可直接调用 feature service；iOS 经 HTTP API。
   图示保留分支，不把所有 Web 请求画成必须经过 HTTP。
3. 响应状态：成功、部分数据不可用、失败三个示例。普通 API envelope 与
   mobile contacts/dashboard 的版本化聚合 Schema 分开说明，不混成一套通用响应。
4. 字段词典：身份与归属、来源与证据、行业与语言、各领域状态。明确 recordId、actorId、
   eventId 等身份不可互换；任务、提醒、联系人和数据库生命周期不是同一个 status 枚举。
5. 当前边界：共享契约是响应形状，不等于数据库表或页面模型。活动核心使用独立关系表；
   并非所有数据都在 orbit_records。编译期一致性不等于所有接口都已做运行时 Schema 校验。

不加入登录系统、编辑器、搜索后台、持久化、上传、外部数据源或生产写入能力。

## 视觉与实现

使用清晰的流程图、并排字段对照、可读 JSON 和紧凑分区。白色背景、深色正文，蓝色与
绿色区分数据层级；不使用渐变装饰、浮动卡片堆叠或与数据无关的图片。功能性流程图承担
主要视觉表达。桌面并排比较，手机按顺序堆叠；长字段名与代码不撑破页面。

独立 Sites 项目，不在 Orbit 应用中引入站点依赖。内容来自当前源码核对，静态内置；
不把私有源码全文上传，只保留必要字段名、演示片段和来源模块说明。只有站点负责代理
创建、编辑、预览和发布该项目。默认私有发布，不开放公共索引。

## 验收

- 三个数据层视图和三个响应状态均可切换，键盘与触屏可操作。
- 示例 ID 在各层对应一致，展示字段能追溯到当前正式类型。
- Web/iOS 分支、独立活动表、运行时校验覆盖范围表述准确。
- 示例不含真实数据或凭据；所有可见内容为中文，源码标识符保留原文。
- 相关数据映射与展示状态有定向测试，生产构建通过。
- 首个可识别版本提供本地预览，完成后交付私有 Sites 链接。
- 本轮未请求浏览器自动化验收，不自行执行截图或 DOM 检查。

## 与字典修复的关系

行业和语言运行时字典将移到 shared/domain，移动端仅同步这两个白名单文件。
站点按修复后的边界讲解；不扩展到其他业务模块，也不宣称剩余运行时回归已全部解决。
