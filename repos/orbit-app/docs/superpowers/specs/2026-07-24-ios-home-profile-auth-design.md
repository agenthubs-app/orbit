# iOS 首页、个人名片与登录迁移设计

## 状态

已于 2026-07-24 经用户确认。

## 目标

在不重做 iOS App 整体视觉的前提下完成三项改进：

1. 首页 Orbit AI 卡片底部的人脉工作台在所有支持的 iPhone 宽度下保持一行。
2. 个人资料页顶部强化为一张可识别、可交换的 Orbit 个人名片，其余资料区保持现有轻量结构。
3. 把 Web 已有的邮箱注册、邮箱登录和 Google 登录迁移到 iOS，并让两端共用同一用户与会话体系。

## 范围

- `HomeScreen` 中的人脉工作台布局与对应布局 view model。
- `ProfileScreen` 顶部个人名片及其纯展示 view model。
- iOS 登录、注册、找回密码、账号状态和退出入口。
- iOS Google 系统浏览器授权与 App 回跳。
- iOS 会话安全存储、启动恢复、服务端验证和失效清理。
- 与 Web 移动登录桥接约定的客户端实现。
- 相关单元测试、类型检查、文档和人工视觉验收。

## 非目标

- 不重做 iOS 全部页面。
- 不把 Web 的完整双栏资料编辑器照搬到手机。
- 不在这次实现资料编辑、资料保存或密码重置后端。
- 不给整个 App 增加强制登录墙；公开活动和无需身份的内容仍可浏览。
- 不接入原生 Google SDK，也不维护第二套 Google 用户体系。
- 不改变 Web 现有登录页的正常访问和行为。

## 设计方向

Orbit 面向参加活动、维护人脉和交换资源的用户。首页的单一任务是让用户快速判断今天要准备什么、联系谁；个人资料页的单一任务是让用户看清别人会如何认识自己。

现有白色页面、紫色操作色和 iOS 系统字体保持不变。视觉上的唯一重点放在个人名片：

| 角色 | 色值 |
| --- | --- |
| 页面背景 | `#F6F6F8` |
| 页面主表面 | `#FFFFFF` |
| 主文字 | `#16161A` |
| Orbit 操作色 | `#6359E9` |
| 名片底色 | `#17211F` |
| 名片辅助文字 | `rgba(255,255,255,0.68)` |

字体继续使用 iOS 系统字体。姓名和关键数字使用 Display 权重，正文使用 Text 权重，标签与状态使用 Caption 权重。不会为这次改动引入新字体。

## 首页人脉工作台

### 当前问题

`PipelineRail` 允许换行，三个最小宽度卡片在窄屏中会形成 `2 + 1` 两行结构。它占据 Orbit AI 主卡片内的核心位置，却看起来像三张互不相关的小卡片。

### 目标结构

三项信息合并到一个横向工作台中：

```text
┌─────────────────────────────────┐
│  3 活动   │   18 人脉   │  4 在推进  │
│  准备复盘 │   可触达关系 │  今日优先  │
└─────────────────────────────────┘
```

- 外层是一张共享表面，内部三个单元固定等宽。
- 单元之间使用细分隔线，不再使用三块独立背景色。
- 每个单元 `minWidth: 0`，容器禁止换行。
- 数字保持最强层级，标签与短说明按可用宽度收紧。
- 320pt、375pt 和较宽屏都显示完整三项，不使用横向滚动。
- 语义和点击行为不变；本次只调整布局密度与层级。

view model 提供明确的单行布局意图，屏幕组件不根据数据内容猜测是否换行。

## 个人名片

### 目标结构

个人资料页保留当前 `AppScreen`、账号入口、简介、标签和关系目标。顶部普通资料卡替换为 `OrbitBusinessCard`：

```text
┌─────────────────────────────────┐
│  [头像]                         ✦ │
│  小雨                             │
│  Orbit 创始人，帮企业把 AI…       │
│  Orbit · 创始人 · AI 企业应用      │
│                                  │
│  能提供  [AI 落地] [日本资源] +3   │
│  想认识  [企业客户] [合作伙伴] +2  │
└─────────────────────────────────┘
```

卡片展示：

- 姓名首字头像和轻量 Orbit 标记；
- 姓名、一句话介绍、公司、职位、行业；
- “能提供”和“想认识”各最多两个标签；
- 超出部分使用 `+N`，不让卡片无限增高。

长姓名和长简介必须截断或限制行数；空字段直接省略，不显示占位假数据。名片使用深墨绿色固定表面，在明暗页面中都保持同一张实体名片的感觉。它是本页唯一强视觉元素，不加入动画、渐变依赖、完成度仪表或装饰性插画。

## iOS 登录体验

### 页面

- 登录页：邮箱、密码、显示/隐藏密码、忘记密码、邮箱登录、Google 登录、创建账号。
- 注册页：邮箱、密码、创建账号、Google 登录、返回登录。
- 找回密码页：沿用现有两步展示；在后端能力补齐前明确提示暂时不能发送，不伪造成功。
- 账号页：展示真实会话用户、登录状态、退出入口；未登录时展示登录与注册入口。

Google 按钮只在服务端已启用 Google provider 时可用。未启用时不显示不可操作的按钮，直接保留邮箱入口。

### 状态文案

| 状态 | 用户看到的文案 |
| --- | --- |
| 用户关闭 Google 授权页 | 已取消 Google 登录 |
| Google 未配置 | Google 登录暂时不可用，请使用邮箱登录 |
| state、PKCE 或回跳校验失败 | 这次登录已过期，请重新试一次 |
| 网络中断 | 网络连接失败，请检查后重试 |
| 保存的会话失效 | 登录已失效，请重新登录 |
| 注册成功 | 账号已创建，请用刚才的邮箱登录 |

界面不出现 PKCE、provider、token、cookie 或实现模式等内部术语。

## Google 登录客户端流程

采用已确认的 Web broker 方案：

1. App 生成随机 `state` 和 PKCE verifier/challenge。
2. App 使用 `WebBrowser.openAuthSessionAsync` 打开 Web 移动 Google 登录起点。
3. Web 使用现有 NextAuth Google provider 完成授权。
4. Web 回跳到固定的 `orbit://account/oauth`，只携带短时交换码和原始 `state`。
5. App 先比对 `state`，再把交换码与 verifier 通过 HTTPS 发送给 Web。
6. Web 原子消费交换码并返回与 Auth.js 兼容的会话 cookie header。
7. App 保存会话，调用 Auth.js session 接口确认用户身份，然后进入原目标页面。

取消授权不创建错误堆栈，也不改变已有会话。任何校验失败都不会保存部分会话。

## 会话存储与恢复

- 新会话存入 `expo-secure-store`，iOS 上对应 Keychain。
- 旧的 AsyncStorage 会话键只用于一次迁移读取；成功迁移后立即删除。
- 启动时先读取 Keychain，再调用服务端 session 接口验证。
- 只有服务端返回有效用户时 `signedIn` 才为 `true`。
- 会话无效、过期或无法解码时清除本地值。
- API client 继续通过统一认证 client 附带会话，屏幕不能直接拼接认证 header。
- 退出登录先请求服务端退出，再清除 Keychain；服务端不可达时向用户说明，不静默假装完成。

## 数据与组件边界

- `AuthSessionProvider` 负责会话生命周期，不负责渲染页面。
- 认证协议解析、cookie 合并、OAuth 回跳解析和 PKCE 校验输入保持纯函数，可在 Node 测试中运行。
- `AccountAuthScreen` 只管理表单、加载和提示状态。
- `ProfileScreen` 只消费 `ProfileSummary`，不读取 Web 代码或数据库。
- `HomeScreen` 只按 view model 的单行布局意图渲染工作台。
- 移动端只通过 HTTP API 使用 Web 登录能力，不导入 `repos/orbits` 源码。

## 错误处理

- Google 授权取消：留在当前页面，保留邮箱输入。
- 回跳 URL 不是固定 scheme/path：拒绝处理。
- `state` 不匹配：清空本次 OAuth 临时状态，不触碰旧会话。
- 交换码过期或重复使用：显示重新登录提示。
- SecureStore 写入失败：不把内存状态标记为已登录。
- session 验证失败：删除失效会话并回到未登录状态。
- API 返回非 JSON 或错误 envelope：沿用统一 API 错误边界。

## 测试与验收

自动化测试覆盖：

- 首页 view model 固定为单行工作台；
- 三个工作台单元都有稳定标签、数字和短说明；
- 个人名片字段映射、空字段、多标签和 `+N`；
- 邮箱注册、邮箱登录、Google 回跳解析、取消和失败；
- state 不一致、PKCE 错误、交换码过期与重复使用；
- SecureStore 恢复、旧存储迁移、无效会话清理和退出；
- 认证 API client 始终从 provider 获取会话。

验证命令：

- `npm test`
- `npm run typecheck`
- Expo 配置检查与 iOS 构建检查

视觉验收至少覆盖 320pt、375pt 和一台较宽 iPhone。真实 Google 账号授权若无法自动化，必须列为人工验收项，不能用本地假成功替代。

## 成功标准

- 首页三项人脉工作台在支持的 iPhone 宽度下始终是一行。
- 个人资料页第一眼能识别为 Orbit 个人名片，其他区域仍保持克制。
- 用户可以在 iOS 用邮箱注册、邮箱登录、Google 登录和退出。
- Web 与 iOS 使用同一用户记录，Google 登录后 App 能获得真实有效会话。
- 敏感会话不再保存到 AsyncStorage。
- 失败、取消、过期和重复交换都可见且不会留下半登录状态。
