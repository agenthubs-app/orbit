# 联系人备注

联系人详情中的「联系人备注」仅属于当前账号，不发送给联系人、不创建任务，也不请求 AI。此区默认收起；展开后可查看全部私人备注并新增，收起不丢未保存输入。标签、行业、关系状态和最近互动仍使用原来的独立入口。

## API 与显示

- 复用 `PATCH /api/contacts/[id]`，只提交 `note: { body, authorLabel: "我" }`；正文仅去首尾空白，换行与用户术语保留。
- 服务端响应的 `privacy: private` 决定哪些记录属于联系人备注。共享或未声明隐私的来源记录不在客户端擅自改为私有，也不被此区重写。
- `src/api/schema/contact-notes.ts` 由 Web 的共享 Schema 同步，不手工维护。响应缺失、联系人不符或字段非法会显示读取/确认错误，不冒充空列表。旧时间字符串可按原文显示。
- 提交中锁定输入和保存按钮；失败保留草稿。只有私密标识、联系人、正文与作者匹配的成功回执才清空输入。已确认记录按 note ID 去重并保留到刷新回读，避免旧响应吞掉新备注。
- 服务端按账号、联系人、作者、规范化正文去重；重试不会新增或改写原创建时间。再次提交完全相同正文也会返回原备注。

## 账号与读取边界

备注草稿、已确认记录和异步回执显式绑定 `actorId + contactId + client`。联系人详情是首个使用 `useApiResource` 可选 `scopeKey` 的页面：换账号先隐藏旧数据、重新按首次读取加载，并隔离不同账号的在途 GET 去重域。未传该选项的其他页面保持既有行为，此变更不代表全 App 资源缓存已经完成账号切换审计。

App 不访问数据库、不导入 Web feature 源码。Web 服务端私密持久化基于提交 `5f9b20825`，两端使用同一备注 Schema 和已有详情接口。无数据迁移或共享功能。

## 验证与交接

- `contact-notes-view-model.test.ts`：全量私有备注、原文、旧时间、未知数据及确认条件。
- `contact-notes-interactions.test.ts`：通过 React Native Web 运行真实详情页、真实 API client，覆盖窄屏触控、草稿折叠、失败重试、空提交与防连点、账号/联系人切换及迟到回执。
- `api-resource-scope.test.ts`：运行真实 hook 和 GET 去重，实现 A 刷新在途、切 B、B 独立回读、A 迟到不能污染 B；同时检查旧调用的刷新失败行为。
- API Schema、纯契约与 domain 副本检查分别验证，不扩大同步白名单。

浏览器测试只替换原生/认证/HTTP 测试边界；尚未做真实账号跨设备验收或 iOS 真机键盘验收。Web 的真实服务与隔离内存存储另测持久化和丢回执重试。Bridge 协调者可据此更新根交接台账；本客户端任务不写根台账，也不覆盖正在进行的样式调整。
