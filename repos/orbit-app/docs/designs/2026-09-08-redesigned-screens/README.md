## 收件箱邮件式修订与原生实现

用户批准上述方向后，要求名称改为「收件箱」，进一步去掉旧术语与难理解的操作，并授权直接设计、实现。本节取代前面关于收件箱「保留四项统计」的描述；联系人两页仍是静态设计稿。

- 新参考：[04-inbox-mail-revision.png](04-inbox-mail-revision.png)，851 × 1847px。邮件列表、搜索、消息/提醒页签与右上角写消息入口；不保留统计卡片或列表中的操作建议。
- 已落到 `src/screens/inbox/RelationshipInboxScreen.tsx` 和 `src/view-models/relationship-inbox.ts`，沿用现有 API、主题与原生导航。没有改联系人列表、联系人详情的实现。
- 写消息是独立编辑状态，正文和主题初始为空；预览显示收件人，可继续编辑。回复预览、润色、隐私入口保留。
- 接口目前只生成非持久化草稿预览。页面明确注明未保存/未发送；没有添加发送、归档、删除、星标等缺少后端支持的功能。
- 无正文/已识别的系统生成提示不会冒充收到的邮件。详情里会显示无正文记录数，可展开查看；真实中英日文往来保留原文，业务数据未删除。
- 提醒显示完整返回列表，空线索卡不再占位；忽略仅影响本次查看，并在页面中说明。
- 最终测试：817 passed、0 failed、0 skipped；TypeScript 通过。原生浅/深色、键盘、消息详情、提醒与触控尺寸已核对。独立审查发现的离线返回与预览收件人问题已补失败→通过回归并复核。
