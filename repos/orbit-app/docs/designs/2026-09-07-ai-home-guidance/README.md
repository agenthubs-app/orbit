## 选定方向的修订稿

[question-starters-v2.png](question-starters-v2.png) 保留已选布局，只把问题示例改为「今天先处理哪些事？」与「最近有哪些活动适合我？」。这是待办与活动两个类型的静态预览，并不代表已实现动态选择或读取了账户当前状态。修订稿的生成提示词见 [REVISION-PROMPT.md](REVISION-PROMPT.md)。

用户已批准的策略：

- 用真实数据确定问题主题，以固定的简短模板呈现，不每次调用模型临时写文案。
- 每次展示两条不同类型：一条回应当前需关注的事情，一条提供另一类用途的发现入口。覆盖待办、跟进、活动准备、活动发现等，不能长期只展示人脉主题。
- 首页「下一步」保留具体事项；问题引导排序、准备、总结或发现，不再列一遍具体待办。
- 停留首页期间不自动跳换；没有足够数据时使用通用问题，不编造待办、跟进或报名状态。
- 点击只填入输入框，用户仍确认发送。不新增导航模块，不改变既有事项操作。

以上修订画面与策略现已获批，不再等待重复确认。

## 原生接入结果

- 复用现有 Today 数据及合同类型解码，不增加 API、不调用模型选题。
- 第一条依次选择：高优先级或已到期的未完成事项 → 尚未开始的会面/活动准备 → 未完成的人脉跟进 → 通用待办规划。第二条为不同类型的活动发现。已完成/取消/无效记录不触发推荐；问题不带编造的人名、事项或报名状态。
- 首次数据就绪后固定问题；缓存被后台结果覆盖时不跳换。主动刷新完成后重新选择；账户或服务器改变时丢弃旧选择，等待对应 loading 或 refreshing 周期完成。
- 两行问题位于「下一步」下方、同一滚动区内，保留原生输入栏及键盘避让。点击仅填入草稿，可修改后自行发送。
- 只过滤服务器默认欢迎记录 `orbit-agent-live-ready` 和准确匹配的默认 assistantMessage 兜底，真实回复及对话详情不受影响。
- Simulator 已检查浅色、深色、两条问题分别填入、键盘打开后滚动并再次填入；未发送消息或修改业务记录。
- 全量测试 769 通过、0 失败、0 跳过；类型检查通过。独立审查发现的「刷新后换账户」问题有失败→通过回归测试。
