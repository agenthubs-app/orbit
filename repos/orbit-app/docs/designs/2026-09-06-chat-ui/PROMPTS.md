## 1

Use case: ui-mockup. Create realistic, production-quality UI designs with clear hierarchy, strong typography, intentional imagery, and purposeful spacing. This is a design exploration for improving the EXISTING Orbit AI mobile conversation UI, later to become a Sites-hosted interactive mobile prototype, NOT a desktop SaaS dashboard or landing page.
Attached image 1 = actual current conversation top, image 2 = actual current bottom with rich result cards and composer; these are product grounding references, not exact layout to copy. Retain Orbit AI brand, Chinese language, and Ocean-blue design system, but rethink hierarchy and interaction of this specific chat surface. Current problems to solve: huge repeated headers, outer cards enclosing all messages, excessive timestamps, input below entire transcript instead of readily reachable.
Target dimensions: app content 402 x 874 logical pixels, portrait 804 x 1748 output or matching natural aspect ratio. One single app screen per image, no collage, no labels naming design options. No device bezel, rounded device mask, phone body, notch, Dynamic Island, OS status bar, clock, battery, home indicator, browser chrome or device shadow. Fill the canvas with app-owned content.
Style invariants: Ocean blue accent #006DB8, pale #EDF8FF, soft #E3F2FC, warm canvas #F7F6F3, white #FFFEFC, dark ink #20242C, muted #626874, borders #E5E4E0. Calm professional native mobile UI, precise Chinese sans-serif, body15-16px, text has real reading contrast. Avoid purple, glass, gradients, decorative art. Use no more than two fonts. Crisp conventional thin native icons only.
Focus on one use case: user asks for business event suggestions, assistant explains its recommendation with an event result and user can continue the conversation. No unrelated dashboard metrics, tabs, badges, invented features, voice recording or AI model picker. Keep only useful controls: back, conversation menu, attachment plus, text input and send. Do not stack cards inside cards. Prefer whitespace, type, alignment then dividers then tint, borders sparingly, shadows last.
Use FICTIONAL demo event data only, not factual event listings or live user data. Current date anchor: 2026-09-06 (Sunday) Asia/Tokyo. Example event next Thursday 2026-09-10 18:30 Tokyo, event title “AI 产品交流会”, brief “东京 · 涩谷”, secondary “小规模交流，适合认识产品与工程伙伴”. No claim that event is live or real. Display only short date “9月10日 周四 · 18:30”. Example user query “这周东京有什么适合我的活动？” Assistant plain Chinese “可以先看这场。人数不多，方便聊具体的合作。” One supporting action “查看活动”. Composer placeholder “继续聊聊…”; never show technical provider errors or implementation labels from reference. Avoid repeating every metadata label per message. If there is room, one earlier short assistant turn “想认识哪一类伙伴？” user followup “做 AI 产品的，最好能聊聊合作。” Keep content focused and comfortably spaced, unclipped. Output a credible production UI screenshot, not concept art.
Direction name (metadata only, do not render): 清爽消息流 / Quiet Thread. Create a familiar and clean chronological messenger layout. Compact 56pt header back on left, centered Orbit AI with tiny subdued subtitle “活动建议”, ellipsis on right. Conversation shown in a generous single open canvas, compact user bubbles right in pale ocean blue with dark text; AI responses left as unboxed natural text aligned to a small subtle Orbit brand label. One short date divider “今天”. Display 2 conversational turns followed by one small low-border white event preview with typographic event title and date, optional tiny conventional calendar icon, no photos necessary. Keep assistant prose and event as visually separate items without outer bubble enclosing both. Bottom fixed composer with plus button, shallow rounded text field and integrated circular solid-blue upward send button. Leave enough air between last answer and composer but don't add empty huge gaps. Light restrained blue is reserved for user bubble and send control. Rich results are secondary to actual conversation. No navigation grid below composer.
