# 状态、适配与验收清单

本文件是给设计细化和后续实现的检查要求。本轮完成的是静态设计资料；下面的运行时项目没有因写成清单而自动通过。

## 1. 每个页面都要考虑的状态

| 状态 | 画面与操作 | 不允许的替代 |
| --- | --- | --- |
| 首次加载 | 保持页面标题和返回；内容区显示对应骨架或简短加载提示 | 白屏、旧账号数据、永久转圈 |
| 已有内容刷新 | 内容保持可读，提示正在更新；失败给局部恢复 | 刷新即清空表单或把旧数据显示成刚更新 |
| 真正空数据 | 说明没有哪类内容，给与该页面相关的下一步 | 把权限错误／网络失败标成“暂无内容” |
| 搜索无结果 | 保留输入和筛选，显示“未找到匹配的人脉／活动”，可清除条件 | 擅自放宽搜索到别的账号或填演示结果 |
| 离线／服务失败 | 具体说明，保留可用内容与草稿，提供重试 | 假成功、伪造新数据、默默丢输入 |
| 未登录 | 登录入口和可返回路径；公开内容仍按既有政策展示 | 以游客身份读私人资料 |
| 无权限 | 原因和退出／重新确认资格；动作不可执行 | 只隐藏按钮而保留可调用的越权操作 |
| 对象删除／失效 | 说明对象不可用，回到列表；清理失效引用 | 跳到另一个同名对象 |
| 写入中 | 锁定重复提交，文案明确；非冲突区域可继续查看 | 每次点击都重复创建 |
| 写入失败 | 当前输入保留，解释重试范围 | 清空内容、假装保存、重试时多次发信 |
| 外部已更新 | 区分服务端新值与本地草稿，让用户复核 | 背景刷新静默覆盖未保存内容 |

设计稿应展示至少一个正常内容态；不能因为所有异常都未单独出 JPEG 就忽略它们。`pages/` 会指出哪张画面是内容态、编辑态或边界态。

## 2. 表单状态

输入字段至少考虑：空、已填、正在编辑、校验错误、只读、提交中。错误放在相关字段附近，不能仅靠颜色；全局错误只用于真正跨字段的问题。

保存失败显示“保存失败，输入已保留”。返回时未保存内容的处理需可预测；不把“留在当前页面”称为已保存到云端。切账号必须清理私密草稿的显示和旧响应归属。

选择控件应明确当前值与允许范围。生成图内的下拉图标只是视觉，不决定字段必须是自由输入还是字典选择；行业等使用已有允许字典。密码使用安全输入，不在截图展示真实密码或令牌。

## 3. 核心业务验收场景

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| N01 | 冷启动，无指定深链 | 目标新首页；不自动进入并发送 AI 对话 |
| N02 | 四个根页分别进入 IORBIT，再关闭 | AI 无底栏；各自返回原来上下文 |
| N03 | 活动详情深链，登录后报名 | 目标活动 ID 和回跳信息保留，返回不循环 |
| N04 | 大列表滚到底部 | 最后一行完整可见、可点，不被悬浮胶囊盖住 |
| A01 | 邮箱注册后资料缺项 | 按服务判定补全，完成后回原目标；已完成不再拦截 |
| A02 | Google 能力关闭／取消登录 | 不显示假入口或假成功，表单／返回仍可用 |
| A03 | 资料保存失败后重试 | 输入未丢；最终按真实响应回读 |
| C01 | 搜索同名不同公司的人脉 | 可区分且使用稳定 ID，不猜测绑定账号 |
| C02 | 外部联系人打开详情 | 不出现可发送的假站内会话 |
| C03 | 编辑资料备注和身份 | 授权字段可编辑；没有互动纪要录入器 |
| C04 | 已删除／无权的联系人引用 | 明确失效，不访问其他记录 |
| B01 | 单面名片，取消／重拍／相册 | 无需第二面也可复核；取消不创建联系人 |
| B02 | 同卡正反面有冲突字段 | 可复核来源，确认仅生成一个联系人 |
| B03 | 离开导入页后返回，或切账号 | 有权者恢复有效服务端进度；旧账号结果不串入 |
| E01 | 未来活动但报名未开放 | 不能提交；显示权威原因 |
| E02 | 问卷输入时刷新或后台更新 | 不清空答案；题集变更明确提示 |
| E03 | 双击提交／网络重试／取消后重报 | 无重复报名；状态、人数和列表回读一致 |
| E04 | 待审核与已报名 | 画面明确不同，不能使用同一个成功提示 |
| T01 | 新建不关联人脉的待办 | 可完成主流程；详情／首页显示同一记录 |
| T02 | 日程跨日、跨时区、重叠 | 时间和位置一致；不按图片固定坐标排程 |
| T03 | 待办完成写入失败 | 恢复真实状态，明确失败，不只勾选本地 UI |
| I01 | 返回、重挂载、初始草稿 | 不重复生成回答；输入和已有历史保留 |
| I02 | 回答生成成功但持久化失败 | 明确“回答已生成但未保存”；重试保存不重调模型 |
| I03 | `@` 同名联系人、失效引用、无工具权限 | 使用 ID，明确错误类型，不把可读页面等同 AI 有权限 |
| M01 | 私人邮件草稿 | 标“未发送”，复制／确认草稿不显示“对方已收到” |
| M02 | 真实聊天发送失败 | 有失败标记与重试；不因联系人存在就准许发送 |
| M03 | 提醒目标删除、切账号、通知解绑失败 | 目标可解释；旧角标不串号；解绑失败可见 |
| O01 | 普通用户访问活动运营深链 | 权限边界完整，不泄露名单和受限操作 |
| O02 | 审核／签到／角色更新中重复点击 | 对象明确、防重复，结果按服务端回读 |
| O03 | 题集冻结、发布前有未保存改动 | 按真实资格禁用并说明，不伪造发布成功 |
| F01 | 后期一篇笔记关联两位人脉 | 两处详情打开同一原文，不复制两份正文 |
| F02 | 后期修改笔记或移除一条关联 | 原文／摘要刷新一致；取消关联不删除整篇笔记 |
| F03 | 旧备注切换到笔记机制 | 旧原文和权限可验证保全后，才移除旧互动写入 |

F01–F03 等后期场景在 APP-16／B8 就绪后执行，不提前标记通过。笔记到日程建议还需 D5 审阅及 B6 支持。

## 4. 视觉矩阵

按页面族验证：列表、详情、表单、统计、日／周／月历、AI 长文、聊天、运营。每个页面至少核对正常浅色；共用组件还需覆盖深色和大字号。

| 维度 | 检查 |
| --- | --- |
| 宽度 | 320／390／430pt，不横向溢出；长英文和值列不互相覆盖 |
| 字号 | 普通和大字号；支持换行与上下字段布局，不关闭字体缩放 |
| 主题 | 浅色、深色；章节带、状态文字、图标和分隔线均可见 |
| 安全区 | 顶部返回、底部胶囊、粘底动作不与系统手势区域冲突 |
| 键盘 | 当前输入、错误与提交可达；底栏不挤压文本域 |
| 文本 | 长中文／日文公司名、英文长句、多行简介、邮件地址完整可读 |
| 列表 | 滚动稳定、返回保留合理位置；无头像／封面仍有可用结构 |
| 图表 | 数值和单位清楚，不把装饰性大小当作真实比例 |
| 日历 | 周日期对应真实日历；刻度不重复；块起点与时长可验证 |
| 图标 | 一套现有图标，点击区和可访问名称清楚；无无效装饰按钮 |

不要从 JPEG 像素推算最终原生字号。先按标注实现受控页面，再在同设备、同字号、同内容下比较。

## 5. 本轮文件检查

交付前检查单页 JPEG 的签名、实际尺寸和非空文件；保留生成原件，对项目副本计算 hash。检查所有页面 ID 唯一、图片与说明一一对应、当前 63 个路由入口无未解释遗漏、相对链接可解析。

本轮不运行 App 功能测试、不启动模拟器、不调用真实业务 API、不提交代码。文件检查不能写成“所有业务验收通过”。具体已执行的文件结果记录在 `DECISIONS_AND_HANDOFF.md`。

## 6. Claude Design 细化时的交付标准

- 沿用一个融合体系；首页与已选底栏不重新选型。
- 每个页面 ID 有独立图或明确的复用／跳转说明，不只有拼图缩略图。
- 保留页面字段和动作语义，补充表单、异常和长内容状态。
- 对图片生成偏差按文字规则校正，不继承错字、虚构计数、错误权限或遮挡。
- 若某项依赖服务端或用户决定，在交付问题清单中保持开放，不用假数据宣称完成。
