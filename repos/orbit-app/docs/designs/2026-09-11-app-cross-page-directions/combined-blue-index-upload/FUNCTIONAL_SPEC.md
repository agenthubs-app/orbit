# 功能与交互规格

适用版本：2026-09-11 融合设计交接。源码基线 HEAD `8b38b4eb8618505ca4f59f20dc323159e1ad784b`。本文件描述当前能力和目标设计的关系，不是后端契约冻结稿，也不是运行时验收结果。

## 1. 产品与使用者

Orbit 帮助用户整理人脉、安排待办与日程、发现和参加活动，并通过 IORBIT 处理与这些上下文有关的问题。移动端优先支持随手查看、现场操作、拍名片、记录交流和快速确认。

普通用户使用自己的资料、人脉和事项；游客可浏览已公开活动；活动主办方和被授权的协作者在同一账号体系中进入运营页。系统管理和活动主办角色不是一回事，不因能登录就允许审核、发布、改角色。

## 2. 如何读状态标记

| 标记 | 含义 |
| --- | --- |
| 现有 | 源码有对应页面／消费链路；没有在本轮证明真实服务可用 |
| 已确认方向 | 用户已决定设计方向；仍需按相应范围实施与验收 |
| 设计建议 | 为完成交接给出的具体交互方案；不能冒充批准的业务规则 |
| 后期 | D7 笔记等已要求延后实施的能力；本轮仅画设计 |
| 兼容／受限 | 旧入口、别名或低频受权限限制页面；不得擅自删除或开放写权限 |

“现有”与“新视觉待审”可同时成立。一个按钮画出来，不表示 API 已具备其全部语义。

## 3. 核心对象与归属

| 对象 | 含义 | 关键边界 |
| --- | --- | --- |
| 账号 | 登录主体、会话和权限 | 不能用联系人 ID 冒充账号 |
| 我的资料 | 当前账号的身份、公司、行业、简介和长期目标 | 以服务端为权威；编辑失败保留草稿 |
| 人脉 | 用户管理的一份联系人记录 | 可以没有平台账号；同名不代表同人 |
| 资料备注 | 称呼、身份辨识和背景说明 | 仍可编辑，不能因移除互动输入而删除 |
| 互动笔记 | 某次交流、会面纪要、约定等内容 | 后期新增独立内容，按所有者权限保存 |
| 笔记关联 | 笔记与一位或多位人脉的关系 | 引用同一正文，不复制多份；不等于分享或通知 |
| 待办 | 用户要完成的事项 | 可以不关联人脉，不一定有精确起止时间 |
| 私人日程 | 已确认的时间安排 | 与公开活动不是同一对象；编辑同一稳定 ID |
| 活动 | 公开或授权可见的活动及其报名流程 | 生命周期、报名窗口、本人报名状态分开 |
| 报名资料 | 当前账号在某活动中的答案和状态 | 按活动与题集版本保存，不变成全局必填资料 |
| AI 会话 | 问题、回答、引用及持久历史 | 生成与保存不同；保存重试不重新生成 |
| 站内消息 | 已验证可联系账号之间的真实消息 | 显示发送结果，服务端校验资格 |
| 邮件草稿 | 尚未发送的私人文本 | 明确标注草稿，不展示为对方已收到 |
| 提醒 | 指向事项或活动等资源的通知 | 有类型、读状态、目标权限；不是聊天消息 |

以上沿用任务审阅稿中已明确的用语，没有重新定义旧备注的迁移映射。旧数据可能混合资料说明和互动内容，需先分类保全。

## 4. 信息架构与入口

```text
首页 ─ 日程／待办／跟进／活动／收件箱
人脉 ─ 列表／详情／资料编辑／添加与名片／分析
IORBIT（中央动作）─ 新会话／历史／引用／连续回答
活动 ─ 发现／详情／报名／参会者／我的活动／授权运营
我的 ─ 资料／编辑／账号／权限／设置

后期笔记 ─ 列表／原文／编辑／关联人脉
           人脉详情只回看关联摘要与原文
```

这棵树说明目标信息架构，不代表每条节点均已是独立路由。具体映射见 `PAGE_CATALOG.md`。当前源码仍有 `/home → /ai` 等旧入口，目标设计不等于它已经修改。

### 导航不变量

正常返回保留来处和必要筛选条件；深链进入能退出到合理根页；登录回跳保留经过校验的目标。未知路径不能形成重定向循环。切换账号后清除旧账号的内容、请求结果、角标和私密编辑状态。

## 5. 注册、登录与资料

现有邮箱／密码登录、注册、Google 登录、找回与重置密码。Google 按服务能力显示；设计稿的 Google 按钮采用该能力已启用的演示上下文，不要求所有环境强制显示。

注册当前为邮箱＋密码，不在注册页增加完整个人资料问卷。登录／注册后读取真实资料，缺项时再进入补全；已经完成的人不重复拦截。完成后回到原先想访问的活动或页面，不总是送去同一默认页。

D2 的设计建议为姓名、行业必填，公司／职位／简介可选；“我能提供／我想寻找／话题”是可选扩展。最终必填集合和完成标志需 B1 确认。行业优先于职位，建议职位可改为自填。活动特定目标只在报名中填写。

保存中防重复，失败保留草稿。后台刷新不能覆盖正在输入的内容；账号变更后旧保存响应不能更新新账号。名片／简历提取结果先复核，再明确应用，不自动把推断写成事实。

找回密码页在请求前显示表单，请求后显示真实返回；不通过不同文案泄露账号是否存在。重置令牌不出现在截图、日志或交接文档中。

## 6. 首页

已确认 Split Day：周日期条与快捷入口、今天日程／待办分栏、联系跟进、近期活动。搜索人脉、收件箱、日历、全部活动可直达对应页面。快捷“写笔记”受后期 B8 约束，不能接到旧联系人互动 Memo 伪装完成。

待办、日程、推荐活动独立读取和恢复。某一块失败只在该块提示，不把整页清空。空数据分别给“添加人脉”“新建待办”“查看活动”等对应动作；没有个人推荐仍可进入全部公开活动。

首页的进入、返回、刷新只读取，不触发模型生成、发消息、自动生成提醒或写日历。日期采用账号时区和明确回退策略；图片固定东京只是样例，不能将其写死为全部用户时区。

## 7. 人脉与资料编辑

列表保留搜索、筛选、来源和状态；筛选只影响可见集合，不改联系人生命周期。搜索范围需由实际接口能力决定，不能把已加载的一页当成全部结果。

详情按身份、资料备注、简介、合作信息、关联内容组织。缺失字段显示缺失或省略，不编造公司、头衔、照片或关联账号。资料编辑只编辑有权限的字段；具体可写字段由已批准契约决定。

D7 的目标：互动内容只写入笔记，详情不再提供互动输入器和保存互动备注按钮。但切换前必须具备笔记写入、按人脉回读和旧内容保全方案；不能先删掉入口让旧内容无法访问。

旧 `ContactNotesSection` 是后续检查重点。不得把私密备注 PATCH 当成新笔记接口，也不得删掉整个备注字段而误伤资料说明。新 UI 使用“资料备注”清楚表达用途。

### 身份、邀请和真实聊天

外部联系人、匹配中、冲突、无权限、已确认可聊天须区分。姓名／照片相似不构成绑定；手机号或邮箱也只能参与服务端确认流程。未知资格默认不允许站内发送。

邀请链接来自服务端，可以预览、复制或由用户打开系统分享；打开详情不自动发邮件／短信。绑定完成刷新资格后再进入真实会话。资格撤销后旧页面也不能继续发送。

## 8. 名片与添加人脉

已有手动、扫码、名片和批次导入等入口，本轮保留它们的角色，不用新视觉删掉可用来源。样例先展示常用的手动／名片路径，其他模式按页面说明继承相同字段和状态规范。

APP-10 目标是正面＋可选反面属于同一张卡，统一复核后创建一个联系人。单面即可完成；不能把两张图片导入成两个联系人。长公司名、源语言、冲突字段、字段来源与重复检查都要可见。

相机授权、拒绝、相册、取消和重拍是必需状态。上传与识别有真实进度；不得用随机百分比或固定延时模拟后台完成。识别可失败，字段可修正，最后必须由用户确认。

现有 `batch` 与 `batch2` 是不同链路，不擅自互相替换。持久导入进度路径 `/contacts/new/import/[id]` 在当前 App 仍是已知缺口；本包提供目标画面，不创建空壳兼容页。退出后按有效导入 ID 恢复服务端进度，不建立本地业务写回队列。

## 9. 活动发现与详情

公开活动可浏览；个人推荐、已报名状态、报名和运营操作按账号与权限加载。设计中的“推荐／全部／已报名”是发现入口的细化建议，保留现有状态筛选能力；具体分段落地应先确认，不把界面微调当成数据集合已经统一。

活动行显示主题、时间、地点和真实报名状态。推荐解释必须有依据；没有理由时使用活动客观介绍，不编造“最适合你”的关系推断。封面缺失使用现有图标／占位样式，不阻止读内容。

详情应说明活动内容、时间地点、流程和主办方。查看参会者、分享和报名都保留各自权限。公开活动预览不自动创建私人日程；报名是否同步安排取决于现有或批准的服务行为，不能由设计图自行决定。

## 10. 报名与答案

必须分开表达三套状态：活动生命周期、报名窗口、当前用户报名状态。未来活动也可能尚未开放报名；已报名也不代表已开始。

| 情况 | 目标表现 |
| --- | --- |
| 可以报名 | 可进入表单，提交前校验题集与资格 |
| 尚未开放 | 说明开放状态；不显示可提交按钮 |
| 已截止／结束／取消 | 明确原因；不靠手机本地日期假定可报名 |
| 满额 | 显示服务端允许的后续动作；没有候补能力就不新增候补 |
| 待审核 | 显示待审核及已提交答案；不是报名成功替代词 |
| 已报名 | 可回看资料；仅在允许时显示取消 |
| 提交失败 | 原答案保留，明确重试动作 |
| 题集已变化 | 提示哪些内容需要复核；不静默清空草稿 |

问题文案、选项、必答、长度约束以服务端题集为准。生成图出现的字数计数不构成新限制。辅助问答属于报名上下文，不能在刷新后反复清空；生成画像或下一题必须有明确用户动作。

提交成功后回读报名、活动详情人数及相关列表；答案还必须在后续匹配中实际被消费。只显示“提交成功”不足以验收。取消和重报也应重新确认权威状态。

## 11. 待办、日程与提醒

待办支持个人事项，不强制联系人。详情展示标题、状态、日期、关联人脉可选、来源和历史；修改时保持同一 ID。完成动作需要可见提交中和失败恢复，不只在本地勾选。

日历保留日／周／月；同一条日程在首页、日历和详情编辑后可回读一致。时间轴的位置由起止时间计算，全天、跨日、重叠、时区变化和无明确时间分别处理。公共活动预览有不同标签，不装成已确认私人安排。

新建／编辑页的保存、返回与草稿保护按共用表单规则。不得要求所有待办都有时分，也不得把“下周再聊”直接写成某一天某一时刻。

D5 仍待确认：后期从笔记提取候选建议，用户检查对象、日期地点后接受／编辑／忽略。多人笔记不为每位联系人复制同一日程；重复接受和网络重试不重复创建。笔记版本或关联变化后应校验建议是否仍有效。

不在本轮增加 Google／Apple 外部日历写入或桌面组件。

## 12. IORBIT 与分析

已确认中央全屏入口。现有历史与会话页保留。D3／APP-05 的统一主动 AI 路径仍按审阅范围细化：业务页只携带上下文草稿，用户点发送才执行；名片 OCR 和报名辅助问答保留嵌入式用途。

`@` 选择器按部分姓名／公司搜索当前账号可访问联系人，同名者显示区别，发送稳定 ID。不能把全部联系人资料塞进问题文字规避服务端工具权限。引用失效、删除或无权访问须明确反馈。

会话的状态至少区分：草稿、发送中、回答生成中、回答已生成且已保存、回答生成但保存失败。重试保存不请求模型；重新生成必须另有明确动作。返回、重挂载和初始预填不自动发送。

AI 邮件能力输出可编辑草稿／复制文本，不自动发信。真实数据不可读时区分无权限、服务故障与空集合；不能用一份漂亮回答掩盖权限错误。

人脉分析中的行业／来源统计及钻取不依赖 AI。已有报告可回看，显示生成时间和数据版本；数据变化时提示可重新分析，不自动重算。长期目标是当前用户的职业／业务目标，不是联系人阶段。

Pipeline 独立入口是否收敛仍是 D4 待审事项。旧生命周期、归档和历史必须保留；本包为兼容页给图，不表示批准继续突出入口或删除它。

## 13. 收件箱、草稿与消息

首页统一收件箱入口承接消息、提醒和活动通知，但每条保留类型。未读数来自当前账号，读状态与角标需要一致；资源删除、无权限或过期给明确解释。

私人邮件草稿和站内聊天分开展示。草稿页显示“未发送”，编辑和复制不算发送；真实消息页显示发送者、时间、发送中／失败／已发送状态，不能对外部联系人生成假会话。

推送需用户选择，锁屏摘要不泄露私密文本。登出、切账号、关闭通知时处理当前设备注册；失败不能显示为完全解绑。此处描述要求，不替代原生通知验证。

## 14. 主办方、运营与兼容页

同一 App、同一账号按活动角色进入运营，不另建主办方 App。活动中心按真实角色显示可管理集合。操作入口不得仅依靠前端隐藏，服务端仍校验。

运营台、审核、签到、角色、报名体验和分析保留各自语义：审核有待处理／已处理和具体申请详情；签到有搜索与结果；角色授予／撤销有对象与生效边界；题集有草稿、预览、发布及冻结；匹配生成有任务状态，不能重复启动或把未发布结果当成已发布。

旧 `/admin` 系列主要核对和跳转，不能和已存在的活动运营写接口混为一谈。`/platform` 当前不具备已验证的平台审核写接口，不添加批准／驳回／账号认证按钮。现场模式与现场签到页只能展示服务提供的码或状态，不能生成假签到成功或假二维码。

## 15. 后期笔记设计

新增笔记列表、原文、编辑和人脉选择的图片是 D7 的后期设计细化。路径若在索引中出现，均为建议，不说明现有 API 或路由已经存在。

编辑从内容开始：标题、正文、相关人脉。可关联零位、一位或多位；是否要求标题和零关联保存的具体规则在 B8 中确认，设计建议允许先记录再整理。关联仅整理私密内容，不自动通知被关联者。

打开人脉详情时按稳定 ID 读取摘要，点击同一笔记原文。修改笔记只改一份正文，取消关联不删除笔记；删除笔记与取消关联必须区别。删除／恢复策略、并发版本、离线草稿和历史迁移尚未冻结，不由 Claude Design 擅自实现。

切换门槛：B8 契约确认 → 独立笔记与关联回读可用 → 旧内容保全与兼容方案验证 → 移除旧互动输入 → 人脉页与笔记页联验。不会在本轮执行这些步骤。

## 16. 数据、接口与跨端原则

App 通过 Screen → hook／view-model → HTTP client → Web API 访问数据，不直接连接数据库。共享类型、Schema 和允许字典通过现有同步命令管理，不手改副本。

成功 GET 的本地快照是按服务器＋账号隔离的读缓存，不是业务数据库副本或离线写入同步系统。缓存数据需与最新状态区分；另一端改动后可通过明确刷新回读，不能宣称全局实时同步。

| 能力 | 已有客户端入口证据 | 仍需确认的边界 |
| --- | --- | --- |
| 账号／资料 | `accountMe`、`profile`、mobile auth | B1 完成判定、必填与职位来源 |
| 人脉 | `contacts`、`contactsSearch`、`contactDetailPath` | B4 账号绑定与聊天资格；B8 旧备注分工 |
| 活动发现 | `publicEvents`、`eventRecommendations`、`eventValueRecommendations` | B7 推荐解释、完整检索与分页 |
| 报名 | `eventRegistrationPath`、interview／persona／cancel helpers | B2 权威资格、题集版本、状态与答案消费 |
| AI | `conversations`、`aiConversationSessions` | B3 请求幂等、保存恢复、类型化引用、工具权限 |
| 名片 | scan／confirm、batch／ingest helpers | B5 同卡双面、字段来源、持久导入进度 |
| 待办／日程 | `tasks`、`scheduleItems`、suggestion／reminder helpers | B6 笔记来源、建议接受类型与去重 |
| 收件箱／通知 | `relationshipInbox`、`notifications`、push token／preferences | 目标权限、跨账号和解绑回读 |
| 笔记 | 现有联系人详情和旧私密备注仅作锚点 | B8 新 API／DTO 尚未确认，不虚构端点 |

入口常量与 helper 名称来自 [endpoints.ts](../../../../src/api/endpoints.ts)，不是新的 wire contract。具体请求字段、方法与资格应以服务端已批准接口及 App 实际消费者为准。

## 17. 交接完成与实现完成是两回事

本轮交接完成标准：独立页面图可打开；每个当前路由有明确映射或兼容解释；文字规格区分现有／建议／后期；文件与图片来源可追溯。

后续实现完成标准：批准范围内的功能、失败恢复、权限、跨页回读、原生交互和跨端验收均有证据。路线文件存在、类型检查通过或图片好看都不能代替这一标准。

历史 App 测试的 1389 通过／1 失败和 Web 的 3134 通过／8 失败只是 9 月 10 日交接记录。本轮未重跑，不把它们写成当前通过结果；基线失败审批继续保留。
