# 交给 Claude Design 的任务说明

请先阅读本文件，再打开本目录的图片与规格。交付目标是 Orbit iOS-first App 的设计细化稿，不是另做一个新品牌，也不是网页式手机外壳。

## 任务

基于本目录的融合稿，完善全 App 的视觉与交互设计。保留已选首页 Split Day，把“浅蓝章节分区”和“字段对齐索引”应用到其他页面。用户要的是更紧凑、清楚、统一的字号和信息密度，整体结构不要大改。

本包包括独立页面 PNG、页面索引、设计系统、功能规格、状态与验收说明。图片是设计参考，不是已经实现的 App 截图。功能文档中的状态标记比画面中的示例按钮更有约束力。

## 阅读顺序

1. `README.md`：范围、交付状态与文件入口。
2. `screens/01-home-approved.png`：已批准首页，不重新设计。
3. `screens/08-contact-detail.png`、`screens/07-contacts.png`、`screens/40-iorbit-conversation.png`：新融合体系的详情、列表、长文基准。
4. `UI_DESIGN_SPEC.md`：颜色、文字、布局、组件与导航规则。
5. `PAGE_CATALOG.md` 与 `pages/`：每页图片、当前路由、入口、字段、动作和实现边界。
6. `FUNCTIONAL_SPEC.md`：主流程、数据归属、权限、后端依赖与后期功能。
7. `STATES_AND_ACCEPTANCE.md`：异常状态、适配和验收。
8. `DECISIONS_AND_HANDOFF.md`：批准记录、冲突优先级和不能自行决定的事项。

## 必须保持

- 底部顺序：首页、人脉、IORBIT、活动、我的。只有四个普通根页；IORBIT 是中央动作，打开独立全屏页。
- 根页底栏采用已批准的悬浮长岛胶囊；二级页、编辑表单、登录、运营和 IORBIT 不显示全局底栏。不能将生成图里的近似轮廓变成新底栏方案。
- 首页保持 Split Day 的周条、快捷动作、左侧今天日程／右侧待办、联系跟进和近期活动结构。不要加入大聊天输入框。
- 人脉列表保留紧凑列表。人脉详情以资料和关联内容展示为主，仍可编辑有权限的资料字段与资料备注。
- 互动过程以后统一写入笔记，再关联一位或多位人脉；人脉详情不保留互动备注输入器。这个方向已确认，但功能留待后期，旧内容必须保全。
- IORBIT 回答是可连续阅读的文章，不是多层卡片或大气泡。进入页面、返回和刷新不应发起新的模型请求。
- 公共活动、私人日程、待办、消息、草稿、笔记是不同对象，不能只因版式相似而合并数据或权限。
- 不缩小触控区域来凑密度；保留普通触控至少 44pt、主操作至少 50pt 的现有要求。

## 请输出什么

在同一套组件体系里细化页面，不再扩展五种平行风格。每张高保真稿使用页面 ID 命名，并给出普通状态和所需的关键异常／编辑状态。

设计交付应包含：组件及变体、字号／行高／间距标注、滚动与固定区域、返回和跳转关系、表单验证、加载／空／失败／无权限状态、长中日英文与大字号样例。中文为当前图片语言；日英版本需保留用户数据原文。

若输出可交互设计原型，使用虚构数据，标明未连接真实服务。所有可点元素应有去向；未获批准的写操作只演示交互状态，不调用真实服务。不要建立业务数据库或伪造报名、聊天、保存成功。

## 不要自行扩展

不要重做后端、改 API 或 Schema、迁移／删除旧备注、设置会员额度、申请外部日历写入、自动发邀请／邮件、加入新支付流程、建立独立主办方 App。不要把素材中的示例人物替换成真实用户资料。

`未来设计` 和 `待确认` 并非可以直接实现的需求。D2–D6、笔记接口 B8、旧备注保全方案及尚未确认的新交互，需要保留为设计问题。已有页面的视觉微调不等于批准改变业务规则。

## 冲突怎么处理

以最新用户决定和 `DECISIONS_AND_HANDOFF.md` 为先，再看文字规格和单页说明，最后看生成图。生成图的错字、日期格、底栏遮挡或不精确尺寸不应照搬。首页独立原稿优先于其他图中重复出现的导航轮廓。

本包没有授权提交、推送、部署或修改 App 代码。若下一阶段改为实现，先确认具体页面／功能范围，继续遵守项目的审批、逐符号影响分析和验证要求。
