# UI 设计规格：浅蓝分区 × 对齐索引

版本：2026-09-11 融合预览稿。适用：APP-01 的导航／首页设计交接与 APP-14 的全 App 排版微调。本文是设计目标，不表示这些数值已应用或已通过原生验证。

## 1. 视觉方向

以已批准首页的紧凑信息密度为基准。长列表使用白底和细分隔；详情、表单与长内容使用浅蓝章节标题带；字段固定标签列、值列对齐。蓝色用来指示动作、选中态和章节，不把整页涂蓝。

合并来源是本目录 `references/source-02-blue-chapters.png` 和 `references/source-03-aligned-index.png`。保留来源 02 的分区感、来源 03 的对齐与细标记，取消重复装饰。首页不参与合并，使用 `screens/01-home-approved.png`。

### 可以改与不能顺带改

可微调字号、字重、行高、区块间距、列表行内留白、表单对齐、章节标题背景。已确认的导航和首页按其单独范围改。

不能借统一风格重排所有业务模块、删掉低频字段、把全部页面改成卡片列表，或新增没有依据的按钮。图片中为了展示某种表单而拆出的编辑画面是设计状态，是否新增路由要另行确认。

## 2. 画幅与适配

主设计坐标采用 390×844pt。单页 PNG 请求 1170×2532px 等比例输出；实际生成尺寸以 `ASSET_MANIFEST.json` 为准，不能把请求尺寸当成实测输出。图片没有系统状态栏、设备外壳和 Home Indicator。

原生实现仍必须处理系统安全区，不能把图片里没有 OS 装饰理解成没有安全区。适配检查至少包含 320、390、430pt 宽度；平板／横屏采用现有内容最大宽度约束，不把一列拉得无限宽。本次没有批准平板专属布局。

- 页面左右内边距建议 16pt；来源代码当前为 22pt，不能未经逐页验证全局替换。
- 内容宽度保持自然；表单和长文不因横屏而无限拉长。
- 纵向滚动为默认。不能为了把整页塞进一张图而减小文字、隐藏正文或压扁控件。
- 根页滚动内容预留底栏高度、下间距和安全区；最后一行必须可完整滚到胶囊上方。
- 编辑时键盘不能覆盖当前字段、错误或主要动作；表单允许滚动，保存按钮不要求一直悬浮。

## 3. 颜色

优先复用 [现有 tokens](../../../../src/design/tokens.ts)。下表区分已有值与融合稿的近似视觉目标，不新增一套与主题平行的硬编码颜色。

| 角色 | 浅色目标／已有值 | 用法 |
| --- | --- | --- |
| 主操作 | `#006DB8` | 按钮、链接、选中图标 |
| 主文字 | `#20242C` | 标题、字段值、正文 |
| 次要文字 | `#626874` | 标签、日期、来源、说明 |
| 主内容底 | `#FFFEFC` | 页面内容、列表、表单 |
| 轻灰底 | `#F3F3F2` | 搜索框、非选中分段背景 |
| 分隔线 | `#E5E4E0` | 列表行和资料行边界 |
| 浅蓝标题带 | 生成指导 `#EDF6FD`；实现优先核对已有 `accentSofter/tint` | 章节分组，不用作大面积重色卡片 |
| 成功／完成 | 现有 `live`／`liveSoft` | 同时显示文字状态 |
| 警告／待处理 | 现有 `amber`／`amberSoft` | 需要注意但可继续的提示 |
| 失败／危险 | 现有 `rose`／`roseSoft` | 错误、拒绝、删除确认 |

深色继续使用现有主题映射，不能简单反相或把浅蓝值硬写到深色。当前图片以浅色为主，深色稿与原生对比属于后续细化／验收，不宣称已经覆盖。

## 4. 文字体系

中文与日文采用系统字体回退，英文使用系统无衬线。无需引入新字体依赖。品牌写法为产品 Orbit／ORBIT，AI 名称固定 `IORBIT`；不能误写为 `ORBIT` 后声称是另一入口。

| 文本角色 | 融合稿建议字号／行高 | 字重与说明 |
| --- | --- | --- |
| 根页标题 | 18–20 / 26pt | 600；左对齐 |
| 二级页导航标题 | 17–18 / 24pt | 600；紧凑居中，和正文标题分开 |
| 详情主标题／人名 | 18–20 / 26pt | 600；可换行 |
| 章节标题 | 14 / 20pt | 600；浅蓝带内左对齐 |
| 列表名称 | 14–15 / 21pt | 500–600；不能靠加粗替代全部层级 |
| 字段值／正文 | 14–15 / 22–23pt | 400；资料以 14pt 起，长文以 15pt 起 |
| 标签／辅助信息 | 12–13 / 18–20pt | 400；保留足够对比 |
| 按钮文案 | 14–15 / 20pt | 500–600；点击区不随字变小 |

这些是细化起点，不是对所有文字机械缩放的指令。当前代码的 28pt 页面标题、22pt 标题、17pt 列表主文与 22pt 页边距应逐场景比对。保留已合适的页面。

长公司名、人名、邮件地址和用户正文保留原文。列表可展示两行摘要，详情／编辑必须能读完整内容。不能把用户数据改成较短的示例来通过验收。

### 阅读密度

人脉列表在普通字号首屏争取展示约 8–10 行，取决于筛选器和安全区；这是对比目标，不是硬性条数。活动约 3–4 行。AI 长回答保留段间距，不压成十几个紧密标签。

动态字号放大时，条数自然减少。允许标签和值从左右列变成上下布局，不能禁用字体缩放或强制单行。

## 5. 间距、容器与分隔

复用 4／8／12／16／24／32pt 的间距节奏。行内图文间距建议 10–12pt；区块之间 16–24pt；正文段间 12pt。

分区优先级：留白和对齐 → 细分隔 → 浅底色 → 必要边界 → 极少量阴影。普通列表不每行套一张卡片，详情不要“卡片里套卡片”。

- 章节条高建议 30–32pt，左侧 2pt 蓝线，标题离线 10–12pt。内容与条带之间留 8–12pt。
- 资料标签列建议 68pt；值列自适应。标签长时换行，不让值列被挤没。
- 输入框复用约 8–10pt 圆角和轻边界；文本域更高但与单行字段对齐。
- 列表头像约 36–44pt；活动缩略图约 88×64–72pt，不把所有事件都做成大海报。
- 只有悬浮底栏、弹层等确有浮层关系的组件使用轻阴影。正文卡片保持平。

## 6. 导航与页面壳

### 四个根页与中央动作

根页：首页 `/home`、人脉 `/contacts`、活动 `/events`、我的 `/profile`。中央 IORBIT 进入 `/ai` 或稳定会话地址，不是第五个持续显示底栏的根页。

底栏顺序固定：`首页 → 人脉 → IORBIT → 活动 → 我的`。普通根项为图标＋标签；中央项为蓝色圆角方块中的轨道图标，下方 `IORBIT`。选中项用浅蓝底／蓝色图标和标签表达，不能只改变一种不易察觉的色差。

胶囊建议：左右各 16pt、距安全区上缘约 12pt、主体约 72pt 高、完整大圆角。精确轮廓以首页原图为准，以上数字仅供标注和原生试配。不能将某张生成图中的贴底条或遮挡变成最终规格。

### 返回

根页无返回箭头。二级页使用明确来源；正常打开时返回真实来源，深链缺少栈时返回所属根页。AI 关闭回到进入前的根页／业务上下文，不强制回 `/ai`。

表单未保存的离开提示属于交互细化建议：保留编辑、放弃更改；不能伪称草稿已经持久保存。取消报名、删除会话等危险动作需要对象明确的确认。

### 顶部动作

最多一个醒目的主要动作。扫描、添加、分享、设置等图标采用现有 Ionicons 系列，统一线宽和视觉重量。每个图标有文本可访问名称，44pt 点击区；不可用动作说明原因，不留无响应图标。

## 8. 各页面族的区别

首页保留分栏日程／待办与简短内容；窄屏和大字号的分栏处理需要专门细化，不通过截字保持双列。

人脉列表使用紧凑人物行；详情使用身份块和对齐资料；资料编辑使用表单。人脉统计和钻取保留统计的语义，不用人物列表代替所有图表。

活动发现是图文列表；活动详情保留介绍、时间地点和资格；报名是有草稿的表单。运营页允许更密集的统计和管理行，但仍受角色控制。

日历保留日／周／月视图，时间轴位置由时间计算。不要照图片复制刻度和块高。待办允许没有联系人和没有确定时间。

IORBIT 长文和真实站内聊天不同。前者是文章式回答与引用；后者保留消息发送者、时间、送达／失败状态。私人邮件草稿必须明确是草稿。

“我的”展示身份与资料入口；设置承担偏好和账号操作；服务地址等低频配置不成为底栏项。管理员／平台页不向普通用户展示特权操作。

## 9. 可访问性与内容

正文对比度设计验收目标至少 4.5:1，大字和图标也应有足够对比。状态必须同时有文字或形状，不仅靠红绿。键盘焦点、屏幕阅读顺序跟随视觉顺序。

文案短、说明具体操作。使用“保存失败，输入已保留”“报名已截止”“你暂时没有查看权限”，不使用“系统异常”“数据为空”概括所有问题。用户端不出现 mock、hybrid、provider、command-center 或内部任务编号。

没有用户头像时用现有首字头像，不编造人物照片为真实用户。当前 PNG 中的姓名、头像、公司、活动和内容全部是虚构展示数据。

## 10. 交付与验收边界

Claude Design 应输出可继续编辑的设计稿和明确的组件／状态说明。本轮只提供静态图与规格，不承诺可编辑 Figma 源文件、可运行原型或原生精确排版。

图片逐页检查文字、结构和主要限制；文件检查只证明 PNG 可读、图片已保存和链接有效。原生字号、大字、键盘、触控、深色和真实接口仍必须单独验证，不能用静态图代替。
