## 用户反馈与本轮约束

第二轮虽然变化了照片、配色和场景，却继续出现大标题、大卡片、大片留白，首屏只容纳少量内容。用户再次明确否决“字体过大、信息过稀疏”。第二轮不再是待实施目标，仍保留原文件供追溯。

继续保留用户选中的[悬浮长岛底栏](../2026-09-11-bottom-navigation/03-floating-island.png)：首页／人脉／中央 IORBIT／活动／我的。IORBIT 仍打开独立全屏工作区。顶部不显示“首页”。

本轮以真实高密度界面为主要参照，约束的不只有字号，还包括可见记录数、行高、空隙和图片面积。目标正文 13pt、辅助 11–12pt、标题 14–15pt；这仍是生成目标，不把栅格图当作精确字体标注。通用“单一主用例、最多两个辅助区”的默认建议不适用于用户明确要求的多功能高密度首页。

## 选定后仍需校准的内容

- 第 2、5 张的窄栏要在真实 390pt 设备上检查最长文案和动态字号；紧凑行的触控区域不能只等于字面高度，必要时允许滚动。
- 第 3 张保持了蓝色底栏，但上部增加绿色方向；这不是整个 App 的品牌色已经更换。
- 栅格图中仍有局部渐变、较大的 ORBIT 字标或计数；实际字重、字号、纯色和图标需在选案修订中统一，不能把提示词当测量结果。
- 第 1 张的“已完成／即将开始”是同一天午后状态的虚构示例，不表示当前时刻或真实账号状态。第 5 张生成器附加了活动人数和“已报名／感兴趣”标签；不是用户已操作，也不是新“感兴趣”能力已获批准。后续应删除或映射到已确认的现有状态。
- 全局联系人搜索、新建入口、按人合并的日程与待办、最近笔记等，需按现有路由和 API 逐项核对；不得从概念图推断全部已有聚合接口。
- 没有运行 App 测试、实机交互、深色、动态字号、安全区或屏幕阅读器检查；没有进行 Web/App 双向业务验证。
