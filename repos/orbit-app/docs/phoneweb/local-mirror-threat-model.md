# phoneweb 本地镜像：威胁模型与降级声明

> 适用范围：浏览器端（phoneweb / `expo export --platform web`）的本地镜像存储层，落地于 Sprint 0077；Sprint 0125 把笔记加入白名单，Sprint 0115 把「你报名的活动」三个域加入白名单，Sprint 0116 把联系人加入白名单，Sprint 0117 把看板关系图（`dashboard-graph`）加入白名单，Sprint 0118 把收件箱通知（`inbox-notifications`）和 AI 会话（`ai-sessions`、`ai-session-messages`）加入白名单，Sprint 0119 把用户之间的消息（`relationship-conversations`、`relationship-messages`）加入白名单，Sprint 0131 加入 12 种「页面副本」（第 2 节「页面副本」）。
> 这是**浏览器本地镜像**，其保护与原生 SQLCipher + SecureStore **不同**，不得对用户或文档宣称等同。

## 1. 它是什么

| 组成 | 浏览器实现 | 原生实现（对照） |
| --- | --- | --- |
| 引擎 | expo-sqlite web：wa-sqlite（wasm）在 Worker 内运行 | expo-sqlite 原生（SQLCipher） |
| 持久化 | OPFS（`AccessHandlePoolVFS`），仅 secure context 可用 | 应用沙盒内 `.db` 文件 |
| 库名 | `orbit-sync-<sha256(baseUrl, actorId) 前 32 位>.db`（OPFS 路径名上限 64 字节） | `orbit-sync-<sha256 全长>.db` |
| 密钥 | Web Crypto AES-GCM-256 `CryptoKey`，`extractable: false`，存 IndexedDB `orbit-sync-keys` | 64 位十六进制随机密钥，存 SecureStore（`AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`） |
| 加密范围 | 仅 `sync_records.payload_json`（仓库边界 `payloadCodec`，每条记录独立 96 位 IV）；连接开启 `PRAGMA secure_delete`，删除的行在库文件里被清零（0125） | 整库（PRAGMA key） |
| 明文列 | `record_id`、`domain_id`、`workspace_id`、`revision`、`updated_at`、`payload_hash` 等元数据 | 无（整库密文） |
| 白名单域 | `notes`（0125 起）、`tasks`、`personal-schedule`、`event-registrations`、`registered-events`、`event-published-results`（0115 起）、`contacts`（0116 起）、`dashboard-graph`（0117 起）、`inbox-notifications`、`ai-sessions`、`ai-session-messages`（0118 起）、`relationship-conversations`、`relationship-messages`（0119 起） | 同左 |
| 退化 | 任一能力缺失 → online-only + 原因，`setScope` 返回 true、`withDatabase` 返回 null | SQLite 二进制缺失 → 同样退化 |

## 2. 白名单及逐域论证

| 域 | Web 是否落盘 | 理由 |
| --- | --- | --- |
| `tasks` | 是 | 正文为待办标题／截止／状态，泄露面小；离线可读的收益最直接（今日待办、跟进） |
| `personal-schedule` | 是 | 用户自己的日程条目，无第三方正文；与待办同属"接下来要做什么" |
| `notes` | **是**（Sprint 0125 起） | **用户 2026-09-27 决定放开**，见本节下方「笔记：决定与接受的风险」。0077 时的结论是「否」：联系人笔记含第三方私密内容与原文，浏览器同源脚本可解密 |
| `event-registrations`（0115） | 是 | 只有本人对自己报名过的活动的状态（已报名 / 已取消 / 审核中 / 候补 / 未通过）和活动编号，没有第三方内容；离线时要能说清「我报名了没有」 |
| `registered-events`（0115） | 是 | 只有本人仍有效报名（rsvped）的活动：标题、介绍、场地、时区、起止时间、签到和结果开放等配置时间。都是活动方公开发布的信息，公开活动详情页本来就给任何人看；不含主办方账号、参会人数以外的名单或工作人员数据 |
| `event-published-results`（0115） | 是 | 发布给本人的那一份结果：本人所在的桌（同桌成员的公开资料、座位、分桌理由和破冰建议）、推荐给本人的人选和理由，以及这场活动参会者名录的公开资料字段（姓名、公司、职位、行业、话题、语言、需求、可提供）。每一项都是同一浏览器会话已经能从 `GET /api/events/:id/operations` 明文读到的内容，字段白名单与该接口共用一个投影（`attendee-public.ts`）。不含关系图、别人的推荐和分桌、名片交换状态、签到状态、画像原文、主办方与工作人员视图。见下方「活动现场：决定与接受的风险」 |
| `contacts`（0116） | 是 | 本人的联系人：列表卡片、搜索文本、联系人详情（关系阶段、标签、本人详情状态里的备注和最近互动、本人引用的来源摘要）。含第三方（联系人本人）的资料和本人写下的关于他的内容，和笔记同级。见下方「联系人：决定与接受的风险」 |
| `dashboard-graph`（0117） | 是 | 本人关系图里每条记录一行：联系人、关系、本人的详情状态（只有标签）、本人名下的万能表 `events` 记录（只有名称、开始时间、来源、来源编号）、待办（标题、状态、关联、截止时间），字段是服务器看板计算读取的那份投影再去掉计算不读的字段（邮箱、电话、简介等）；来源（evidence）行只有记录时间，不含正文。和联系人域同级：含第三方的名片资料和本人写的关系摘要。见下方「看板关系图：决定与接受的风险」 |
| `inbox-notifications`（0118） | 是 | 本人的类型化收件箱通知（提醒、建议、动态），含历史：标题、原因、三种语言的文案、来源摘要、对象名、处置和已读状态。可能含第三方的名字（名片交换、约谈）和笔记摘要，和联系人域同级。来源已失效的通知以「来源已不可用」的形态下发，不带正文。见下方「收件箱与 AI 会话：决定与接受的风险」 |
| `ai-sessions`、`ai-session-messages`（0118） | 是 | 本人的 AI 会话列表（标题、第一个问题和最近一条的摘要、置顶／分组／自定义标题），以及本设备打开过的会话（最多 20 个）的消息原文：本人写下的问题和 AI 基于本人数据给出的回答，和笔记同级。卡片不同步，只缓存最后一次联网打开时的卡片。见下方「收件箱与 AI 会话：决定与接受的风险」 |
| `relationship-conversations`、`relationship-messages`（0119） | 是 | 本人仍是有效成员的对话（对方的名字、最后一条消息的 320 字预览、未读数、本人读到的序号），以及这些对话的**全部历史消息**：对方写给本人的原文和本人发出的原文。对方的原文是第三方私密内容（对方不知道这份副本在浏览器里），风险和笔记里关于第三方的内容同级。撤销关系后两人的设备都删除这个对话和它的全部消息。见下方「用户之间的消息：决定与接受的风险」 |
| 页面副本（0131）：`self-profile`、`agent-actions`、`agent-ledger`、`relationship-tasks`、`task-suggestions`、`today-page`、`today-summary`、`relationship-lifecycle`、`meeting-details`、`home-schedule`、`public-events`、`event-recommendations` | 是 | 服务器实时算出的页面，设备只保存上次联网读到的那一份，绑定租约的授权纪元。逐项论证见下方「页面副本：决定与接受的风险」 |
| 工作人员能看到的参会者名单、主办方运营数据 | 否 | 设计案 C 类，永不落地 |

白名单在 `web-mirror-storage.ts` 的 `WEB_MIRROR_DOMAIN_IDS`（同步域）和 `WEB_MIRROR_PAGE_COPY_IDS`（页面副本，0131）硬编码，协调器只为白名单域绑定读取作用域与拉页；租约里其它域的授权在浏览器**既不存储也不拉取**。

### 笔记：决定与接受的风险（Sprint 0125）

- **决定**：用户 2026-09-27 回复 0108 报告第 9 节第 1 条，决定浏览器版也把笔记放进本地镜像，phoneweb 断网时能看笔记。
- **接受的风险**：同源脚本（XSS、被注入的第三方脚本、能注入本站的浏览器扩展）可以借用不可导出的密钥解密笔记正文，也可以直接调用镜像仓库读出明文。笔记里包括联系人笔记中关于第三方的私密内容和原文（第三方本人没有同意，也不知道这份副本在浏览器里）。这一点与待办、个人日程相同，但笔记的泄露面大得多；原生的 SQLCipher + SecureStore 不存在这个问题。
- **已有缓解**（都由浏览器测试覆盖，`tests/web-notes-mirror-browser.test.ts`、`tests/web-mirror-storage-browser.test.ts`）：
  - **按源隔离**：OPFS 与 IndexedDB 只对本源可见，别的站点读不到。
  - **落盘加密**：每条笔记的 `payload_json` 是 AES-GCM 密文（每条独立 IV），直接读 OPFS 文件字节找不到标题和正文；记录 id、修订号、时间戳按本文件第 1 节为明文元数据。
  - **换身份清库删钥**：换账号、换服务器时先删密钥再删库文件。0125 起，打开一个身份时还会删掉本源里其他身份的密钥和库文件（包括这一页从未打开过的，例如会话过期后另一个人登录），同一个源只留一个身份的镜像。
  - **撤权按 epoch 清空**：租约不再授予 `notes` 时，协调器把该域所有 epoch 的行、游标、索引一起删除，页面不再显示；`secure_delete` 让被删的行不在库文件的空闲页里留下 id 或密文。
  - **非 secure context 不落盘**：经局域网 IP 等 http 地址访问时不创建库和密钥，笔记页回到在线读取，不报错。
  - **退出登录、清除站点数据**：镜像和密钥一并删除。
- **未缓解的部分**：同源脚本在页面打开期间能读到当前身份的全部笔记；这需要靠站点本身防 XSS（CSP、依赖审查）而不是本地镜像来防。
- **已有浏览器升级**：库结构与域列表无关，不需要清库重建。升级后第一次同步只多拉一次 `notes` 的首页（没有游标），待办和个人日程的游标不变、不重拉。拉完之前笔记页显示「正在同步」，不会显示成空列表。`secure_delete` 只影响升级之后的删除；升级前删掉的待办、日程行可能还留在旧库文件的空闲页里（密文和 id），换身份或退出登录删库时一起消失。

### 活动现场：决定与接受的风险（Sprint 0115）

- **决定**：按 0125 的规则逐域论证后，三个活动域都进浏览器镜像。协调者 2026-09-28 受用户委托批准的设计要求 phoneweb 断网也能打开活动详情、现场页（首页、参会者、分组、议程、资料面板）和日历，只放原生不能满足这一点。
- **为什么风险可以接受**：
  - 活动公开信息和本人报名状态本身几乎没有泄露面。
  - 「发布给我的结果」里有第三方（同场参会者）的资料，但只是参会者彼此可见的公开字段，和联网时同一会话从现场接口读到的完全相同。同源脚本在页面打开期间本来就能带着会话 Cookie 直接请求这个接口，所以本地副本没有让同源攻击者多拿到什么；它多出来的只是「会话过期或断网后，页面打开时仍可解密」这一段时间窗口。
  - 比笔记的风险小：没有本人写下的私密原文，也没有联系人笔记里的第三方评价。
- **已有缓解**（沿用第 2 节笔记的全部缓解：按源隔离、逐条 AES-GCM、换身份清库删钥、同源只留一个身份、撤权按 epoch 清空加 `secure_delete`、非 secure context 不落盘、退出登录删除），加上活动域自己的规则（服务端 `features/sync/event-domain-reader.ts`，真库测试 `sync-event-domains-postgres`）：
  - 取消报名、报名被拒或撤回后，下一次同步把这场活动和发布给本人的结果作为删除下发，本地行被删（`secure_delete` 让它不留在空闲页）。
  - 结果在 `resultsAvailableAt` 之前不下发；主办方重新发布而新结果尚未开放时，旧结果也作为删除下发。
  - 名录过大时只保留与本人结果有关的人（`directoryComplete: false`），单个活动不会让同步失败。
- **未缓解的部分**：页面打开期间，同源脚本能读到这些活动行，和笔记一样要靠站点防 XSS。活动方把整场活动删除（只有种子重置脚本 `resetEventForSeed` 和运维清理会这样做）时，源行消失，设备不会收到删除；要等下次换身份、退出登录或撤权才清掉。
- **已有浏览器升级**：库结构与域列表无关，不需要清库重建。升级后第一次同步给三个新域各拉一次首页（通常各 0–几行）。

### 联系人：决定与接受的风险（Sprint 0116）

- **决定**：按 0125 的规则逐项论证后，`contacts` 进浏览器镜像。协调者 2026-09-28 受用户委托批准的设计要求 phoneweb 断网也能打开联系人列表、搜索和详情（SC-0116-04），只放原生做不到这一点；用户在 0125 已为笔记接受了同一类风险。
- **下发的是什么**：每个联系人一行，字段白名单只有 `id`、`card`（列表卡片）、`tags`（本人详情状态的标签）、`search`（服务端搜索用的原文和排序键）、`detail`（`GET /api/contacts/:id` 的数据，去掉 provenance 和写入标记）。服务端从本人拥有的四类记录（contacts、connections、contact_detail_states、evidence，`user_id` = 本人）拼出，没有主人或属于别人的来源记录一律不读（`features/sync/contact-domain-reader.ts`，真库测试 `sync-contact-domain-postgres`）。不含记录元数据（provider、来源行、采集内部字段）。
- **为什么风险可以接受**：
  - 每一项都是同一浏览器会话从 `/api/contacts/page`、`/api/contacts/:id` 明文读到的内容；同源脚本本来就能带着会话 Cookie 直接请求这些接口，本地副本多出来的只是「会话过期或断网后，页面打开期间仍可解密」这一段时间窗口。
  - 风险和笔记同级而不是更高：详情里的备注、最近互动、来源摘要是本人写下或采集的关于第三方的内容（第三方本人不知道这份副本），这正是 0125 为笔记接受的那一类。
- **已有缓解**：沿用第 2 节笔记的全部缓解（按源隔离、逐条 AES-GCM、换身份清库删钥、同源只留一个身份、撤权按 epoch 清空加 `secure_delete`、非 secure context 不落盘、退出登录删除），加上联系人自己的规则：
  - 软删除联系人后，下一次同步作为删除下发，本地行被删（`secure_delete` 不留在空闲页）；删掉一条关系、改一条来源或详情状态，会重发整个联系人，本地行被新版本覆盖。
  - 联系人、关系、详情状态、来源四类纳入主人守卫（0113 机制）：任何写入把已有主人的行改给别人或清空主人都会被数据库拒绝，所以不会出现「转手后旧主人的设备还留着」；产品里也没有联系人转手功能。
  - 没有主人（0114 判断不了）的来源行、只被别人引用的来源行、谁都没引用的来源行，永远不下发。
- **未缓解的部分**：页面打开期间，同源脚本能读到当前身份的全部联系人和详情，和笔记一样要靠站点防 XSS。关系行如果被改挂到另一个联系人名下（产品里没有这种写法），旧联系人在设备上的副本要等它自己下次变化才更新。
- **已有浏览器升级**：库结构与域列表无关，不需要清库重建。升级后第一次同步给 `contacts` 拉一次首页（每页最多约 768KB）；拉完之前联系人页显示「正在同步」，不会显示成空列表。

### 看板关系图：决定与接受的风险（Sprint 0117）

- **决定**：协调者 2026-09-28 受用户委托批准的设计（看板读取方案第 7 步）要求 App 上的看板和联系人分析由手机读本地数据自己算，断网也能看；phoneweb 断网也要能看，所以 `dashboard-graph` 进浏览器镜像。按 0125 的规则逐项论证如下。
- **下发的是什么**：本人（`user_id` = 本人）六类记录里每条一行，字段白名单只有 `collection`、`recordId`、`occurredAt`、`updatedAt`（记录的两个时间，UTC 微秒）和 `data`。`data` 是服务器看板读整张图时取的那份投影（`DASHBOARD_GRAPH_PROJECTION_SQL`），再去掉任何计算都不读的字段（`DASHBOARD_GRAPH_DEVICE_OMITTED_FIELDS`：联系人的 personId、邮箱、电话、简介，关系的信任度和共同话题，活动的地点和结束时间）：联系人的姓名、单位、职位、地点、行业、自定义标签、阶段、来源引用和时间；关系的阶段、价值类型、分数、摘要、建议动作；详情状态只有标签；活动只有名称、开始时间和来源引用；待办只有标题、状态、关联联系人和关系、截止时间。来源（evidence）行的 `data` 恒为 null：看板计算从不读来源正文，只用它的记录时间。联系人的 `accountId` 指向别的账号时，这一行不在本人的图里（作为删除下发）。服务端读取见 `features/sync/dashboard-graph-reader.ts`，真库测试 `sync-dashboard-graph-postgres`。
- **为什么风险可以接受**：
  - 每一项都是同一浏览器会话已经能从 `/api/dashboard*`、`/api/mobile/contacts-dashboard`、`/api/contacts/*` 明文读到的内容（看板和联系人分析的数字、短列表、名字，都是由这些字段算出来的）；同源脚本本来就能带着会话 Cookie 请求这些接口，本地副本多出来的只是「会话过期或断网后，页面打开期间仍可解密」这段时间窗口。
  - 和联系人域同级而不是更高：第三方资料和本人写的关系摘要与 `contacts` 域的 `detail` 相同；来源正文完全不下发，比联系人域的 `detail`（含来源摘要）还少。
- **已有缓解**：沿用第 2 节笔记的全部缓解（按源隔离、逐条 AES-GCM、换身份清库删钥、同源只留一个身份、撤权按 epoch 清空加 `secure_delete`、非 secure context 不落盘、退出登录删除），加上这个域自己的规则：
  - 软删除任一记录、联系人的 `accountId` 离开本人，下一次同步作为删除下发，本地行被删（`secure_delete` 不留在空闲页）。
  - 六类记录全部纳入主人守卫和提交顺序锁（0113 机制）。万能表 `events` 从本 Sprint 起也在其中：产品代码改不了一条活动记录的主人。唯一登记的「转手」处理方式是演示种子的活动主人重置（`demo-event-owner-reset`），它在同一事务里轮换原主人的授权纪元，原主人的设备随之整域重建、不再持有这些活动。
- **未缓解的部分**：页面打开期间，同源脚本能读到当前身份的整张关系图，和笔记一样要靠站点防 XSS。硬删除（产品里没有，只有种子重置或运维清理）不会下发删除，要等下次换身份、退出登录或撤权才清掉。
- **已有浏览器升级**：库结构与域列表无关，不需要清库重建。升级后第一次同步给 `dashboard-graph` 拉一次首页（重度账号约 5,000 行、数 MB，按页拉取，每页 ≤768KB）；拉完之前看板和联系人分析显示「正在同步」。

### 收件箱与 AI 会话：决定与接受的风险（Sprint 0118）

- **决定**：协调者 2026-09-28 受用户委托批准的设计要求 phoneweb 断网也能打开收件箱（含详情）、AI 会话列表和打开过的会话（SC-0118-04），只放原生做不到这一点。按 0125 为笔记定下的规则逐项论证后，三个域都进浏览器镜像。
- **下发的是什么**：
  - `inbox-notifications`：本人（`user_id` = 本人）每条通知一行，字段白名单是通知本身去掉 `actorId`，加上服务器对来源是否仍可用的判断 `sourceState`（`features/sync/inbox-domain-reader.ts`）。来源已失效（联系人被删、约谈取消、交换申请撤销等）的通知，服务器在同步前把判断写回这一行（领新流水号），下发时去掉 `copy`、`object`、来源摘要和已建待办，只留「来源已不可用」。
  - `ai-sessions`：本人个人子空间里每个会话一行：服务器会话列表那一项（标题、第一个问题和最近一条各截 240 字、条数、时间），加本人的整理信息（置顶、分组、自定义标题）。
  - `ai-session-messages`：只下发同步请求点名的会话，即本设备打开过的会话（最近打开的 20 个，更早的在本机删除）；一个会话第一次被点名时从最近 50 条开始，之后是新增或修改的消息。卡片（请求记录）不同步：App 只在本机缓存最后一次联网打开时拿到的卡片，淘汰会话时一起删除。
- **为什么风险可以接受**：
  - 每一项都是同一浏览器会话从 `/api/inbox/notifications`、`/api/ai/conversations/sessions`、`/api/ai/conversations/sessions/:id` 明文读到的内容；同源脚本本来就能带着会话 Cookie 请求这些接口。本地副本多出来的，只是「会话过期或断网后，页面打开期间仍可解密」这一段时间窗口。
  - AI 会话的正文是本人写下的私密内容，加上 AI 基于本人联系人、笔记给出的回答，风险和笔记同级，是用户在 0125 为笔记接受过的那一类；收件箱和联系人同级。
  - 范围有上限：消息只到本设备打开过的 20 个会话，不是全部会话。
- **已有缓解**：沿用第 2 节笔记的全部缓解（按源隔离、逐条 AES-GCM、换身份清库删钥、同源只留一个身份、撤权按 epoch 清空加 `secure_delete`、非 secure context 不落盘、退出登录删除），加上这三个域自己的规则：
  - 来源失效的通知下发时不带正文，本地行被覆盖为「来源已不可用」；归档或删除的通知作为删除下发。
  - 删除 AI 会话后，会话行和它的消息都作为删除下发（`secure_delete` 不留在空闲页）。
  - 本设备淘汰一个打开过的会话时，删除它的消息行和缓存卡片；缓存卡片和消息一样经过 `payloadCodec` 逐条加密（`sync_meta` 里的值）。打开过的会话 id 列表本身是明文元数据，和 `record_id` 同级。
  - 四类集合（`inboxNotifications`、`orbit_agent_chat_sessions`、`orbit_agent_chat_messages`、`orbit_agent_chat_session_organizations`）纳入提交顺序锁；收件箱和整理信息纳入主人守卫（`user_id`），AI 会话和消息的主人是个人子空间，数据库守卫拒绝把它们移到别的 workspace 或集合。
- **未缓解的部分**：页面打开期间，同源脚本能读到当前身份的收件箱和打开过的会话原文，和笔记一样要靠站点防 XSS。服务器端硬删除（产品里没有）不会下发删除，要等下次换身份、退出登录或撤权才清掉。
- **已有浏览器升级**：库结构与域列表无关，不需要清库重建。升级后第一次同步给三个新域各拉一次首页；消息域在打开某个会话之前是空的。

### 用户之间的消息：决定与接受的风险（Sprint 0119）

- **决定**：协调者 2026-09-28 受用户委托批准的设计要求收件箱对话列表和聊天页本地优先，断网时 phoneweb 也要显示对话列表和聊天历史并标明「截至」（SC-0119-04），只放原生做不到这一点。用户决定手机本地放全部历史（消息数据方案第 9 步决定 5）。按 0125 为笔记定下的规则逐项论证后，两个域都进浏览器镜像。
- **下发的是什么**（`features/sync/relationship-message-domain-reader.ts`，真库测试 `sync-relationship-messages-postgres`）：
  - `relationship-conversations`：本人每一行成员记录对应一行（主人 = 成员表的 `account_id`），内容是服务器会话摘要页的那一项（对话编号、本人的联系人编号、两人的账号和显示名、资格版本号、最后一条消息的编号、发送人、时间和 320 字预览、本人的未读数），加本人读到的序号和对话的最新序号。服务器摘要页和这一行用同一段 SQL 生成。
  - `relationship-messages`：本人为有效成员的对话里的每一条消息（全部历史），行编号 `对话编号/序号`，内容是发送人、发送人显示名、正文、发送时间。
- **为什么风险可以接受**：
  - 每一项都是同一浏览器会话从 `/api/relationship-communication/conversation-summaries`、`/conversations/:id/messages` 明文读到的内容（后者可以一页页往前翻到第一条）；同源脚本本来就能带着会话 Cookie 请求这些接口。本地副本多出来的，是「会话过期或断网后，页面打开期间仍可解密」这段时间窗口，以及「不用联网就能一次读到全部历史」。
  - 对方写的消息是第三方私密内容，和 0125 为笔记接受的「联系人笔记里关于第三方的内容」同一类；和笔记不同的是，这些内容本来就是对方主动发给本人看的。
- **已有缓解**：沿用第 2 节笔记的全部缓解（按源隔离、逐条 AES-GCM、换身份清库删钥、同源只留一个身份、撤权按 epoch 清空加 `secure_delete`、非 secure context 不落盘、退出登录删除），加上这两个域自己的规则：
  - **撤销关系后两边都删**：撤销把两行成员标为「已离开」，各领新流水号；两台设备下一次同步都收到这个对话的删除，本地仓库在同一个事务里按行编号前缀删掉这个对话的全部消息（所有 epoch），`secure_delete` 不留在空闲页。服务器上的对话、成员和消息都保留（用户决定）。
  - **离开的人不会回来**：数据库守卫拒绝把成员行从「已离开」改回「有效」、把已撤销的对话改回有效，也拒绝把成员行、对话或消息挪到别的账号、对话或 workspace（`SYNC_RELATIONSHIP_OWNER_GUARD_SQL`）。设备删掉的历史不会再被下发，所以这条规则保证不会出现「重新加入后历史缺一截」。
  - 三张表纳入提交顺序锁（0109），书签可靠；第三个账号的对话和消息一行都不会读到。
- **未缓解的部分**：页面打开期间，同源脚本能读到当前身份全部对话的全部历史，和笔记一样要靠站点防 XSS。行编号（对话编号和序号）是明文元数据：能看出有几个对话、每个对话大约多少条消息，看不到内容和对方是谁。服务器端硬删除（产品里没有，消息永久保留）不会下发删除。
- **已有浏览器升级**：库结构与域列表无关，不需要清库重建。升级后第一次同步给两个新域各拉首页；消息按流水号从旧到新分页下发（每页 ≤768KB），全部拉完之前聊天页显示「正在同步」。

### 页面副本：决定与接受的风险（Sprint 0131）

- **决定**：用户 2026-09-28 要求「我需要这些离线也能看」，协调者按授权批准：首页、个人资料、Agent 动作中心和 All Actions 账本、关系待办、待办建议、今日、关系下一步、约谈详情、活动列表和推荐，断网时都显示上次同步的内容和「截至」，phoneweb 同样覆盖。这些页面由服务器每次实时计算（资料服务、Agent 队列、跟进分类 SQL、今日服务、推荐排序、公开目录），没有可以增量下发的行，所以不新增同步域，而是保存「页面副本」：该页面最近一次成功的联网读取结果（`src/data/sync/page-copies.ts` 的 `PAGE_COPY_DEFINITIONS`，共 12 种）。
- **存在哪、怎么绑定**：存在当前身份自己的本地库 `sync_meta` 里（原生：SQLCipher 整库加密；浏览器：每个值经 `payloadCodec` 单独 AES-GCM 加密，和同步行相同）。键里带「工作区 + 授权纪元」，这两个值取自当前被接受的离线读取租约：
  - 每次同步接受新租约时，删除所有不属于该纪元的副本（纪元轮换，例如权限变化、演示重置）；租约不再授予任何域时，全部删除（撤权）。
  - 只有在已接受的租约有效期内（≤ 7 天、同一账号、同一服务器）才能读；租约过期后副本和同步域一样锁定。
  - 换账号、换服务器、退出登录时整库删除（第 3 节「同一浏览器换账号」）。
  - 只从 2xx 且通过页面自身校验的回应保存；每种副本有字节上限（128–512KB），超过就不保存并删除旧副本；按项目保存的两种（关系下一步、约谈详情）只保留最近打开的 20 个。
- **为什么不需要主人守卫和提交顺序锁**：这两样保护的是增量同步（行离开主人时要作为删除下发；书签不能漏掉先领号后提交的行）。页面副本每次整份替换，没有书签可漏；内容就是同一会话刚从服务器拿到的回应，主人就是当时登录的账号，权限变化由授权纪元的轮换清除。
- **逐项论证**（每一项都是同一浏览器会话从对应接口明文读到的内容；同源脚本本来就能带着会话 Cookie 请求这些接口，本地副本多出来的只是「会话过期或断网后，页面打开期间仍可解密」这段时间窗口）：
  | 副本 | 接口 | 内容与级别 |
  | --- | --- | --- |
  | `self-profile` | `/api/profile` | 本人资料（名片字段、标签、介绍）。本人自己的数据，低于联系人域 |
  | `agent-actions` | `/api/agent/actions` | Agent 建议的动作（联系人名字、理由、建议做法）。和收件箱同级 |
  | `agent-ledger` | `/api/agent/ledger`（最多 3 页） | Agent 操作记录（标题、原因、状态、来源标签）。和收件箱同级；3 页是首屏加一周的正常活动量 |
  | `relationship-tasks`、`task-suggestions`、`today-page`、`today-summary` | 跟进、建议、今日接口的第一页 | 待办标题、联系人名字、截止时间。和待办域同级 |
  | `relationship-lifecycle` | `/api/connections/:id/lifecycle`（最近 20 个） | 一段关系的阶段和下一步。和联系人域同级 |
  | `meeting-details` | `/api/schedule-items/:id/meeting-details`（最近 20 个） | 约谈的时间、地点、对方、议程。和联系人域同级 |
  | `home-schedule` | `/api/schedule-items` | 首页日程卡的上次回应；断网时只用其中已确认的约谈（个人日程和已报名活动读同步域）。和个人日程同级 |
  | `event-recommendations` | `/api/recommendations/events` | 给本人的活动推荐。低 |
  | `public-events` | `/api/events/public` | **公开活动目录，平台数据，不按用户归属**：任何访客都能读到。仍按身份保存和清除（而不是做成全设备共享缓存），这样只有一条清除规则，也不会让下一个登录的人看到上一个人浏览过的目录时间点。泄露面几乎为零 |
- **未缓解的部分**：页面打开期间同源脚本能读到这些副本，和笔记一样要靠站点防 XSS。副本反映的是上次联网时的服务器结论：例如一条 Agent 建议在服务器上已被别处处理，断网时仍会显示（页面顶部的「截至」说明了这一点，所有写入入口在断网时都禁用）。
- **已有浏览器升级**：库结构不变（用 `sync_meta`），不需要清库重建；升级后第一次联网打开这些页面时各保存一次。

## 3. 威胁模型

| 威胁 | 浏览器镜像的结论 | 说明 |
| --- | --- | --- |
| 物理拿到设备磁盘、离线读取 OPFS 文件 | **正文受保护**，元数据不受保护 | `payload_json` 为 AES-GCM 密文；密钥不在文件里，而在浏览器配置文件的 IndexedDB 中（同一磁盘上，由浏览器自身的配置文件加密与操作系统账户保护）。记录 id、修订号、时间戳明文可见 |
| 导出密钥 | 不可能（JS 层面） | `extractable: false`；`crypto.subtle.exportKey` 抛 `InvalidAccessError`（浏览器测试 SC-0077-02 覆盖） |
| **同源脚本**（XSS、被注入的第三方脚本、恶意扩展） | **不受保护** | 同源脚本可以*使用*密钥解密（虽不能导出），也可直接调用镜像仓库。这是与原生最本质的差异：原生的 SecureStore 与沙盒把攻击面限制在应用进程内。0125 起这包括笔记正文与联系人笔记里的第三方内容，是用户明确接受的风险（第 2 节） |
| 跨站点／跨源 | 受保护 | OPFS 与 IndexedDB 按源隔离 |
| 同一浏览器换账号 | 受保护 | 换 actor 或换 server 即换库换密钥；切换前先记录 pending-cleanup，再关库、删密钥、删文件；上一身份的行不会留给下一身份（浏览器测试 SC-0077-03）。0125 起打开任一身份时也删除本源内其他身份的密钥和文件，覆盖「上一身份在这一页从未打开」的情况（SC-0125-02） |
| 密钥丢失、文件残留（清了 IndexedDB 未清 OPFS，或恢复的配置文件） | 受保护 | 无密钥的库文件视为孤儿：先删除再生成新密钥，绝不用新密钥打开旧文件 |
| 撤权（租约不再含该域） | 受保护 | 复用 0075 协调器路径：域按 epoch 退役并清空；`secure_delete` 保证删除的行不留在空闲页（0125） |
| 撤销关系（0119） | 受保护 | 两行成员标为「已离开」并领新流水号，双方设备收到对话删除，本地仓库连同这个对话的全部消息一起删除；成员行不能从「已离开」改回，历史不会以残缺形式回来 |
| 通知来源失效（0118） | 受保护 | 服务器在同步前把读取时的判断写回通知行并领新流水号，设备收到不带正文的「来源已不可用」 |
| 删除 AI 会话、淘汰打开过的会话（0118） | 受保护 | 删除作为删除下发；本机淘汰时删消息行和缓存卡片 |
| 删除联系人（0116） | 受保护 | 联系人软删除后领到新流水号，作为删除下发；本地行被删除（`secure_delete`） |
| 看板关系图的记录删除或离开本人（0117） | 受保护 | 软删除、联系人 `accountId` 离开本人都领新流水号并作为删除下发；活动记录转手只有登记的演示重置一种，它轮换原主人的授权纪元，设备整域重建 |
| 取消报名、报名被拒（0115） | 受保护 | 报名记录的主人仍是本人并领到新流水号，活动域据此下发删除；本地这场活动和发布给本人的结果被删除，只留下「已取消 / 未通过」状态行 |
| 页面副本（0131）的纪元轮换、撤权、租约过期 | 受保护 | 接受新租约时删除其他纪元的副本，租约不授予任何域时全部删除；租约过期后不可读；按项目的副本只留最近 20 个 |
| 浏览器"清除站点数据" | 镜像与密钥一并删除 | 这是预期行为，不是故障；下次登录重新拉取 |
| 非 secure context（例如经局域网 IP 访问 phoneweb） | 不落盘 | OPFS 与 `crypto.subtle` 在非 secure context 不可用；设置页显示"需要 HTTPS 或 localhost" |
| SharedArrayBuffer / COOP-COEP | 不需要 | 只使用 expo-sqlite 的异步 API；不提升页面隔离级别 |

## 4. 降级声明

以下任一情形，浏览器保持**在线读取**，不抛错、不弹窗，只在设置页"本地镜像"卡片给出原因：

| 原因码 | 触发 | 设置页文案 |
| --- | --- | --- |
| `insecure-context` | `window.isSecureContext === false` | 需要 HTTPS 或 localhost |
| `no-opfs` | `navigator.storage.getDirectory` 缺失 | 浏览器缺少 OPFS、IndexedDB 或 Web Crypto 支持 |
| `no-indexeddb` / `no-webcrypto` / `no-worker` | 对应全局对象缺失 | 同上 |
| `open-failed` | 运行期失败：IndexedDB 打不开、Worker/wasm 加载失败、开库或迁移失败 | 同上；本页面会话内保持在线读取，刷新页面重试。密钥与文件保留，不会因一次失败被抹掉 |

## 5. 部署要求（phoneweb）

- expo-sqlite web 以 `new Worker(new URL("./worker", location.href))` 启动 Worker，请求路径随当前路由变化。`scripts/build-web-sqlite-worker.mjs` 预构建 `public/worker.js` 与 `public/wa-sqlite-<hash>.wasm`（由 `npm run web:export` 自动执行）；`phoneweb-server.cjs` 把任何以 `worker` 结尾的路径映射到 `/worker.js`，并以 `application/wasm` 提供 wasm。
- 局域网 IP 访问是非 secure context：这是浏览器规则，不是缺陷。要在手机上验证落盘，需 HTTPS（例如 zrok 隧道）或桌面 `localhost`。

## 6. 离线冷启动身份（Sprint 0127）

用户 2026-09-27 决定：断网时冷启动，信任上次联网验证过的身份，最长 30 天。

| 项 | 原生 | 浏览器 |
| --- | --- | --- |
| 存什么 | `{baseUrl, accountId, user{id,email,name}, validatedAt}`；不含 Cookie | 同左 |
| 存在哪 | SecureStore `orbit.offlineIdentity.<baseUrl>`，`AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`，与会话 Cookie 同级 | IndexedDB `orbit-sync-keys`（与镜像密钥同库）；只在本地镜像可用（secure context 等）时写入，否则离线冷启动保持关闭 |
| 何时写 | 登录成功、联网冷启动校验成功、断网恢复后复核成功、在线时回前台且距上次校验超过 12 小时 | 同左 |
| 何时删 | 退出登录（第一步）、服务端明确拒绝（401/403 或 Auth.js 会话为空：停用、改密、撤销） | 同左 |

判定规则（`src/api/offline-identity.ts`）：

- **拒绝**：`/api/auth/session` 返回 401/403，或 2xx 的 JSON 里没有 user；`/api/account/me` 返回 401/403。清掉身份记录，再用换账号的清理路径（打开该账号作用域后 `setScope(null)`，带崩溃恢复标记）删除本地库和密钥，最后删 Cookie。
- **不可达**：网络错误、超时、5xx、404、2xx 但不是 JSON（例如强制门户页）。距 `validatedAt` 不超过 30 天就用缓存身份进入并打开该账号的本地库；超过 30 天或没有记录则进登录页，不删任何数据。
- 进入离线后每 10 秒、以及每次回到前台复核一次；联网后服务端拒绝则清空并退回登录页；仍不可达且已满 30 天则回登录页，不删数据。
- 界面语言：服务端确认过的语言偏好随身份一起存（同一存储、同一清除时机），离线时用它而不是设备语言。
- 会话恢复重新运行（Sprint 0130）：浏览器前进后退、错误边界「重试」、根布局重新挂载、开发版改动认证文件后的 Fast Refresh 都会让恢复流程再跑一次。恢复开始时只「挂起」已打开的本地库（`suspendScope`：暂停读写，不关库、不删库、不删密钥）；确认是同一（服务器、账号）后原样恢复，不重拉。以下情况才清空：服务器不同（挂起时立即清空）、确认成另一个账号、服务端明确拒绝（沿用上面的「拒绝」定义）、原生端没有保存的会话、退出登录。浏览器端的退出登录此前不删本地库（要等下一个身份打开时才删），0130 起与原生一样在退出时删库删钥。

已知限制：

- 设备时钟被往回拨可以延长 30 天窗口；本地没有可信时间源。
- 服务端校验用户状态时若数据库故障，Auth.js 也会返回空会话，客户端会按「拒绝」清空本地数据（数据在服务端仍在，重新登录后重新拉取）。
- 升级前已登录、升级后从未联网校验过的设备没有记录，第一次断网冷启动仍进登录页。
- 离线可读的内容还受服务端下发的离线读取租约约束（≤7 天）；租约过期后身份仍被信任，但本地数据会显示为锁定。
