## 功能映射与本版取舍

以下是 Orbit 的具体提案；不是声称 ChatGPT 所有细节都这样实现。

| 对象／动作 | Orbit 本版规则 |
| --- | --- |
| 分组 | 使用“分组”名称表达项目式容器，避免与 Orbit 的其他业务项目混淆。一层结构，一个会话最多属于一个分组；不做嵌套目录或多标签系统。 |
| 侧栏 | 搜索／新对话 → 分组入口与列表 → 置顶会话 → 最近会话。分组打开后展示本组会话；全局最近列表展示未分组且未置顶会话。全局置顶可引用组内会话并标注所属组，不复制记录。 |
| 新建分组 | 输入非空名称后保存，名称上限 80 字符；允许同名，以稳定 ID 区分。可改名。取消不创建空记录。 |
| 组内新对话 | 在组内点新对话，首次发送后归入该组；未发送草稿不进入会话历史。组归属不是结构化 AI 入口，也不会带入同组其他对话内容。 |
| 移动 | 长按会话／更多 → 移动到分组 → 选择已有分组或新建；允许移到另一个组及移出为未分组。保留会话 ID、消息、开头与置顶状态。 |
| 置顶 | 长按／更多可置顶及取消。各列表先置顶后按最近消息时间降序，同时间以 ID 稳定排序；改名／移组不伪装为新消息。不设照搬订阅套餐的置顶数量限制。 |
| 改名 | 同一菜单修改展示标题，非空、最多 120 字符。原标题／第一条发送内容和入口元信息不随之变化。 |
| 搜索 | 在服务端当前账号可访问的全部历史中按标题及已保存用户消息原文做文本匹配，可限定分组；不是只搜已加载的 12／50 条，不新增向量搜索或模型调用。 |
| 删除会话 | 显示会话名称和确认提示。成功回执后从全部列表移除；若正在打开该会话，停止继续写该 ID 并回到空白新对话。失败保留会话并提示可重试。 |
| 删除分组 | 本版选择“删除分组，保留会话”：确认后原子移出所有会话为未分组，再删除容器。明确显示保留会话，不提供隐含批量删会话。此项刻意不同于 ChatGPT 的删除项目连带删除内容规则。 |
| 归档／分享 | 截图中存在，但不是本次要求的必需功能，本 Sprint 不新增；不展示无实现的假菜单。分组共享、成员管理、文件和项目记忆也排除。 |
| 来源详情 | 会话更多菜单内“会话信息”展示入口名称、模板版本（适用时）、创建时间和第一条实际发送内容。常规历史列表不强塞技术字段。关联对象不存在或无权限时只显示“关联内容不可用”，不泄漏其原文。 |

列表分页、空态、加载中、失败重试均为必需状态。长按另有可聚焦的更多按钮，保证屏幕阅读器及不能长按时仍可操作；不新增全 App 导航或设计系统。

## 入口信息不等于分组

- **最初入口**：首次发送时冻结，描述用户从哪里开始；例：新对话、首页问题、联系人模板、笔记模板。
- **最初内容**：用户编辑后实际发送的第一条消息，不是模板默认文字，更不是模型返回后截取的最新消息。
- **当前分组**：用户随时可调整的整理信息；移动不会改写最初入口，组内新对话也不因此被伪标为模板入口。
- **续聊入口**：从历史或另一个页面重新打开同一会话，不覆盖其起源；本版不建设逐次访问轨迹或行为分析系统。
- **旧来源未知**：旧数据没有可靠记录则标为未知。现有 `source: conversation/session` 是存储来源，不能拿它冒充业务入口，更不能用标题猜测。

结构化入口只带用户已批准的引用／模板进入 IORBIT，仍由用户确认发送；记录元信息不新增自动调用、自动发消息或自动创建事项。
