# Sprint 0113 — 同步地基：说明书、主人检查、专用表取号

## 要实现什么

要把活动、联系人、通知、AI 对话、消息放进手机，同步程序得先会三件事：

1. 每类数据自带一份「说明书」：归属怎么判断、哪些字段影响谁能看、跟着一起下发的附属数据、下发哪些字段、从哪里读（万能表、专用表或个人子空间）。
2. 一道自动检查：任何代码或批量脚本改了同步数据的「主人」或「身份」字段却没有相应处理，测试就报错。顺带修掉一个已发现的问题：通用写入在更新时会把没传的主人清空。
3. 让专用表（活动相关）也能领流水号，这样手机的书签对专用表同样有效。

本 Sprint 只打地基，不新增任何放进手机的数据类别（从 0115 起逐类加入）。

## 做完能看到什么

- 同步注册表升级到第 2 版，笔记、待办、个人日程三类都有完整说明书，行为不变。
- 故意写一段改主人的代码、或一个批量改主人的脚本，自动检查会报错。
- 通用写入更新一行时，没传主人不再把原来的主人清空。
- 活动的几张专用表每次新建或修改都领流水号，同步程序能按说明书从专用表读取（先用一个测试类别验证）。
- App 按服务器下发的类别清单同步，不再写死三类。

## 怎么验收

说明书与检查各有真库测试；三类现有数据的双账号同步测试结果与改前一致；专用表测试类别的增量同步（全量 → 改一行传一行 → 再同步 0 行）通过。
