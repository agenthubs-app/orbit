## 链接校验是推广，不是放宽

Planner 判断 1 说这条 refinement 必须按 kind 推广。落地时发现它**不是一条均匀的规则**，表里就照实写成不均匀的：

- 人脉推荐带 `contact:review:<id>` action，可以拿来绑定，**这个要求保留**；
- `data_query` 条目（待办／日程／笔记）**一个 action 都没有**，无从绑定，只能以自身 id 为准；
- 但无论哪种，**只要带了指向别的记录的 href，链接一律作废** —— 这条比原来更严：原实现只校验那一条 review action，站外 href 挂在别的 action 上就漏过去了。

## 两个只有真跑才会发现的问题

**1. 日程的详情路由不是一个，是三个。** 卡片推导出 `/schedule/<id>`——这压根不是路由，点下去落到首页。真实路由是 `/schedule/personal|meetings|events/<id>`，由条目自己的 `kind` 字段决定。改成按 `kind` 取路由段，说不清自己是哪种的条目**不给链接**，而不是给一个走不通的。为此 `kind` 也进了恢复白名单——它不显示在卡面上，只用来决定去哪。

**2. 时刻按标签名判断格式，中文标签就漏了。** 原来只有 `/At$/` 的标签才格式化，所以 `startsAt` 读成"9/24 14:00"，同一个字段叫「开始」就原样打印 `2026-09-24T05:00:00.000Z`。改成按值判断：像 ISO 时刻就格式化，只有日期没有时间的（`2026-09-21`）保持原样，不凭空长出一个 00:00。

两个都是 0094 带进来的，单测没照出来——测试用的夹具恰好是英文标签的那几种，而"链接以正确前缀开头"不等于"那是个能走通的路由"。补了对应用例。
