# Sprint 0025 — 笔记 × 人脉搜索式关联

## 要实现什么

把现有笔记列表、编辑、详情和联系人笔记入口改成最新 4a Ink & Signal 设计；关联联系人时只显示一个加号／搜索入口，用户输入姓名词后再看到有限候选，不预加载或平铺全部联系人。

## 做完能看到什么

- 笔记列表具有标题、摘要、更新时间、关联人脉／活动和检索筛选；新建、阅读与编辑是清晰分开的页面状态。
- 编辑器支持通过 `@关键词` 或“已关联”旁的加号搜索联系人。候选按姓名、公司和职位区分同名者，选择后成为稳定 ID 关联；没有输入时不渲染全量联系人。
- 笔记详情显示关联来源、活动和由该笔记创建的待办；联系人详情的“笔记”页签可检索关联笔记并带着该联系人新建笔记。
- 保存失败、版本冲突、搜索迟到响应、切换账号／服务器和离线时都保留当前草稿，不显示虚假的“已保存”或空结果。

## 怎么验收

用大规模联系人夹具证明页面从不一次渲染全量联系人，并验证一字搜索、连续改词、同名选择、多选、取消和恢复草稿。随后启动当前源码构建出的 Web/API，让 Web 浏览器与原生 iOS App 使用同一账号和数据库，双向创建、编辑、搜索并回读同一篇笔记；Web/API 或共享契约改动后必须重新生产构建并重启服务再验收。
