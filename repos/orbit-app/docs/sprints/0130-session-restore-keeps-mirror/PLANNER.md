# Sprint 0130 — 会话恢复保留本地副本

**Plan revision:** 1。**模式:** existing-codebase / single-generator。运行状态只在登记表。
**原需求:** 0125 REPORT 第 8 节第 1 条。协调者在代码中核实：`AuthSessionProvider.tsx:206-210`，`restoreSession` 的第一步是 `syncLifecycle.setScope(null)`。原生 `sync-lifecycle.ts:135-168` 和浏览器 `sync-lifecycle.web.ts:215-243` 在 `current && !scope` 时都会 `purge()`，删库删钥。这个 effect 依赖 `[baseUrl, baseUrlReady]`（`:304`），provider 重新挂载或依赖变化都会让它再跑一次。协调者评为 P1，排在 0125 之后、0109 之前。
**单一目标:** 恢复同一身份时不清空本地副本；只在身份确实变化或服务端明确拒绝时清空。
**基线:** 0125 合并后的 `chat-agent`（开工时追加提交号）。执行顺序：0125 → **0130** → 0109。
**进入条件:** 无外部授权。

## 范围

1. **查清触发条件**：列出所有会让 `restoreSession` 重新运行的情况（provider 重新挂载、`baseUrl`/`baseUrlReady` 变化、错误边界重试、浏览器前进后退或 `popstate`、Expo Router 根布局重新挂载、开发版 Fast Refresh 等），每一项在原生和浏览器上分别验证是否触发。
2. **修复**：
   - 恢复流程不再无条件 `setScope(null)`。改为先判断：已打开的作用域与待恢复的（服务器、账号）是否相同。相同则保留；不同，或服务端明确拒绝（沿用 0127 的「拒绝」定义），才清空。
   - 在身份确认之前需要暂停读取时，可以只「挂起」作用域（不删库删钥），确认后再恢复。
   - 换账号、换服务器、退出登录、服务端拒绝这几条清空路径保持现有语义，测试不能退化，尤其是 0077 的「上一身份的行不会留给下一身份」和 0125 的「同一个源只保留一个身份」。
3. **断网下的重新挂载**：provider 重新挂载时如果网络不可达，按 0127 的离线身份规则进入，本地副本保留。
4. **0125 遗留**：断网时笔记列表的「返回首页」按钮没有反应，一并查清修复或登记原因。
- 排除：断网写。
