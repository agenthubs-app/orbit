# Sprint 0130 — 恢复登录时不再清掉本地副本

## 要实现什么

0125 在浏览器上发现，协调者核实后确认原生也有同样的风险：App 恢复登录会话时，第一步会调用 `syncLifecycle.setScope(null)`。**只要当时已经打开了本地库，这一步会把整个本地库删掉重建**，哪怕恢复的是同一个账号。

- 冷启动时还没有打开的库，所以不会删，断网冷启动能看到本地内容就是因为这个。
- 但根布局重新挂载、服务器地址重新确认等情况会让恢复流程再跑一次：在线时会悄悄整库重拉；断网时笔记、日程、待办页会变成「同步失败」，本地内容全部丢失，要等联网才恢复。

本地优先（0108、0125、0127，以及后面的 0115–0119）都建立在「本地副本不会被无故删除」之上，所以这个问题要先修。

## 做完能看到什么

- 同一个账号恢复登录时，本地副本原样保留，不重拉、不清空。
- 只有真正换了账号、换了服务器，或者服务端明确拒绝会话（0127 的规则）时，才清空本地数据。
- 浏览器的前进后退、错误重试、根布局重新挂载、服务器地址重新确认之后，断网状态下笔记、日程、待办依然能看。
- 查清并列出所有会让恢复流程重新运行的情况，逐一验证。
