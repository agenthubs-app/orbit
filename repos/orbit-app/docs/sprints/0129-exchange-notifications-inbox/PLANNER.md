# Sprint 0129 — 名片交换通知接入新收件箱

**Plan revision:** 1。**模式:** existing-codebase / single-generator。运行状态只在登记表。
**原需求:** 0127 REPORT 第 1、12 节：SC-0127-04 未满足的一半。
**单一目标:** 名片交换（以及其它只写旧通知表的类型）的通知在 App 与网页的新收件箱里可见、可读、可跳转。
**基线:** 0128 合并后的 `chat-agent`（开工时追加提交号）。执行顺序：0128 → **0129** → 0125 → 0109。
**进入条件:** 无外部授权。

## 已查明的事实

- 0127 运行时：event-operations worker 处理交换的 outbox 后，写入 created、accepted 两条通知到旧通知表，`/api/notifications` 可读；App 收件箱「通知」为空（截图 `evidence/sprint-0127/run-01/screens/10-a-inbox-notification.png`）。
- 0100、0104、0122 改过新收件箱（未读数用服务端全局总数；旧版 App 遇未知类型会整页失败，0104 已修）。
- 开工时先查清：旧通知表与新收件箱的数据模型、写入方与读取方清单；0118（通知放进手机）依赖新收件箱，本 Sprint 的结果要写成 0118 可直接使用的形式。

## 范围

1. 查清所有只写旧通知表的通知类型，列表写进报告。
2. 名片交换两类通知改为写入新收件箱（或由新收件箱读取时合并），并选定一种方式说明理由：
   - 避免双写不一致；
   - 未读数与全部已读口径与 0122 一致；
   - 点击跳转到现场页的资料面板（`/events/[id]/live?person=`）或已建的联系人。
3. 已有的旧通知：一次性迁入（可重复执行、预演 → 执行 → 再预演），或读取时合并去重，二选一，说明对生产的影响。
4. 其它类型：能接的接上，不能接的写明原因与建议去向。
5. 旧版 App 兼容：新类型不会让旧版收件箱整页失败（沿用 0104 的容错）。
- 排除：推送通知（Expo）；通知偏好设置的新功能。
