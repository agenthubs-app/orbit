## 固定产品边界

- 收件箱顶层只有“消息 / 通知”，首访消息，记住当前账号最近选择；外层只显示未读点。消息按未读消息数，通知按未读通知数分别计数。
- 消息是真实联系人通信，显示头像、真实称呼、原文、时间、阅读与发送状态；关闭 AI 和通知 Push 不影响通信。已删除联系人用明确不可用称呼，不回退内部 ID；历史正文不被 AI 改写。
- 通知只有提醒（time-outline）、建议（sparkles-outline）、动态（swap-horizontal-outline）。消息入口 chatbubble-ellipses-outline；通知入口 notifications-outline。文字标签始终存在，沿用 Ink 主题与 Web 对应图形。
- 每条通知有具体对象/动作、原因或变化、来源、时间信息和一个主操作。提醒必须有可信时间；建议可无截止日期；动态必须来自实际变化。来源不是额外类别。
- 阅读、忽略、已处理、已采纳、业务完成互相独立。通知全部已读不清除消息游标，消息已读不完成任何业务对象。关闭 Push 不删除入箱记录。
- 不发送“复核与某人的下一步”、单纯“久未联系”等空泛文案。系统文案遵循账号中/日/英语言；人名、原文、用户输入保持原样。

不新增微服务。现有 notifications 模块拥有通知记录、投递意图、源映射；原业务服务继续拥有任务、日程、消息等事实。使用现有持久化模式和迁移目录，启动时查实表与事务边界再登记必要文件。必须持久化的通知/动作/去重/投递账本不能只用进程内 Map。

三个阶段的启用边界：0037 先分离消息与现有通知列表；0038 以账号级开关启用新通知读面，旧数据暂不全量重放；0039 可在已授权 QA 账号自动入箱，但新增 AI Push 保持关闭；0040 验证策略、来源失效及旧流切换后启用新 Push。既有用户明确设定的提醒继续由原链唯一执行，不能因新开关关闭而丢失，也不能双响。新旧接口兼容窗口与回退映射由 0040 收口。

## 来源和自动发现门槛

来源为服务端已保存且当前账号可访问的笔记/会议说明、允许 AI 分析的 Orbit 消息、任务、日程/约谈/报名、联系人事实和用户目标、已实际接通且授权的邮件/日历、真实后台事件。外部连接不存在时标记不可用，不补建邮件产品或伪造数据；本期必须打通笔记、允许分析的消息、任务/日程和目标/联系人组合。

每个候选保留原文版本、作者、事实时间、读取时间和对象；模型仅提取和解释。权限、频率、分页、重试、门槛和路由由确定性代码执行。原文中的指令不允许更改权限、调用工具或发送消息。模糊时间不造日期，同名不猜绑定，“我会发送”按实际发言人解释；没有 Orbit 回复记录不等于未通过其他渠道回复。事件结束不证明参加过。AI 不自动发通信、不静默创建任务，采纳才调用现有幂等任务创建链。

AI 开关关闭后取消未执行的发现及该功能未投递意图，已入箱历史保留；再次开启不重放同版本内容。用户自己设定的提醒和真实业务动态不依赖模型。消息分析权限独立；来源撤权/删除后隐藏摘录、禁用动作并取消未投递意图，下一次请求不得返回已失权正文。

## 有界默认策略及测试常量

| 规则 | 固定默认值/行为 | 实现归属 |
| --- | --- | --- |
| 用户提醒 | 按显式时间执行，不占 AI 限额 | 0038 保持，0040 验证 |
| 原文明确承诺 | 精确未来时间前2小时；发现时已进窗口则当前；只有日期则账号时区当天09:00；不追推已过期旧承诺 | 0039 |
| 自动会前提醒 | 开始前30分钟；用户显式设置优先 | 0038 生成，0040 替换旧默认多阶段 |
| 自动 AI Push | 每账号本地日最多2次，建议最多占1次；多设备共用事务配额 | 0040 |
| 建议入箱 | 每账号本地日最多3条；普通建议静默；有真实时间窗口的建议才可能 Push | 0039 入箱，0040 Push |
| 消息提示 | 不占 AI 限额；每会话60秒内最多一次声音；应用内仍保留所有真实消息，支持免打扰 | 0040 |
| 安静时段 | 默认22:00–08:00；延期发送前重新核对，过期/完成不补推；用户显式选定夜间提醒允许例外，仍尊重 OS 设置 | 0040 |
| 建议有效期 | 7天或事实窗口结束，取较早者；重复扫描不续命；失效不计默认未读 | 0039 |
| 扫描上限 | 每页50个变更源，每账号每轮最多200条/4页，最多2次模型请求，每请求最多20个最小证据包；保留剩余游标，不丢分页剩余项 | 0039 |
| 重试上限 | 每候选最多3次调用（首次及两次重试，重试分别等待5分钟/30分钟）；永久失败或耗尽进入可见失败状态，不生成空话。中断恢复不重置计数 | 0039 |
| 费用 | 沿用项目 AI/OCR 累计 $5 硬限额，先核对账本及未结算预留；不足时停止付费步骤，保留进度，不扩额 | 0039/0040 |

扫描数是确定性执行预算，不是新的用户通知类型。队列按账号公平领取，事务租约、到期恢复与幂等 upsert 防止进程重启丢任务或重放。模型结构校验失败也消耗尝试次数；没有数据变化不重新调用。预算预留须在调用前原子扣留，未知费用不能当零。详细产品规则以设计规格为准；技术批量值变更保留原因与测试，不放宽用户硬限额。

去重按 actor+真实事项/动作语义关联，不能仅比较标题或 sourceId。确认为同一承诺的笔记、待办和日程合并证据到同一条提醒；无法确认相同则不自动合并不同事项，也不为含糊候选制造重复催促。已忽略/已处理同一事实永不因重扫复活；只有影响对象、动作或时间的有效事实变化才可产生新版本，普通改写不重置阅读。

## 执行与验证共同约束

遵守 [RULES](RULES.md)：单 Generator、不使用已卸载的 brainstorming/executing-plans、不另派评审；代码变更前逐符号 GitNexus impact，高风险先说明；按行为写 RED → 最小实现 → GREEN。本组涉及身份、持久化与投递，按 H 档；开发中定向测试，收口一次受影响端集成检查，重复全量仅有新风险/失败依据时运行。

每次启动记录实际 baseline HEAD、Planner SHA256、owner、文件锁、run-01 和环境；规划时不预填。每一 Planner 的文件白名单含本端相应行为测试；必须新增的接线文件按 RULES §0 记录用途和 SC，不因此重复问批准。App 不直连数据库或导入 Web 源码；共享 contract/schema 走现有同步脚本，不手改生成副本。

Web 浏览器和 iPhone 17 Pro Simulator 必须使用同一 QA 账号/数据库/API；通信再使用一个已授权真实测试账号作对方。同一记录必须验证双向操作后重开回读。Web/API/共享代码每次变更后，先 production build、停止旧进程、重启新产物、健康检查，再验 App。禁止只跑 Metro/mock/路由或继续使用旧 Web 进程。

每项保留页面、API和持久化结果的对应证据，脱敏存入 App build/harness-state/evidence/sprint-NNNN/run-01/，先确认路径被忽略。真实 OS 推送需要有效项目、provider、令牌和能收到远程推送的运行环境；Simulator 注入通知或列表可见不替代真实 provider→设备验收。

收口检查两端相关测试/typecheck、共享副本、Web构建/重启和原生运行。Git diff --check 与 GitNexus detect_changes 后按既有授权提交，协调者集成固定 SHA 到 chat-agent，并验证实际合并树；相同树可复用无影响证据。只有执行结束才创建 REPORT，记录逐SC结果、成本、缺项、版本、证据和交接。更新 bridge/status.md、bridge/handoffs.md 由协调者执行，不伪造 verified。push/远程发布只按已有适用授权，非本规划的新增要求。

局部失败最多两轮修复后评估，假设最多三次只读诊断；阻塞只绑定对应动作，继续无依赖工作。中断保存 checkpoint 并恢复原 run。迁移/真实外部写入核实精确目标和已有授权；先 dry-run，可恢复归档，不删除用户笔记/任务/消息，不把过期空话变成新未读。
