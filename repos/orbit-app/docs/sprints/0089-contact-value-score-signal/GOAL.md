# Sprint 0089 — 联系人列表那个"价值分"要么有区分度，要么别占位置

## 要实现什么

`/contacts/list` 每行最显眼的右侧位置放着一个价值分：78 个人里 76 个是 84，2 个是 72。这个数字几乎不携带信息，却占着列表里最贵的位置。本 Sprint 先查清 84 是怎么算出来的（种子写死、还是算法退化成常数），再决定：能算出真区分度就修算法，算不出就把这个位置让给真正有信息的内容，并且在分数不可信时不显示分数。

## 做完能看到什么

- 联系人列表右侧不再是一片相同的 84：要么是有分布的分数，要么是别的有信息的内容（如最近互动时间／待办数）。
- 分数缺失或不可信时显示为"—"或不显示，不用一个假的默认值填充。
- 一份分布报告：修前修后各自的取值分布。
