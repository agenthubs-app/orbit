## 已查明的事实（2026-09-28，开工时核对）

- 消息编号 = 对话 + 发送人 + requestId（`repos/orbits/features/relationship-communication/service.ts:236-243`）；发送事务锁对话行（`message-store.ts:252-291`）。
- 检查顺序是先资格（`:256-264`，REVOKED / STALE）后查重复（`:265`）；指纹包含 qualificationVersion（`:266-269`）。资格版本目前只在建立和撤销时变化（`service.ts:538`、`:589`）。
- 发送后服务器清掉「发送时刻及以前保存的草稿」（`service.ts:651`，0122）。
- App 聊天页断网时发送显示「需要联网」（0119）；资格表没有登记消息发送（`repos/orbit-app/src/api/schema/offline-policy.ts:46-49`）。

## 范围与文件

1. **服务器**：发送时先在同一事务、同一行锁内按消息编号查重复——已存在且发送人、对话、正文一致就返回原消息（不再要求资格版本相同）；之后才做资格检查。正文不同仍报 REQUEST_REUSED。离线重放的发送不得删除「发送之后才保存」的草稿（实现方式由 Generator 选，例如只在本次请求新建了消息时清理，并以真库测试钉住）。
2. **App 资格表**：登记消息发送为 `offline_queue`（只限本机有、状态有效的对话）。
3. **App 聊天页**：断网发送入队，requestId 即修改编号；待发送消息排在最后，气泡下方「待发送」，确认后用服务器序号与时间；失败显示「未发送 · 重试 · 复制」。提示条改为「消息会在联网后发送」。
4. **撤销处理**：对话已撤销或已离开时，待发送消息标失败；对话从本机删除后，收件箱顶部一行「N 条消息未能发送：这段关系已结束 · 复制内容 · 放弃」。
5. 收件箱列表的最新一条与未读数按叠加计算（自己发的不算未读）。
- 排除：标记已读、草稿、邀请、撤销的断网；图片与附件；浏览器版断网写。
