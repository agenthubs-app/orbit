# Sprint 0096 — 私有活动的可见位置

**Plan revision:** 1。**模式:** existing-codebase / single-generator。运行状态只在登记表。
**原需求:** 0093 报告「缺口」一节。
**单一目标:** 让聊天里创建的私有活动在 App 里可打开，且不因此对外可见。
**易读目标:** [GOAL.md](GOAL.md)。
**基线:** 0093 合并后的 `chat-agent`。未启动，run_count = 0。
**进入条件:** **需要用户就可见性语义做一次决定**（见判断 1）。在决定之前不进入实现。

## 已查明的事实（0093 实测）

| 事实 | 证据 |
| --- | --- |
| 记录确实建好了 | `events` 集合 16→17；`GET /api/events/<id>` 200，返回完整内容（标题、时间、地点、纳入理由） |
| App 详情页读的是公共目录 | 浏览器网络记录：`GET /api/events/public/<id>` → 404 |
| 不止详情页 | `route-domain-inventory.ts` 列出 7 个 App 活动界面全部读 `/api/events/public`：首页、活动列表、详情、报名、主办方、日程预览、平台页 |
| 公共目录是另一个子系统 | `features/events/core/public-catalogue*`，带 publicCode、organizerId、participantCount |
| 纳入理由已落盘 | 活动记录的 `evidence[].excerpt` 与 `relationshipContext` |

**判断 1（须用户决定）：私有活动的归属。** 两条路：
- **A. 私有活动有自己的详情路径**，不进公共目录。改动局限在一个新的读路径 + 草稿卡链接；公共目录语义不动。
- **B. 创建后需发布**，私有活动先是草稿态的公共活动，发布后才对外。语义更统一，但要处理主办方身份、报名、公共编码，改动面大得多。

没有用户决定之前不选。**A 是更小、更可逆的一条**，但它会让"活动"在 App 里存在两种详情页，这是要承认的代价。

**判断 2：不得让私有活动漏进任何对外列表。** 无论选哪条，必须有反例测试：另一个账号读不到；同账号的公共活动列表、主办方页不多出这条。

**判断 3：先确认这条记录到底属于谁。** 0093 写入时带的是 actorId 与 workspaceId；读路径必须按同一把尺子限定，不能只靠"知道 id"。
