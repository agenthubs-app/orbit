# Sprint 0139 — 通知发现入队不再因整表锁频繁失败

## 要实现什么

0137 在排查测试偶发失败时发现了一个生产风险：

- 通知发现的入队（`enqueuePage`）在最严格的 serializable 事务里，一次最多读 52 行 `orbit_records`。
- Postgres 给每张表最多记 32 个细粒度的读锁，超过以后会把锁升级成**整张表**的读锁。
- 一旦升级，任何用户往这张表写数据，都会让这次入队报冲突错误（40001）。重试三次也可能全部失败。
- 生产上所有用户都写同一张 `orbit_records` 表，用户一多，通知发现就会频繁失败。

## 做完能看到什么

- 别的账号持续写入 `orbit_records` 时，通知发现的入队照常成功，不会被无关的写入拖垮。
- 正确性不变：同一批候选不会被重复入队，也不会漏掉。
- 有一个能稳定复现「整表锁」的测试：修之前失败，修之后通过。
