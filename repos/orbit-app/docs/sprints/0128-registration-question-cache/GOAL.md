# Sprint 0128 — 报名问题只生成一次

## 要实现什么

0126 全局回归发现：主办方没有发布报名问题集时，**每一个可报名用户每读一次报名页，服务端就调用一次 DeepSeek 生成问题**，没有任何缓存。这在生产上同样存在：访问量越大，付费调用越多，而且同一场活动的问题会被反复生成、每次还不一样。

## 做完能看到什么

- 同一场活动、同一种语言，问题只在第一次需要时生成一次，保存下来，之后所有人读到的都是这一份，不再调用模型。
- 活动内容（标题、介绍、标签等影响问题的字段）变了，或主办方发布了问题集，才会换成新的问题。
- 多人同时打开报名页，也只会发出一次生成请求。
- 读报名页和提交报名时看到的是同一套问题，不会再出现「问题变了，请刷新」。

## 怎么验收

真库测试证明重复读取和并发读取只调用一次模型；运行时读取小票与付费登记对照。
