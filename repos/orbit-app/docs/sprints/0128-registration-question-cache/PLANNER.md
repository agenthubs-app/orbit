# Sprint 0128 — 报名问题缓存（每场活动每种语言只生成一次）

**Plan revision:** 1。**模式:** existing-codebase / single-generator。运行状态只在登记表。
**原需求:** 0126 REPORT 第 4、6 节登记的 P2；协调者评估为生产付费放大，升级为 P1，并于 2026-09-27 告知用户，排在 0127 之后。
**单一目标:** 报名问题在没有已发布问题集时只生成一次并持久保存，所有读取复用。
**基线:** 0127 合并后的 `chat-agent`（开工时追加提交号）。执行顺序：0127 → **0128** → 0129 → 0125 → 0109。
**进入条件:** 无外部授权。

## 已查明的事实（2026-09-27）

- `repos/orbits/app/api/events/[id]/registration/route-handlers.ts:303-360`：GET 在 `questions !== "false"` 且用户可以 register、reactivate、update 或 apply 时，先 `getPublishedQuestionSet(event.id)`，再调用 `generateEventRegistrationQuestions`。
- `features/events/registration/question-generator.ts:211`：有已发布问题集时直接返回（`aiProviderRequested: false`）；没有时，只要 `allowModelGeneration` 不为假就调用模型，结果不保存。
- 提交时用问题集校验（:461、:507「The registration questions changed」），所以生成结果不稳定时，读和写之间会不一致。
- `portraitProofs=true` 路径不允许模型生成，不在本问题内，但要确认它不受影响。

## 范围

1. **持久缓存**：
   - 键为（活动、语言、影响问题的活动内容的摘要），值为问题集和来源信息（模型、时间）。
   - 存放位置沿用现有存储习惯：万能表新类别，或活动专用表。选定后说明理由，并登记到读取量棘轮与离线清单。
2. **单次生成**：
   - 并发读取只允许一个请求调用模型，其余等待或读到结果。可用唯一约束加「先占位后填充」，也可用 advisory lock。
   - 生成失败时不缓存失败结果，按现有确定性回退返回，并记录日志；同一键在短时间内不重复失败重试，需设置退避。
3. **失效**：
   - 活动内容摘要变化时生成新的一份。
   - 主办方发布问题集后，始终优先用已发布的。
   - 旧缓存行保留，由提交校验按版本识别，不影响已经打开旧表单的用户提交。
4. **提交一致性**：提交校验读取同一份缓存，只有在缓存确实换代时才返回「问题变了」。
- 排除：改问题生成的提示词或质量；主办方界面。
