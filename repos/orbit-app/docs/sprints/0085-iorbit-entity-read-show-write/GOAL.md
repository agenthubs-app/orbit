# Sprint 0085 — IORBIT 对五种实体的读、展示、写

## 要实现什么

IORBIT 要成为商业活动管家：对人脉、活动、待办、日程、笔记五种实体，能读（作为 context 送给模型）、能展示（对话里的简洁小卡片，详情点进去看）、能写（Agent 起草、用户确认后真正创建）。现有"建议动作"小窗要变成可点击、可写入的创建入口；去掉每条回复下的"AI 运行依据"。个人记忆与个人信息不在本 Sprint。

## 做完能看到什么

- 对话里五种实体各有统一的小卡片；点卡片进入对应详情页。
- 说"根据这篇笔记整理一个待办"→ 出现待办草稿卡（标题／日期可改）→ 点确认 → 待办真的创建 → 卡片变为已创建并可点开；人脉、活动、日程、笔记同理。
- 用户说"确认"时，系统按状态机确认上一张草稿卡，而不是让模型用文字"演"确认。
- 回复下方不再有"AI 运行依据"面板。

## 怎么验收

设计案（含五种实体卡片规格、草稿→确认→创建→回读的状态机、写入接口清单、prompt 或 workflow 的拆解）先获批；实现后用 TODO 第 4 条那个 session 的原话在 Simulator 与 phoneweb 走通五种实体的创建；服务端与 App 单测覆盖状态机。
