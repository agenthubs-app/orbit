# Sprint 0099 — 每个请求一张读取小票

## 要实现什么

生产环境里，我们现在不知道每个接口、每个用户从 Neon 读走了多少数据。本 Sprint 让服务器在每个请求结束后写一张「小票」：哪个接口、替谁、读了几条查询、多少行、多少字节、数据库耗时、返回给客户端多少字节。

这是后面所有读取优化的计量基础：先记一周基线，之后每个方案上线都能量出实际效果。

## 做完能看到什么

- 本机打开 App 的任意页面，数据库里多出对应的小票，数字和测试里的读取成本账本一致。
- 小票同时以一行日志输出（只含账号指纹）；配置了 Axiom 密钥时也发一份到 Axiom，没配置时自动跳过。
- 数据库关掉或写小票失败时，请求本身照常成功。
- 代码里所有创建数据库连接池的地方都接上了计量器；以后新建连接池没接会被测试拦下。

## 怎么验收

本机跑读取成本账本里的操作，对照小票；故意让小票写入失败，确认请求不受影响。
