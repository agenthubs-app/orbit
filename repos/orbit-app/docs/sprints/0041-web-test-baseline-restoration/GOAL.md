# Sprint 0041 — 恢复可信的 Web 测试基线

## 要实现什么

让 Orbit Web 的测试重新成为可信门禁：不依赖外部服务的标准本地测试在干净工作树中稳定全绿；需要 PostgreSQL、浏览器运行证据或其他环境的集成测试拥有明确前置检查，在环境齐全时真实运行，缺少前置时以可操作的阻塞清单失败，而不是静默跳过或混入普通基线。

## 做完能看到什么

- `npm test` 只运行仓库定义的确定性 Web 测试，完整列举并覆盖所有不依赖外部环境的测试文件；新增测试不能因未登记而消失。
- `npm run test:integration` 在运行前检查实际所需的数据库和运行环境：条件齐全时执行真实集成测试，条件缺失时返回非零退出码并逐项说明缺什么。
- 当前已复现的产品审计、运行证据、活动 fixture、存储 provider、appointment 并发和 maintenance heartbeat 失败被逐项修复或归入有证据的集成档，不通过删除断言、扩大 skip 或改成假成功取得绿色结果。
- `npm run test:all` 在具备全部前置的环境中同时执行确定性与集成档，重新成为 Web 合并与发布收口门禁。

## 怎么验收

先在 Sprint 固定基线保存完整失败清单和脱敏环境摘要，再分别验证三个入口：标准本地档必须全绿；故意移除集成前置时，集成档必须输出准确阻塞并失败；恢复前置后，集成档和 `test:all` 必须全绿。还要用清单完整性测试证明每个 `tests/**/*.test.ts(x)` 恰好属于一个档位，不能遗漏、重复或靠文件名过滤隐藏失败。OAuth adapters 不在本 Sprint 范围，继续保留 TODO。

完整范围、执行顺序和验收证据见 [PLANNER.md](PLANNER.md)。本页不表示已经实现；状态以执行后的 `REPORT.md`、登记表和主线合并验证为准。
