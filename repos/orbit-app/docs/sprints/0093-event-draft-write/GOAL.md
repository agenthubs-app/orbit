# Sprint 0093 — 活动草稿写入：解开 source note 前置条件

## 要实现什么

0085 把草稿卡和状态机做好了，待办／笔记／日程三种已在真实库走通。活动的草稿能正常生成，但确认时被活动服务自己的前置条件挡下：`A source note is required before staging a manual event in the mock.`

本 Sprint 只做一件事：查清这条前置条件是产品规则还是 mock 遗留，然后让活动也能从草稿卡确认创建——或者在**确认之前**就把缺什么说清楚，而不是等到写入失败。

**人脉不在本 Sprint，也不在后续计划里。** 2026-09-19 用户决定：放弃"通过 AI 聊天添加人脉"这条路，人脉继续走既有的名片／二维码／手动录入／推荐确认流程。相关代码已在本 Sprint 一并移除，不是留着不用。

## 做完能看到什么

- 对 IORBIT 说"新建一个活动：10月10日上午10点在大阪办关西跨境商务对接会"→ 出活动草稿卡 → 确认 → 活动真的创建并可点开；
- 或者（若 source note 确属产品规则）草稿卡在确认前就说明需要来源笔记，并给出补来源的入口。

## 怎么验收

真实库走通一次"未确认不写入 → 确认后写入 → 回读 → 重复确认不重复写"；结论写清这条前置条件的性质。
