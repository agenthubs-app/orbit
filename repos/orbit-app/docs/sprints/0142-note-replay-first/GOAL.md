# Sprint 0142 — 笔记重传先认出「已经做过」

## 要实现什么

手机上传笔记修改时，服务器先查这条修改是不是已经做过；做过就直接返回上次的结果，再去检查活动、联系人和计划的权限。这样，已经存上但没收到回执的修改，不会因为之后权限变了（比如取消了活动报名）被当成失败扔掉。

## 做完能看到什么

- 笔记关联了一个已报名的活动，修改已存上但回执丢了；之后取消报名，再重传：服务器返回原来的结果，手机上「未同步」消失。
- 同样情况下的一次全新修改，仍然会因为没有权限被拒绝。
- 同一个修改编号、内容不同，仍然被拒绝。

## 怎么验收

服务器笔记服务的定向测试覆盖以上三种情况；orbits 笔记相关测试和类型检查通过。
