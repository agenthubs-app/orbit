# Sprint 0035 — 提供商无关的失效检测与恢复同步

## 要实现什么

让 Web、其他设备或服务器写入后，前台 App 通过轻量状态检查或已配置的可替换 transport 获知“需要同步”并拉取增量；即使提示丢失、App 长时间在后台或网络中断，也能在启动、回前台和手动刷新时通过 cursor 恢复一致。

## 做完能看到什么

- 同账号在 Web 修改笔记、待办、跟进或个人日程，前台 App 在一个状态检查周期内拉到最新 revision，不需要下载完整集合。
- App 在后台错过消息、离线数小时或杀进程后，重新打开仍会补齐全部变化和删除。
- 同一批高频提示会合并成一次同步，不形成请求风暴；断线重连使用有界退避。
- 状态响应或 transport 提示只携带水位与领域摘要，不含笔记正文、任务内容或其他个人数据；跨账号请求被拒绝。

## 怎么验收

以 PostgreSQL 状态接口、transport adapter、去抖协调器和 AppState 恢复测试覆盖重复、乱序、丢失、断线、账号切换和推送点击。再运行 production Web/API 与 Simulator，同账号实测前台有界更新、后台漏提示后的 cursor 修复和删除墓碑；不以 Supabase、Neon 或其他单一供应商作为完成前提。
