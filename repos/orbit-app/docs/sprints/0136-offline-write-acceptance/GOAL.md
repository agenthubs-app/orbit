# Sprint 0136 — 断网写全链验收

## 要实现什么

笔记、待办、日程、消息都能断网写之后，把它们放在一起再验一遍：四类同时有没传上去的修改时，杀进程、重装前后、换账号、服务器拒绝登录、服务器数据库出错，修改都不丢、不重复、不串到别人那里。验收通过后，把历史上被卡住的 0034、0035、0036 登记为「由新 Sprint 承接完成」。

## 做完能看到什么

- 一张覆盖四类数据和各种意外情况的验收表，每一格都有同一版本的证据。
- 统计一轮真实使用里冲突出现的次数，决定以后要不要自动合并不同字段。
- 登记表里 0034、0035、0036 的状态更新，写明由哪些 Sprint 承接。

## 怎么验收

「本机数据库扮演服务器」测试跑完整矩阵；Simulator 上同一账号四类各做一次断网修改，走一遍意外情况，恢复后在网页逐项读回。

完整验收项见 [PLANNER.md](PLANNER.md)。本页说明预期目标，不代表已实现；当前状态见[登记表](../README.md#sprint-登记表)。
