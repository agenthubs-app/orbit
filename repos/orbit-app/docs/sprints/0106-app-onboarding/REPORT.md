## 1. 结论

- 新增 `/profile/onboarding`：欢迎页加 5 步引导。登录后资料未完成的用户，以及从 `/profile/continue` 进入的用户，都会来到这里（不再跳到 `/profile?complete=1`）。
- 每一步点「继续」时依次执行：`PUT /api/profile` → 核对回执（mutationId、版本号前进、字段一致）→ `GET` 回读确认。遇到 409 时先重读再重发一次，第二次仍冲突就报错。
- 中途退出后再进入，会显示「继续设置你的资料（已完成 N / 5）」，从第一个未完成的步骤接着做。「稍后」直接跳到 `next`，不会锁住 App。
- 第 4 步：自我介绍为空时自动生成，「换一版」最多 3 次，只有成功才扣次数。失败时按 OnbStates C 显示，可以手写。
- 第 1 步「扫自己的名片」：原生端弹出「拍照 / 从相册选择」，用的是现有扫描接口。第 5 步「拍名片」打开现有的 `/contacts/new/batch2`。
- 保存失败时出现红色提示条和「重试」；断网时出现琥珀色提示条。两种情况下已填的内容都保留。
- **用户决定（2026-09-27）**：
  1. 完成的判定标准是「第 1–4 步都已保存」，保持子代理的实现。代价是：老用户如果没填「提供与寻找」或自我介绍，每次登录都会看到续填卡片，可以点「稍后」跳过。
  2. 第 3 步每组选项先显示 8 项，下面有「展开更多 / Show more / もっと見る」。已选的项即使排在 8 项之后也会显示；展开只作用于当前这一组。
- 中、英、日三种语言都能完整走完。没有新增服务端接口，也没有改网页端。

## 2. 与设计稿的差异（子代理说明，协调者认可）

- **生日**：用 `YYYY-MM-DD` 格式的文本框，没有用日期选择器。原因是日期选择器需要新的原生依赖，而现有的资料编辑器也是文本框。
- **行业**：点开后在下方展开整行列表。
- **日文用户的自我介绍会生成英文**：服务端 intro-draft 只支持中文和英文，网页版对非中文用户也发 `en`。
- **没有「iOrbit 预选了 2 项」这行提示**：它依赖 `seek-suggestions`，按 PLANNER 排除在范围外。
- **第 5 步的「已自动导入」改为「已导入」**：现有的导入流程不会自动确认名片，保留原文会不属实。
- **日文选项按日文保存**：网页端会把它们当作自定义标签显示，数据不会丢失。
