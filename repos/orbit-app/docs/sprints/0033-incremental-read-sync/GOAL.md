# Sprint 0033 — 增量读取同步

## 要实现什么

让 App 首次分页下载云端权威记录，之后只按不透明游标读取变化和删除；页面先读本地镜像，并按新鲜度决定是否联网，不再每次打开都下载整份数据。

## 做完能看到什么

- 笔记、待办（其中人脉跟进按 `category=relationship` 派生）和个人日程在重启 App 后能立即显示最近一次已同步内容，随后只拉取增量。
- 下拉刷新一定检查服务器；普通返回页面在 TTL 内不重复请求，过期、前台恢复或失效提示会触发增量同步。
- 服务端分页过程中发生并发写入也不会漏记录或重复记录；删除会通过墓碑从本地消失。
- 网络失败时继续显示明确标注同步时间的本地内容；没有本地内容时仍显示真实失败，不伪造空列表。

## 怎么验收

用服务端游标和真实 PostgreSQL migration 测试证明稳定快照、分页、actor/workspace 隔离和墓碑；用 App 测试证明 bootstrap、delta、TTL、手动刷新、可信 workspace 恢复、reset 和旧快照兼容迁移。最后重建并重启 Web/API，让 Simulator 与 Web 使用同账号，在 Web 改动四个领域后由 App 增量读到相同 revision。
