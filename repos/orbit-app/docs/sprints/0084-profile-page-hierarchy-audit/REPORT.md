# Sprint 0084 报告 — 资料与设置页的四角色排版

**状态:** completed。**run-01，唯一一次 Generator。**

## 先用人话说

编辑资料、设置、账号这些页面，把四种完全不同的东西压在同一个 15px 粗体上：**分组标题**（通用／基本资料）、**能点进去的入口**（权限中心／选择标签）、**字段标签**（名字／所在地）、**静态值或输入框**。读者只能靠右边那个灰色小箭头猜哪一行能点。

改法是把层级倒过来：**分组标题从全页最重变成全页最轻**（12px/600 灰），内容变成最重（16px）。可点的行同时具备三处差异——比标题大 4px、蓝色箭头、按下去底色变化——而不只靠箭头。

顺带修掉设置页最刺眼的一处：`服务器` 分组标题下面唯一那行也叫 `服务器`，同一个字符串上下相邻、只差一档字重。行标签改成 `当前服务器`。

八个页面命中，落在三个文件里（六个资料页共用一套 primitives）。

## 与 PLANNER 的偏差

**1. 范围比设计案列的窄，有据。** 设计案把活动详情、待办详情、个人日程编辑也列进来了。逐个看过源码后排除：这三处的 `sectionTitle` 领起的是正文段落（`EventDetailScreen:396/672/692` 的"关于""当天安排"）、弹层标题（`TaskDetailScreen:565`）和按日期分组的卡片列表（`ScheduleScreen:754`），它们下面**没有标签值行**，四角色不同列，本 Sprint 要修的那个毛病不存在。强行套规格只会让这些页的正文标题莫名其妙变小。排除理由逐条写在审核文档里。

**2. 规格没有放进 `textStyles.section`。** 仓里已有的 `textStyles.section`（15/800）被 65 个文件引用，覆盖全 App 的内容区段标题。改它等于把本 Sprint 扩大到每一个屏幕。新增 `rowRoleStyles` 只服务这四个角色。

**3. 设计案里一句话没有照字面执行，已定。** 设计案写"行标签改为'当前服务器'，与它跳转到的页面标题一致"，但目标页 `ApiSettingsScreen` 的标题仍是"服务器"。**决定保持现状**：设计案"需要你确认的三件事"里只写了改行标签；而且"服务器"作为一个独立页面的标题是准确清楚的，改成"当前服务器"反而别扭——列表里那种"上下两行同一个字符串"的歧义在页面标题上并不存在。该修的歧义已经修掉了。

**4. 两处实现细节是被测试逼出来的，值得记。**
- 四个角色最初都带了 `lineHeight`。原生 Dynamic Type 测试立刻红：它只缩放 `fontSize`，写死的 `lineHeight` 原地不动，两倍字号下标题被裁。这正是既有 primitives 一直不写 `lineHeight` 的原因。去掉，并把原因写进 token 注释。
- 设计案要求按压时**底色变化**。把 `pressed`（透明度）换成底色后 `app-wide-account` 红了——它把透明度下降当作"按压被立即响应"的证据。底色是**附加**区分度不是替代，两者都保留。
- 行标签从 15/22 变成 16 后设置页行高从 50 变成 50.5，`paddingVertical` 从 13.25 回调到 13，50pt 节奏不变。
