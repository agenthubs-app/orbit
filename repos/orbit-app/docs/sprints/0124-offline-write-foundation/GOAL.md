# Sprint 0124 — 断网写的地基：待上传队列与清空保护

## 要实现什么

断网写要先有地方放「还没传上去的修改」，而且这些修改在任何情况下都不能丢。本 Sprint 把手机上的待上传队列做成能用的：每条修改带唯一编号、按顺序上传、失败会重试、新建的临时编号上传后换成正式编号。同时改掉所有清空本地库的路径：清空之前，先把待上传的修改放进按账号加密的「保险箱」，同一账号重新登录后接着上传。服务器这边，数据库出错时不再被手机当成「账号被拒」。

本 Sprint 不开放任何一类数据的断网写，界面上不变；笔记从 0132 开始。

## 做完能看到什么

- 队列里的修改在断网、杀进程、重启后都还在，联网后按顺序上传；重复上传只算一次。
- 冷启动被拒、运行中收到 401、主动退出时，本地副本被删，但待上传的修改留在保险箱里；同一账号登录后它们到达服务器。
- 登录页在有保险箱时说明「这台设备上还有某账号的 N 项未同步修改」，登录其他账号前要确认。
- 服务器数据库出错时，手机按「连不上」处理，不清空。

## 怎么验收

手机端用真实 SQLite 和测试专用的类别跑队列、重试、临时编号和保险箱测试；「本机数据库扮演服务器」测试验证账号状态接口；Simulator 上演示清空路径保住队列。
