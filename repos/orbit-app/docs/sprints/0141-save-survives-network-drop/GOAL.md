# Sprint 0141 — 保存时网络断了，修改不丢

## 要实现什么

在待办和日程页面点保存时，如果请求刚好因为网络断开而失败，修改要存进待上传队列、标「未同步」，联网后自动传上去；不能再显示「操作失败」把修改丢掉。

## 做完能看到什么

- 待办列表里勾选完成、推迟，待办详情里改标题或日期：请求发出时断网，行上显示「未同步」，联网后服务器上能读到这次修改。
- 个人日程（不重复的）新建、编辑、删除：同样的情况，日历上显示「未同步」，联网后到达服务器。
- 服务器明确回了错误（比如 400、409、500）时，行为和现在一样，不会误进队列。

## 怎么验收

App 定向测试覆盖「请求在传输层失败」和「服务器回错误」两种情况；App 全量测试和类型检查通过。
