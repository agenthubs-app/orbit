# Sprint 0034 — 个人数据离线写入与冲突处理

## 要实现什么

让用户在断网时仍可确认新建、编辑或删除笔记、待办、已确认跟进和个人日程。App 将这些操作加密保存在当前账号的本机队列；恢复网络后按确认顺序提交，服务器以持久幂等回执保证重放不会重复生效。

本 Sprint 依赖 0033 已完成并合并的增量读取链路，以及 0033 Note DELETE 的数据库级 CAS 修复。没有这两个前置条件，不开放对应离线写入口。

## 做完能看到什么

- 断网保存后，列表和详情立即显示“仅本机，等待同步”；强制退出并重开 App 后仍可继续查看和处理。
- 恢复网络后，待同步标记只在服务器事务已经提交、canonical ID 和 revision 已原子落地到本机后消失；网络抖动或重复提交不会创建重复记录。
- 同一记录已在 Web 或其他设备变化时，App 不静默覆盖。用户能看到本机内容和云端内容，并按冲突类型选择使用云端、重新确认保留本机或另存副本。
- 关系跟进只能从加密的已同步联系人资格快照离线创建；上传时服务器会重新核验资格，已失效的关系不会被写入。
- 登录过期不会删除待同步内容；它会被锁在原账号 scope，只有同一账号重新认证后才能继续。主动登出若存在待同步内容，必须先明确确认数据处理结果。
- 邀请、报名、共享 meeting、权限、账号删除和 AI 外部动作断网时明确不可用，不进入离线队列。
- Web 和 Orbit AI 只看到服务器已确认的 canonical 内容；本机待同步草稿不会被冒充为已经上传。

## 怎么验收

以真实 PostgreSQL、加密 SQLite、production Web/API 和 iOS Simulator 完成四域离线 create/update/delete、强制重启、同实体 FIFO、重放、账号切换、会话过期、三类冲突及关系资格失效验收。同账号 Web 必须回读相同 canonical ID/revision；AI 在确认前只能读旧云端值，确认后才能读新值。
