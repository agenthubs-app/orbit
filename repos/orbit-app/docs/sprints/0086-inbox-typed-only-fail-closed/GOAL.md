# Sprint 0086 — 收件箱只认三类通知，无法归类的记录读取即失败

## 要实现什么

收件箱现在出现大量"来源已不可用"条目。调查结论：三类通知（提醒／建议／动态，Sprint 0038）已合入主线，但被 `ORBIT_TYPED_INBOX_ACTORS` 账号白名单关着，开发环境没有配置，所以对所有账号都是关闭态；App 收件箱因此仍读旧的 `/api/notifications`，那条旧链把种子里 40 条"复核与 X 的下一步"生成记录和目标已丢失的 reminderPlans 直接标成"来源已不可用"（0046 加的安全提示）。0040 的旧数据迁移代码存在，但从未对开发库执行。

本 Sprint 按 2026-09-16 通知设计执行到底：三类通知成为唯一收件箱来源；不满足内容门槛的旧记录按设计隔离而不展示；读取路径对"无法归类"的记录直接失败并报错，而不是渲染一条看不懂的占位。

## 做完能看到什么

- 收件箱通知页只出现提醒／建议／动态三类，每条有具体标题、原因、来源、时间与主操作；不再有"来源已不可用"。
- 旧的 40 条生成记录与失效 reminderPlans 被迁移隔离，留有可审计记录；不会作为未读出现。
- 如果库里再出现无法归类或来源不可解析的通知记录，`/api/inbox/notifications` 返回明确错误码，App 显示"收件箱数据异常（代码）"，而不是把它们混进列表。
- `ORBIT_TYPED_INBOX_ACTORS` 白名单退役，三类通知默认对所有账号生效。

## 怎么验收

本机库先复现"来源已不可用"，跑迁移后消失；注入一条坏记录 → 接口失败、App 提示；Simulator 与 phoneweb 收件箱截图；两端全量对照。
