## 1. 结论

- **104-A 草稿迟到回执（P2）**：App 和网页都已修好。「已保存」只绑定发起保存时的那段正文和当时所在的会话；保存还没完成时继续编辑，界面保持「未保存」；同一时间只允许一个保存请求。保存过程中切换会话或账号，旧的回执会被丢弃。
- **104-C 发送后草稿复现（已复现并修复）**：真库测试在修复前失败——已经发出去的正文被当成草稿读了回来。现在由服务端在发送请求内部，清掉「发送时刻及以前保存的草稿」；发送之后再写的草稿，即使同一个请求重试也不会被删。两端去掉了原来那次失败也不报错的清空请求。
- **104-B 未读数（P2）**：App 直接用服务端返回的全局未读总数，不再对跳过的条目按 `readAt` 扣减。dismissed、scheduled、unavailable 三种都不会少算，多页结果的口径一致。「全部已读」只有在列表里确实有可读的未读条目时才可点。
- **98-C**：App 的通知筛选补上了 `aria-selected`。原来只设了 `accessibilityState`，react-native-web 不会把它输出到网页上。网页端本来就是对的，补了一条断言。
- **103-A**：App 的 All Actions 和网页的「建议与行动」都加了「加载更多」，按 cursor 一直翻到最后一页。页末文案写「已加载全部 N 条」，不会把最后一页的条数说成总数。
- **99-C**：管理页和「读取量翻倍」报警的文案改为「只统计记录了数据库读取的请求」；用户排行注明不含未归属的读取。
- **101-A**：服务端本来就把未知的能力声明当作没有声明。这次加强了真库测试，并做了变异检查。
- **0103 时钟测试**：运行时和请求记录共用同一个注入的时钟，分别在 2020 年、冲刺当天、2099 年三个时间点跑，全部通过。
