# Sprint 0093 — 人脉与活动的草稿写入：解开两处既有阻挡

## 要实现什么

0085 把五种实体的草稿卡、状态机和写入适配器都做好了，待办／笔记／日程三种已在真实库走通。剩下两种各被一处**既有**机制挡住，且都不是 0085 能顺手改的：

- **人脉**：一条既有安全护栏在模型跑之前就拦下了"把某某添加为联系人"这类措辞；
- **活动**：活动服务自己要求先有 source note 才能创建。

本 Sprint 只做一件事：分别决定这两处怎么放行，然后让人脉与活动也能从草稿卡确认创建。

## 做完能看到什么

- 对 IORBIT 说"把王一凡添加为联系人，梅田餐饮的投资合伙人"→ 出人脉草稿卡 → 确认 → 落成联系人草稿 → 跳既有确认页转正。
- 说"新建一个活动：10月10日上午10点在大阪办关西跨境商务对接会"→ 出活动草稿卡 → 确认 → 活动真的创建并可点开。
- 两条既有机制放行的边界写清楚：放行了什么、没放行什么、为什么仍然安全。

## 怎么验收

两种实体各在真实库走通一次"未确认不写入 → 确认后写入 → 回读 → 重复确认不重复写"；既有护栏对**未经草稿卡**的直接写入企图仍然拦截。
